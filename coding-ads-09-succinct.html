簡潔データ構造 ― 情報理論の最小値まで空間を削る

「要素数 n に比例した空間」はまだ太っている。rank/select を軸に、情報理論の下限 OPT まで切り詰める

← MIT 6.851 シリーズ目次へ ← コーディング基礎シリーズ目次へ

これまでの回では「時間」を削ることに集中してきました。この回は「空間」が主役です。多くの「線形空間」のデータ構造は、実は $O(n)$ ワード = $O(n\log n)$ ビットを使っていて、情報理論的に必要な最小ビット数 (OPT と呼びます) からはまだ遠い位置にいます。木の形・ビット列・順列のような「構造そのもの」を、できるだけ OPT に近いビット数で保持しながら、ナビゲーション (親・子・部分木サイズ) を定数時間で答える ― それが 簡潔データ構造 (succinct data structure) です。鍵になる道具が rank (ここまでに 1 はいくつあるか) と select (何番目の 1 はどこにあるか) で、この 2 つの O(1) 演算さえ手に入れば、木を「ビット列」として持つだけでナビゲーションが全部手に入ります。後半では同じ発想を文字列検索の主役である接尾辞配列・接尾辞木に適用し、ゲノム解析の実務で今も使われている FM-index / BWT の直接の土台を見ます。

この回の位置づけ

これまでの回 (二分探索木・ハッシュ・整数データ構造) は「クエリをどれだけ速く答えるか」を競っていましたが、どれも暗黙に「ポインタ 1 個・整数 1 個は 1 ワード ($w$ ビット、実務ではおよそ 32〜64 ビット) のコストがかかる」という前提を置いていました。$n$ 個のポインタを持つ構造は $O(n)$ ワード = $O(n\log n)$ ビットです。しかし、たとえば「$n$ 個のノードを持つ二分トライの形」そのものを表現するのに本当に必要なビット数は、形の種類の数を 2 進対数で数えるだけで求まり、$O(n)$ ビットで足ります。この「ワード単位で考えるか、ビット単位で考えるかで $O(\log n)$ 倍もの差がある」というギャップが、この回の全てです。前提として、情報理論的下限を数える数え上げ論法と、木の種類に関する基本用語を先に補習します。

前提の補習 (1) 情報理論的下限 ― 「あり得る形の数」を数えて下限を出す

あるデータ構造が取り得る「形」の種類が $N$ 通りあるなら、どの形なのかを区別するために最低 $\lceil\log_2 N\rceil$ ビットが必要です (さもないと異なる 2 つの形が同じビット列になり、区別できなくなってしまう)。これが数え上げ論法による情報理論的下限で、この回では OPT (情報理論的に最適な空間) をこの方法で求めます。たとえば、$n$ 要素の順列は $n!$ 通りあるので、順列を表すには $\log_2(n!) \approx n\log_2 n$ ビットが必要です。逆に言えば、「形の種類を数える」→「log を取る」の 2 ステップだけで、どんなに複雑な構造でも下限が出せます。この回で繰り返し使うのは、$n$ ノードの二分トライの形の種類を数えるステップで、これにはカタラン数 $C_n = \frac{1}{2n+1}\binom{2n}{n} \approx 4^n$ が登場します ($\binom{2n}{n}$ は「$2n$ 個から $n$ 個選ぶ」組み合わせの数で、統計の場合の数の計算と同じものです)。よって $n$ ノードの二分トライの OPT は $\log_2(4^n) = 2n$ ビット程度、ということがこの数え上げだけでわかります。

図: 形の総数の対数が、区別に絶対必要な最小ビット数 (OPT) になる

前提の補習 (2) 二分トライ・順序木・括弧列 ― この回で行き来する 3 つの表現

  • 二分トライ (binary trie): 各ノードが「左の子」「右の子」をそれぞれ持つか持たないかを自由に選べる木。BST (二分探索木) と違い、ノードは値を持たず、形そのものが情報です。
  • 順序木 (ordered tree): 各ノードが 0 個以上の子を順序付きで持てる木 (子の個数に制限がない代わりに「子なし」は許されない数え方をする)。
  • 括弧列 (balanced parentheses): ( と ) が正しく対応した文字列。木を深さ優先探索 (DFS) でなぞり、ノードに最初に触れたとき (、2 回目に触れたとき ) を書き出すと得られます。

この 3 つは $n$ ノードに対してどれもちょうど $C_n$ (カタラン数) 通りの形を持ち、互いに 1 対 1 に対応します (全単射、bijection)。この回では「二分トライでは簡単に書けない部分木サイズの計算が、括弧列に移ると rank/select だけで書ける」という場面で、この対応関係を実際に使います。

L17. 簡潔な二分トライと rank/select

implicit / succinct / compact ― 3 段階の空間効率

名前空間意味例
implicit (暗黙)$\mathrm{OPT}+O(1)$データの並べ替え (順列) だけで表現する。ポインタさえ持たない二分ヒープ、ソート済み配列
succinct (簡潔)$\mathrm{OPT}+o(\mathrm{OPT})$先頭の係数が 1 (OPT の定数倍にならない余剰のみ許す)この回のほぼすべての構造
compact (コンパクト)$O(\mathrm{OPT})$定数倍は許すが $w$ 倍のような余計な因子は持たない多くの「$O(n)$ ワード」構造を $O(\mathrm{OPT}\,\mathrm{bits})$ に落としたもの

達成の難度は implicit が最も高く、compact は succinct に近づくための足場としてよく使われます。この回で主役になるのは succinct です。

ミニサーベイ ― 何がどこまで分かっているか

  • 簡潔な辞書。 値域 $u$ から $n$ 個を選ぶ選び方は $\binom{u}{n}$ 通りなので $\mathrm{OPT}=\log\binom{u}{n}$ ビット。これに近い空間で $O(1)$ membership クエリを答える構造が知られています。
  • 簡潔な二分トライ。 $n$ ノードの二分トライの形は $C_n\approx 4^n$ 通りあるので $\mathrm{OPT}\approx 2n$ ビット。$2n+o(n)$ ビットで左の子・右の子・親を $O(1)$ で答える構造が、この節の主役です (もともとの動機は「オックスフォード英語辞典を CD に収める」という実用上の空間制約でした)。
  • ほぼ簡潔な $k$ 分トライ。 $(\lceil\log k\rceil+\lceil\log e\rceil)n+o(n)+O(\log\log k)$ ビットで、子のラベル指定・親・部分木サイズを $O(1)$ で答える構造が Benoit, Demaine, Munro, Raman, Raman, Rao によって示されています。
  • 簡潔な順序木。 $n$ ノードの順序木も $C_n$ 通り ($\mathrm{OPT}=2n$ ビット)。Clark と Munro が $2n+o(n)$ ビットで $i$ 番目の子・親・部分木サイズを $O(1)$ で答える構造を示しました。
  • 簡潔な順列。 $\pi^k(i)$ (順列を $k$ 回適用した位置) を答えるクエリに、$(1+\varepsilon)n\log n+O(1)$ ビット・$O(1)$ 時間、または $\lceil\log n!\rceil+o(n)$ ビット・$O(\log n/\log\log n)$ 時間の構造が知られています。
  • 整数の implicit な表現。 $n$ ビット整数の increment/decrement を $O(\log n)$ ビット読み・$O(1)$ ビット書きで行えますが、$O(1)$ ワード演算で済ませられるかは OPEN です。

レベル順表現 ― 二分トライをビット列として書き出す

二分トライを根から 1 段ずつ、各段の中では左から右に訪れるレベル順で並べ、各ノードについて「左の子を持つか (1/0)」「右の子を持つか (1/0)」の 2 ビットを書き出します。$n$ ノードなら $2n$ ビットで、$\mathrm{OPT}\approx 2n$ にちょうど一致します。

図: A-B-C-D-E-F-G をレベル順に訪れ、各ノードの (左の子, 右の子) の有無を 2 ビットで書く (lec17 の例)

外部ノード形式 (external node formulation) では、存在しない子を外部ノードとして明示的に数え、レベル順に「内部ノードなら 1、外部ノードなら 0」を 1 ビットずつ書きます。$n$ ノードの二分トライには外部ノード (空いている枝) がちょうど $n+1$ 個あるので、全体で $2n+1$ ビットになります (先頭に根の分だけ 1 ビット多い以外は、2 ビット版と同じ内容です)。

定理: $i$ 番目の内部ノードの子は位置 $2i,2i+1$

Theorem (lec17). 外部ノード形式のビット列で、$i$ 番目の内部ノードの左右の子は位置 $2i$ と $2i+1$ にある。
証明の骨格 (帰納法)。 $i=1$ (根) では、ビット列の最初の 1 エントリが根自身で、位置 $2,3$ がその子なので成立。$i>1$ では、帰納法の仮定により $i-1$ 番目の内部ノードの子は位置 $2(i-1),2(i-1)+1$ にある。レベル順は「子の順序も親の順序を保つ」(親が先に現れるノードの子は、後に現れる親の子より先に現れる) ので、$i-1$ 番目と $i$ 番目の内部ノードの間にあるノードはすべて外部ノード (子を持たない) であり、$i$ 番目の内部ノードの子は $i-1$ 番目の子のすぐ後、つまり位置 $2i,2i+1$ に続く。

この定理の系として、位置 $i$ の親は位置 $\lfloor i/2\rfloor$ の内部ノードです。問題は、ビット列の「位置」(何ビット目か) と「それが何番目の内部ノード (= 1 の数で数えた順位) か」の変換を $O(1)$ でできるかどうかにかかっています。

rank と select ― 2 つの演算で木の航行が手に入る

$n$ ビットの文字列に対して次の 2 つの演算を $O(1)$ 時間・$o(n)$ 追加空間で行えると仮定します。

  • rank(i) = 位置 $i$ 以前にある 1 の個数
  • select(j) = $j$ 番目の 1 がある位置

これだけで、レベル順ビット列 (空間 $2n$ ビット) の上に次のクエリが作れます。

  • left-child$(i)$ = $2\cdot\mathrm{rank}(i)$
  • right-child$(i)$ = $2\cdot\mathrm{rank}(i)+1$
  • parent$(i)$ = $\mathrm{select}(\lfloor i/2\rfloor)$

合計空間は、ビット列の $2n$ ビットに rank/select 用の $o(n)$ ビットを足した $2n+o(n)$ ビットで、まさに succinct の定義 ($\mathrm{OPT}+o(\mathrm{OPT})$) を満たします。ただしレベル順表現は「深さ」の情報を直接持たないため、部分木サイズは計算できません (これは後述の括弧列表現で解決します)。

Rank の実現 ― 2 段の間接化 (Jacobson, 1989)

素朴に「$k=\frac12\log n$ ビットごとのチャンクに分けて、チャンクごとの累積 rank を保存する」だけでは、チャンク数が $n/k=O(n/\log n)$ 個、各累積 rank に $\log n$ ビット必要で、合計 $\Theta(n)$ ビットになってしまい space が吹っ飛びます。正しい作り方は 2 段の間接化です。

  1. 長さ $\frac12\log n$ のビット列すべてに対する rank 問い合わせの答えをルックアップテーブルに前計算する。長さ $\frac12\log n$ の文字列は $2^{\frac12\log n}=\sqrt n$ 通りしかなく、各クエリの答えは $O(\log\log n)$ ビットで書けるので、テーブル全体は $O(\sqrt n\log n\log\log n)=o(n)$ ビット。
  2. $n$ ビット全体を長さ $\log^2 n$ のチャンクに分け、各チャンクの終わりに「ここまでの累積 rank」を $\log n$ ビットで保存する。チャンク数は $O(n/\log^2 n)$ 個なので、合計 $O(n/\log n)$ ビット。
  3. 各チャンクをさらに長さ $\frac12\log n$ のサブチャンクに分け、サブチャンクの終わりに「チャンク内での累積 rank」を $O(\log\log n)$ ビットで保存する (チャンク自体が $\log^2 n$ しかないので、チャンク内の rank は $\log\log n$ ビットで足りる)。サブチャンク数は $O(n/\log n)$ 個なので、合計 $O(n/\log n\cdot\log\log n)=o(n)$ ビット。
  4. クエリ rank$(i)$ = (チャンクの累積 rank) + (サブチャンク内の累積 rank) + (サブチャンク内の残りをルックアップテーブルで見る)。3 つすべて $O(1)$ なので合計 $O(1)$。

図: チャンク (log²n ビット) → サブチャンク (½log n ビット) → ルックアップテーブルの 3 層構造

この構成で空間は $O(n\frac{\log\log n}{\log n})=o(n)$ ビット、時間は $O(1)$。(任意の定数 $k$ について $O(n/\log^k n)$ まで改善できますが、講義では扱いません。)

Select の実現 (Clark & Munro, 1996)

select は「同じサイズの区間」ではなく「同じ数の 1 を含む区間」で分割する点が rank と対照的です。$\log n\log\log n$ 個ごとの 1 を「特別な 1」として、その位置を $O(1)$ 個ずつ記録 ($O(n/\log\log n)$ ビット。これで大まかな位置にテレポートできます)。残った範囲は、1 が疎であれば (その分だけ区間が長くなるが、該当するチャンクの個数自体が少ないので) 位置を全部書いても安い、1 が密集していれば (区間はまだ短いが、さらに細かく絞らないとルックアップ表に収まらない) 中身をさらに再帰的に分割する、という疎密で分岐する再帰を行い、最終的に $O(\frac12\log n)$ 以下の範囲に落として rank と同じルックアップテーブルに帰着させます。最終的な空間は $O(n/\log\log n)$ ビット、時間は $O(1)$。

部分木サイズは括弧列で ― 3 つの表現の全単射

レベル順表現は深さの情報を捨てているので部分木サイズを計算できません。そこで「二分トライ ⇔ 順序木 ⇔ 括弧列」という全単射を使います。二分トライの右スパイン (根から右の子をたどり続けた経路) を「兄弟列」とみなして 45° 回転させると順序木になり、順序木を DFS でなぞって最初に触れたノードに (、2 回目に ) を書けば括弧列が得られます。

デモ ・ rank(i) / select(j) の 3 段計算

読み取り。どちらの演算も「まず粗い単位 (チャンク) で大まかな位置に飛び、次に細かい単位 (サブチャンク) で絞り、最後に小さな範囲だけを表引きする」という同じ 3 段の形をしています。チャンク・サブチャンクのサイズを $n$ に応じて正しく選ぶ (本文の $\log^2 n$ と $\frac12\log n$) ことで、この 3 段すべてが $O(1)$ になり、かつ合計の追加空間が $o(n)$ に収まります。

L18. 圧縮接尾辞配列・接尾辞木

テキスト $T$ (長さ $|T|$、アルファベット $\Sigma$) の中でパターン $P$ を探す標準的な道具が接尾辞配列 (suffix array): $T$ のすべての接尾辞 (ある位置から末尾までの部分文字列) を辞書順に並べた配列で、各エントリは接尾辞の開始位置だけを整数で持ちます。$P$ の検索は接尾辞配列上の二分探索で行えます。素朴な接尾辞配列・接尾辞木は $O(n)$ ワード ($O(n\log n)$ ビット) を使うので、テキスト $T$ を保存するだけに要る $|T|\log|\Sigma|$ ビットという情報理論的な OPT からは遠い ― これを近づけるのが今回の主題です。

サーベイ ― どこまで OPT に近づいたか

研究空間 (ビット)クエリ時間

Ferragina, Manzini, Mäkinen & Navarro$H_k(T)\cdot|T| + O(|T|/\lg^{\varepsilon}n)$$O(|P| + |\text{output}|\cdot\lg^{1+\varepsilon}|T|)$

ここで $H_k(T)$ は$k$ 次の経験エントロピーです。統計でいう条件付きエントロピーそのもので、「直前の $k$ 文字 $w$ がわかっているとき、次の文字の分布がどれだけ散らばっているか」を表します。

$H_k(T)=\sum_{|w|=k}\Pr\{w\text{ が出現}\}\cdot H_0(w\text{ の直後に続く文字})$

テキストの文字が完全にランダムで予測できないなら $H_k(T)$ は $\log|\Sigma|$ に近く、$|T|\log|\Sigma|$ ビット (単純に文字を並べるのと同程度) が必要です。しかし自然言語やゲノム配列のように「直前の文字列から次の文字がかなり予測できる」テキストでは $H_k(T)\ll\log|\Sigma|$ になるので、$H_k(T)\cdot|T|$ ビットという目標は、テキストの冗長性に応じて本当に必要な分だけ空間を使う、という狙いです。これは $|T|\log|\Sigma|$ ビットよりも厳しい (小さい) 目標になり得ます。

圧縮接尾辞配列の作り方 ― 文字を 2 つずつ畳み込む

アルファベットを二進 ($|\Sigma|=2$) とし、$T_0=T$・$n_0=n$・$SA_0=SA$ から始めて、隣り合う 2 文字を 1 文字に畳み込んでいきます。

$T_{k+1}=\big(T_k[2i],T_k[2i+1]\big)_{i=0,1,\dots}, \quad n_{k+1}=n_k/2$

そして「偶数番目の接尾辞 (= $T_k$ 上での開始位置が偶数のもの) だけを取り出して 2 で割る」ことで $SA_{k+1}$ が得られます。これは $SA_k$ から $SA_{k+1}$ への変換なのでトップダウンでは簡単ですが、クエリ $SA_0[i]$ を答えるには逆にボトムアップ、つまり小さい方から大きい方を復元する必要があり、そのために 3 つの関数を定義します。

  • is-even-suffix_k(i): $SA_k[i]$ が偶数の接尾辞かどうか
  • even-succ_k(i): $i$ 自身が偶数ならそのまま $i$。奇数なら、$SA_k[i]$ のすぐ次の接尾辞 ($SA_k[i]+1$) に対応するインデックス $j$
  • even-rank_k(i): $i$ 番目の接尾辞より手前にある「偶数の接尾辞」の個数 (= is-even-suffix_k をビット列と見た rank)

これらを使うと次の式で $SA_k$ を $SA_{k+1}$ から引き戻せます。

$SA_k[i] = 2\cdot SA_{k+1}\big[\,\mathrm{even\text{-}rank}_k(\mathrm{even\text{-}succ}_k(i))\,\big] - \big(1-\mathrm{is\text{-}even\text{-}suffix}_k(i)\big)$

直感的には、$i$ が偶数接尾辞ならそのまま 1 段下の配列を引いて 2 倍するだけ。奇数なら「1 つ次の (偶数の) 接尾辞」の答えを同じ式で求めてから 1 を引く、というだけです。is-even-suffix はビット列として $o(n_k)$ の rank 構造で持てるので、1 段の変換は $O(1)$。再帰を $\ell$ 段 ($\ell=\lg\lg n$ 程度) で止めれば、クエリは $O(\ell)$ 時間、最下層 ($n_\ell=n/\lg n$ 程度) は素朴な接尾辞配列で $O(n)$ ビットに収まります。ただし各段の補助構造を全部足すと $\tfrac12 n\lg\lg n+5n+O(\cdots)$ ビットになり、これは圧縮 ($O(n)$ ワード止まり) ではあっても、まだ compact ($O(n)$ ビット) ではありません ($\lg\lg n$ という余計な因子が残っています)。

コンパクト接尾辞配列 ― 段を飛ばして因子を消す

この $\lg\lg n$ の因子を消すには、すべての段を保持するのではなく、$0,\varepsilon\ell,2\varepsilon\ell,\dots,\ell$ ($\ell=\lg\lg n$) という$1+1/\varepsilon$ 段だけを保持し、一度に $\varepsilon\ell$ 段分 (つまり文字を $2^{\varepsilon\ell}$ 個ずつ) まとめて畳み込みます。「偶数」の定義を「$Tk\varepsilon\ell$ 上の位置が $2^{\varepsilon\ell}$ で割り切れるか」に変えるだけで、同じ even-succ・even-rank の仕組みがそのまま使えますが、1 回の変換で $2^{\varepsilon\ell}$ 回分の「次の偶数接尾辞」を辿る必要があるため、1 段あたり $O(2^{\varepsilon\ell})$ 時間かかります。段の数は $1+1/\varepsilon$ 個なので、クエリ全体の時間は

$O(2^{\varepsilon\ell}\lg\lg n) = O(\lg^{\varepsilon}n\cdot\lg\lg n) = O(\lg^{\varepsilon'}n) \quad (\varepsilon'>\varepsilon)$

になります。各段の補助構造 (差分の単項符号化 + is-even-suffix の rank 構造) を合計すると $(6+1/\varepsilon)n+o(n)$ ビット程度になり、さらに「どうせ使わない段の even-succ を省く」「is-even-suffix を疎なビット列として簡潔な辞書で持つ」といった最適化を加えると $(1+1/\varepsilon)n+o(n)$ ビットまで落とせます。これで空間は正しく $O(n)$ ビット (compact) になり、時間は $O(\lg^{\varepsilon}n)$ 程度 (正確には任意の $\varepsilon'>\varepsilon$ で $O(\lg^{\varepsilon'}n)$) で両方が成り立ちます。

デモで使う具体例 (本文の数値例)

講義ノートの具体例をそのまま使います。$n=8$ の接尾辞配列が $SA_0=[1,2,6,5,7,4,3,8]$ のとき、偶数の接尾辞だけを取り出して半分にすると $SA_1=[1,3,2,4]$ になります。下のデモでこの変換を実際にトレースします。

デモ 2. 圧縮接尾辞配列 ― $SA_0 \to SA_1$ を実際に辿る

デモ ・ is-even-suffix / even-succ / even-rank を実行

$SA_0=[1,2,6,5,7,4,3,8]$ (1-indexed の開始位置)。位置 $i$ (1〜8) を選ぶと、$SA_1[\mathrm{even\text{-}rank}(\mathrm{even\text{-}succ}(i))]$ を実際に計算し、公式で $SA_0[i]$ を復元して元の値と一致するか確認します。

読み取り。$SA_1$ だけ (半分のサイズ) から $SA_0$ の全エントリが復元できる、というのがこの圧縮の本質です。これを $\ell=O(\lg\lg n)$ 段繰り返すとクエリは $O(\ell)$ 時間になり、最下層は $n/\lg n$ 程度まで小さくなりますが、全段の補助構造を単純に足すと $\lg\lg n$ という余計な因子が残ります (次の「コンパクト接尾辞配列」で、段を飛ばすことでこの因子を消します)。

接尾辞木への拡張 ― 括弧列 + その場で計算する文字深さ

接尾辞木 (共通の接頭辞をまとめた木構造) も同じ発想で圧縮できます。木の形そのものは L17 の括弧列表現で $4n+o(n)$ ビットに収まりますが、各辺の長さ (文字深さ) までは空間の都合で持てません。そこで検索中に文字深さをその場で計算します。あるノード $x$ から子 $y$ に下るとき、$y$ の文字深さは「$y$ の部分木の中で最も左の葉」$\ell$ と「最も右の葉」$r$ が何文字共通しているかで決まります。$\ell,r$ の接尾辞配列上の位置がわかれば、テキスト上で $x$ の文字深さ分だけ読み飛ばした続きを $\ell,r,P$ で同時に比較し、$\ell,r$ が分かれる位置が $y$ の文字深さになります。この「葉を探す」操作は括弧列上の rank/select で書けます。

操作意味式
leaf-rank(here)この位置より左にある葉の数$\mathrm{rank}_{())}(\text{here})$ (文字列 ()) の出現数で rank)
leaf-select(i)$i$ 番目の葉の位置$\mathrm{select}_{())}(i)$
leaf-count(here)この位置の部分木に含まれる葉の数$\mathrm{rank}_{())}(\text{親の対応する}\mathtt{)}) - \mathrm{rank}_{())}(\text{here})$
leftmost-leaf(here)部分木の最も左の葉$\mathrm{leaf\text{-}select}(\mathrm{leaf\text{-}rank}(\text{here})+1)$
rightmost-leaf(here)部分木の最も右の葉$\mathrm{leaf\text{-}select}(\mathrm{leaf\text{-}rank}(\text{親の対応する}\mathtt{)}) - 1)$

これにより、パターン検索全体のコストは $O(|P|+|\text{output}|)\times O(\text{接尾辞配列の 1 回の参照コスト})$ になります。Grossi と Vitter はこれを改良し、$O(|P|/\log_\Sigma|T| + |\text{output}|\cdot\log_\Sigma^{\varepsilon}|T|)$ まで高速化しました。

簡潔な接尾辞木 (Munro, Raman, Rao)

パターンが短い ($|P| \lt b$) 場合は、長さ $b$ のすべてのビット列に対する答えをあらかじめルックアップテーブルに持たせます ($2^b$ エントリ、各 $O(\log n)$ ビットなので $b \lt \frac13\log n$ なら $O(\sqrt n)$ ビット)。長い場合は接尾辞配列を長さ $b$ のブロックに分け、各ブロックの先頭の接尾辞だけを集めた接尾辞木を作って ($O(n/b)$ ビット)、まずそこで大まかな範囲を絞り、別のルックアップテーブル (サイズ $b$ の文字列同士の比較を前計算したもの) で $b$ 文字ずつ読み進めます。読み進む回数は $|P|/b$ 回で、各回 $O(b)$ 時間のテーブル引きなので、合計 $O(|P|)$ 時間で範囲が絞れます。これは「1 文字ずつ比較する」のではなく「$b$ 文字をまとめて 1 回のテーブル引きで処理する」という、ちょうど $b$ 文字分をまとめて読むビット詰めの発想です。

OPEN (lec18). 圧縮接尾辞配列のクエリ時間を $O(n)$ 空間のまま $o(\lg^{\varepsilon} n)$ まで下げられるかは未解決です。

実務での出番 ― 正直な評価

  • rank/select そのもの (強く実在する)。 ビット列に対する rank/select は、簡潔データ構造ライブラリ sdsl-lite (rank_support・select_support) にこの講義の 2 段分割の考え方に近い実装として入っています。sdsl-lite はバイオインフォマティクス・検索エンジンの研究実装で広く使われている C++ ライブラリです。
  • FM-index / BWT (強く実在する。ゲノム解析の主力)。 lec18 が引用する Ferragina & Manzini の "Indexing Compressed Text" は、Burrows-Wheeler 変換 (BWT) されたテキストの上に rank 操作だけで検索を行う FM-index の提案論文です。これは現在もショートリード (次世代シーケンサが出す短い DNA 配列) をゲノムに貼り付ける (アライメントする) ツールの主力方式で、BWA や Bowtie2 はいずれも FM-index (およびその発展形) を検索の核に使っています。本講義で扱った圧縮接尾辞配列は Grossi-Vitter の系列で、FM-index (Ferragina-Manzini の系列) とは厳密には別の構成ですが、どちらも「接尾辞配列を rank/select で圧縮して持つ」という同じ目標を共有する近い親戚です。
  • 括弧列・簡潔な木 (実在するが用途は限定的)。 sdsl-lite には bp_support という括弧列ナビゲーション構造があり、この講義のまま使われています。検索エンジンの用語辞書に使われる Lucene の FST (Finite State Transducer) は目的 (圧縮された木構造で文字列を検索する) は似ていますが、構成技術は有限オートマトン的なもので、この講義の rank/select ベースの手法とは別物であることは明記しておきます。
  • 静的であることの制約は実務にそのまま響く。 L17 で述べたとおり「厳しい空間制約は動的構造と相性が悪い」ため、簡潔データ構造はほぼ常に静的 (構築後は変更しない) です。頻繁に更新が入るデータベースのインデックスにそのまま使われることは少なく、検索対象が固定されるバッチ的な用途 (全文検索のインデックス構築、ゲノムのリファレンス配列、辞書の配布) で主に使われます。
  • 圧縮接尾辞配列・圧縮接尾辞木そのもの (理論と実務の橋の上)。 Grossi-Vitter や Sadakane の具体的な構成をそのまま実装したライブラリは専門的な文字列処理ライブラリ以外では稀ですが、「エントロピー圧縮したテキストの上で検索する」という設計目標自体は FM-index 系の実装に直接引き継がれており、バイオインフォマティクスでは理論と実務の距離が他の回よりずっと近いトピックです。
