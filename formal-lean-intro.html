この回の前提: 第 16 回 induction タクティクで帰納法を証明に変える

これまでの 5 回は Rocq という証明支援系を使ってきました。ここで Lean 4 というもう 1 つの証明支援系に乗り換えます。道具が変わっても、第 16 回から見てきた「帰納法」「証明は項である」という考え方そのものは変わりません。変わるのは書き方だけです。Lean は、非営利団体 Lean FRO (Lean Focused Research Organization) が開発を進めている証明支援系で、数学を形式化した大規模ライブラリ Mathlib (100 万行を超える) の基盤としても使われています。この回では Lean 4 の基本の文法を見て、Rocq との対応を確認します。

1. Lean 4 は証明支援系であり、プログラミング言語でもある

Lean 4 では、普通の関数は def で定義し、#eval でその場で計算結果を確かめられます。

def double (n : Nat) : Nat :=
  n + n

#eval double 21

#eval double 21 は 42 という計算結果を表示します。ここまでは普通のプログラミング言語と同じです。Lean 4 が証明支援系であるのは、この同じ言語の中に「命題を書く」theorem と、「証明を組み立てる」by というタクティクモードが用意されているからです。

2. theorem ・ by ・ rfl

Rocq の reflexivity に対応するのが Lean の rfl です。両辺が計算によって同じ形になるとき、rfl だけで証明が終わります。

theorem two_plus_three : 2 + 3 = 5 := rfl

theorem add_zero_ex (n : Nat) : n + 0 = n := rfl

theorem ... := rfl のように、タクティクモード (by) を使わず証明の項を直接書くこともできます。これは第 18 回で見た「証明は項である」という考え方が、Lean でもそのまま当てはまることを示しています。

3. Rocq との対応と、足し算の定義が生む非対称

ここまでに使った道具は、おおよそ次のように対応します。

Inductive  ↔ inductive
Theorem    ↔ theorem
intros     ↔ intro
simpl      ↔ simp
reflexivity ↔ rfl

ところが、第 16 回で見た「n + 0 = n は計算だけでは示せない」という話は、Lean では逆の形で起きます。Lean の Nat.add は、Rocq の plus とは逆に、2 番目の引数で場合分けして定義されています。そのため n + 0 = n は 2 番目の引数が具体的な 0 なので rfl だけで計算が進みますが、0 + n = n は 2 番目の引数 n が未知のままなので、今度はこちら側が場合分けを必要とします。

theorem zero_add_ex : forall (n : Nat), 0 + n = n
  | 0     => rfl
  | n + 1 => congrArg Nat.succ (zero_add_ex n)

このように n を 0 の場合と n + 1 (1 つ手前の数の次) の場合に分け、後者では zero_add_ex n という「1 つ手前の数についてはもう証明が終わっている」結果を congrArg (両辺に同じ関数を適用しても等式は保たれる、という部品) で使っています。これは第 16 回の induction と同じ内容を、パターンマッチという別の書き方で表したものです。どちらの言語でも、足し算がどちらの引数で計算を進めるかによって、simpl や rfl だけで通る側と帰納法が要る側が入れ替わる、という点は共通しています。

図: Rocq と Lean では足し算の場合分けの軸が逆なので、簡単な側と帰納法が要る側も入れ替わる。
