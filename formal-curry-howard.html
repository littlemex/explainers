命題は型、証明はプログラム ― Curry-Howard 対応

A -> B の証明は A の証拠を B の証拠に変える関数そのもの

← 形式検証シリーズ目次へ

この回の前提: 第 16 回 induction タクティクで帰納法を証明に変える

これまでの回では、証明を intros ・ induction ・ rewrite のようなタクティクの列として書いてきました。しかし Rocq の内部では、タクティクはあくまで作業の手順であり、実際に保存されるのは証明の項という 1 つのデータです。この回では、命題 (Prop) が実は型であり、証明がその型を持つ普通のプログラムの値である、という Curry-Howard 対応という見方を見ます。

1. Prop は bool とは別の種類の型

bool の値は true か false のどちらかで、計算すればどちらになるか必ず決まります。一方 2 + 2 = 4 のような Prop (命題) は、値ではなく主張です。Prop の世界では、計算して true/false のどちらかに潰すのではなく、「この主張が成り立つことを示す証拠は何か」を問います。証拠が実際に組み立てられたとき、その主張は証明済みになります。

この「証拠」は、ただの印ではなく、具体的なデータとして存在します。P -> Q (P ならば Q) という命題の証拠は、P の証拠を受け取って Q の証拠を返す関数です。つまり「ならば」の証明は、ごく普通の関数そのものです。

Definition id_proof : forall P : Prop, P -> P :=
  fun P (H : P) => H.

この id_proof は、P の証拠 H をそのまま返すだけの関数です。Proof. ... Qed. を使わず、証明の項を直接書いています。型チェッカーは、この関数の型が本当に forall P : Prop, P -> P と一致するかどうかを確認するだけで、証明が正しいと認めます。

図: bool は計算結果、Prop は証拠の有無を問う。ならばの証明は証拠変換器 (関数)。

2. かつは組、またははどちらか

「かつ」(/\) を証明するには、両方の証拠が必要です。だから P /\ Q の証拠は、P の証拠と Q の証拠を 2 つ並べた組です。conj は、この組を作るコンストラクタです。

Definition and_example : 2 + 2 = 4 /\ 3 + 3 = 6 :=
  conj eq_refl eq_refl.

一方「または」(\/) は、どちらか一方の証拠だけで十分です。or_introl は左側の証拠から P \/ Q を作り、or_intror は右側の証拠から作ります。

Definition or_example : 1 = 1 \/ 2 = 3 :=
  or_introl eq_refl.

タクティクで書いた destruct や split も、結局はこの conj ・ or_introl ・ or_intror といった部品を組み立てたり分解したりする作業の言い換えにすぎません。destruct H as [HP HQ] は、組になっている証拠 H から 2 つの部品 HP と HQ を取り出す操作です。

3. Print で証明の中身を見る

タクティクで完成させた証明も、裏では 1 つの項に変換されています。Print コマンドでその項を覗くことができます。

Theorem and_commut_ex : forall P Q : Prop, P /\ Q -> Q /\ P.
Proof.
  intros P Q H.
  destruct H as [HP HQ].
  split.
  - apply HQ.
  - apply HP.
Qed.

Print and_commut_ex.

Print and_commut_ex. を実行すると、変数名や表示の細かい形はツールのバージョンで変わることがありますが、おおよそ「H を conj HP HQ という組として受け取り、そこから HQ と HP を取り出して conj HQ HP という新しい組を作る関数」という形の項が表示されます。これは、destruct と split という 2 つのタクティクの指示が、最終的に 1 つの組み立て済みの値へと変換されたことを意味します。命題は型、証明はその型を持つプログラムの値である、という Curry-Howard 対応がここに現れています。
