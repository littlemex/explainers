ここから数回は、第 06 回で予告したもう一つのやり方 ― 証明支援系 ― を、Rocq という実在のソフトウェアで実際に触っていきます。Rocq は型・関数・証明をすべて同じ言語で書き、Rocq 自身がすべての証明の手順を 1 つずつ検査します。本シリーズが参照する定番の教科書 Software Foundations の書き方にそのまま沿って進めます。

1. Rocq とは何か

Rocq は 証明支援系 (proof assistant) と呼ばれるソフトウェアです。少し前までは Coq という名前でしたが、開発チームが利用者への投票を行った上で Rocq に改名されました。新しい名前は、開発元であるフランスの研究機関 Inria の Rocquencourt という場所にちなんでいます。対話的な証明の進め方と、タクティク (証明を組み立てる小さな指示) の言語を提供する証明開発システムで、本シリーズが参照する教科書 Software Foundations も、現在は Rocq の文法で書かれています。

2. 自分で型を定義し、関数で計算させる

Rocq では、新しい型を Inductive というキーワードで定義します。曜日を表す型 day は、7 つの曜日をそのまま列挙するだけで作れます。

Inductive day : Type :=
  | monday
  | tuesday
  | wednesday
  | thursday
  | friday
  | saturday
  | sunday.

この型を使う関数は Definition と match で書きます。次の営業日を返す関数 next_working_day は、土曜日と日曜日を月曜日に戻すという分岐を含みます。

Definition next_working_day (d : day) : day :=
  match d with
  | monday => tuesday
  | tuesday => wednesday
  | wednesday => thursday
  | thursday => friday
  | friday => monday
  | saturday => monday
  | sunday => monday
  end.

Compute (next_working_day friday).
(* ==> monday : day *)

Compute を使うと、その場で計算させて結果を確認できます。friday の次の営業日は monday になります。

図: next_working_day は平日を 1 日進め、土曜・日曜だけ月曜に戻す。

3. bool も自分で作れる

bool という型も、Rocq の中で特別扱いされているわけではありません。true と false という 2 つの値を持つ、ただの Inductive 型です。自分で定義し直すと、それ以降のコードでは Rocq が元から持つ bool の定義をこの行から先で上書き (シャドーイング) して使うことになります。

Inductive bool : Type :=
  | true
  | false.

Definition negb (b : bool) : bool :=
  match b with
  | true => false
  | false => true
  end.

Definition andb (b1 : bool) (b2 : bool) : bool :=
  match b1 with
  | true => b2
  | false => false
  end.

4. 最初の証明を書く: 第 2 節の曜日の計算を確かめる

Example は「この式はこの値に等しい」という小さな主張です。Proof から Qed までの間に、その主張を示す手順 (タクティク) を書きます。simpl は式の計算を実際に進め、reflexivity は両辺が完全に同じ形になったことを確認します。

Example test_next_working_day :
  (next_working_day (next_working_day saturday)) = tuesday.
Proof. simpl. reflexivity. Qed.

simpl が next_working_day を 2 回計算して saturday から tuesday まで進め、両辺がどちらも tuesday という同じ形になったところで reflexivity が成功します。Qed は、この証明がここで確かに完成したことを Rocq に確定させる合図です。
