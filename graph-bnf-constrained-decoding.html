BNF とグラフで生成を縛る

constrained decoding の考え方を、グラフによる意味・関係の制約へ広げられるか。触って確かめると「構造で縛るのは有意義、事実で縛るのは危険」という境界が見えてくる。

普通の constrained decoding は、文法パーサが「今この続きとして許されないトークン」の確率をゼロにするだけの仕組み。これをグラフに置き換えると何ができて、どこで危うくなるのか。まず全体像、次に触れるデモ、最後に「グラフが BNF を超える点」を整理する。

1. BNF は「構文」を止める

LLM logits
↓
BNF parser: 許されないトークン → −∞
↓
softmax → 生成

これが成り立つ理由は 3 つ。1 prefix 単調に検証できる2 語彙のズレを吸収できる3 設計上「行き止まり」が無い

2. グラフに置き換えると「意味・関係」を止めたくなる

LLM が Company A acquired ... まで生成
↓
グラフ: A の出辺 {acquired→B, owns→C, employs→D} で候補を限定
↓
constraint mask → logits → 生成

アナロジーは美しい。だが意味制約は上の 3 条件を欠く。それをデモで確かめる。

3. デモ: グラフ制約デコードを動かす

LLM が次の一語を選ぶ。グラフには A の関係だけが載っている。モードと「正解の世界」を切り替えて挙動を見る。

Knowledge Graph（閉じた世界）
Company A
acquired →Company B
owns   →Company C
employs →Person D
生成中の文
Company A acquired ___
正解は Company B（グラフ内）
スイッチを入れると「正解が Company E（グラフに無いが真実）」の世界へ

デモから読み取れること

  • 制約なし: モデルの素の確率。グラフ外の Company E も選べる。
  • Hard mask: グラフに無いものを −∞。正解がグラフ内なら綺麗に効く。だが正解がグラフ外（E）だと、確信たっぷりに Company B へ流し込まれる — 幻覚の抑制ではなく別の幻覚の製造。
  • Soft bias: logit' = logit + λ·compat(token, G)。0 にはせず持ち上げるだけ。ただし compat を測るには hidden state とグラフを同じ空間に載せる学習（重い GNN）が要る。

4. なぜ意味の hard mask は危ういのか

構文マスク（無害寄り）

valid なトークンへ再正規化しても、構文的に正しければ大きな害はない。行き止まりも設計で防げる。

意味マスク（有害）

閉世界仮説「グラフに無い＝偽」を強制。グラフは常に不完全なので、真を殺し、言いたくなかったことを言わせる。did not acquire のような意味反転も判定できない。

補足: 厳密には構文マスクも無害とは限らない。mask と再正規化はモデル分布を歪めることが知られ（Grammar-Aligned Decoding）、制約が強すぎると構文は完璧でも意味を壊す失敗も報告される。正しくは「構造制約は構文妥当性を保証するが分布忠実性は保証しない。事実制約はそこに閉世界誤差を上乗せする」という多層の問題。

5. では BNF とグラフの違いは何か

構造制約として使う限り、両者は別の軸の力を持つ。BNF は入れ子・再帰（スタック）、グラフは参照・束縛・到達可能性（関係の記憶）。

BNF / CFGグラフ（構造制約として）
得意再帰・入れ子（括弧の対応、式のネスト）参照整合・変数束縛・到達可能性
状態スタック（ネスト深さ）現在ノード + 束縛の集合（既出エンティティ）
アルファベット作成時に静的固定データ由来で動的・既出値に依存できる
検査範囲局所的にインクリメンタル大域的（全体が valid な部分グラフを成すか）

「宣言した id と使う id が一致せよ」は CFG では書けない（agreement/reference は文脈自由の外）。実際 CFG ベースの制約デコードは「変数の使用前定義」を扱えないと報告されている。グラフの到達可能性なら「直前に束縛したノードから届く要素だけ許す」が書ける。だから一番強いのは合わせ技 —— 構文の骨格は BNF、参照の穴埋めはグラフ。text-to-SQL がまさにこれ（SQL 文法 + スキーマ束縛）。

6. まとめ

グラフを型システム / 状態機械（構造）として使う限り、BNF と同じ意義がある。事実データベースとして mask に使うと、閉世界仮説で真を殺し確信ありげな誤りを製造する。境界は「型で絞る（安全）」対「事実で絞る（危険）」。そして学習ゼロで出力層に刺す hard 構造制約は validity を保証するが、valid 候補の中の正しさ（correctness）は上げない —— それは検証器 reward の学習が担う層。
