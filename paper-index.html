クイック 第 25 回

精度を下げられるうちは 2:4 スパース化より量子化が勝ち、2:4 は下限で効く

Qin, “Is 2:4 Sparsity Still Worth It? Semi-Structured Sparsity versus Quantization in LLM Inference”

2:4 スパース化と 1 段低い精度への量子化を、同じビット数と同じ約束の速さでそろえて比べた研究を解説。2:4 の誤差が密な FP8 の 5〜16 倍になる理由、下限の FP8 に重ねると H100 の vLLM で prefill の処理量が 27% 高い結果、再学習が欠かせない点を並べる。

 クイック 第 26 回

2 ビットに縮めたモデルも、自分で書いた答えの上で教え直すと推論力がかなり戻る

Zheng, Xiong et al., “Right On Q: Recovering Reasoning under Quantization via Self-Generated Trajectories”

2〜3 ビットに縮めたモデルに、自分で書いた答えの上で元のモデルが次の語の確率を教え、低すぎる候補と高すぎる候補で KL を切り替える方法を解説。2 ビットの Qwen3-8B で 9 テスト平均が 70.68 点と比較手法の 60.42 点を上回る結果、くり返しによる失敗が減る点を並べる。

 クイック 第 27 回

GPU と CPU のメモリに通し番号をつけ、履歴の重複を減らして同時に書ける数を増やす

Zhu, Cao et al., “UlaCache: Unified Logical Addressing for Sparse LLM Serving”

GPU と CPU の KV 置き場に変わらない論理アドレスをつけ、履歴の写しを減らす UlaCache を解説。H200 と B300 で HiSparse を上回る最高速度、GPU 置き場を共有で管理する PB-LRU、本文で倍率が欠けている点を並べる。

 クイック 第 28 回

下書きモデルのメモを減らすときは、最近書いた語を残し、選び直すと当たりが続く

Tsur, Ashkenazi et al., “RIFT: KV Cache Compression for Draft Models with Complementary Compressibility Training”

投機的デコードの下書きモデルの KV キャッシュを決まった量に減らすとき、直近の語の枠と途中での選び直しを加える RIFT を解説。SnapKV で 63.0% まで落ちた採用長を、学習を足すと減らさないときの 98% 以上に保てる結果、全部のメモの置き場が要る点を並べる。

 クイック 第 29 回

注意の係を少なく太くすると、長い文章から情報を探す力が上がる

Tokui, Yamaguchi et al., “Head Dimension Matters in Language Models for Long-Context Retrieval”

パラメータ数・計算量・KV キャッシュをそろえたまま、注意のヘッドを少なく太くすると長文検索の成績が上がることを示した研究を解説。3B で太さ 512 が RULER 平均 50.93 点と太さ 128 の 35.93 点を上回る結果、学習の損失では見分けられない点を並べる。

 クイック 第 30 回

文章全体を何回かで直す言語モデルは、部品の組み合わせで実用的な速さと品質に届く

Kuleshov, Arriola et al., “How To Build A Modern Diffusion Language Model”

伏せ字の下書きから文章全体を何回かに分けて直す拡散言語モデルの作り方を、マスク拡散・ブロック拡散・書き直し・速いサンプラーなどの部品ごとにまとめた解説。Nemotron Diffusion が同規模の自己回帰モデルの約 2〜8 倍の処理量をほぼ同じ品質で出した報告、規模の課題を並べる。

 クイック 第 31 回

くり返し型の言語モデルでは、過去の語のメモは最後のほうの周回分が正確なら足りる

Lu, Li et al., “Prefix Keys and Values Matter Late: RIPE Caching for Self-Speculative Decoding in Looped Language Models”

同じ層を何周もくり返すモデルで、古い語には最後の周回のメモ 1 枚、最近 64 語には全周回分を残す RIPE を解説。Huginn-0125 で全部残す場合の 11.9% の記憶量で大きな誤差の位置を 89% 減らす結果、深い周回のメモほど大事なこと、効かなかった工夫を並べる。

 クイック 第 32 回

実モデルでは質問とキーの向きがそろわず、ランダムに残すだけでほぼ最適になりうる

Chen, Feng et al., “Attention under Bounded Key–Query Similarity: Space Complexity and Transformer Anisotropy”

質問とキーのコサイン類似度が 0 の近くに収まるという仮定で、残すトークン数のほぼ最適な上限と下限を示した理論を解説。Llama 3.1・Qwen3・Ministral 3 の 8B モデルで一様サンプリングがほぼ最適な範囲かその近くにある測定、量子化などには当てはまらない点を並べる。

ツールの結果がもうすぐ返るかも見て、待っている仕事をまとめて GPU に割り当てる

Li, Ye et al., “TAO: Tool-Aware Joint Scheduling for LLM-Based Agentic Serving”

文字・画像・音声・動画を小さな 1 モデルで同じ数の並びにし、大きなモデルに並ぶ
