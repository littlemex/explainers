検証器で VLM の精度を上げる
― 形式制約 (BNF / グラフ) の視点で再整理

これまでの調査を、今回検討した「BNF 制約付き生成のグラフ拡張」と「検証の出力層への前倒し」という視点で 1 枚に畳み直す。実証済みと設計仮説を分けて記す。

持ち帰る一文: 生成時は構造（構文・スキーマ・参照束縛）だけで縛って validity を確保し、事実の正しさは生成後の field-keyed 検証と検証器ランキングに委ねる。事実で生成を縛れば真の候補を殺して誤答へ確率質量を流し込み、構造で縛りすぎても意味を壊す。だから境界の両側の副作用を測りながら多層で分業する。

VLM（画像を読む AI）の出力を信じず、検証器で整合性を機械判定して精度を上げる調査を全 12 回続けてきた。今回、別の入口 ― BNF constrained decoding をグラフによる意味・関係制約へ拡張できるか、検証器を生成後でなく出力層に前倒しできるか ― を検討した。このグラフ拡張と検証の前倒しは同じ骨格を共有し、調査が経験的に引いた境界線と、形式手法・文書 AI の先行研究が引く境界線は概ね重なる。ただし単純な「安全 / 危険」の二分ではなく、境界の両側にそれぞれ副作用がある。数値は原則として小規模（n が一桁〜二十）の探索的計測で、傾向の提示であり統計的検定ではない。

1. これまでの調査の到達点

  • 中心思想: VLM を仮説生成器とみなし、決定論的検証器で整合性を機械判定する。「verifier で候補をランクする」設計は Cobbe 2021 arXiv:2110.14168 が起点。
  • 最大の敵: 整合的誤読（coherent misreading）。壊れた出力でなく、流暢で辻褄の合った誤り。
  • ハードゲート vs ソフトレビューの相補性（第 4 回）: 決定論ゲート = 正しいルール上で誤拒否 0 / 検出 4/6（規則の範囲外の誤り 2 件は素通し）、AI レビュー = 全検出だが誤拒否 2/5。得意が正反対なので二段で使う。
  • presence から field-keyed へ（第 6・11 回）: 「値が紙のどこかに在るか（presence）」では整合的誤読を素通しする。「その欄の証拠に束縛されているか（field-keyed）」に変えると流用型の誤りを理想条件での上限値として 100% 捕捉・誤拒否 0。証拠が汚れると分離は崩れる（第 12 回）。
  • 検証器自体の検証（第 3・7 回）: AI に検証ルールを書かせると欠陥ルールが黙って通る（自由記述 7/20）。登録時に決まった形で審査すると 0。

2. BNF から グラフ、そして constrained decoding へ

BNF constrained decoding は文法パーサが「今この続きとして許されないトークン」の logit を −∞ にする構文制約。xgrammar 2411.15100・outlines 2307.09702・llguidance が実装し、静的な文法・スキーマに対しては対応する部分集合の範囲で構造妥当性をほぼオーバーヘッドなく保証する。

グラフに置き換えると、状態が「パーサのスタック」から「グラフ上の現在ノード + 束縛済みの集合」になる。ただし現在ノードと直前の関係だけを状態にする素朴な版は有限状態機械に留まり、スタックを持つ CFG より弱く任意深さの入れ子を表現できない。参照束縛の力は束縛済みの集合を状態に持つ側から来る。だからグラフは BNF の上位互換ではなく直交する ― 入れ子・再帰はスタック（BNF）の領分、参照整合・変数束縛はグラフの領分。

グラフが CFG を超える力の核は参照束縛。CFG は有界な一致なら書けるが、非有界の複写・交差依存は文脈自由でない。実装面でも SynCode 2403.01632 が「変数の使用前定義のような semantic constraint は CFG ベース制約付き復号では扱えない」と明記する。離れたセクション間の ID 相互参照が連鎖すると到達可能性（推移閉包）まで要る（言語理論の帰属は末尾）。

なお請求書ドメインで最強の検証器「合計が合うか」は、BNF でもグラフ到達可能性でもない第三のクラス、算術・集約制約である。これを decode 時に強制すると、合計欄は独立に読まれた値でなく検算結果のコピーになり、「独立に読んだ二系統の一致」という検証シグナルそのものが消える（明細の誤読を検出できなくなる）。だから生成では縛らず、検証と生成を独立に保ったまま後述の第 2・第 3 層に置く。

3. 境界線はどこか ― 両側に副作用がある

軸は 2 つ。第一に何で縛るか（構造か事実か）、第二に構造で縛る側にも副作用があること。今回の線引きは調査が実データで見つけた境界と重なるが、線は二分でなく多層になる。

第一の軸 ― 構造 vs 事実

field-keyed = 構造・参照束縛（安全側）

「その欄の証拠（bbox）に束縛されているか」。値が正しいフィールドから届くかを問う参照制約で、グラフが CFG を超える束縛の力に対応する。LMDX 2309.10952 が「localize 機構の欠如」を既存 LLM 抽出の根本欠陥と明示、DocILE 2302.05658 が「正しいアイテムへの割当」を独立タスク化。

presence = 事実照合（危険側）

presence と事実 hard mask はどちらも同じ閉じた資源（文書 / KG）を参照するが、病理の向きが逆。presence は十分条件として使う（在れば受理 → 偶然一致で整合的誤読を過剰受理）。事実 hard mask は必要条件として使う（無ければ棄却 → 真の候補を殺し誤答へ確率質量を流し込む）。「存在 ≠ 支持」は領域を跨いで確認される（ALCE 2305.14627、ELI5 で最良でも 50% で完全支持が欠落）。

デモ ― 同じ閉じた資源を

同じ資源でも、使い方の向きで正反対の系統誤差が出る。どちらも「事実照合を検証原理に据えると系統誤差が入る」という同じ教訓の両端。

第二の軸 ― 構造で縛る側も無害ではない

  • 分布忠実性は保証しない: Grammar-Aligned Decoding 2405.21047 は mask & renormalize がモデル分布を体系的に歪めることを示す（ASAp で補正可）。素朴な hard mask は「文法的だが不自然」を作る。
  • 強すぎると意味を壊す: Structure Snowballing 2604.06066 は、Outlines ベースの構造制約で自己修正を強制しても改善せず「構文はほぼ完璧だが深層の意味誤りを検出できない」失敗（formatting trap / alignment tax）が生じると報告。ただし制約がモデルの意味的容量を超えたときの条件付き現象。

実務がこの多層性を裏づける。KG grounding の主要研究は事実の生成時 hard mask を避け、retrieve 段の集約（GraphRAG 2404.16130、HippoRAG 2405.14831 は "without any extra training" の PageRank）、事後検証（KGR 2311.13314）へ向かっている。

補足: field-keyed とグラフ / Synchromesh 2201.11227 の束縛は「同型」ではなく類比 + 重要な相違。Synchromesh の symbol table/scope は生成 prefix から決定論的に構築でき構成上外部誤差源を持たないが、field-keyed の bbox 束縛は誤りを含む外部 OCR に依存し、制約自体が汚れうる。これが第 12 回（証拠を汚すと分離が +1.00 → −0.15 へ符号反転）の弱点そのもの。

4. 新しい問い ― 検証を「出力層アタッチ」へ動かせるか

これまでの検証器はすべて事後だった。問いは、検証器を VLM の出力層に前倒しし生成時に精度を上げられるか、RL をせずに。前提として constrained decoding は自己回帰テキストデコーダにのみ作用し視覚エンコーダには何も要求しないので、VLM にそのまま適用できる。ただし制約の根拠（OCR / bbox）が視覚側から来る点で純テキストと質的に異なる。

  • 学習ゼロで validity は取れる: 抽出出力を文書スキーマに constrained decoding で強制すれば、対応スキーマの範囲で schema-valid が保証され壊れた抽出が減る。logit processor を各ステップに挟むだけで再学習不要。スキーマを文法規則に動的注入する GCD 2305.13971 が既存実装。許容値集合を trie で縛る構想の最も直接的な先行実装は GENRE 2010.00904。
  • 手に入るのは validity であって correctness ではない: mask は invalid を消すだけで valid 候補の順位はベース VLM のまま。正しい型を誤った欄に束ねる整合的誤読は構造 mask では直らない。correctness への影響は評価方法論に交絡し一般には決まらない（フォーマット制約が推論を下げるとする Tam 2024 2408.02442 に対し、開発元 dottxt が非査読ブログでその評価方法の欠陥を指摘し逆の結果 ― 決着なし）。
  • 事実で mask してはいけない（§3 の必要条件としての事実 mask による過剰拒否・流し込み）。

VLM 固有の 5 つの壁

  1. トークンアラインメント: OCR 証拠文字列と VLM トークナイザ境界は一致せず、値を許すには全トークン化パスの trie が要る（DOMINO 2403.06988 が関連）。フィールド・文書ごとの動的 trie 構築で、静的文法の "near-zero overhead" は成り立たない。
  2. 値の正規化: 「¥12,300」「12,300円」「12300」は同値。正規化バリアントを trie 側に入れるか事後で吸収するかが設計に直結。
  3. OCR 誤りの伝播と逆転: OCR が誤れば真値が許容集合から漏れ制約が正解を殺す。さらに VLM は OCR-free に画素から読めるため、VLM が正しく OCR が誤るケースでは、OCR 束縛は強いモデルを弱い証拠に隷属させる。
  4. スキーマ順序: 生成順を固定し文書の自然な読み取り順と衝突しうる（キー順が精度に影響することは経験的に報告）。
  5. escape のトレードオフ: 流し込み回避に「該当なし / 不確か」の escape を入れるべきだが、不確実時にそこへ逃げ abstention 過多で recall が落ちる。

5. 分業の階層（介入コストの安い順）

同じ決定論検証器（field-keyed 束縛・算術検算）を、第 2 層ではランカー、第 3 層ではゲートという二役で使う。各層をクリックすると詳細。

1構造制約 ― constrained decoding学習ゼロ・今日できる
出力を文書スキーマ / 型 / 状態機械に束ねて壊れた出力を減らす。validity 保証。ただし分布歪み（GAD）と容量超過時の意味破壊（structure snowballing）に注意。事実値そのものは縛らない。
2検証器ランクの best-of-n学習ゼロ・RL の前に
検証器を k サンプルのランカーに使い、valid だが誤りの残差を選別で削る。Cobbe 2021 の verifier ランクを生成時に効かせる最も安いレバー。field-keyed は pass/fail の二値なので、ランキングには段階スコア（例: 通過フィールド数）への変換が要る。
3参照束縛の検証 ― field-keyed（事後）実証済み（上限値）
第 2 層と同じ検証器を最終出力のゲートに使い、値が正しい欄の証拠に束縛されているかを機械判定。整合的誤読の主戦場。理想条件での上限値は実証済み、実環境での実力値はこれから。
4順位学習 ― RL重い・要 go/no-go
best-of-n でも残る誤りに、検証器 reward で順位を学習する（process reward が outcome を上回る: Lightman 2023 / 人手ラベル不要化: Math-Shepherd）。ただし過剰最適化で真性能が劣化する reward hacking（Gao 2022）と、最終正誤は outcome だけでも同等で差は推論過程に出る（Uesato 2022）という留保。

6. 最小構成と計測計画

最小構成: VLM 抽出を JSON スキーマ文法で constrained decoding し（壊れた出力を削減）、フィールドごとに field-keyed 証拠束縛を事後ゲートで判定。事実値そのものは mask しない。必ず escape を文法に含める。

計測: 合成請求書 testbed で、hallucinated field rate・整合的誤読の捕捉率・誤拒否率を、(a) 制約なし / (b) 事後ゲートのみ / (c) constrained decoding + 事後ゲート / (d) (c) + 検証器 best-of-n の 4 条件で比較。validity と correctness を分けて測る（JSONSchemaBench 2501.10868 が先行）。escape は abstention 単体でなく risk-coverage 曲線で評価。加えて「trie が真値を含んでいた率（真値カバレッジ）」を単独指標として測る ― 壁 1〜3 が合流する故障「真値が許容集合から漏れる」を直接測る安価な診断で、「decode 時制約は事後検証より正解を殺しやすい」という仮説の本丸。

デモ ― 4 条件で同じ請求書を抽出する。VLM はしばしば「合計」欄に、紙の上に実在する別の値（小計 ¥12,300）を入れてしまう（整合的誤読）。条件を切り替えて、構造妥当性・整合的誤読の捕捉・正しい値の選択がどう変わるか見る。

小計¥12,300
消費税¥1,230
合計¥13,530 ← 正しい合計

要点: 構造制約（c）は「壊れた出力」を消すが、整合的誤読は消せない ― 捕捉はゲートの仕事。正しい値を積極的に選ぶには best-of-n（d）が要る。validity と correctness は別物。

決定変数: constrained decoding と best-of-n で「valid だが誤り」がどれだけ残るか。その残差が RL に投資する価値の有無を決める。学習ゼロの層はそれ自体が有用な成果であり、かつ RL 投資の go/no-go を測る計測器を兼ねる。

7. 誠実な限界（実証済み vs 設計仮説）

  • 実証済みは事後検証側（第 4 / 6 / 11 / 12 回、いずれも小規模）。生成時アタッチ側の「constrained decoding + 束縛検証 + best-of-n」の統合は設計仮説で、比較の実データはこれから。
  • constrained decoding が保証するのは対応スキーマ範囲の構造妥当性だけ（どのエンジンも JSON Schema 仕様を完全カバーしないことは JSONSchemaBench 自身が示す）。整合的誤読は構造 mask では減らず、強すぎる制約はむしろ意味を壊しうる。
  • ハード検証の保証は非対称かつ規則依存。捕捉対象の誤りについての誤受理ゼロであって、範囲外は素通しし（第 4 回の 4/6）、正しいものも拒否しうる。形式検証の Clover 2310.17807 は自ベンチマーク上で誤受理 0・正解の 13% 棄却。「通したものは正しい」に寄せるほど「正しいものを落とす」。
  • field-keyed の 100% 捕捉は理想条件での上限値。実環境では証拠品質の変動が生成の自由度を壊すため、上限値を実力値と誤読してはいけない。
  • グラフを latent（hidden state）に埋め込んで logit を連続調整する soft guidance は、結局 GNN / Graph Transformer の joint 学習を要する重い設計（GreaseLM 2201.08860 / QA-GNN 2104.06378）。本稿の対象外。

脚注（言語理論と帰属）: 非有界の複写が文脈自由でないことは pumping lemma（Bar-Hillel, Perles, Shamir 1961）、自然言語の交差依存の非文脈自由性は Shieber 1985（スイスドイツ語）が標準の帰属。有界な agreement は非終端の展開で CFG でも表現できる。一階述語論理だけでは到達可能性（推移閉包）を表現できないことは記述的複雑性 / 局所性の結果による。

関連: constrained decoding の一般的な直感は 「BNF とグラフで生成を縛る」（触れるデモつき）で扱う。本ページはそれを VLM 検証の文脈に接続した統合回。
