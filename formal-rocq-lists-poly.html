リストと多相 ― 同じ帰納法がどんな型にも効く

cons で作るリストに対する帰納法と、型そのものを引数にする多相の書き方

← 形式検証シリーズ目次へ

この回の前提: 第 16 回 induction タクティクで帰納法を証明に変える

前回、自然数に対する induction で n + 0 = n を証明しました。自然数は「O か、何かの次の数 S n かのどちらか」という形をしていましたが、実はリストも同じ形をしています。「空か、1 個取り出した残りのリストかのどちらか」です。だから同じ induction の進め方がそのまま使えます。さらに、リストの中身の型を決め打ちせず「どんな型 X でもよい」と書けるのが多相です。

1. リストも O / S n と同じ形をしている

自然数を O と S で組み立てたように、自然数のリストは nil (空リスト) と cons (先頭に 1 個追加する) で組み立てます。

Inductive natlist : Type :=
  | nil
  | cons (n : nat) (l : natlist).

Fixpoint app (l1 l2 : natlist) : natlist :=
  match l1 with
  | nil => l2
  | h :: t => h :: (app t l2)
  end.

app (リストをつなげる操作、++ という記号で書く) は最初の引数 l1 で場合分けしています。l1 が空なら l2 をそのまま返し、l1 が h :: t (先頭 h と残り t) なら、先頭 h を残して残り t の方だけ app を呼び直します。これは plus が S n' のとき S (plus n' m) と先頭を残したのと同じ形です。

図: nat の O / S n と natlist の nil / h :: t は同じ形の再帰構造。

2. app_assoc を induction で証明する

(l1 ++ l2) ++ l3 = l1 ++ (l2 ++ l3) (つなげる順番を変えても結果は同じ、結合法則) を証明します。l1 について induction すると、前回と全く同じ骨組みになります。

Theorem app_assoc : forall l1 l2 l3 : natlist,
  (l1 ++ l2) ++ l3 = l1 ++ (l2 ++ l3).
Proof.
  intros l1 l2 l3. induction l1 as [| n l1' IHl1'].
  - reflexivity.
  - simpl. rewrite -> IHl1'. reflexivity.
Qed.

l1 が空のとき、両辺は単に l2 ++ l3 になり reflexivity で終わります。l1 が n :: l1' のとき、simpl は両辺の先頭の n を外に出し、残りの部分が (l1' ++ l2) ++ l3 = l1' ++ (l2 ++ l3) という「l1' についての同じ主張」になります。これがまさに帰納法の仮定 IHl1' そのものなので、rewrite で両辺を揃えられます。先頭を 1 つ外すたびに、残りについて同じ形の主張が顔を出す、というのがリストに対する帰納法の実感です。

3. 型 X を引数にする多相リスト

natlist は nat しか入れられません。文字列のリストが欲しくなったら、また同じ定義を書き直す必要があります。これを避けるために、型そのものを引数として受け取る多相リストを定義します。

Inductive poly_list (X : Type) : Type :=
  | poly_nil
  | poly_cons (x : X) (l : poly_list X).

Arguments poly_nil {X}.
Arguments poly_cons {X} _ _.

X は「後で決める型」を表す引数です。poly_list nat なら natlist と同じもの、poly_list bool なら真偽値のリストになります。Arguments は、poly_nil や poly_cons を使うたびに毎回 X を書かなくても、Rocq が値から X を推測してくれるようにする指示です。多相版の app も、中身の型が何であるかに関係なく、natlist の app と全く同じ形で書けます。そして poly_app l poly_nil = l のような性質も、X がどの型であっても induction l で全く同じ手順で証明できます。型を引数にしても、リストの形 (空か、先頭と残りか) が変わらない限り、帰納法の進め方は変わりません。

図: 型 X をどれにしても、リストの構造と induction の進め方は変わらない。
