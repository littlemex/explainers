Jev の実物と、互換を名乗る 4 つのサーバに公式 SDK を向ける
形は揃う。「confidence」の意味は揃わない

この章の結論。TypeSafe AI の公式 Python SDK (typesafe-sdk 0.7.1) を1 行も変えずに、公開されている 2 つ (Kev・Decider) と自作の 2 つ (Lux の再利用版・Prismyra) の計 4 つのサーバに向けたところ、 4 つとも 3 つの答えの型を SDK の厳しい型チェックのまま読み込めました。通信の形は、もう誰でも真似できる段階にあります。

揃わなかったのは中身の意味です。同じ confidence という欄に、実装ごとに違う式の値が入っていました (Jev 自身は式を公開していません)。 出力トークンの数え方も、確率の丸め方も違います。そして自作のサーバは、冷えた状態の最初の 1 回が SDK の既定の 10 秒で時間切れになりました。 Jev 本体は順番待ち (waitlist) だけで API キーが得られず、呼んでいません。

2. 公式 SDK を 4 つのサーバに向ける

公開されている System One 互換のサーバは 2 つありました。Kev (jaredpalmer/kev、commit 62c9183) の kev.serve と、 Decider (Mapika/decider、commit abadc94) の decider.serve です。 Decision 1.0 はサーバを同梱していないので (第 47 章 §4)、第 49 章の再利用版の Lux と Prismyra の前に、System One の形で答える薄いサーバ (s1_server.py) を自分で書きました。

試したのは、状態 1 つに Choice (3 択)・Noul・Score (3 段階) を 1 問ずつの 1 リクエストです。4 つとも SDK が例外を出さずに読み、SDK 経由の確率と、同じサーバに生の JSON で送った確率は完全に一致しました。 ただし試したのはこの 1 形のリクエストで、エラーの返し方 (422 や 429) や 255 個の選択肢は確かめていません。

confidence に 0.8 以上なら自動で処理、と閾値を置いたコードは、繋ぐ先を替えると黙って意味が変わります。 3 択で最大確率 0.85 の答えは、Decider なら 0.85、Kev なら 0.775 です。Jev の式は非公開なので、どちらが「本物と同じ」かは誰にも分かりません。 Jev のドキュメント自身が「全部の確率を返すので、自分の物差しを使ってよい」と書いている通り、閾値は confidence ではなく probabilities から自分で計算するのが、実装を替えても壊れない使い方です。

出力トークンも揃いません。Kev の 177 は「返した答えの JSON をトークンに区切った数」で (kev/api.py の output_tokens、「生成の量ではない」と注記あり)、生成はしていません。 ほかの 3 つは 0 と返します。Jev は出力トークンを無料としているので請求は変わりませんが、使用量を記録して比べる側 (tierbook のような仕組み) は、この欄を実装をまたいで比べてはいけません。

4. 冷えたサーバの最初の 1 回

自作のサーバを起動した直後に、SDK を既定の設定のまま呼ぶと、最初の 1 回が TypeSafeAPITimeoutError: Request timed out (timeout=10.0) で失敗しました。 SDK は時間切れを 2 回まで再試行しますが、その呼び出し全体が失敗しました。その後の呼び出しは 1 秒未満だったので、最初の計算で GPU のカーネルを組み立てる時間が 10 秒を越えたのだと考えています (推測)。

直し方は、サーバが待ち受けを始める前に 3 つの型を 1 回ずつ答えさせる空回し (warm_up()) を入れることです。入れた後は、起動直後の最初の呼び出しも成功しました (空回しは 1.0 秒。カーネルの組み立て結果がディスクに残っていた状態での値です)。 Decider は起動時に CUDA graph を全部取り込んでから待ち受け、Kev は最初の呼び出しでも 10 秒以内に返したので、この 2 つでは問題は出ませんでした。 Lux の同梱の実装は、そもそも 64 問で 45.6 秒かかる (第 49 章) ので、既定の SDK からは使えません。この章で「Lux が SDK で動いた」と言っているのは、再利用を足した自作のサーバのことです。

まだ言えないこと

  • Jev 本体とは比べていません。「互換」は SDK 0.7.1 の型と通信の形について言えることで、Jev と同じ答えを返すという意味ではありません。
  • 試したリクエストは 1 つの形だけです。エラー応答、255 個の選択肢、64k トークン近い入力、非同期版の SDK は確かめていません。
  • Kev の配信は 1 行 8,192 トークンまでで、それより長い状態は 422 で断ります (第 52 章)。Jev の 32k とは違います。
