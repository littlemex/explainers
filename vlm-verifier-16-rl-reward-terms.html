第 16 回・RL 実測

安い VLM を SFT なしの強化学習だけで鍛える

日本語の文書画像を Markdown に書き起こす課題で、7B の小さなモデルを「教師ありの模倣学習 (SFT) を一切せず」に強化学習だけで伸ばせるか、という検証の現在地です。
結論は一言で言えます。報告する指標の項目を報酬が見ていないと、その項目は必ず払わされる。

0. 前提: 何を測っているのか

題材は OmniDocBench-JASyn という日本語文書のベンチマーク (518 ページ)。画像を入力し、Markdown を出力させて、次の 3 つの項目で採点します。この 3 項目の平均が公式スコア Overall です。

1本文
正解テキストとの編集距離。1 に近いほど良い (100 点満点換算)。
2表
TEDS。表の木構造とセル内容の一致度。
3数式
CDM。LaTeX を実際に画像へ描画して文字を突き合わせる。

ここが今回の話の心臓部です。我々の学習の報酬は 1 と 2 しか見ていませんでした。3 の数式は「重いから」「合成データに入れていないから」学習の対象外でした。すると何が起きるか、次のデモで体感してください。

1. やったこと (初学者向けに一段ずつ)

強化学習 (GRPO) とは、ここでは何をしているのか

SFT は「正解の書き起こしを丸ごと見せて真似させる」学習です。今回の強化学習 (GRPO) はそれをしません。代わりに次を繰り返します。

  • 1 ページの画像に対し、モデルに 8 通りの答えを書かせる (温度をつけてサンプリング)。
  • 8 通りそれぞれを採点する。この採点関数が「報酬」で、今回は「本文の一致度」と「表の一致度」の平均。
  • 同じページの 8 通りの中で平均より良かった答えの確率を上げ、悪かった答えの確率を下げる。

正解文そのものを教えないので、モデルは「自分が既に出せる答えの中で、点が高い方に寄っていく」だけです。ここが後で重要になります。

合成データで学習し、公開ベンチマークで測る

学習データは自前で 1200 ページ生成しました (HTML と CSS で日本語の文書を組み、Chromium で画像化し、正解は DOM から機械的に取り出す)。評価は Stockmark 公開の JASyn 518 ページで、そのうち 121 ページだけを「選択用 (dev)」に使い、残り 397 ページ (test) は最後の一回しか触りません。学習中の判断に test を使うと数字が嘘になるためです。

ここで最初の落とし穴。合成データを作るとき「数式は公式指標の 2 項では採点されないから入れない」と判断しました。コードにその理由もコメントで残っています。この判断が、後で 3 項目のうち 1 項目を丸ごと失う原因になります。

2. 報酬は数式に対して「無関心」だった

「報酬が数式の省略を積極的に得点にしていたのでは?」という疑いは、実測で否定できます。完璧な答えから数式を消しても、報酬は 1 桁も動きません。逆に、数式を $$...$$ で囲まずに素のテキストとして書くと大きく減点されます。つまりモデルが見ている勾配は「数式を正しく囲んで書く = 無料、素テキストで書く = 高い罰、そもそも書かない = 無料」でした。

読みどころは 3 つです。

  • SFT は同じデータで、公式指標では base より下に落ちます。数式項が -19.65。強化学習は -8.33 なので、未学習カテゴリの壊し方が RL の方が穏やかでした (直接比較で RL が +11.3pt、CI が 0 を除外)。理屈は素朴で、SFT は「数式のない書き方」を正解として能動的に教え、RL は「自分が既に出す答えの中で点の高い方に寄る」だけだからです。
  • データを足すだけでは足りません。v3nf (データに数式あり・報酬は 2 項) は数式項をまだ base より下に留め、Overall も判定不能のままです。
  • 報酬項を足すと初めて有意になります。v3fr は Overall +4.819 で CI が 0 を除外。しかも partial も最良で、第 3 項を見たことで他の 2 項が悪くなるどころか良くなりました。

4. まだやっていない: 検証器と文法 (BNF) を「推論時」に使う

ここまでは全部「学習で直す」話でした。もう一つの道が「モデルは触らず、出力の作り方だけ変える」推論時の工夫です。3 段階あります。

A文法制約デコード (BNF)
出力トークンを文法で縛り、構文的に壊れた答えをそもそも生成できなくする。表の閉じタグ抜けや $$ の片側落ちが原理的に消える。
B検証器 (reference-free)
正解を見ずに答えの健全性だけ判定する関数。構文の整合、同じ行の反復、空セルだけの表、画像に無い文字列の混入など。
Cbest-of-N 選択
N 個サンプリングして検証器が一番マシなものを選ぶ。学習不要で、モデルの持つ「当たり」を引き当てる。
既に測って失敗した近縁の手法があります。「反復ループを罰する」デコード制約 (repetition_penalty, frequency_penalty) は dev で -3〜-35pt。日本語文書は表のセルや助詞が正当に反復するので、大域的なペナルティはループと表を区別できません。出力側でループを切り詰める後処理も -0.2pt。つまり「乱暴な制約」は効かないことは分かっています。A の文法制約は「構文だけを縛り、内容には触らない」ので性質が違い、まだ未検証です。

6. この検証で得られた再利用できる教訓

  • 報酬は、報告する指標の全項目を覆う。覆っていない項目は必ず代金として払われる。今回は 3 項のうち 1 項を落とし、上がった 2 項をちょうど打ち消した。
  • カテゴリをデータに足すだけでは直らない。データ被覆で損害の大半 (5.8pt) は戻るが、報酬項がないと base より下に留まり、公式スコアは判定不能のまま。
  • 「完璧な答えを入れて満点が返るか」を毎回確かめる。今回、公式の数式スコアが 0.29 と出て環境不良を疑ったが、真因は自前の自己診断コードが $$ を二重に付けていたことだった。「同一入力を両側に入れたら 1.0 になるか」という単体の当たり判定 (identity probe) を作って初めて切り分けられた。
  • 合成指標だけを見ない。「Overall は動かなかった」で終わらせると、実際に起きた「2 項は有意に改善し、1 項が有意に悪化した」という情報量の多い事実が消える。項別に信頼区間を出す。
  • ベンチマーク側の穴も測る。公式の数式スコアは余剰な数式を罰しないので、候補を増やすだけで約 1pt 稼げる。自分の報酬では余剰にペナルティと一致下限を入れた。
