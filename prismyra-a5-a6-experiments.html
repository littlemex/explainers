Prismyra 実験5・6・6b: 計算問題を足す、容量を増やす、見落としを直す
容量を正しく増やしたら、初めて合格した

結論から。検算できる計算問題を学習に足す実験 (実験5) は不採用になった。LoRA (重みの差分だけを学習する軽い学習の仕組み) の容量を 4 倍にする実験 (実験6) も、最初の試し (a6) では不採用だったが、学習の設定に 2 つの見落とし (係数が薄まっていたこと、起動のたびに答えがわずかに揺れる計算の仕組みがあったこと) を直したうえでやり直した候補 (実験6b、a6b) は、事前に決めた 3 つの合格ラインをすべて満たした、この一連の実験で初めての合格になった。学習の行の上でのずれの縮み方は 51.2% (rank16 は直すと 26.8%) で、初めて「半分以上縮める」の基準を超えた。

この文書でやったこと。検算できる計算問題 10 種類・15,000 問をプログラムで作り、7 種類を学習に足し 3 種類をとっておいて測った (実験5)。LoRA の rank を 16 から 64 に増やして学習し (実験6)、学習後に見つかった 2 つの見落とし (係数の薄まり、起動のたびの揺れ) を直して再挑戦し (実験6b)、合格したので本番の5セット・鍵をかけた2,050問・速さまで進めた。すべて学習・評価が終わっており、この文書は結果を見たあとに書いている。

1. 何をしようとしていたか

Prismyra は、35B (350億個の数の重みを持つ) の大きなモデルの中の 36 層だけを使い、1 回読むだけで選択問題の答えの確率を出す「読み出し」である。前の章 (診断: 知らないのか、考えないのか) で、元の大きなモデルに考えさせてから答えさせると、計算が必要な問題で正解率が上がることが分かった。だが、その「考える力」を読み出しに移す学習は、効果が小さかった。

そこで、2 つの別の手を試す計画が立てられていた (/Users/akazawt/tmp/smr/redesign/IDEAS-CEILING.md の 6.2 節)。

  • 実験5 (この文書では a5 と呼ぶ): 答えをプログラムで検算できる計算問題 (群の位数、mod の逆元、多項式の根、行列式、置換の偶奇) を 1 万〜2 万問作り、学習に足す。答えの出し方そのものが身につくなら、学習していない型の計算にも強くなるはずである。
  • 実験6 (この文書では a6 と呼ぶ): LoRA (元の重みは変えず、小さな差分の行列だけを学習する軽い学習の仕組み) の大きさ (rank、差分行列の次元数) を 16 から 64 に増やす。rank が小さすぎて学習が止まっているなら、容量を増やせば伸びるはずである。

実験6を走らせる条件。前の章の調べ (N2、学習済みの rank16 の候補 R4 が、学習に使った行の上でさえ先生の答えにどれだけ近づけたか) で、ずれ (KL、2 つの確率の違いを表す数) が 34% しか縮まらなかった (50% 未満) ことが先に確かめられていた。だから「容量が足りないかもしれない」実験6を走らせる根拠があった。

2. 実験5: 検算できる計算問題を学習に足す

2.1 問題の作り方

プログラムで答えを検算できる 10 種類の計算問題を、/Users/akazawt/tmp/smr/probes/scripts/gen_a5.py で作った。どの問題も、正解を作ったのと同じ計算 (剰余の計算、拡張ユークリッドの方法、多項式への代入、行列式の展開、並び替えの転倒数) でプログラムが出した値を正解にし、はずれの選択肢も同じ計算で「正解と違う」ことを確かめてから入れている。人が目で見て正しいかを判定した問題は 1 つもない。

10 種類のうち 7 種類 (10,500 問) を学習データに足し、3 種類 (4,500 問、ちょうど 3 割) を学習に一切使わずとっておいた。とっておく型は、学習に入れた型と計算の中身は同じだが、答えの書き方 (表記) の最後の一段だけが違うものを選んだ。これは「学習に入れた型を覚えただけ」なのか「計算のやり方そのものが身についた」のかを見分けるためである。

各型 1,500 問。学習用 7 種類 = 10,500 問、とっておき用 3 種類 (表の「no」の列) = 4,500 問。ちょうど 3 割。

学習に足したデータは、既存の学習データ (kd/train_L1.json、31,418 行) の末尾に、この 10,500 行をそのまま追加したもの (kd/train_L1_a5.json、41,918 行)。学習そのものは、現在のベースの読み出し (L1) と全く同じ出発点・同じ学習率 (2.5e-5)・同じ rank (16) で、データだけが違う。学習は L40S (GPU) 4 枚で 353.5 分 (約 23.6 GPU 時間) かかった。

2.2 結果: 3つの合格ラインのうち、満たしたのは1つだけ

とっておいた3種類 (4,500問) の全体では、A (ベースモデル) の 48.56% に対して a5 候補は 44.96% と、むしろ 3.60 点下がった (95% 区間 [-5.31, -1.91]、符号検定 p = 0.0001)。合格ラインは +10 点以上だったので、符号も逆という結果である。

ただし、3つの型を1つの数字にまとめると、中身の割れ方が見えなくなる。型ごとに見ると:

行列式 (3×3)40.27%48.73%+8.47点
多項式の根 (mod p 版)31.87%33.20%+1.33点

最も目立つ結果。2×2の行列式を学習に入れたら、学習していない3×3の行列式が+8.47点伸びた。これは「計算のやり方そのものが身につく」ことがあり得る、という良い兆候である。だが、並び (リスト) で渡す置換の偶奇を学習に入れたら、サイクル記法 (例えば (2 5)) で渡す同じ計算が73.53%から52.93%へ大きく落ちた。計算の中身は同じでも、問題の書き方 (表記) が変わると、素のモデルより悪くなることがある、という示唆である。

新しい数学300問 (今回はじめて使う、まだ一度も開けていない集まり) では +2.00 点 [-1.00, +5.00] で、合格ライン +5 点に届かない。FS 全体 (5,200 問、何度も使ってよい選抜用の集まり) では +0.71 点 [+0.27, +1.15] (符号検定 p = 0.0020) で、ここだけは合格ラインの -0.5 点を上回る。

実験5の判定: 不採用。3 つの合格ライン (とっておいた型で+10点以上、数学300問で+5点以上、FS全体で下端が-0.5点より上) のうち、満たしたのは FS 全体の 1 つだけ。3 つすべてを満たさないと採用しない、という最初の約束のとおり、不採用とする。

3. 実験6: LoRAの容量を4倍にする

3.1 やったこと

LoRA は、元の巨大な重み行列 W はそのまま凍結し、小さな 2 つの行列 A (rank × 入力の次元) と B (出力の次元 × rank) の積だけを学習する軽い学習の仕組みである。rank が小さいほど学習する数は少なく、速いが、学習できる「向き」の数も少ない。前の章で学習させた rank16 の候補 (R4) は、学習に使った行の上でさえ先生の答えに十分近づけなかった (ずれの縮み方 34%、半分未満)。そこで、rank を 16 から 64 に増やした。

すでに rank16 で学習済みの候補 (results/lora_kd_L1.pt、呼び名「L1」) があったので、ゼロから学習をやり直すのではなく、L1 の学習済みの重みを rank64 の最初の16次元にそのままコピーし、残りの48次元はふつうの新しいLoRAと同じ乱数で初期化する「かさ上げ」を行った (/Users/akazawt/tmp/smr/probes/scripts/pad_lora_rank.py)。学習データ・損失・学習率 (2.5e-5) は R4 (rank16で学習済みの候補) と同一、rank だけを変えた。

学習後に見つけた見落とし。LoRA の実際の計算は W + (B @ A) × (alpha / rank) である。alpha (もう1つの倍率を決める数) は 32 のまま変えなかったので、rank が 16→64 になると係数 (alpha / rank) は 2.0→0.5 に下がる。つまり、最初の16次元の重みの値 (数字) は L1 と完全に一致させたが、学習が始まる瞬間の実際の出力 (効き目) は、L1 の 4 分の 1 に薄まった状態からのスタートになっていた。この見落としは学習が終わってから気づいた。学習そのものは rank64 の全次元を学習率 2.5e-5 で動かすので、下の「縮み方」は測れるが、その縮み方は L1 の正しい続きからではなく、薄まった状態からの続きである点を、結果を読むときの注意として明記する。

クラスタ全体の GPU 予約の上限のため、本来 4 枚想定だった GPU を 3 枚で学習させた (373.0 分、約 18.65 GPU 時間)。

3.2 結果: ここも3つのうち1つだけ、しかも2つはごく僅かな差で不合格

学習に使った2,500行 (R4のときと同じ行) で、先生の答えとのずれ (KL) を学習前と学習後で比べた。KL は 0.496 → 0.259 で 47.7% 減った。rank16 (R4) は 34% 減だったので、容量を増やすと縮み方は確かに大きくなった。だが、合格ラインの「50%以上縮める」にはわずかに届かない。

先生の答えと違っていた419行のうち、学習後に先生と同じ答えに変わったのは207行 (49.4%、R4は41.7%)。何段もの計算が要る種類 (kd_aqua、代数の文章題) だけで見ると、一致率は52.7%→64.8%、KLは41.3%減 (R4は21%減) で、ここも伸びが大きい。

新しい数学300問では+2.33点 [-0.67, +5.33] で、合格ライン+1点を点推定では上回る (3つの合格ラインのうち、唯一満たした項目)。FS全体 (5,200問) では+0.42点 [+0.04, +0.83] (符号検定p=0.043) で、合格ラインの+0.5点にごく僅かに届かない。

実験6の判定: 不採用。3つの合格ライン (ずれの縮み方50%以上、数学300問で+1点以上、FS全体で+0.5点以上) のうち、満たしたのは数学300問の1つだけ。学習の行のずれの縮み方 (47.7%) もFS全体 (+0.42点) も、合格ラインのすぐ近くで僅かに届かなかった。rank64はrank16より明らかに良い方向に動いているが、「容量を増やせば直る」と言うにはまだ足りない。

4. 学習用の計算そのものに、起動のたびに答えが揺れる原因が見つかった

実験6 (a6) の「ずれの縮み方 47.7%」を書いたあと、容量を正しく増やす直し方 (次の節) をする前に、測り方そのものを疑う必要が出てきた。

見つかったこと。学習の行での測り方 (n2_fit.py、学習用の素の PyTorch の計算で、サービング用の vLLM エンジンとは別の道) には、起動するたびに答えがわずかに変わる原因があった。重みも設定も一字一句同じ L1 を、2 回別々に起動して同じ200行を読ませただけで、答えの確率が最大 0.448 ずれ、200行中30行で一番大きい答えが変わった。原因は、Triton (GPU 向けの計算を書く言語) のカーネルが、起動のたびに「どの実装が一番速いか」を測って選ぶ仕組み (autotune) にあり、速さが僅差の候補の間で、どちらを選ぶかが揺れていた。

Prismyra のサービング用エンジン (prismyra/kernels/autotune.py) には、この揺れを止める仕組み (起動時にすべての autotune の選び方を 1 つに固定する) がすでにあった。これを学習用の測り方にも足したところ、同じ L1 を 2 回起動した差は完全に 0.0 になった。

この直しをきっかけに、前の章の R4 (rank16) の「ずれの縮み方 34%」も測り直したところ、固定した状態では 26.8% だった。元の 34% という数字は消さず、訂正として記録を残す (THINKING-PROBES.md に追記)。a6 の 47.7% は、たまたま固定する前と後で同じ値になった (保証されたものではない、運が良かっただけ)。

5. 実験6b: 2つの見落としを直すと、初めて合格した

実験6には、もう1つの見落とし (前の章で見つけた alpha/rank の係数の薄まり) があった。この2つ (薄まりと起動の揺れ) を両方直して、同じデータ・同じ学習率で学習をやり直した候補を実験6b (a6b)と呼ぶ。alpha を128にして rank64でも係数 (alpha/rank) を2.0に保ち、学習が始まる瞬間の出力が L1 と完全に一致することを、学習の前に確かめた。

新しい数学問題がMMLUだけでは139問しか集まらなかったので (3回の抜き取りでMMLUの数学プールがほぼ尽きていた)、MMLU-Pro の math、AQuA-RAT の test、GSM8K を4択に変換したものを足し、同じ重なりの確かめで300問 (n1e_math) を作った。

学習前後のKLを、固定した測り方で比べると、0.327 → 0.160 で 51.2% 減り、合格ラインの50%を初めて超えた (rank16・R4は固定した状態で26.8%、直す前のa6は47.7%)。新しい数学300問 (4つの出どころ混成) では+3.33点、FS全体では+0.54点で、どちらも合格ラインをわずかに超えた。

実験6bの判定: 合格。3つの合格ラインをすべて満たした、この一連の実験で初めての候補になった。ただしFSの合格は+0.04点差という、きわどい差であることは明記する。

6. 本番の手順まで進めた結果

7. 全体から読めること

3つの実験 (5、6、6b) をまとめると、計画書 (IDEAS-CEILING.md 6.3節) が先に書いていた「全部落ちたときの読み方」は、見落としを直す前の段階 (実験5、最初の実験6) では当たっていたが、見落としを2つ直した実験6bでは、初めて破られた。
