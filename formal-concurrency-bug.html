この回の前提: 第 09 回 不変条件と TLC

前回、不変条件を TLC に検査させる方法を見ました。今回は、実際に不変条件が崩れる仕様を用意し、TLC にその反例を出させます。題材は「共有の数を 2 つの処理が同時に増やそうとすると、1 回分の更新が消えてしまう」という、並行処理の定番のバグです。

1. 読む→足す→書く、を 2 段階に分けると何が起きるか

複数の処理が同じ共有変数を更新するとき、1 回の更新を「値を読む」「書き込む」のように複数の段階に分けてしまうと、間に別の処理の更新が入り込んで、せっかくの更新が消えてしまうことがあります。これをlost update (更新の消失) と呼びます。

共有のカウンタ cnt を 2 つの処理 p1, p2 がそれぞれ 1 回ずつ +1 したいとします。各処理は「cnt を読んで変数 temp に入れる」→「temp+1 を cnt に書き込む」という 2 段階で動きます。p1 と p2 がどちらも先に cnt=0 を読んでしまうと、どちらも「0+1=1」を書き込むことになり、2 回更新したはずの cnt は最終的に 1 のままになります。期待する結果 2 との食い違いが lost update です。1 つの処理だけを見ていると「読んで +1 して書く」という手順は正しく見えますが、複数の処理が同時に動く状況まで考えないと、この食い違いには気づけません。第 07 回で見たインターリーブの考え方が、まさにこの「気づきにくい順番」を見つけ出す道具になります。

図: p1 と p2 が両方先に cnt=0 を読んでしまうと、更新が 1 回分消える。

2. PlusCal で書く

このような「読んで、書く」という手順を、TLA+ よりプログラミング言語に近い見た目で書ける補助言語が PlusCal です。PlusCal では、1 歩として原子的に実行される範囲を ラベル (label) で区切ります。各ラベルの内部で起こることは、一度にすべて実行されるとみなされます。プロセス (処理) の部分は次のようになります。

process Counter \in Procs
variables temp = 0;
begin
Read:
  temp := cnt;
Write:
  cnt := temp + 1;
end process;

PlusCal で書いたアルゴリズムは、専用の翻訳機によって、各処理がどこまで進んだかを示す pc という変数を持つ、素の TLA+ に自動的に翻訳されます。複数の処理があるときは pc は処理ごとの関数になり、pc[p] のように処理を指定して参照します。翻訳結果はファイルの BEGIN TRANSLATION と END TRANSLATION の間に書き込まれ、TLC はその TLA+ を検査します。次の節では、中身が見えるように、同じ考え方を素の TLA+ で手書きした版を使います (値の名前の付け方や、全部終わった後の扱いなど、翻訳機が機械的に作る細部とは少し違います)。上の PlusCal を翻訳して TLC にかけても、同じ反例が出ます。

3. TLC が反例を出す ― 直すと通る

手で書いた素の TLA+ では、pc[p] が "read" のときに値を読み "write" に進む Read(p) と、"write" のときに書き込み "done" に進む Write(p) を、別々のアクションとして定義します。

Init ==
  /\ cnt = 0
  /\ pc = [p \in Procs |-> "read"]
  /\ temp = [p \in Procs |-> 0]

Read(p) ==
  /\ pc[p] = "read"
  /\ temp' = [temp EXCEPT ![p] = cnt]
  /\ pc' = [pc EXCEPT ![p] = "write"]
  /\ UNCHANGED cnt

「全処理が done になったら cnt は処理数と等しいはずだ」という不変条件 NoLostUpdate を書き、Procs = {p1, p2} で検査すると、TLC は p1 と p2 が両方 "read" を済ませてから書き込む順番を見つけ、NoLostUpdate の違反を報告します。

Next == \E p \in Procs : Read(p) \/ Write(p)

Spec == Init /\ [][Next]_vars

NoLostUpdate ==
  (\A p \in Procs : pc[p] = "done") => cnt = Cardinality(Procs)

直し方は、読む・書くを分けないことです。Inc(p) という 1 つのアクションの中で cnt' = cnt + 1 まで一度に行えば、他の処理がその間に割り込む隙がなくなります。この版を同じ NoLostUpdate で検査すると、TLC は到達可能な状態をすべて調べ終え、違反を報告しません。読む段階と書く段階を分けるという、見た目には小さな書き方の違いだけで、不変条件が崩れるかどうかが変わる、という点を覚えておいてください。

Inc(p) ==
  /\ pc[p] = "ready"
  /\ cnt' = cnt + 1
  /\ pc' = [pc EXCEPT ![p] = "done"]

図: 2 歩に分けた版は割り込める。1 歩にまとめた版は割り込めず、不変条件が常に保たれる。
