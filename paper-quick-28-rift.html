下書きモデルのメモを減らすときは、最近書いた語を残し、選び直すと当たりが続く

元の論文: Tsur, Ashkenazi et al., "RIFT: KV Cache Compression for Draft Models with Complementary Compressibility Training"

ひとことで言うと、「投機的デコードの下書き係は、メモ（KV キャッシュ）を決まった量しか持てないとき、最初に読んだ文章から大事な部分だけを選んで残すやり方だと、長く書くほど当たりが減っていく。RIFT は、メモの一部を最近書いた語に割り当て、書いている途中で残す部分を選び直す。さらに、メモが少ない状態に慣れさせる学習を足すと、Qwen3.5-4B が Qwen3.5-122B の下書きをする場合（入力 32K 語、出力 4K 語、メモ 8K 語分）、メモを減らさないときの採用語数の 98% 以上を保てた。学習なしで従来の SnapKV を使うと、同じ入出力の条件で 63.0% だった」という研究です。

見つけた場所: arXiv 週報 2026-10-29

何が問題だったのか

投機的デコード（小さな下書きモデルが先に何語か書き、大きな本体モデルがまとめて確かめて、合っていた分だけ採用するしくみ）では、下書き係の当たり具合を採用長（AL、1 回の確認で採用される語の平均数）で測ります。

考える力を使うモデルは、長い入力を読んで長い答えを書きます。すると下書き係も、過去の語ごとのメモ（KV キャッシュ）が大きくなります。一部の層だけが Attention（過去の全部の語を見る部分）で、残りが別のしくみのハイブリッド型（混ぜた作り）でも同じです。たとえば Qwen3.5-4B は Attention の層が 25% だけなのに、64K 語の依頼を 4 本同時に扱うと、KV キャッシュが使用メモリの 51.1% を占めます。

そこで、メモを決まった量（予算）までに減らします。よく使われる SnapKV は、プレフィル（最初に入力をまとめて読む段階）で大事そうな語を選んで残します。もう一つの SWA（スライディングウィンドウ、直近の決まった数の語だけ残す方法）は、大事さを考えません。

ところが、Qwen3.5-4B の下書きでは SWA のほうが SnapKV より当たりました。書き進めるにつれて SnapKV の AL は 36.7% 下がり、SWA は 41% 上がりました。著者らは、最初に選んだメモがだんだん役に立たなくなるこの現象を「デコードの古びれ」と呼んでいます。理由として、最近の語は本体モデルが確かめた文章なので下書きにとって大事なこと、考える過程の文章が入力のまとめの役をしている可能性があることを挙げています。実際に、モデルが注意を向ける先は、入力から書いた文章のほうへ移っていきました。なお、全部の層が Attention の Llama3.1 では、SnapKV のほうが SWA より良いままでした。

RIFT のやり方

RIFT は手間の少ない順に 3 種類あり、それに学習を組み合わせられます。

1. RIFT-stat: 予算を分ける

メモの予算のうち決まった割合を直近の語（SWA の部分）に取っておき、残りを SnapKV などが選んだ大事な入力の語に使います。割合を変えると、遠くの情報と最近の流れのどちらを重く見るかを調整できます。実際のサーバーはメモをページ単位で持つので、メモをまとまり（ブロック）に分け、ブロックの中の点数の平均で選びます。

2. RIFT-dyn: 途中で選び直す

書いている途中、決まった語数ごとに、全部のメモに点数をつけ直して残す部分を選び直します。最近の語を使って点数を出すので、今の状態に合った選び方になります。そのため、全部のメモを GPU のメモリ（HBM、GPU に付いた高速メモリ）か別の場所に置いておく必要があります。選び直すほど当たりますが、そのぶん時間がかかります。

3. RIFT-ada: 必要なときだけ選び直す

一定間隔ではなく、最近の採用長が下がった、下書きの迷い具合（エントロピー）が上がった、質問側の向き（クエリ）が前回選び直したときから大きく変わった、などの合図で選び直します。連続しすぎないよう最短間隔を、古くなりすぎないよう最長間隔を決めます。合図の基準値は、モデルと温度（答えのばらつき）の組ごとに調整します。

4. メモが少ない状態に慣れさせる学習

本番と同じように「直近の語＋点数の高い入力の語」だけが見える目隠し（マスク）を作り、その状態で下書きモデルを知識蒸留（大きいモデルの答え方をまねさせる学習）します。追加部分は LoRA（少しの重みだけ足して学習する方法）で学習します。

測ったこと

主に SPEED-Bench（投機的デコード用の評価セット）で、下書きは 1 回 11 語、出力は最大 4K 語、メモ予算 8K 語分、温度 0 です。

当てはまらないところ・残された課題

  • 今の GPU だけの環境では、外付けの下書きモデルは、MTP や EAGLE、DFlash のように本体にくっつけた下書き部品より全体の速さで劣ると著者ら自身が書いている。この研究は、メモリの少ない SRAM 型の専用チップで下書きする将来の構成を想定している
  • 本体にくっつけた下書き部品は対象外。予備実験では、MTP は SWA だけでもメモを減らさないときの 94%（32K 入力）と 95%（100K 入力）を保てた
  • 途中で選び直すには全部のメモを HBM か別の場所に置く必要があり、予算が抑えるのは下書き側のメモリだけで、全体のメモ量は減らない
  • 選び直しの時間の負担は GPU で簡単に測っただけで、専用チップでは大きくなるかもしれず、まだ測っていない
  • RIFT-ada の基準値はモデルと温度ごとに調整が必要で、結果には調整に使ったデータも含まれる
  • 出力を無理に長くした実験では文章がくり返しになりやすく、自然な長い答えとは違う可能性がある
  • 学習の効果は予算が大きいほど小さい。投機的デコード以外での効果はまだ予備的な結果

インフラを作る人にとっての意味

下書き係のメモを決まった量に抑えるときは、入力から選ぶだけでなく、最近の語の枠と途中での選び直しを用意すると当たりが保ちやすい、という結果です。特にハイブリッド型のモデルで差が大きく出ました。一方で、全部のメモをどこに置き、選び直しの時間をどこで払うかという設計が新しく必要になります。
