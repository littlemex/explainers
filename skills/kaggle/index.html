← skills シリーズへ戻る

スキルの背骨はワークフローの段階です。「join した」「CV と LB がずれた」「提出直前」といった状況がそのまま発火条件になります。情報取得と提出そのものは既存の nvidia-kaggle スキルに任せ、ここではその情報を戦略・検証・規律に変換する部分だけを担います。

ワークフローと発火タイミング

コア 類型不変の背骨 (01-08) 対戦/エージェント型 (10) LLM 推論型 (11)

解説ページ

01 brief 以外はドラフト (現時点で分かっている情報から書いた暫定版) です。

常時 ・ 全段階

/kaggle rules

Kaggle 全般で徹底したいルール (美しい実装か・テストを書いたか・デグレが無いか・公式 eval で測っているか等) を再ロードし、直近の作業を項目ごとに自己採点する。指定するだけでルール一式がコンテキストに戻る。

公開開く →
 01 ・ 問題理解

/kaggle brief

コンペに join した直後に打つ。overview とルールを、指標の数式・提出形式・実行制約・コンペ類型の判定・初手仮説を含む戦略 brief に変換する。他スキルの入力を規格化する入口。

公開開く →
 02 ・ 問題理解

/kaggle metric

指標を自前で再実装し sample submission で検算。閾値やランク平均など事後処理で稼げる余地を先に洗い出す。

ドラフト開く →
 03 ・ 検証設計

/kaggle validation

データ構造に合った split と多シード CV + 有意差ゲート。CV-LB の相関を最初から追い、乖離時の再点検の起点にする。

ドラフト開く →
 04 ・ 探索

/kaggle eda

データ取得後の定型 EDA。target 分布・train/test drift・リーク候補列の機械検出を回す。

ドラフト開く →
 05 ・ 実験ループ

/kaggle exp

1 実験 1 レコードで config/CV/LB/仮説を記録。上位者も手書き ablation 表で管理する空白を埋める最有望の自動化対象。

ドラフト開く →
 06 ・ 実験ループ

/kaggle ensemble

OOF 相関を見てブレンド/スタック。LLM 系は mergekit マージや蒸留にシフトする。

ドラフト開く →
 07 ・ 提出

/kaggle sub-check

提出直前の毎回ゲート。形式/index/null と、Code comp のオフライン動作・実行時間を確認してから nvidia submit を呼ぶ。

ドラフト開く →
 08 ・ 振り返り

/kaggle retro

終了後に上位 writeup と自分の実験ログを突き合わせ、見落としを diff にして恒久 knowledge base に残す。

ドラフト開く →
 10 ・ 検証設計

/kaggle sim-agent

対戦/エージェント型のローカル対戦ハーネスと自己対戦レーティング。提出枠が少ないぶんローカルのアリーナが真の信号。pokemon-tcg 系で使う。

ドラフト開く →
 11 ・ 実験ループ

/kaggle llm-kernel

LLM をカーネル内で動かす工学。モデル同梱・量子化・vLLM・時間予算設計 (AIMO 系)。

ドラフト開く →
 12 ・ 実験ループ

/kaggle tabular-baseline

LightGBM + OOF + feature importance の定型一式。validation の split を必ず使う。

ドラフト開く →
