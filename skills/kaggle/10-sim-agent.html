ドラフト ― このページは現時点で分かっている情報から書いた暫定版です。スキルの実体 (.claude/skills/kaggle/SKILL.md) はサブコマンドの仕様を定義済みですが、手順の細部は実装時に変わる可能性があります。

対戦/エージェント型コンペでの「validation にあたる作業」。ローカル対戦ハーネスと自己対戦レーティングを組む。提出枠が 1 日 5 件と少ないため、公開 LB ではなくローカルのアリーナが真の信号になる。

要点

発火条件類型が対戦/エージェント型のとき (pokemon-tcg-ai-battle など)。
前提BRIEF.md で対戦型と判定済み。提出は agent(observation, configuration) の callable。
出力レーティング表 + 敗着/リプレイログ。

やること

  • 共通インタフェースは def agent(observation, configuration): return action。kaggle_environments.make(env).run([a, b]) で対戦、env.train() で固定相手学習。
  • ローカル対戦ハーネスを組み、seed 固定で決定論的に対戦し、リプレイ JSON を保存する (失敗/検証エピソードの診断は agent ログ + リプレイで行う、これは Kaggle の提出ゲートと同じ流儀)。
  • 自己対戦レーティング (TrueSkill/Elo) を N 戦で付け、信頼区間まで出してノイズを改善と誤認しない。勝率や敗着の分布など試合統計も集める。
  • 公開上位 agent を (許される範囲で nvidia-kaggle の kernel 取得を使い) 相手プールに入れ、負け筋を記録して分析する。
  • リモート実行イメージのバージョンをピン留めして再チェックする (実行イメージ更新で全提出が数日動かなくなった実例が Lux AI である)。
