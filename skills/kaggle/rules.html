/kaggle rules

Kaggle 全般で徹底したいルールを再ロードし、直近の作業を項目ごとに自己採点する

段階: 全・常時類型: 全
← Kaggle スキル群へ戻る

ワークフローの段階ではなく、常時守るべきチェックリスト。このスキルを指定するだけで、毎回説明し直さなくてもルール一式がコンテキストに戻り、直近の作業をルールごとに採点させられる。FAIL があれば先に直してから進む。

使い方

発火条件実装/実験の一区切りごと、提出前、または方針がぶれたと感じたとき。いつでも。
やること各ルールに PASS / 該当なし / FAIL(理由) を出す。FAIL があれば他を止めて先に直す。正直に FAIL と言えることが価値。
出力ルールごとの採点表 + FAIL の修正。
PASS 該当なし FAIL → 先に修正

ルール

1. 美しい実装ハードコード無し。band-aid でなく本質的な修正か (並列化・効率・正しい抽象)。共有すべきコピペが無いか。
2. 正しさを実際に確かめたか再利用コードは単体テストが通る。modeling run は OOF/CV 健全性 + 自明ベースライン比較で検証し、実際に走らせた数値を出す。走らせずに緑と主張しない。
3. デグレが無いか既存挙動を壊していない。CV/LB を黙って下げていない。ユーザーの編集を戻したり上書きしたりしていない。
4. 測定は誠実かコンペ公式の指標/eval だけが真実。自作の代理指標で良し悪しを判断しない。実測/引用/未計測を区別する。粒度を潰して数字を良く見せない。
5. 重い計算をローカルで回さない採点・eval・大規模学習はクラスタか EC2 へ。手元のノート PC で回さない。
6. CV を信じ、提出枠を賢く使うよく設計した CV を信じる。多シード + 有意差で採否を決め、提出枠をノイズに浪費しない。
7. リーク対策正しい実体単位で split。未来情報の混入なし。リーク候補列を確認済み。
8. 秘密の保護KAGGLE_API_TOKEN 等の資格情報を print/log/echo しない。
9. 外部アクションは確認提出・データセット公開は外部可視で枠を消費する。nvidia-kaggle の submit/upload を呼ぶ前に必ずユーザー確認。
10. 正しい層に置く・重複しない手順は skill、陳腐化する知識は解説記事、コンペ固有事実はその案件の CLAUDE.md。nvidia-kaggle が既にやることを再実装しない。
11. 記録したか変更/実験を /kaggle exp に 1 行残し、後から辿れる。

横断的な新ルールを学んだら /skill-curate でこのリストを育てる。コンペ固有のルールはここでなく、そのコンペの CLAUDE.md に置く。

実行例

# 実装が一区切りしたので自己採点
/kaggle rules

# → 採点 (抜粋)
1 美しい実装      : PASS
2 テスト          : FAIL  新しい特徴量関数に単体テストが無い → 先に追加
3 デグレ          : PASS  既存 CV 0.842 を下げていない
4 測定は誠実か    : PASS  公式 metric で評価
6 CV を信じる     : FAIL  1 シードで LB に出そうとしている → 多シード + 有意差ゲート
=> FAIL が 2 件。まず 2 と 6 を直してから提出に進む。

境界と実体

このスキルはルールを再ロードして自己採点し、FAIL を先に直させるためのもの。ルール自体の育成は /skill-curate、コンペ固有の制約はその案件の CLAUDE.md が担う。
