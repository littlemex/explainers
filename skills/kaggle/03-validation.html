CV 設計と CV-LB 追跡

段階: 検証設計類型: 予測系優先度: 3
← Kaggle スキル群へ戻る
ドラフト ― このページは現時点で分かっている情報から書いた暫定版です。スキルの実体 (.claude/skills/kaggle/SKILL.md) はサブコマンドの仕様を定義済みですが、手順の細部は実装時に変わる可能性があります。

データ構造に合った CV split を組み、CV と public LB の相関を最初から追う。CV-LB の乖離を見つけたときの再点検の起点でもある。

要点

発火条件最初の学習前。または CV と LB が乖離したとき。
前提BRIEF.md (指標・データのグルーピング) を読んでいること。
入力学習データ。
出力split 実装 + CV-LB 追跡表 (adversarial validation を回した場合はその報告も)。

やること

  • 正しい「実体」単位で GroupKFold を選ぶ。Eedi では QuestionId 単位より ConstructId 単位のほうが LB 相関が良かった、という実例がある。時系列は TimeSeriesSplit、不均衡は StratifiedKFold を根拠つきで。
  • 多シード CV (例 5-fold × 複数シード) を基本にし、変更は paired t-test など有意差で採否を決める。提出枠をノイズに浪費しない (ISIC は 10 シードで p 値ゲート)。
  • 特徴量エンジニアリングによる CV 改善は LB と相関しやすく、ハイパラ調整による CV 改善は相関が薄い (Home Credit)。この違いを踏まえて何を信じるか決める。
  • 任意で adversarial validation (train 対 test の分類器) を回し、分布シフトと drift 上位の特徴量を検出する。
  • CV-LB 追跡表 (実験 → CV → public LB → 差) を最初から付け、相関を監視する。差が広がったらこのスキルを再実行する。

実行例

# 最初の学習前、または CV-LB 乖離時
/kaggle validation

# → split 実装 + CV-LB 追跡表 (抜粋)
split     : GroupKFold(ConstructId, k=5), seeds=[0,1,2]
gate      : paired t-test, p<0.05 のみ提出
tracking  : exp / CV / LB / gap を追記中
