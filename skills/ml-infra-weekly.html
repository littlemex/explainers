/ml-infra-weekly

最近読んだブログと arXiv の URL を貼ると、一覧の表、記事ごとのコメント、元記事の図、課題から結果までの要点、今後の調査の表を持つ Zenn の記事を 1 本書く

入力: 読んだ記事の URL の束出力: Zenn の下書き 1 本レビュー: 観点を変えて 5 回続き: 次に確かめることを本に残す
← skills シリーズへ戻る

/arxiv-digest がその週の論文を自動で集めるのに対し、こちらは自分が選んで読んだ記事だけを扱う。記事ごとに、自分の声で「なぜ気になったか、将来こうなりそうか」を書く叩き台を置き、その下に元記事で一番大事な図と、中学生でも読める「課題、ねらい、やったこと、結果」を並べる。最後に、読んで気になったことを今後の調査の表にまとめる。

要点

いつ打つ読んだブログと論文がたまり、まとめて Zenn に残したいとき
タイトルML infra weekly: <分類の言葉> ~YY/MM/DD。毎週出すとは限らないことを、はじめにの冒頭で少しふざけて断る
一覧の表タイトル (英語の原題にリンク)、日本語 1 文のサマリー、代表著者組織の 3 列
記事ごとの形コメントの枠、元記事の図と出典、課題・ねらい・やったこと・結果の 4 項目、の順。括弧書きはできるだけ使わず、専門用語は初めて出たところで 1 文で説明する
図元記事の図を元の URL で貼り、図の主張を 1 文の alt にする。取れないときだけ、色だけに頼らない pptx の図を作る
まとめ1〜2 文と、今後の調査の表 (調査すること、きっかけの記事、確かめ方)
実装claudecode/.claude/skills/ml-infra-weekly/SKILL.md

流れ

  1. URL を 3〜4 本ずつに分けてサブエージェントに読ませ、記事ごとに取材メモを書かせる。メモには原題、所属、節ごとの要約、全部の図の URL と 200 の確認を入れる。
  2. URL に添えられた問いは、コメントの中で答える。同じ名前の別物がありうるときは両方を調べる。
  3. 形どおりに下書きを書き、改行、生の URL、絵文字、図とリンクの到達を機械で確かめる。
  4. 観点を変えて 5 回レビューする。初めての読者、取材メモとの突き合わせ、敵対的な専門家、zenn-doc の規約、最後に全体の総点検。
  5. 直した下書きを渡す。Zenn への作成と公開は、出すと言われてから。

号を出したあと: 次に確かめることを実機で確かめて本に残す

各号の最後の「今後の調査」の表のうち、実機で確かめる価値があるものは、翌週以降に実際に動かし、Zenn の本 Distributed AI - Experiments に章として残す。本は「ML infra weekly で次に確かめると書いた項目を、実際に確かめた記録」で、号が出るたびに章を足していく。

章の並び新しい号ほど前。はじめにの章の直後に新しい号の章を差し込み、古い号の章を後ろへずらす。末尾には足さない
章の題[YY/MM/DD:#N] 主張の題。号の日付と「今後の調査」の表の番号を付ける。例: [26/10/29:#3] 学習と推論の確率は本当に一致するか
章の形はじめに (号の URL と何番目の項目か)、この章で使う言葉、仕組みの図、何をどう測ったか、結果、分かったことと分からなかったこと、distributed-ai に取り込むもの (表)、参考資料、まとめ
実験のコードlittlemex/distributed-ai の investigations/ に検証ごとのディレクトリを切り、本からは commit 固定のリンクで指す
レビュー章ごとに 3 回。Fable 5.2、Opus 5.5、GPT-6 Sol、GPT-6 Astra の 4 つに同じ問いを投げる

初回は、非同期のチェックポイントで「保存の呼び出しにかかった時間」を「学習が止まる時間」と書き、学習全体では速くなっていないことを見落とした。手法の売りの指標だけでなく、区間の実時間でも必ず確かめる。

初回で分かったこと

初回は 14 本を扱った。レビューで一番多く直したのは、数字が「何の時間か」の取り違えだった。たとえば「最適化手法の更新が 79% 短い」を「学習の 1 ステップが 79% 短い」と読める形で書いていた。もう 1 つは、元記事に無い前提をコメントに足していたことで、検証環境がローカルの NVMe なのに、共有のファイルシステムでも同じ確かめ方が使えると書いていた。どちらも、取材メモを全部付けて突き合わせる回で見つかった。

サブエージェントを同じ作業ディレクトリで並行に動かすと、抽出用のスクリプトを互いに上書きした。スクリプトの名前はエージェントごとに分けさせる。
