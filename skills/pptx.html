コーポレートテンプレを適用し、編集可能なネイティブ shape でスライドを組む

対象: 顧客提示資料・登壇資料実体: 自作の pptxkit画像ゼロ
← skills シリーズへ戻る

スライドを PNG で貼るのをやめて、PowerPoint のネイティブ shape で組む。受け取った側が箱を動かし、文字を打ち替え、表の数値を差し替えられる。テンプレの配色とフォントと余白は自動抽出するので手写ししない。

要点

発火条件顧客提示や登壇のスライドを作るとき。とくに受け取った側が改稿する資料、値の差し替えが前提の試算表。
入力載せる内容と、適用したいコーポレートテンプレの pptx。
出力テンプレ適用済みの pptx、生成スクリプト、目視用の PNG、全枚のスピーカーノート。
解く問題ブロックの高さを目分量で決めて文字がはみ出す・箱が重なる・表がフッタに食い込む、という毎回の事故。

なぜ画像を貼るのをやめたか

同じ内容のデッキを draw.io から PNG にして貼る方式と、ネイティブ shape で組む方式の両方で作り、XML を数えて比較した。

観点ネイティブ shapedraw.io → PNG
画像の数019
ファイルサイズ0.04 MB14.78 MB
受け手が編集できるかできるできない
文字の検索・コピーできるできない
拡大したときの劣化しないする
外部依存なしdrawio CLI
既製シェイプautoshape のみAWS 公式アイコン等が豊富
自動レイアウトないない

どちらにも自動レイアウトは無い。座標は自分で決めるしかない。だから差は「受け手が編集できるか」と「既製シェイプがあるか」の 2 点に絞られる。

使い分け ― どちらで作るか

ネイティブで作る

  • 本文スライド全部。見出し・箇条書き・カード・表・数値タイル
  • 試算表。顧客が値を差し替える前提のものは必ずネイティブ
  • フローチャートと状態遷移。autoshape の菱形・角丸で足りる
  • ブロック図・レイヤ図。破線の境界枠 + 箱 + 矢印で表現できる範囲
  • グラフ。ネイティブチャートにすればデータも編集できる

draw.io で作る

  • AWS 公式アイコンを多用するアーキテクチャ図
  • 要素が数十個ある密な図。崩れないことを画像で保証したいとき
  • ブラウザで直接編集させたい図
draw.io を使う場合も、貼り付けるのはその 1 枚だけにする。周りの体裁はネイティブで組み、デッキ全体を画像にしない。

核心 ― y を持たない

はみ出しと重なりの原因は例外なく「何行になるかを数えずに高さを決めた」こと。だからブロックを積むだけの API にして、高さの計算を 1 か所に閉じ込め、コンテンツ下端を越えた瞬間に例外で落とす。

# y を書く場所がどこにも無い。足すと下に進む
s = d.slide("見出しは主張で書く", eyebrow="SECTION", sub="補足の 1 行")
s.metrics([("4 台", "推奨", "等価置換"), ("8 台", "現行", "p5.48xlarge")])
s.cards([("題", "本文"), ("題", "本文")])
s.callout("覚えて帰ってほしい 1 行")
s.notes("読み上げ用のノート。括弧は使わない")

# 下端を越えると Overflow 例外。黙って隠れることがない
pptxkit.measure.Overflow: table が下端を 16px 超えた (bottom=656, limit=640)

この例外が、これまで PNG を何十枚も目視して探していた崩れを、実行時に自動で見つける。s.remaining() で残り px も見られる。

テーマは手写ししない

テンプレの pptx を読んで、配色・フォント・余白規約を機械的に抽出する。色をコードに直接書かないので、テンプレを差し替えれば配色が全部追従する。

from pptxkit import theme
print(theme.describe(theme.load("templates/corp-dark.pptx")))

canvas     : 1280 x 720 px   dark=True
grid       : ml=43 cw=1202 title_y=32 content=145..640 blank_layout=5
fonts      : title='Corp Display' body='Corp Sans' ea='メイリオ'
bg/tx      : #000000 / #FFFFFF   muted=#8C8C8C
surface    : #161D26  line=#383838  accent=#41B3FF  tint=#1F3E56

抽出するもの。

  • clrMap の反転。 bg1="dk1" のダークマスターを正しくダーク判定する。実際に適用したコーポレートテンプレがこれで、白背景だと思い込むと文字が全部読めなくなる
  • clrScheme の accent1..6、fontScheme と master の titleStyle / bodyStyle
  • master のプレースホルダから左余白・タイトル位置・コンテンツ上端
  • master の装飾 shape の位置からコンテンツ下端。 ロゴや著作権行に食い込まない
  • line / muted / tint / surface は bg と tx の混色で導出

手順

  1. テンプレを決める。無ければ既存スライドを全削除した素体を templates/ に登録する
  2. 内容を先に決める。見出しは体言止めでなく主張。結論は 2 枚目に先出しする
  3. gen.py に本編を書く。長くなったら appendix.py に分ける
  4. 実行して Overflow を潰す。例外が出たらブロックを削るか文言を短くする
  5. PNG に落として目視する。例外が出なくてもパネル内のテキストが枠を割ることはある
  6. スピーカーノートを全枚入れる。括弧を書くと notes() が例外で落とす
python3 gen.py
PYTHONPATH=<pptxkit> python3 -m pptxkit.check out.pptx ~/tmp/<project>

PNG は ~/tmp/<project>/ に置く。使い捨てなのでリポジトリに入れない。生成スクリプトと出力 pptx は成果物としてリポジトリ側に置く。

python-pptx が API を出していない箇所

ここだけ XML を直接書いている。触るときは中身を読む。

症状原因と対処
矢印に先端が付かないshape.line に API が無い。a:tailEnd を XML で足す
表に白い罫線が出る既定 table style。tableStyleId を no-grid にしてセルごとに a:lnB を書く
日本語が別フォントで組まれるfont.name は latin だけ。a:ea を別に書く
接続矢印のラベルが左上隅に落ちるadd_connector の初期座標で中点が決まる。begin_connect 後にラベルは実座標へ別途置く
図形に勝手に影が付くautoshape は既定で影あり。shadow.inherit = False
使わないプレースホルダの枠が残る空文字にするのではなく要素ごと削除する
字送りが崩れる端末に無い表示用ウェイトを body に指定している。素のファミリに落とす

図解もネイティブで組む

矢印は図形の接続点に結ぶので、後から箱を動かすと線が追従する。フローチャートも状態遷移もこれで足りる。

a = sh.node(slide, t, x, y, 200, 64, "現行\np5 x 8")
b = sh.node(slide, t, x+280, y, 200, 64, "pilot\np6-b300 x 2")
q = sh.node(slide, t, x+280, y+120, 200, 64, "k を確定", shape=MSO_SHAPE.DIAMOND)

sh.connect(sh.arrow(slide, t, 0,0,1,1), a, 3, b, 1)   # 0=上 1=左 2=下 3=右
sh.connect(sh.arrow(slide, t, 0,0,1,1), b, 2, q, 0)
sh.group_frame(slide, t, x-14, y-30, 700, 120, "測定フェーズ")

禁止事項

  • 目分量で高さを決める。必ず測定を通したブロックを使う
  • PNG を貼ってデッキを作る。既製シェイプが必要な 1 枚だけに限る
  • 色を直接書く。テーマから取る。テンプレ差し替えで壊れる
  • スピーカーノートに括弧を書く。読み上げで崩れる
  • 目視を飛ばす。Overflow が出なくても崩れることがある
