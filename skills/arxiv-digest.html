/arxiv-digest

その週の arXiv から、分散学習・分散推論・LLM の基盤に関わる論文を選び、日本語の要約を付ける

入力: arXiv のその週の公開分出力: explainers の週報 1 枚所要: 集めるのに 20〜30 分
← skills シリーズへ戻る

打つと、arXiv がその週に公開した論文を 8 分野から集め、テーマと著者の所属で絞り、1 本ずつ日本語で要約して、テーマで絞り込める 1 枚の HTML にする。できたページは arXiv 週報 に並ぶ。

要点

いつ打つ週に 1 回、その週の新しい論文をまとめて眺めたいとき
見る分野cs.DC・cs.LG・cs.CL・cs.AI・cs.AR・cs.PF・cs.NI・cs.OS (他分野からの相互掲載を含む)
テーマ集団通信・ネットワーク / 分散学習 / 推論・サービング / カーネル・低精度 / モデル構造 / 学習効率・スケーリング / 強化学習の基盤
追う組織第 1 群: Amazon・NVIDIA・Google DeepMind・Meta・Stanford・Microsoft・OpenAI・Anthropic・Apple。第 2 群: Berkeley・MIT・CMU などの大学と、Alibaba・ByteDance・DeepSeek・Huawei などの企業 (計 47)
実装claudecode/.claude/skills/arxiv-digest/ の SKILL.md と scripts/

4 段の絞り込み

取りこぼしを減らすため、前の段ほど広く取り、後ろの段で落とす。初回 (2026-10-29、arXiv の公開日 10/22〜10/28) の本数を並べる。

段やること本数
1. 一覧arXiv の一覧ページ (pastweek) から論文番号を取り、詳しい情報を API で取る2,739
2. テーマ題名と要旨に、7 テーマの語のどれかが出るか441
3. 所属本文 1 ページ目の著者欄に、追う組織の名前が出るか155
4. 読む要旨を読み、テーマに実際には関係しないものを外して日本語で要約する88

4 段目は 30 本ずつサブエージェント 5 体に並行で書かせ、最後に、要約に出てくる数字が 1 つずつ要旨に出てくるかを機械で照合する。初回は要旨に無い数字が 0 件だった (引っかかった 6 件は 1.22B を「12.2 億」とするような単位の言い換え)。

使い方

/arxiv-digest

あとは手順書のとおりに進む。集める段は裏で回し、終わると要約に進み、ページを作って開き、explainers に載せる。途中で落ちても、各段の結果を作業ディレクトリに残してあるので、打ち直せば続きから進む。

走らせて見つけて直した 4 つ

  • 投稿日で区切ると落ちる ― 最初は arXiv の API の投稿日で 7 日分を区切った。窓の前に投稿されて窓の中で公開された論文が落ち、cs.LG では 776 本 対 一覧ページの 1,306 本 と 4 割欠けた。論文番号は一覧ページから取る形に変えた。
  • 著者欄の切り出しを誤ると所属が化ける ― arXiv の HTML の作りが想定と違い、切り出しに失敗したときにページの頭を丸ごと読んでいた。要旨の「NVIDIA の GPU で実験」が所属として当たり、所属で残る割合が 65% に跳ねた。著者欄だけを読む形に直して 35%。
  • 短い語は別の語に当たる ― ZeRO を拾うつもりの語が zero-shot の論文 116 本 に当たった。語を足したら、当たった語の出現数を数えて上位に変な語が無いかを見る。
  • 一度に書かせすぎると落ちる ― 31 本の要約を 1 回で書かせたら、5 体とも出力の上限で止まった。1 回 10 本までに分けて書かせる。

残っている限界

  • 所属は著者欄の文字の一致で決めるので、略称だけの所属や、著者欄に所属を書かない論文は落ちる。逆に、題名の一部が組織名と同じ綴りだと誤って拾う (初回は「on Apple Silicon」を Apple と読んだので直した)。
  • 要約は要旨だけを読んで書く。実験の数字は論文の主張で、確かめてはいない。
  • テーマで外す判断はサブエージェントがする。初回はオンポリシー蒸留の 2 本が「アルゴリズムだけの論文」として外れていたので、手で戻した。
