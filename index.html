Prismyra ・ 実測記

効かない高速化を消し、効くものだけを測って残す

文書を 1 回読んで多数の質問に logit で答えるライブラリ Prismyra の実測記。「保存方式を変えると 8〜9% 遅い」と報告していた高速化 (paged) は、確率差が 0.0000 と完璧すぎたことから配線が繋がっていないと分かり削除。「幅を変えても時間は同じ」は短い文脈だけの話で、24,327 トークンでは 1.51 倍に悪化していた。メモリの受付チェックは保持分しか見ておらず、読む一時ピーク 5.63 GiB を見落として受け付けてから落ちる状態だった。層ごとの複製をやめて一時メモリを 4.970→3.482 GiB に削減。そして一番大事な主張「読み取った答えは生成した答えと区別できない」が、10,199 トークンでは -5.0% (区間がゼロを含まない) まで崩れて初めて分離した。テトリスの決定ループでは結論を 2 回間違え、壊れているのは「見る」でも「評価する」でもなく 34 候補を積み上げて比較する 3 番目の鎖だと分かった。vLLM に速度で 4.3 倍負けていた原因はカーネル起動 32,873 回のうち 93% が線形注意の層だったことで、同梱カーネルに差し替えて 1.9 倍まで詰め、さらに通過を録画して再生することで枝パスを 113.5→32.6 ms (3.5 倍・確率まで完全一致) にした。そこで初めて、削除した paged 経路の本当の価値がメモリではなく「形の固定」だったと分かる。比較相手 (ikermoel/open-alternative-jev) の中身も並べてあり、彼ら自身の測定が「自分たちの標準方式より素の vLLM の方が速くて正確」と言っているので、本当の対戦相手は最初から vLLM の prefix cache だった。自分のミスで無効にした測定 5 件もそのまま残す。

 推論基盤 ・ 理論

分離推論が効く条件を、机の上で先に決める

分離が速くなる理由を式にすると 1 つしか残らない。decode を少数の機械に集めると相席が増え、重みを読む代金を割り勘にできることだけ。108 通りを探索して勝ったのは 17 件で、すべて「1 文字あたりの約束が厳しく最初の 1 文字の約束が緩い」角に集まった。さらに goodput をトークンで見て API 価格と比べると、分離が勝つ領域と自前運用が成立する領域は重ならない。そして最大の発見は、この判定が「約束を守った」の定義に丸ごと依存していたこと。1 文字あたりを平均で測ると分離は 0.3 倍、p99 で 4.6 倍、最悪の間隔で 13 倍に反転する。売る分位点と流すベンチマーク (AgentX などの実トレース) を決めないと、測った数字が何を意味するかも決まらない。並列度・比率・ノードの割り方・受け渡し経路まで踏み込み、Fable と Codex の敵対的レビューを 5 巡かけて結論が反転する修正を 8 件入れた。触って確かめるデモが 4 つ。最後に合成の負荷をやめ、会話が積み上がり枝が同時に生えるエージェントの形で流し直したところ主役がもう一度入れ替わった。1 回の反復で処理するトークンの予算は捌ける仕事を 1.5 % しか動かさないのに最悪に近い間隔を 32 倍動かす。裾はほぼ無料で買える。ただし約束を跨げない大きさのまま刻むと悪化する。そして会話の履歴は書いた側に残るので、再利用が効く形は分離がいちばん損をする形でもある。ここで前版の主張を 1 つ撤回した。最後に L40S 1 枚を借りて vLLM を動かし、費用モデルを実測から当てはめてから別の負荷を予測し、測って突き合わせた。理論の土台である割り勘は実測で 41 倍として出て、定数項はデータシートの 85 % で検算が通った。そして「無料」は撤回で、実機では約束の両端の交換だった。間隔 p99 が 5.7 倍良くなる代わりに最初の文字までが 2.1 倍伸び、空いているときは交換にすらならない。シミュレータは順位付けには使えるが崩壊点は当てられない。そして最後に coding agent の比率 (入力が何万トークンで出力が数トークン) を測って、この問い自体が意味を失う領域を見つけた。天井の式は読む側が支配しても 1 に潰れるので 1 万対 1 の上限は 1.067 倍しかなく、天井が最も高い 1000 対 1 を選んで測っても GPU 2 枚の分離と GPU 1 枚の統合が全軸で 1 割以内に一致する。入力 120,000 トークンでは凍結した予測 1.067 倍に対して実測 1.05 倍で的中し、しかも最初の文字までは 27 % 悪化した。ふつうの会話で分離を全軸で上回っていたフラグも、ここでは逆効果になる。理由は 1 つで、出力が 12 トークンだと守るべき文字の隙間が 11 個しかないから。AgentX の実物は未実行で、真似たのは形だけである。

 DeepEP と EFA・シリーズ

順序を仮定しない all-to-all ― DeepEP を AWS EFA へ

MoE の dispatch/combine を GPU カーネルから直接 NIC を叩いて実行する DeepEP を、順序保証のないネットワーク (EFA の SRD) の上で正しく動かすとはどういうことかを一次ソースから読み解く全 13 回。ibverbs・libfabric・NVSHMEM・NCCL GIN・EFA-GDA の関係を「誰が WQE を書くか」で串刺しにし、末尾ポインタ方式が折れる 3 か所、in-band header と数え上げ signal で組み直したプロトコルとその正しさが立つ 3 つの不変条件、signal 512 本という予算が 176 rank の壁を作る構造、そして EFA インスタンスなしで検証する emulator が作れるかの判定まで。後半では実機で emulator を通します ― ホストの CUDA 転送では resident なカーネルにバイトが届かないことを 93 秒という数字で確定させ、BAR mapping に替えて dispatch と combine を通し、わざと契約を破っても壊れないカーネルの頑健さまで。到着順シミュレータと予算計算機のデモつき。
