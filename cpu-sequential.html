この回の前提: 第 02 回 トランジスタから論理ゲートへ、第 03 回 組み合わせ回路

組み合わせ回路は、入力が決まれば出力が一瞬で決まり、過去に何があったかは一切残りません。CPU がプログラムを実行するには、レジスタの値や実行中の場所 (プログラムカウンタ) を次のクロックまで覚えておく「記憶」が必要です。そこで使われるのが、出力の一部を自分の入力に戻す「順序回路」です。この回路が安定して動くには、クロックという合図の「立ち上がる瞬間」だけで値を確定させる、という約束が欠かせません。ここでは NOR ゲート 2 個のラッチから D フリップフロップ、レジスタまでを図で追います。

1. 組み合わせ回路には「記憶」が無い

第 03 回で見た組み合わせ回路 (ゲートをつないだだけの回路) は、出力が常に今の入力だけで決まります。入力を変えた瞬間、信号がゲートを伝わる時間 (伝搬遅延) の後に、出力は新しい値に切り替わります。1 クロック前に何だったか、という「過去」は回路のどこにも残りません。

CPU のレジスタやプログラムカウンタは、次の命令を実行するまで値を覚えていなければなりません。組み合わせ回路だけではこれができないので、出力の一部を自分自身の入力に配線でつなぎ戻す (フィードバック) という発想が必要になります。

図: 左は入力だけで出力が決まる組み合わせ回路。右は出力の一部を入力に戻すことで「前の状態」を参照できる回路になる。

2. SR ラッチ ― NOR 2 個をたすき掛けにする

記憶を作る最小の回路は、NOR ゲート 2 個を互い違いにつないだSR ラッチ (Set-Reset latch) です。片方の NOR の出力をもう片方の NOR の入力に戻すことで、入力 S (Set) と R (Reset) を 0 に戻した後も、出力 Q が直前の値を保ち続けます。rj32 の intro/sequential.dig には、この NOR 版 SR ラッチがそのまま「S-R Flip Flop」という名前の回路として置かれています。

図: NOR1 の出力 Q (緑色) が NOR2 の上側の入力へ、NOR2 の出力 ¬Q (紫色) が NOR1 の下側の入力へ戻る。S=R=0 のとき、この配線だけで直前の値が保たれる。

S=1, R=0 で Q=1 にセット、S=0, R=1 で Q=0 にリセット、S=R=0 では直前の値を保持します。S=R=1 は Q と ¬Q が両方 0 になる矛盾した状態で、禁止された入力として扱われます。

3. クロックを足して「決める瞬間」を 1 つに絞る

SR ラッチは S や R が変わるたびに即座に反応します。しかし CPU の中では、たくさんの回路が同時に値を変えようとしています。回路のあちこちが好きなタイミングで Q を書き換えると、他の回路がどの値を信じればいいか分からなくなります。そこで「クロック (clock) という合図が来た瞬間だけ値を更新する」という約束を導入します。これがD フリップフロップ (D flip-flop) です。rj32 の intro/sequential.dig には、まず SR ラッチにクロックで開閉するゲートを足した「S-R Flip Flop with Enable」、続けてそれを D 入力 1 本に単純化した「D Flip Flop」、最後に立ち上がりエッジだけで動く「D Flip Flop with Clock」の 4 段階が順番に並んでいます。

図: Q はクロックの立ち上がりの瞬間の D だけを取り込む。D がその間に何度変化しても、次の立ち上がりまで Q は動かない。

この「立ち上がりの瞬間だけ反応する」という性質により、D フリップフロップは周りの回路の信号がまだ安定していない途中経過を取り込まずに済みます。CPU 全体が同じクロック線を共有していれば、全てのレジスタが同じ瞬間に一斉に値を更新する、という前提を作れます。

4. セットアップタイムとホールドタイム (一般論)

Digital は理想化されたシミュレータで、伝搬遅延のない (あるいは単純化された) ゲートでクロックと信号の関係を確認できますが、実在する半導体のフリップフロップには、もう少し厳しい制約があります。これは rj32 や Digital 固有の話ではなく、順序回路一般に共通する性質です。

D フリップフロップが D の値を正しく取り込むには、クロックが立ち上がる直前のセットアップタイム (setup time) と直後のホールドタイム (hold time) の間、D の値が変化せず安定している必要があります。この窓の中で D が変化すると、Q が 0 と 1 の中間の不安定な電圧で止まってしまう「メタステーブル (metastable)」という状態になることがあります。

図: 立ち上がりの前後にある狭い窓 (セットアップ・ホールドタイム) の中で D を変化させてはいけない。

CPU の設計では、クロックの周期をこの窓より十分長く取り、かつ配線の長さや信号経路によって生じる「ある信号が他より遅れて到着する」ずれ (クロックスキュー) もこの窓に収まるようにします。クロック周波数を上げられる上限は、最も遅い経路がこの窓に間に合うかどうかで決まります。

5. レジスタ = 複数ビットの記憶 ・ 「状態」という考え方

D フリップフロップを 16 個並べて同じクロック線をつなぐと、16 ビットの値を 1 つの単位としてクロックの立ち上がりごとに更新できるレジスタになります。Digital にはこれを 1 つの部品にまとめた「Register」要素があり、クロック入力 C に加えて、更新してよいかを決めるen (enable) 入力を持ちます。en が 0 のときはクロックが来ても値を更新しません。

図: 複数の D フリップフロップが同じクロック線を共有し、一斉に同じ瞬間に値を更新する。これがレジスタ。

CPU のプログラムカウンタ、汎用レジスタ、キャリーフラグなどは、すべてこの「クロックの立ち上がりでだけ変わる記憶」の集まりです。ある瞬間の CPU の「状態」とは、これらのレジスタの値の組み合わせそのものを指します。次の第 06 回では、この記憶同士をどう配線でつなぎ、第 08 回ではレジスタを束ねた「レジスタファイル」をどう作るかを見ていきます。

6. 実装のポイント

生の NOR/NAND からラッチを自作しない。 Digital には既に検証済みの D フリップフロップ (D_FF) やレジスタ (Register) の部品が用意されています。rj32 の intro/sequential.dig はあくまで「中がどう動いているか」を見せる教材用の回路で、実際の CPU 本体 (dig/rj32.dig 以下) は NOR の組み立てではなく、ライブラリの D フリップフロップやレジスタをそのまま使っています。理屈を理解したら、自作のラッチをデータパスに組み込む必要はありません。

フィードバックのループは必ずクロックで切る。 SR ラッチのような「出力を入力に戻す」配線は、クロックという関所を 1 つ挟まないと、信号が回路の中を無限に回り続けたり (発振)、入力の変化が伝わるタイミングによって結果が変わってしまったりします (競合)。CPU の設計で状態を持たせたい場所には必ずクロック付きの D フリップフロップ・レジスタを使い、クロックなしのフィードバックは作らない、というのが安全な指針です。

クロックは 1 本を全体で共有する。 レジスタごとに別々のクロック線を好きなタイミングで動かすと、「あるレジスタの新しい値を別のレジスタがまだ古い値のまま読んでしまう」といった食い違いが起きやすくなります。rj32 を含め多くの小さな CPU は、単一のクロックをチップ全体に配り、更新してよいかどうかは個々のレジスタの en (enable) 入力で制御する、という設計を取ります。

図: 教材として理屈を学ぶ回路と、実際にデータパスへ組み込む回路は分けて考える。
