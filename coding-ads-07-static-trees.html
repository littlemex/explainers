静的な木を定数時間で捌く ― LCA・RMQ・Level Ancestor

前処理に線形時間、クエリに定数時間。3 つの問題が実は 1 つの問題であることを見る

前回・前々回で見た動的最適性は「木を操作し続ける」世界の未解決問題でした。この回はうってかわって、木を一度作ったらもう変更しない (静的) という設定です。制約が強くなった分、驚くほど強い結果が手に入ります。範囲最小値クエリ (RMQ)、最小共通祖先 (LCA)、レベル祖先 (Level Ancestor, LA) という見た目の違う 3 つの問題が、前処理 $O(n)$・クエリ $O(1)$ という最適な形で、しかも線形空間で解けることを MIT 6.851 (Erik Demaine, 2012 年春, Lecture 15) の講義ノートに沿って確認します。鍵になるのは、RMQ と LCA を互いに変換する 2 種類の還元、べき乗区間を使う sparse table、そして「大きい方は粗く、小さい方は丸ごと覚える」という間接参照 (indirection) のテクニックです。

この回の位置づけ

静的な木のクエリは「1 回だけ前処理して、その後は何度もクエリに答える」という設定です。動的最適性のように木を操作し続けるわけではないので、使える道具が変わります。具体的には、配列の添字に直接アクセスできる word RAM モデルを使い、動的計画法で前計算したテーブルを引くという、ふつうのアルゴリズムの道具立てに戻ります。その代わりに要求されるハードルも上がり、「前処理 $O(n)$・クエリ $O(1)$・空間 $O(n)$」という全部が最適な解を目指します。

これを理解するには、(1) 配列添字にアクセスできる word RAM モデル、(2) 木を深さ優先探索 (DFS) でなぞる Euler tour (オイラー路)、(3) 「大きい方は粗い代表値で済ませ、小さい方は表引きで済ませる」という間接参照 (indirection) のテクニックが前提になります。先に手早く補習します。

前提の補習

word RAM モデル

word RAM では、ポインタをたどることしかできないポインタマシンとは違って、配列 A の添字 A[i] に単位時間でアクセスできます。整数の足し算・引き算・ビット演算も単位時間です。この回のアルゴリズムは「配列の決まった位置を何個か読んで min を取る」といった操作を多用するので、ポインタを辿るしかない前回までのモデルより道具が豊富になります。

Euler tour (オイラー路) による木の線形化

根付き木を深さ優先探索 (DFS) でなぞり、ノードに入るたび・出るたび (= 辺を下るたび・上るたび) に記録を取ると、木全体を 1 本の列に変換できます。この列は木の形をすべて保持しており、木の上の質問を配列の上の質問に変換する (今回の LCA↔RMQ の還元の片方がまさにこれ) 際の基本テクニックです。

間接参照 (indirection) ― 大きい方は粗く、小さい方は丸ごと

この講義シリーズで繰り返し出てくる考え方です。配列をサイズ $b$ の小さなブロックに分け、(a) ブロックどうしをまとめた「親配列」には粗い (asymptotically ゆるい) アルゴリズムを使い、(b) ブロック内部は $b$ が小さいことを利用してルックアップテーブル (あらかじめ全パターンの答えを表にして持つ) で定数時間にします。$b$ を $\log n$ 程度に選ぶと、親配列のサイズが $n/\log n$ 程度まで縮むので、親配列側のゆるいアルゴリズムの対数因子が打ち消し合い、全体として線形時間・線形空間に収まる、というのがこの回で何度も登場するパターンです。

深さ (depth) と高さ (height) は別の量

ノード $v$ の深さは根から $v$ までの距離、高さ $h(v)$ は $v$ から葉までの最長距離です。深さは根から下に数え、高さは $v$ から下の部分木だけを見て決まります。同じ深さのノードでも、部分木の形が違えば高さは全く違います。Level Ancestor の議論では高さ $h(v)$ がノードを分類する軸として使われるので、ここで区別しておきます。

1. 3 つの問題を定義する

Range Minimum Query (RMQ, 範囲最小値クエリ)

$n$ 個の数の配列 $A$ を前処理しておき、クエリ $\mathrm{RMQ}(i,j)$ には「$A[i], A[i+1], \dots, A[j]$ の中で最小の要素の添字 $k$」を答えます。値そのものではなく添字を求めるのがポイントです (添字が分かれば値は $A[k]$ を見るだけなので、添字を求める方が一般的で難しい問題です)。

Lowest Common Ancestor (LCA, 最小共通祖先)

根付き木 $T$ ($n$ ノード) を前処理しておき、クエリ $\mathrm{LCA}(x,y)$ には「$x$ と $y$ の両方の祖先であって、最も $x,y$ に近い (最も深い) ノード」を答えます。

Level Ancestor (LA, レベル祖先)

根付き木 $T$ を前処理しておき、ノード $x$ と整数 $k \le \mathrm{depth}(x)$ が与えられたクエリ $\mathrm{LA}(x,k)$ には「$x$ から根の方向に $k$ 段上がった祖先」、つまり $\mathrm{LA}(x,k) = \mathrm{parent}^k(x)$ を答えます。

図: 3 問とも「静的な構造を 1 回前処理し、繰り返しクエリに答える」という形は同じ。

LCA と LA は見た目が似ていますが、使う技法はかなり違います。一方、RMQ と LCA はほぼ同一の問題であることが、この後すぐに分かります。

2. RMQ と LCA の相互還元

2.1 Cartesian tree ― RMQ から LCA への還元

Cartesian tree (カルテシアン木) は配列 $A$ から二分木 $T$ を作る方法で、RMQ と LCA を結びつけます (Gabow, Bentley, Tarjan, 1984)。作り方は再帰的です。$A$ の最小値 $A[i]$ を木の根にし、根の左部分木を「$i$ より左側の要素 $A[{<}i]$ の Cartesian tree」、右部分木を「$i$ より右側の要素 $A[{>}i]$ の Cartesian tree」とします。

図: 最小値 2 が根になり、左側 [8,7]・右側 [8,6,9,4,5] がそれぞれ再帰的に Cartesian tree になる。できた木は min-heap。

最小値が複数ある (同じ値が並ぶ) 場合は、どれを根にするか任意に決めてよい (講義ではこちらを採用) か、同値のものを 1 つのノードにまとめて非二分木にするか、の 2 択です。どちらを選んでも答えは変わりません。

できた木 $T$ はそのまま min-heap です。 さらに重要なのは、$A$ 上の $\mathrm{RMQ}(j,k)$ の答えは、$T$ 上で $A[j]$ と $A[k]$ に対応するノードの $\mathrm{LCA}$ であるということです。$j < i < k$ をまたぐ範囲なら、最小値 $A[i]$ は根であり、$A[j]$ は左部分木、$A[k]$ は右部分木にあるので LCA はまさに根 $=A[i]$ になります。範囲が完全に左か右に収まる場合は、対応する部分木の中の RMQ に帰着するので、帰納法で一般の範囲に対しても成り立つことが分かります。

2.1.1 線形時間での構築

素朴な再帰で Cartesian tree を作ると $\Omega(n\log n)$、下手をすると $O(n^2)$ かかります。しかし、圧縮トライを線形時間で作るのと同じ考え方で、線形時間で構築できます。配列を左から右に見ていき、各要素を木の右側の背骨 (right spine) を上に向かって歩きながら適切な位置に挿入します。左から処理しているので、挿入する要素は常にそれまでに作った木の「最も右」の要素になります。

この挿入は償却定数時間です。各挿入は右の背骨だけを触りますが、背骨上で触れたノードは必ず新しいノードの左部分木に入り、その後は右の背骨から外れます。つまり「右の背骨を長く歩いた」コストは、その分だけ背骨の長さが短くなったことに課金できるので、比較モデルの範囲内でも線形時間で構築できます。

2.2 LCA から RMQ への還元

逆方向、二分木 $T$ から配列 $A$ を作る還元もできます。$T$ を通りがけ順 (in-order) でなぞり、各ノードに木での深さをラベル付けして並べれば配列 $A$ ができます。

図: この深さ列は、この木が元々作られた配列 A=[8,7,2,8,6,9,4,5] に対する RMQ と同じ答えを返す。

この深さ列に対する $\mathrm{RMQ}(i,j)$ は、元の木での $\mathrm{LCA}(i,j)$ と同じ答えになります。注意点として、この還元で作った配列は隣接要素の差が $\pm1$ とは限りません (深さが 2 つ以上一気に変わる箇所があります)。この性質を使うのは後の節 (3.2) で、別のやり方が必要になります。

2.3 RMQ の値域を小さい整数に縮める (universe reduction)

RMQ の配列の要素は、本来どんな順序集合の値でもかまいません。しかし 2.1 と 2.2 の還元を続けて使うと ― まず Cartesian tree を作り、それを今度は深さ列に変換し直す ― 元の値がどんなものであっても、$\{0,1,\dots,n-1\}$ の範囲の整数だけを扱う RMQ に還元できます。これで、以降は「小さい整数の配列」だけを考えればよく、word RAM モデルで定数時間の操作が使える土台が整います。

3. 定数時間 LCA・RMQ

LCA と RMQ を前処理 $O(n)$・クエリ $O(1)$・空間 $O(n)$ で解く手法は、最初に Harel と Tarjan (1984) が示しました。講義で扱うのは Bender と Farach-Colton (2004) によるもう少し扱いやすい手法です。

3.1 まず ±1 RMQ に還元する

Bender-Farach-Colton の手法は、隣接要素の差がちょうど $+1$ か $-1$ になる特殊な ±1 RMQ を使います。2.2 節の「通りがけ順+深さ」の還元は差が $\pm1$ とは限らないので使えません。代わりに Euler tour (オイラー路) を使います。DFS で木をなぞり、ノードに入るたびと、子から戻ってくるたびの両方で、そのノードを配列に書き足します。1 歩ごとに深さがちょうど $\pm1$ だけ変わるので、できる配列は確実に ±1 RMQ の条件を満たします。

図: 各辺を 2 回 (下りと上り) 通るので、通りがけ順より長い配列 ($O(n)$ のまま) になるが、1 歩ごとの差は必ず ±1。

$\mathrm{LCA}(x,y)$ を求めるには、$x$ が Euler tour 配列で最初に現れる位置を $\mathrm{first}(x)$ として、$\mathrm{RMQ}(\mathrm{first}(x), \mathrm{first}(y))$ を計算すればよい、というのが Bender-Farach-Colton の還元です ($\mathrm{first}$ はツアーを作りながら同時に記録できます)。この新しい配列は、2.2 節の配列の隙間を埋めたものに相当し、2 点間の最小値はどちらの配列でも変わらないので、この還元も正しく動きます。

3.2 $O(n\log n)$ 空間・$O(1)$ クエリの sparse table

区間の長さが 2 のべき乗であるすべての区間について、あらかじめ RMQ の答えを前計算しておきます。長さ $2^k \le n$ の区間は $n$ 通りの開始位置があり、べき乗の個数は $\lg n$ 通りなので、合計 $O(n\lg n)$ 個の答えを表に持てば済みます。

クエリ $\mathrm{RMQ}(i,j)$ (長さ $k=j-i+1$) に答えるには、$2^{\lfloor \lg k \rfloor}$ の長さの区間を 2 つ、両端にぴったり合わせて取り、両方の答えの min を取ればよいことに気づきます。

$$\text{区間は常に、両端それぞれを覆う長さ } 2^{\lfloor \lg k \rfloor} \text{ の 2 区間の和集合で覆える}$$

この 2 区間は重なっても構いません。min は同じ値を 2 回数えても結果が変わらない (idempotent, 冪等) ので、重なりがあっても答えは正しいままです。これが「2 個の前計算済みの答えを引くだけで任意の区間に答えられる」理由で、クエリは $O(1)$ です。添字そのもの (argmin) が欲しいときは、値ではなく最小値の位置を表に持てば同じ議論がそのまま成り立ちます。

3.3 間接参照で空間を $O(n)$ に落とす

$O(n\lg n)$ 空間を $O(n)$ に落とすには、ここでも間接参照を使います。配列をサイズ $\tfrac12 \lg n$ の下位ブロックに分け、各ブロックの最小値だけを集めたサイズ $2n/\lg n$ の親配列を作ります。

クエリは、両端が別ブロックにある場合、(a) 両端のブロック内で部分範囲の RMQ を 2 回、(b) その間のブロック群に対する親配列上の RMQ を 1 回、の合計 3 回のサブクエリに分解できます ($i,j$ が同じブロック内に収まる場合は、その 1 ブロック内だけで両端指定の RMQ を解く必要があります)。親配列は $O(m\lg m)$ ($m = 2n/\lg n$) の sparse table で構わない理由は、$\lg m = \lg(2n/\lg n) = \Theta(\lg n)$ となって対数が打ち消し合い、$O(m \lg m) = O(n)$ に収まるからです。

3.4 小さい配列の RMQ をルックアップテーブルで解く

残る問題は、サイズ $n' = \tfrac12 \lg n$ の小さいブロック内の RMQ をどう定数時間で解くかです。考えられる配列の形は非常に限られているので、答えを全部表にして持つという力押しが使えます。

まず、各ブロックの最初の要素を 0 にずらして考えれば十分です (相対的な位置だけが答えに影響するため)。さらに隣接差が $\pm1$ であることを使うと、長さ $n'$ のブロックは $+1/-1$ の列 ($n'-1$ 個のビット) で完全に決まるので、ありうるブロックの形は

$$2^{\,n'-1} = 2^{\frac12\lg n - 1} = \Theta(\sqrt{n})$$

通りしかありません。これは実際のブロックの個数 ($\Theta(n/\lg n)$) よりもずっと少ない数です。$\sqrt{n}$ 通りの形それぞれについて、$n'^2$ 通りのクエリ区間すべての答え (添字、$\lg n$ ビットで表せる) を表にすると、表全体のサイズは

$$O\!\left(\sqrt{n} \cdot \left(\tfrac12\lg n\right)^2 \cdot \lg\lg n\right) = O(n)$$

ビットに収まります。各ブロックは「自分がどの形か」を指すポインタを 1 個持つだけでよく、これで小さいブロック内の RMQ も定数時間、全体として前処理 $O(n)$・クエリ $O(1)$・空間 $O(n)$ の ±1 RMQ が完成します。

(講義録では長さ $n'$ の列として $2^{n'} = \sqrt n$ と数えています。隣り合う差の個数は $n'-1$ なので上のように数えるほうが細かいですが、どちらでも $\Theta(\sqrt n)$ 通りという結論は同じです。)

3.5 一般の RMQ・LCA へ戻す

±1 RMQ が線形空間・定数時間で解けたので、3.1 節の還元 (LCA → ±1 RMQ) を通して LCA も同じ複雑さで解けます。さらに、一般の (差が ±1 とは限らない) RMQ も、2.3 節の universe reduction を通せば同じ結果に帰着します。これで「RMQ も LCA も、前処理 $O(n)$・クエリ $O(1)$・空間 $O(n)$ で最適に解ける」という、この節の主目的が達成されます。

4. Level Ancestor (LA) ― 6 つのアルゴリズム

$\mathrm{LA}(v,l)$ は「$v$ から $l$ 段上の祖先」を返すクエリです。講義では、前処理時間 $g(n)$・クエリ時間 $f(n)$ の組を $\langle g(n), f(n) \rangle$ と書き、Bender と Farach-Colton の論文にある 6 通りのアルゴリズム A から F を順番に見ていきます。だんだん賢くなり、最後に両方が最適な $\langle O(n), O(1) \rangle$ に到達します。

アルゴリズム前処理クエリ核になる考え方
A$O(n^2)$$O(1)$ノード×レベルの表を DP で全部埋める (力押し)
B$O(n\lg n)$$O(\lg n)$ジャンプポインタ (倍々、いわゆる binary lifting)
C$O(n)$$O(\sqrt n)$最長路分解 (longest path decomposition)
D$O(n)$$O(\lg n)$梯子分解 (ladder decomposition)
E$O(n\lg n)$$O(1)$B と D の組み合わせ
F$O(n)$$O(1)$マクロ・ミクロ木分解 + E (Dietz, 1991)

表の列は講義の表記 $\langle g(n)\text{(前処理)}, f(n)\text{(クエリ)} \rangle$ に対応 (上の表では分かりやすさのため列を分けて書いています)。

アルゴリズム A: $\langle O(n^2), O(1) \rangle$

ノードとレベルの 2 軸を持つ表を、レベルを増やしながら動的計画法で埋める力押しです。表のマス数がノード数 $\times$ 深さなので $O(n^2)$ の前処理が必要ですが、埋めた後はただの表引きなので $O(1)$ クエリです。

アルゴリズム B: $\langle O(n\lg n), O(\lg n) \rangle$ ― ジャンプポインタ

各ノードに、$2^0, 2^1, 2^2, \dots$ 段上の祖先へのジャンプポインタを持たせます。クエリは、残りの段数のうち半分より多く進むジャンプを繰り返し選んでいけば、$O(\lg n)$ 回のジャンプで到達できます。前処理はジャンプポインタを動的計画法で埋めるだけなので $O(n\lg n)$ です。

アルゴリズム C: $\langle O(n), O(\sqrt n) \rangle$ ― 最長路分解

木から最も長いパスを取り除き、残った連結な部分木に同じ操作を再帰的に繰り返します。これで木全体が互いに素なパス (配列として保持) の集まりに分解され、各パスの先頭 (そのパスの根側の端) は、1 つ上の再帰レベルで取り除かれたパスの配列の中の 1 要素を指します。クエリは、このパスからパスへのポインタを上に辿りながら、各パス内では配列添字で $O(1)$ に進みます。

最悪の場合、分解されるパスの長さが $k, k-1, \dots, 2, 1$ と 1 つずつ短くなり、どのパスも子が 1 本しかない形になることがあり、このときパスからパスへのポインタを辿る回数が $O(\sqrt n)$ になります ($1+2+\cdots+k \approx n$ より $k \approx \sqrt{2n}$)。前処理はノードの高さを 1 回計算しておけば、それを使って最長路を高速に見つけられるので $O(n)$ です。

アルゴリズム D: $\langle O(n), O(\lg n) \rangle$ ― 梯子分解 (ladder decomposition)

最長路分解に一工夫を加えます。各パスを、根の方向にさらに 2 倍の長さまで延長します (延長後の経路が根に達したらそこで止めます)。延長後のこの経路を梯子 (ladder) と呼びます。各ノードは「延長前の自分のパスに含まれていた、最上位の梯子」を記録します (延長によって後から自分を含むようになった、他のより低い梯子は数えません)。

図: パスを根方向に 2 倍延長するので、あるノード $v$ を含む梯子の高さは $v$ 自身の高さの 2 倍以上になる。

これが効く理由はこうです。ノード $v$ は、高さ (= 自分の下の最長路の長さ) 以上のサイズを持つパスの上に乗っています。延長によって、そのパスが乗っている梯子は少なくとも元のパスの 2 倍の高さを持ちます。つまり $v$ からジャンプするたびに、乗っている梯子の高さが最低でも 2 倍になるので、根に届くまでに必要なジャンプの回数は $O(\lg n)$ 回で済みます。各ジャンプの中では配列添字なので $O(1)$、前処理はアルゴリズム C と同様 $O(n)$ です。

アルゴリズム E: $\langle O(n\lg n), O(1) \rangle$ ― ジャンプポインタ + 梯子

アルゴリズム B と D を組み合わせます。クエリでは、まずジャンプポインタで目的の祖先まで少なくとも半分まで進みます。ジャンプ先のノードが乗っている梯子は、(ジャンプ元のパスの深さより深くまで伸びていて、かつ少なくとも 2 倍の高さまで延長されているので) 目的の祖先も含んでいることが保証されます。したがって、梯子の中を配列添字で 1 回ジャンプすれば終わりです。合計で $O(1)$ クエリ、前処理はジャンプポインタ分の $O(n\lg n)$ です。

アルゴリズム F: $\langle O(n), O(1) \rangle$ ― Dietz のアルゴリズム

最後に、アルゴリズム E の前処理も $O(n)$ に落とします。鍵になる観察は、「$v$ のレベル祖先が分かれば、$v$ の子孫のレベル祖先もそこから分かる」ということです。したがって葉だけにジャンプポインタを張れば十分で、葉の個数を $L$ とすると前処理は $O(n + L\lg n)$ になります。一般の木では $L = O(n)$ なので、まだ $O(n\lg n)$ のままですが、$L = O(n/\lg n)$ まで減らせれば $O(n)$ に落ちます。

葉が $O(n/\lg n)$ 個の木を作る

木をマクロ木 (根を含む大きい方) と、そこから垂れ下がるサイズ $\le \tfrac14 \lg n$ のミクロ木たちに分割します。木の DFS を 0 (下る) と 1 (上る) のビット列として符号化すると、サイズ $n$ の木は長さ $2n-1$ のビット列で表せるので、ミクロ木の種類数は多くとも $2^{2(\frac14\lg n)-1} = O(\sqrt{n})$ 通りです (実際にはこれより少なく、0 と 1 の個数が等しく、どの接頭辞も 0 が 1 以上という制約があります)。各ミクロ木は力押しの表 (アルゴリズム A と同様の考え方) で持てます。マクロ木の葉の個数は $O(n/\lg n)$ に抑えられます。

クエリ $\mathrm{LA}(v,l)$ は、$v$ がマクロ木にあれば「葉までジャンプしてから梯子を遡る」(アルゴリズム E と同じ) 方法で、$v$ がミクロ木にあって答えもそのミクロ木内にあればルックアップテーブルで、$v$ がミクロ木にあって答えがミクロ木の外にあれば同様に葉経由でジャンプして答えます。これで前処理 $O(n)$、クエリ $O(1)$ が両方達成されます。

実務での出番

前回・前々回 (動的最適性) とは対照的に、この回の内容は競技プログラミングと文字列処理の分野で、ほぼそのままの形で日常的に使われています。

Bender-Farach-Colton のアルゴリズムそのものが、競技プログラミングの標準的な参考資料である cp-algorithms.com の LCA 解説ページ に、Euler tour → ±1 RMQ → ブロック分割 + sparse table という、この講義で見た手順そのままで実装例付きで載っています。一方、sparse table 単体 (3.2 節) は 専用ページ があるほど定番の道具で、「区間が 2 つの重なってもよいべき乗区間で覆える」という同じ説明が載っています。

ただし間接参照で $O(n\lg n)$ 空間を $O(n)$ に削る 3.3-3.4 節の仕上げは、競技プログラミングの実装では普通省略されます。実戦では $O(n\lg n)$ 空間の sparse table (またはさらに単純な、クエリ $O(\lg n)$ の sparse table) で十分なことが多く、最後の一手間 (ブロック分割+ルックアップテーブル) にかかる実装コストに対して得られる漸近的な改善が実用上は割に合わないからです。この「漸近的には最適だが、定数部分の実装コストが高すぎて実戦では手前のバージョンで止める」という判断は、この講義シリーズ全体で繰り返し現れるパターンです。

アルゴリズム B (ジャンプポインタ、binary lifting) も同様に競技プログラミングの定番で、専用の解説ページ があります。実務でも「$\langle O(n), O(1) \rangle$ の梯子分解」より「$\langle O(n\lg n), O(\lg n) \rangle$ のジャンプポインタ」の方が圧倒的に実装されている頻度が高く、梯子分解やマクロ・ミクロ木分解 (アルゴリズム D, F) は実装の複雑さに見合う対数因子の改善が実戦ではほとんど問題にならないため、主に理論的な到達点として扱われます。

LCA という概念自体は、木ではなく DAG (有向非巡回グラフ) の上で、分散バージョン管理システムの Git にも現れます。git merge-base はブランチをマージする際に使う「最良の共通祖先」を探すコマンドで、公式ドキュメント には「2 つのコミットから親をたどって到達できる祖先」を探す、とまさに LCA と同じ考え方が説明されています (コミット履歴は木ではなく DAG なので、祖先が複数ありうる点は異なります)。

RMQ は文字列処理・バイオインフォマティクスでも中心的な道具です。接尾辞配列 (suffix array) と LCP 配列 (隣接する接尾辞どうしの最長共通接頭辞の長さ) を組み合わせ、LCP 配列への RMQ を使うと、任意の 2 つの接尾辞の最長共通接頭辞を定数時間で求められます (Wikipedia: LCP array)。これはゲノム検索や全文検索インデックスの基礎技術です。

最後に小さな余談ですが、Cartesian tree は前々回 (L05) で触れた treap (キーでの BST + ランダムな優先度でのヒープ) の正体そのものです。treap は「各キーにランダムな優先度を持たせた Cartesian tree」と定義されており、この講義シリーズの異なる回で出てきた道具が、実は同じ構造の応用だったという発見があります。
