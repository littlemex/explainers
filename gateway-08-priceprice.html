第 8 章 値段の値段 — 一番公式に見えたものが一番間違っていた

この章の 3 行 ここまでの章で使った層の単価は、手入力 → ゲートウェイ自身のレートカード → AWS Price List API と 3 回出どころを変えた。2 回目の「もっと公式に見えたもの」が実は一番ひどく、gemma-4 の入力単価を 正しい $0.14 の 36 倍にしていた。正しい値の取り方にも 3 つの落とし穴があり、 そのすべてに一度は引っかかった。

1 回目 — 手入力、単純な打ち間違い

最初、各層の単価はハーネスに手で打ち込んであった。ドキュメントを読んで転記しただけなので、 古い数字を見ていたり単純に読み違えたりする。実際に gemma-4 の入力単価は $0.30 と入力されていたが、 AWS が公開している値は $0.14 だった。これ自体は珍しい話ではなく、値の出どころを 1 か所に まとめる動機になっただけである。

2 回目 — もっと公式に見えたものが、もっと悪かった

次に、単価をゲートウェイ自身のレートカード (課金のために社内で持っている設定) から読み込む方式に 変えた。ハーネスの外にある、システムが実際に使っている値なので、手入力より信頼できるはずだと考えた。

13 行のうち 5 行が同じ行を指していた そのレートカードには 13 モデルぶんの行があったが、うち 5 行が同一の default 行を 参照していた。このカード自身のコメントによれば、default は「レートが分からないモデルに 意図的に高い値をあてがう」ための行で、料金を取り過ぎることで誤って安全側に振るガードレールだった。 ガードレールとしては正しい設計である。単価表として読み込むには、それを単価だと思って読み込んだ側 が間違っていた。

gemma-4 はこの default 行を引いていて、値は入力 $5.00。AWS の $0.14 との比は 36 倍。結果として、この系列でもっとも安いはずの層が、比較対象の中でもっとも高い層として 扱われることになった。

デモ: gemma-4 の入力単価は、聞く相手で 36 倍動く

スライダーで 3 つの出どころを切り替えてみてほしい。値そのものは全部実測 (実際にそう入力/参照/取得された値) で、 補間は無い。

gemma-4 の入力単価 $/Mtok

動かして見えること

  • 「ゲートウェイ自身の値」が一番信頼できそうに見えて、一番遠い。手入力の間違いは 2.1 倍だが、 レートカードの default 行は 36 倍。出どころの見た目の公式さと、値の正しさは無関係。
  • 間違った値は、間違って見えない。$5.00 という数字だけを見て「gemma-4 は高い層だ」と 結論するのは、その 1 個の数字を疑わなければ自然な読み方である。

3 回目 — 正しく取っても、3 つの落とし穴がある

いまは AWS Price List API から、モデルごとの Bedrock 提供リージョンと standard サービスティアを指定して取得している。この「正しい取り方」自体にも、最初に取ったときは全部で 3 回間違えた。

落とし穴具体的に何が起きるか
リージョンはモデルごとに違うClaude 系は us-east-1、gemma-4 と gpt-5.x 系は us-east-2、grok-4.6 は us-west-2 から取る必要がある。1 リージョンに固定すると一部のモデルの行が存在しないか別の値になる
サービスティアは名指ししないと決まらないAWS は同じモデルに standard、flex、priority、batch、global- 系の行を公開していて、値は最大 5 倍離れる。grok-4.6 は 1 リージョンだけで 18 行ある
最小値を取ってはいけない複数行から機械的に最安値を選ぶと、誰も選んでいないサービスレベルを黙って選んだことになる
なぜ「最小値」が罠なのか batch や flex は速度や可用性を落として安くするサービスレベルで、 今回の層の比較が前提にしている「同時実行を捌く」用途には合わない。値だけ見て一番安い行を拾うと、 比較の対象そのものが静かに変わってしまう。この章の表と第 1 章の追加行は、すべて standard ティアで統一している。

この章で壊しておきたい誤解

よくある思い込み実際は
システムが実際に使っている値が一番信頼できるその値がなぜそこにあるかを確認しないと、意図的な過大請求のガードレールを単価だと思い込む
値の出どころが公式に見えれば正しいゲートウェイ自身のレートカードは一番公式に見えて 36 倍外れていた
1 つの API から取れば地域差の問題は消えるモデルごとに提供リージョンが違う。1 リージョンに固定すると一部のモデルの値が欠けるか変わる
公開されている値なら 1 モデルに 1 つの値段しかないサービスティアで最大 5 倍違う行が並ぶ。名指ししないと決まらない
複数の値があるなら安いほうを使えばよい最小値は誰も選んでいないサービスレベルを黙って選ぶことになる
