第 17 章 「誰なら解けるか」を測る。価格はあとから代入する

この章の 3 行 第 16 章までは「今の価格・今の顔ぶれで何が最適か」を測っていた。プールは変わる — 箱のモデルも インスタンスも API も固定ではない — ので、その答えは成果物にならない。 そこで測る対象を item × 候補の正誤行列 に移した。すると「このプールは routing する価値があるか」 という判定自体が行列から自動で出るし、価格は関数への引数になる。 そして安い probe が第 1 次元 (難しさ) を、分野ラベルが第 2 次元 (領域) を持っていた。

枠組みの誤り: 最適値は成果物ではない

前章までの結論は「箱 → 安い API → 高い API が最良」「完璧な予測器の価値は 1 件 4 セント」だった。 どちらも測定としては正しいが、成果物としては誤りである。箱が性能が良くて少し高い配置もあり、 安い箱と高い箱を併用する配置もあり、全部 box のことも全部 API のこともある。 つまりコストと性能は変動するもので、だからこそ最初に測る。求められているのは今の設定の最適値ではなく、 配置が変わっても答えを出し続ける機構である。

「入れ子だから予測器の価値は 4 セント」は法則ではない それは gain(価格ベクトル) という関数の1 評価点である。関数として持っていれば、 価格表の差し替えや候補の入れ替えは再評価で済み、再測定は要らない。法則として読んだのが誤りだった。

測るのは 1 つ: item × 候補の正誤行列

行が item、列が候補、セルが verified な正誤。この行列を族ごとに 1 回測れば、以降はすべてその関数になる。 3 つの価格非依存な統計量が「per-item の routing に中身があるか」を答える。

統計量意味
Loevinger の H1 なら完全な能力の梯子。候補の順序が item に依存しない
第 1 成分の分散シェア行列のどれだけがその 1 本の梯子か
ペアごとの排他勝利質量安い候補が高い候補に勝つ頻度。価格で重み付ければ金額になる

手元の 2 つの族に当てると、同じ機構が違う判定を返す。

統計量を 1 度間違えた記録 最初は Guttman の生の再現係数を使い、知識 0.75・agentic 0.77 で「同程度に構造がある」と出た。 誤りである — 生の係数は構造ではなく周辺分布で動く。H は「独立ならこれだけ違反が出る」で 正規化した版で、これが問いに合う統計量だった。

そして H = 1 が殺すのは「専門性による routing」だけである。純粋な梯子でも費用制約下の 難易度 routing は成立する (易しい item は安い段で終わる)。同じ機構が一方の族で 4 セント、 他方で 1〜3 割を出すのは矛盾ではない。

予測器: item 側は資産、候補側は d+1 個

形は多次元 IRT で、低ランク logistic 行列分解と同じものである。

logit P(候補 m が item i を解く) = a_m · θ(x_i) + b_m

θ を安い probe 特徴から回帰するのが肝で、これが候補の入れ替えに耐える資産になる。 候補は互いに排他でない (1,187 件のうち 299 件は 8 層すべてが正解する) ので、 tier に対する softmax は構造的に誤り。この形なら P(B が解く | A が失敗) も カスケード用に出る。

20 件では候補の正解率をそのまま使うより悪い (二値 20 件で 2 パラメータは過適合)。 100 件で 9 候補中 7、200 件で 9 候補すべてが基準に勝つ。利得が最大なのは probe に識別力がある弱い側で、 frontier の候補は雑に置いても差が出ない — probe がその領域で識別できないからである。

そして第 2 次元の正体は「分野」だった

probe 特徴だけで学習すると、2 次元目が何も買わない。ところが行列自体は 1 次元ではない (H = 0.6375)。 矛盾に見えるが、これは特徴集合についての言明であって行列についての言明ではなかった。

第 1 成分を引いた残差を見ると答えが出る。第 2 軸は分野である — item スコアの平均が 数学で +0.2115、健康で −0.1839、工学と法学が正、経済と哲学が負。probe との相関は弱く (margin −0.283)、 プロンプト長とは無相関 (+0.048)。だから分野ラベルを特徴に足すと、2 次元目が初めて効く。

「専門用語が多い」を別軸にできるか — できない。それは同じ軸である

知識を要する item かどうかを分類軸にすれば意味があるのではないか。3 通りの推定器で測った。

軸としては当たっている。分野レベルで rare-word 率と第 2 次元の相関は r = −0.766 で、 記号中心で一般語彙の数学 (mean idf 1.289 / rare 率 0.077) から専門用語の健康 (2.352 / 0.218) へ走る。 第 2 次元の名前として「知識依存度」は妥当である。

ところが item 単位の推定器はどれも予測器を悪化させる。probe + 分野が d=2 で 0.4414 のところ、 語彙特徴を足すと 0.4475、モデル自身の prompt surprisal を足すと 0.4539、surprisal 単独では 0.4777 で 情報なし (0.4787) と変わらない。

最初に書いた理由 (「1 問が短すぎて推定できない」) は誤りだった 本文を交互に半分に割った split-half 相関は 56 語で 0.756、216 語で 0.740 — どの長さでも同じ量を 安定に測れている。そして長さで四分割しても第 2 次元との相関は上がらない (最短 −0.144、最長 −0.002)。 語数は最初から問題ではなかった。

正しい理由は分解で出る。

専門語彙の量は「科目の性質」であって「問題の性質」ではない。分野間に全情報があり分野内は 0.007 = 教科書的な生態学的相関である。健康の 2 問は語彙プロファイルが同じで、違うのは難易度で、それは probe が読む。 だから分野ラベルは per-item 量のノイズの多い代理ではなく、その量の正しい粒度だった。対照が示すとおり、 item 単位で効く信号は分野間と分野内でほぼ同じ相関を持つ。

そして「大規模な agentic タスクなら話が違う」には機構がある — 理由は語数ではない この corpus では変動の単位が「科目」で、軸は科目内で定数だった。agentic の入力には特定のリポジトリと 特定の issue が入るので、「このコードとこの報告がどれだけ見慣れないか」は同一リポジトリ内で item ごとに 変わり得る。24 エピソードで測ると リポジトリ内 sd 0.0525 / リポジトリ間 sd 0.0783 = 比 0.67 で、 astropy 内が 0.321〜0.480、pytest-dev 内が 0.364〜0.558。軸はリポジトリの定数ではないので、 per-item 情報を持つための構造的前提は満たしており、上の否定的結果はそのまま転移しない。 ただし予測できるかは 24 件では測れず、transcript の issue は 500 文字で切られていた。

実際のテナントで意味を持つのか — 分野が 1 つしかない環境

これがいちばん重い問いである。分野は 7 科目あるベンチマークの性質で、金融ワークロードしか流れない テナントには分野が 1 つしかないので、分野に依拠した軸は定義上何も寄与しない。3 つ測った。

単一ドメインの失敗は標本数の問題だった。1 分野の中だけで学習・評価すると、7 分野のうち 5 つで 候補の平均より悪くなる。ところが分野内の AUC は 0.69〜0.83 で順序は保たれており確率が壊れている。 混合ドメインを同じ較正件数に絞ると同じ失敗を再現する。

L2 を入れると 70 件が −3.9% → −0.2% に戻るので過適合である。つまりテナントが必要とするのは 自分のトラフィックから約 140 件の verified ラベルで、これは新候補を置くアンカー 100〜200 件と同じ order。 機構全体が「百数十件」という 1 つの数字を要求する形になった。

第 2 軸は probe から発見できない item を候補の正誤パターンでクラスタリングし、そのバケツを probe 特徴から当てさせると、 K=2 で 86.1% (多数派 86.1%)、K=3 で 60.8% (60.8%)、K=4 で 51.8% (52.2%) と一度も多数派を超えない。 予測バケツを特徴に戻しても 0.4517〜0.4528 で、probe 単独 0.4531 と変わらず人手分野の 0.4415 に届かない。 分野ラベルは、いくら安く探っても復元できない外部情報を持っている。

ただしトピック分類である必要はない。分野が効いた理由は「候補の順位が異なるグループに item を 分割していた」ことだけである。単一ドメインのテナントで有用な分割は、そこでその役割を果たす何か — 製品ライン、文書種別、顧客セグメント、エンドポイント、言語 — であればよく、与えられた label が その役割を果たすかは、そのテナント自身の行列に対する between/within 分解で判定できる。 一般形は「機構は外部から 1 つの分割を要求し、それが使えるかを自分で検証し、駄目なら probe 単独 (難易度のみ) に degrade する」である。degrade 先が baseline より良いことも測れている (probe 単独 0.4531 対 情報なし 0.4763)。

そして分野を固定すると構造は減るどころか増える。分野内の第 2 成分は 14〜21%、Loevinger H は 全体 0.6375 より低い (数学 0.4431、工学 0.5829、法学 0.5919)。H が低い = 候補の順位がより item 依存。 単一ドメインのテナントは per-item routing の余地が混合ベンチマークより大きい。

箱を鍛えるのは別の責務。ただし境界は双方向

「箱を tuning して強くする」は routing の責務ではない。tuned box は新候補として入り、 アンカー 100〜200 件で d+1 パラメータを推定するだけで済む — 行列の再測定は要らない。 ここまでは所有者の読みどおりである。ただし条件が付く。

  1. バージョンは重みだけでなくサービング設定まで。chat template のフラグ 1 個で精度が 7pt 動き、 バッチ構成で 8% の item の正誤が反転した実測がある。「同じ重み」は「同じ候補」ではない。
  2. routing は自分には不要な探索を負担する。選んだ経路しか記録されていないログには、 選ばなかった経路の結果が無い。一定割合のランダム化 (不要なエスカレーション、止めたい走行の継続) を routing 側が払い、学習側が使う。
  3. 境界は双方向。学習側がアンカー集合の item で tuning すると、tuned 候補のパラメータが過大推定され 下流の利得が全部腐る。学習側 → routing の「汚染マニフェスト」が要る。 「後から勝手に使いなよ」で抜けるのはここ。
  4. probe は測定専用の凍結物にする。θ は箱自身のprobe 特徴から回帰している。 probe がサービング中の箱だと、tuning した瞬間に probe の分布が動いて θ 回帰が黙って劣化する。 艦隊を改善する行為が測定器を壊すので、probe はサービングとは別にバージョン管理する。

まだ言えないこと

構造の数字は走行ノイズで補正していない。箱の反転率は測ってある (短答 3.3% / 長答 8.0%) が API 側は未測定なので、H = 0.6375 は構造の上限である。agentic の H = 1.0 も 20 件 3 候補で、 うち 1 つが 20/20 なので退化している。「このプールは梯子だった」と言えるだけで、 「agentic のプールは梯子である」とは言えない。

そして学習側はまだ存在しない。この章はインタフェースを定め、機構のパラメータを測っただけである。
