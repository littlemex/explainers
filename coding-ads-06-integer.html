整数データ構造 ― ハードウェアの力で log log まで縮める

配列が「整数」であることを使うと、比較だけの世界の $\Theta(\log n)$ の壁を破れる。その代償と手口を見る

← MIT 6.851 シリーズ目次へ ← コーディング基礎シリーズ目次へ

二分探索も平衡二分探索木 (BST) も、要素同士を「比較する」操作しか使わないという意味で 比較モデル の住人です。このモデルでは、$n$ 個の中から 1 個を特定するのに $\Omega(\log n)$ 回の比較が理論上どうしても必要になります。しかし実際のコンピュータの整数は、比較だけでなく足す・引く・掛ける・ビットをずらす・AND/OR を取る、といった演算もすべて 1 クロックでできる「ただのビット列」です。この回では、整数であることを本気で使うと述語 (predecessor: ある値より小さい最大の要素を返す) をどこまで速く解けるかを、van Emde Boas 木・fusion tree という 2 つの構造と、それがなぜ最適に近いかを示す下限証明、そして線形時間整数ソートまで、ハードウェアの気持ちで追いかけます。

この回の位置づけ

二分探索や BST が解く predecessor (述語) 問題 ― 「集合 $S$ に挿入・削除をしながら、クエリ $x$ 未満の最大要素 (または $x$ 超の最小要素) を答える」 ― は、要素を抽象的な「比較可能な記号」として扱うなら $\Theta(\log n)$ 時間が下限です。しかし要素が $w$ ビットの整数だとわかっているなら、話は変わります。整数は「足す・引く・掛ける・AND/OR・シフト」を定数時間でできる値なので、1 回の操作で $n$ 個のうちの「半分」を捨てるのではなく、整数のビット幅 $w$ の半分を一気に捨てる、といった比較モデルには存在しない動きができるようになります。この回はその力を体系的に使い切る話です。前提として、計算量の記号 ($O/\Theta/\Omega$、最悪・平均・償却) は第 2 回で扱った内容をそのまま使います。加えて、この回だけで新たに必要になる 3 つの道具 ― (1) 「どの演算が定数時間で許されるか」を精密に決める計算モデル、(2) 1 回あたりのコストを均して評価する償却計算量とポテンシャル法、(3) 再帰の時間を閉じた式に直すマスター定理 ― を先に補習します。

前提の補習 (1) 計算モデル ― 「何が定数時間か」を決める約束

計算量を厳密に議論するには、まず「1 回の操作に何ができて、それにいくら払うか」を決める必要があります。本講義では主に次の 5 つのモデルを使い分けます (強い方から弱い方へ)。

どのモデルでも「ワード幅 $w$ は問題サイズ $\log n$ 以上必要」という前提 (fixed universe assumption、全要素がちょうど $w$ ビットの整数であると約束する) を置きます。配列の添字を表すだけでも $\log(\text{配列サイズ})$ ビット要るからです。モデルが強いほど「できることが多い」ので、そのモデルで出した下限はより弱いモデルにもそのまま通りますが、上限 (アルゴリズム) は弱いモデルで動くものほど価値があります。本講義の下限は cell-probe モデルで、上限 (vEB・fusion tree) は word RAM で与えられるため、両者はきちんと噛み合います。

前提の補習 (2) 償却計算量とポテンシャル法

償却計算量 (amortized complexity、ならし計算量) とは「1 回の操作が何回も繰り返されたときの、1 回あたりの平均コストの上限」のことです。平均ケース解析 (入力の確率分布を仮定する) とは違い、入力やタイミングについて何の仮定も置かず、ある操作列全体の総コストを操作回数で割った値を保証します。たとえば配列を 2 倍に拡張する動的配列の push は、拡張が起きた回だけ $O(n)$ かかりますが、拡張は要素数が 2 倍になるたびにしか起きないので、$n$ 回の push 全体では $O(n)$ しかかからず、1 回あたり均すと $O(1)$ です。

これを厳密に証明する標準的な道具がポテンシャル法です。データ構造の状態に「ポテンシャル $\Phi$」という非負の数値を割り当て (直感的には「将来の高コスト操作のために今の構造に貯めてある前払いの残高」)、各操作の償却コストを

$\hat{c_i} = c_i + \Phi_i - \Phi_{i-1}$

と定義します ($c_i$ は実際のコスト、$\Phi_i$ は操作後のポテンシャル)。この式の両辺を全操作にわたって足すと $\Phi$ の中間項がすべて打ち消し合って $\sum c_i = \sum \hat{c_i} + \Phi_0 - \Phi_m$ となるので、$\Phi_0$ を 0、$\Phi$ を常に非負に保てば、償却コストの合計は実コストの合計の上限になります。この回では y-fast 木や signature sort の「大きさが変わったら再編成する」という操作の償却コストを評価するのに同じ考え方 (再編成が起きるまでに溜め込める「余裕」を数える) を使います。

前提の補習 (3) マスター定理 ― 再帰の時間を閉じた式にする

この回で繰り返し出てくる再帰は $T(u) \le T(\sqrt{u}) + O(1)$ という形です。$u$ 自体で考えると読みにくいので、$u = 2^w$ すなわち $w = \log_2 u$ と置き換えます。$\sqrt{u} = 2^{w/2}$ なので、この再帰は「ビット幅 $w$ を半分にして定数時間を足す」という再帰 $T'(w) \le T'(w/2) + O(1)$ と同じです。これは中学校の指数の計算と同じ理屈で、$w$ を $w/2 \to w/4 \to w/8 \to \cdots$ と半分にし続けて $O(1)$ になるまでの回数は $O(\log w)$ 回。よって $T'(w) = O(\log w)$、すなわち $T(u) = O(\log w) = O(\log \log u)$ です。

図: 「要素数 $n$ を半分にする」(二分探索) ではなく「ビット幅 $w$ を半分にする」再帰なので、$\Theta(\log n)$ ではなく $O(\log \log u)$ になる

この「$u$ を半分にするのではなく $\log u$ を半分にする」という発想の転換こそが、この回で扱う整数データ構造すべての核心です。

L11. Predecessor 問題と van Emde Boas 木

predecessor 問題は「集合 $S$ (サイズ $n$、各要素は $w$ ビット整数で全体の値域は $U=\{0,\dots,u-1\}$) に対して挿入・削除・$x$ の predecessor/successor を答える」というものです。各モデルで知られている最良の時間は次の通りです。

$O(\min\{\log w, \log_w n\})$ を最小化する $w,n$ の組み合わせを計算すると、両者が釣り合う点でおよそ $O(\sqrt{\log n})$ 高確率が最良になることが知られています。ここからは、まず $O(\log w) = O(\log\log u)$ を実現する van Emde Boas 木を見ます。

再帰的な構造 ― 高位ビットで部屋を選び、低位ビットで中を探す

$w$ ビット整数 $x$ を、上位 $w/2$ ビット $c=\mathrm{high}(x)$ と下位 $w/2$ ビット $i=\mathrm{low}(x)$ に分けます ($x = c\cdot\sqrt{u} + i$ と考えても同じです)。サイズ $u$ の vEB 木 $V$ は、サイズ $\sqrt{u}$ の vEB 木を $\sqrt{u}$ 個 ($V.\mathrm{cluster}[0..\sqrt{u}-1]$、ワード幅は半分の $w/2$) 並べたもので、$x=\langle c,i\rangle$ が入っているなら $i$ は $V.\mathrm{cluster}[c]$ に入っています。加えて「どの $c$ について $V.\mathrm{cluster}[c]$ が空でないか」を記録するサイズ $\sqrt{u}$ の要約構造 $V.\mathrm{summary}$ と、最小値 $V.\min$・最大値 $V.\max$ を直接 (再帰せずに) 持ちます。

図: lec11 Figure 1 を再構成。$x=\langle c,i\rangle$ の $i$ は cluster[c] に入り、$c$ は summary に記録される

Successor / Insert / Delete

Successor($x=\langle c,i\rangle$): まず $x$ が $V.\min$ より小さいか $V.\max$ より大きいかを見る (前者なら答えは $V.\min$、後者なら答えなし)。そうでなければ、$V.\mathrm{cluster}[c]$ の最大値が $i$ より大きいかを調べる。大きければ「$x$ と同じクラスタの中にまだ答えがある」ので $\mathrm{cluster}[c]$ の中で再帰的に successor を探す。そうでなければ、$V.\mathrm{summary}$ の中で $c$ の successor $c'$ を再帰的に求め、答えは $\mathrm{cluster}[c']$ の最小値になる。どちらの場合も再帰するのは 1 回だけで、再帰先はサイズ $\sqrt{u}$ の vEB 木です。

Insert($x=\langle c,i\rangle$): $V$ が空なら min=max=x にして終了。$x \lt V.\min$ なら $x$ を新しい min にして、古い min を (入れ忘れないように) 代わりに挿入する。$\mathrm{cluster}[c]$ が空だったら、まず $c$ を $V.\mathrm{summary}$ に再帰的に挿入してから $i$ を $\mathrm{cluster}[c]$ に挿入する (空のクラスタへの挿入は min をその場で設定するだけなので実質 $O(1)$)。$\mathrm{cluster}[c]$ が空でなければ summary への挿入は不要で、$i$ を再帰的に挿入するだけ。

Delete はこの逆で、$x$ が min だった場合は「次の min」を summary 経由で探し直す必要がある点がやや込み入りますが、再帰の深さはやはり 1 段だけです。

Theorem (lec11). vEB 木は successor・predecessor・insert・delete をすべて $O(\log\log u)$ 時間で行う。証明: どの操作も $T(u)\le T(\sqrt u)+O(1)$ を満たし (再帰は 1 回だけ)、前提の補習 (3) のマスター定理により $T(u)=O(\log\log u)$。

もう一つの見方 ― ビットベクトルの二分探索

vEB 木は「$v[i]=1 \Leftrightarrow i\in S$」というビットベクトル $v$ の上に立てた深さ $w$ の二分木として見ることもできます (van Emde Boas 自身の 1975 年の原論文の視点)。各ノードにはその区間に 1 つでも要素があるかを示すビット (子の OR) と、区間内の min・max を持たせます。固定された $x$ について根からの経路上のノードの値を見ると、1 がいくつか続いた後 0 が続くという単調な列になります ($x$ の祖先のうち「$x$ を含む区間に要素がある」ノードは必ず連続して上から続く)。この 1→0 の境目を 二分探索 で見つければ、境目の左右どちらの子が 0 かによって、残った子の min か max を読むだけで successor/predecessor がわかります。木の高さが $w$ なので二分探索は $O(\log w)=O(\log\log u)$ 回の比較で終わります。

図: 1→0 の境目のノードを u とすると、successor/predecessor は u の「答えがある側」の子の min か max

ただしこの視点をポインタマシンで実現するには、各ノードから「高さ $2^i$ の祖先」への直接ポインタ (stratified tree) を持たないと二分探索ができず、空間が $O(u\log w)$ に膨らみ、更新も $O(\log u)$ かかります。先の再帰的な定義 (min を再帰的に持たない) と同じ工夫を使うと更新は $O(\log\log u)$ に落ち、これはポインタマシン上で最適だと知られています。

間接化 (indirection) ― 償却で更新を速くする

もう一つの更新高速化の手段が間接化です。整数の集合をサイズ $\Theta(w)$ の二分探索木 $\Theta(n/w)$ 個に分割し、各 BST から代表元 1 個を選んで、その代表元だけを上位構造 (この回の文脈では vEB 木) に入れます。各 BST のサイズが $[\tfrac12 w, 2w]$ を超えたら分割、下回ったら隣と merge します。分割・merge・上位構造の更新はどれも $O(w)$ 時間かかりますが、分割直後のサイズは必ず $[\tfrac23 w, \tfrac32 w]$ に収まるため、次に分割・merge が必要になるまでにさらに $\Theta(w)$ 回の更新が必要です。前提の補習 (2) のポテンシャル法で言えば、「$\Theta(w)$ 回分の余裕」を毎回の更新でコツコツ貯めておき、分割・merge のときにその残高で $O(w)$ のコストを払う、という設計です。結果、償却 $O(1)$ の間接化コストに、下位 BST 自体の更新 $O(\log w)=O(\log\log u)$ が乗るだけで済みます。

空間を $\Theta(u)$ から $\Theta(n)$ に落とす

ここまでの vEB 木は、クラスタや summary を「値で添字付けした配列」として持つため $\Theta(u)$ 空間が必要です。これを $\Theta(n)$ に落とす手段が 2 つあります。

  • ハッシュ表に置き換える。空のクラスタ配列を保持せず、動的完全ハッシュ表に置き換えます。各ハッシュ表のエントリをその cluster の min に紐づけて課金すると、実在する各要素は「自分の親」と「summary に現れるエントリ」の高々 2 回しか課金されないので、合計 $\Theta(n)$ 空間で済みます。$O(1)$ 期待時間のハッシュ表を使えば、クエリ・更新は高確率 $O(\log\log u)$ のまま。
  • y-fast 木 (下記)。Willard による別解。

x-fast 木 ― 中間ステップ

「1 の値を持つノードだけ」をハッシュ表に保存するのが x-fast 木です。各 1 ノードを、根からの左右の経路をビット列 (左なら 0、右なら 1) にエンコードしたキーとしてハッシュに入れます。これにより、与えられたビット列がノードとして存在するかを $O(1)$ で判定できるので、先の二分探索は高確率 $O(\log w)$ で行えます。しかし更新は、挿入・削除された要素のすべての祖先 (最大 $w$ 個) を更新しなければならず $O(w)$ 時間かかり、空間も各要素が $w$ 個のプレフィックスを持つため最悪 $O(nw)$ まで膨らみます。

y-fast 木 ― 間接化で x-fast の弱点を消す

y-fast 木は、x-fast 木を上位構造として使い、間接化を適用します。全体をサイズ $\Theta(w)$ の二分探索木 $\Theta(n/w)$ 個に分け、各 BST の代表元だけを x-fast 木に入れます。クエリは x-fast 木で $O(\log w)$ 時間で担当 BST を特定し、その中を $O(\log w)$ 時間で探すので query は $O(\log w)$ のまま。更新は、x-fast 木側の更新が $\Theta(w)$ 回の下位 BST の更新に 1 回しか起きないため償却され、支配項は下位 BST の $O(\log w)$ になります。上位構造のサイズが $\Theta(n/w)$ なので空間は $O(n/w \cdot w) = O(n)$ に収まり、めでたく $O(\log w)=O(\log\log u)$ 時間・$\Theta(n)$ 空間を達成します。

デモ. van Emde Boas の successor クエリを 1 ステップずつ追う

$u=16$ (4 ビット、$\sqrt{u}=4$ のクラスタが 4 個、さらにその中が $\sqrt4=2$ のクラスタ 2 個に再帰) の vEB 木に、集合 $S=\{2,3,4,7,14,15\}$ を実際に挿入して構造を作ります。クエリ $x$ を選んで「successor を追う」を押すと、本文の Successor アルゴリズムをそのまま実行しながら、各再帰呼び出しで「高位ビット $c$ / 低位ビット $i$ への分割」「cluster の中を見るか summary に回るか」を記録します。ステップを 1 つずつ送って、再帰のたびにビット幅 (ワードサイズ) が $16\to4\to2$ と半分になっていく様子を確認してください。

集合は $S=\{2,3,4,7,14,15\}\subset\{0,\dots,15\}$ に固定しています。$x$ を変えて何度も試せます。

読み取り。どのクエリでも再帰は高々 2 段 ($u=16\to4\to2$) で終わります。これは「$n$ を半分にする」二分探索の再帰ではなく「ワード幅 $w=\log u$ を半分にする」再帰だからです。$u$ がもっと大きくても、再帰の回数は $\log\log u$ 回のまま増えにくいという感覚をここで掴んでください。

L12. Fusion tree ― ビット単位の並列処理で $O(\log_w n)$

vEB 木・y-fast 木はビット幅 $w$ が小さいときに強い ($O(\log w)$)。fusion tree は逆に要素数 $n$ が $w$ に対して小さいときに強い構造で、$O(\log_w n)$ 時間・$O(n)$ 空間を実現します。基本構造は分岐数 $w^{1/5}$ の B 木で、高さは $\Theta(\log_w n)$。問題は「1 ノードに並ぶ $k=w^{1/5}$ 個のキーの中で predecessor/successor を $O(1)$ 時間で答える」方法で、ノード 1 個を素朴に読むだけで $O(w^{1/5}\cdot w)=O(w^{6/5})$ ビット触ることになり $O(1)$ には到底見えません。これを $k^{O(1)}$ の前処理で解決するのが fusion tree のアイデアです。

スケッチ (sketching) ― 「比較に効くビットだけ」を抜き出す

$k$ 個のキー $x_0\le x_1\le\cdots\le x_{k-1}$ を、深さ $w$ の二分木上のパス (各ビットが 0 なら左、1 なら右) として重ね描きすると、$k$ 本のパスが分岐する内部ノードは高々 $k-1$ 個しかありません (帰納法で証明できる単純な事実: パスが 1 本増えるたびに新しい分岐点は高々 1 個しか増えない)。つまり、この $k-1$ 個以下のビット位置 $b_0,\dots,b_{r-1}$ ($r\le k-1$) だけが、$k$ 個のキー同士の大小関係を決めるのに効いています。この $r$ 個のビットだけを抜き出して並べた $r$ ビットの文字列を sketch(x) と呼びます。

図: 分岐しない区間のビットはどの 2 つのキーの大小関係にも影響しないので、sketch から削って良い

sketch は $k$ 個のキーの順序をそのまま保つので、$\mathrm{sketch}(x_0)\le\cdots\le\mathrm{sketch}(x_{k-1})$ です。しかも各 sketch は $O(w^{1/5})$ ビットなので、$k$ 個全部の sketch を合わせても $O(kw^{1/5})=O(w^{2/5})=o(w)$ ビットしかなく、1 ワードに収まります。

desketchify ― クエリ $q$ が元のキーに含まれないとき

クエリ $q$ はキー $x_0,\dots,x_{k-1}$ のどれとも一致しないのが普通です。すると $q$ の二分木上の経路は、$b_0,\dots,b_{r-1}$ のどれとも違うビット位置で他のパスから分岐してしまうかもしれません。この場合 $\mathrm{sketch}(q)$ が $\mathrm{sketch}(x_i)$ たちの中でどこに位置するかは、$q$ が $x_i$ たちの中でどこに位置するかと無関係になり得ます。これがスケッチだけでは predecessor/successor を答えられない理由です。

直すには、$\mathrm{sketch}(x_i)\le\mathrm{sketch}(q)\le\mathrm{sketch}(x_{i+1})$ となる sketch 近傍 $x_i,x_{i+1}$ を見つけたあと、$q$ と $x_i$ (または $x_{i+1}$) の最長共通接頭辞 (= フュージョンツリー内での最小共通祖先) の長さ $y$ を計算します。この長さ $y$ の接頭辞を持つノード $n$ こそが、$q$ の経路が「ノード内のどのキーの経路からも分岐してしまう」最も高い (浅い) ノードです。すると、$n$ の 2 つの子部分木のうち $q$ 側には元のキーが 1 個もなく、もう一方には必ず $x_i$ か $x_{i+1}$ が入っているので、そちら側に答えがあるとわかります。具体的には、$q$ の $(y+1)$ 番目のビットが 1 なら predecessor は接頭辞 $p0$ に続けて 1 を並べた文字列 $e=p011\cdots1$ (その部分木の一番右) の predecessor として、0 なら successor は $e=p100\cdots0$ (一番左) の successor として求まります。どちらの場合も、answer が見つかれば隣の sketch 近傍を見るだけで predecessor/successor の両方が得られます。

乗算で sketch を近似する

完全な sketch の抜き出しは AC⁰ (定数深さ回路) モデルでは 1 操作ですが、word RAM では「ビットを散らばった位置から詰める」操作そのものが自明ではありません。そこで、重要なビットだけを残すマスク AND をかけた $x' = x\ \mathrm{AND}\ \sum 2^{b_i}$ に、ある定数マスク $m=\sum 2^{m_j}$ を掛け算します。$m_j$ を適切に選ぶと (各 $m_j$ を $r^3$ を法として互いに重ならないように取り、$w$ 付近にスペースを空けて並べる、という鳩の巣原理に基づく構成)、積 $x'\cdot m$ の中で重要なビットが

  1. 互いに衝突しない (桁あふれで混ざらない)
  2. 元の順序を保つ ($b_0+m_0 \lt b_1+m_1 \lt \cdots$)
  3. $O(w^{4/5})$ ビットの狭い範囲に収まる

という 3 条件を満たす場所に移動します。あとはマスクして右シフトすれば、乗算と標準的な word RAM 命令だけで sketch の近似が $O(1)$ 時間で手に入ります。

並列比較 ― 1 回の減算で $k$ 個の大小判定

ノードの全キーの sketch を 1 ワードに詰めた「node sketch」$1\,\mathrm{sketch}(x_0)\,1\,\mathrm{sketch}(x_1)\cdots$ (各 sketch の前に 1 を立てて連結) を作っておきます。クエリ側は $0\,\mathrm{sketch}(q)$ を $k$ 回繰り返したもの $\mathrm{sketch}(q)^k$ を用意し (sketch(q) に繰り返し用のマスクを掛けるだけ)、node sketch から 1 回の減算で引きます。各ブロックの先頭ビットは $1\,\mathrm{sketch}(x_i)$ が $0\,\mathrm{sketch}(q)$ より必ず大きいので桁借りがブロック間を越えず、結果の先頭ビットは「$\mathrm{sketch}(q)\le\mathrm{sketch}(x_i)$ かどうか」をちょうど表します。先頭ビットだけを AND で抜き、1 の数を数える (もう一度乗算してまとめて足す) と、それが $\mathrm{sketch}(q)$ の rank、すなわち 0→1 の境目の位置になります。

最上位の立っているビット (MSB) を $O(1)$ で求める

desketchify の最長共通接頭辞の長さは「2 つの数を XOR して最上位の 1 ビットの位置を求める」ことで得られます。$w$ ビットの語を $\sqrt w$ 個の $\sqrt w$ ビットのクラスタに分け、(a) どのクラスタに 1 ビットがあるか (summary ベクトル $y$) をビット演算 3〜4 手で求め、(b) $y$ を sketch して $\sqrt w$ ビットに圧縮し、(c) $\sqrt w$ 通りの 2 のべき乗との並列比較で最初の非空クラスタ $c$ を見つけ、(d) そのクラスタだけを取り出して同じ並列比較を繰り返しクラスタ内の最初の 1 ビット $d$ を求め、(e) 答えを $c\sqrt w + d$ とします。各ステップは $O(1)$ の word RAM 演算なので、全体も $O(1)$ です。

ハードウェアとの接続。 ここで word RAM の算術だけから組み立てている「最上位の立っているビットを求める」関数は、現代の CPU では LZCNT/BSR (x86) や CLZ (ARM)、コンパイラ組み込みの __builtin_clz として 1 命令で手に入ります。fusion tree がこれをハードウェア命令として「発明」したわけではなく、むしろ逆です ― 1990 年当時専用命令を仮定せずに +,-,\times,\mathrm{AND},\mathrm{OR},シフトだけでこの関数が $O(1)$ で計算できることを証明した、という理論的な存在証明です。現代のハードウェアは全く別の実装 (シリコン上の OR 木による並列検出) で同じ関数を 1 サイクルで提供しているので、学ぶべきは「同じ関数を導く 2 つの独立な道がある」という事実であり、両者に実装上の系譜があるわけではありません。ただし、$k$ 個の値を 1 ワードに詰めて 1 回の演算で処理する、という発想そのものは、現代の SIMD や SWAR (SIMD Within A Register) と同じ「ワードレベル並列性」の精神であり、そこは本物の接続です。

L13. Predecessor の下限 ― なぜこれ以上速くできないか

vEB 木と fusion tree を組み合わせた上限は $O(\min\{\lg w, \log_w n\})$ でした。この回では、静的 (挿入・削除なし) で多項式空間の predecessor 問題について、セルプローブモデルで

$\Omega\left(\min\left\{\dfrac{\lg w}{\lg\lg n}, \log_w n\right\}\right)$

という下限を証明し、上限が $\lg\lg$ 因子を除いて最適であることを示します (この下限自体は Beame-Fich-Xiao の結果で、ここでは Sen-Venkatesh による round elimination というきれいな証明手法で導きます)。この下限の美しさは、特定のハードウェア命令や乗算トリックに一切依存せず、「そもそも何らかの操作で解けるか」という情報理論だけに依拠している点です。証明を簡単にするため、本当の predecessor ではなく彩色 predecessor (集合の各要素が赤か青に塗られていて、$x$ の predecessor の色だけを答える、もっと易しい問題) を使います。元の predecessor が解ければ彩色 predecessor も解けるので、易しい方の下限はそのまま元の問題の下限にもなります。

通信複雑性としての定式化

Alice は値 $x$ (クエリ) を知っていて、Bob は値 $y$ (データ構造の中身) を知っている、という通信複雑性のモデルを使います。2 人は交互にメッセージを送り合って $f(x,y)$ を計算します。Alice のメッセージは $a$ ビット、Bob のメッセージは $b$ ビットに制限されており、1 ラウンド (Alice→Bob→Alice) がちょうど 1 回のセルプローブに対応します (Alice のメッセージ = 読みたいアドレス、$a=O(\log(\text{空間}))$ ビット。Bob のメッセージ = そのセルの内容、$b=w$ ビット)。したがって $t$ 回のセルプローブは $2t$ 回のメッセージ交換と等価で、通信量の下限がそのままセルプローブ数の下限になります。この章の主張は、この通信モデルで必要なメッセージ数が $\Omega(\min\{\log_a w, \log_b n\})$ であること。多項式空間 ($a=\Theta(\log n)$) の下で整理すると、冒頭の $\Omega(\min\{\lg w/\lg\lg n, \log_w n\})$ が得られます。

図: データ構造へのアクセスを「会話」として数え、会話量の下限から探索時間の下限を導く

読者の持っている直感との接続 (注意つき)。 「アクセス 1 回を 1 ラウンドの往復として数え、往復の回数で下限を評価する」という発想は、分散システムの RPC のラウンド数で性能を議論する感覚に近く、直感の足がかりになります。ただし通信複雑性の $a,b$ ビット制限は抽象的な理論的制約であり、実際の RPC のレイテンシや CAP 定理の議論と技術的に同一の道具ではありません。ここでは「手法の発想が似ている」というアナロジーに留めてください。

Round elimination ― 1 ラウンドの価値を定量化する

核心の道具が round elimination lemma です。関数 $f$ の「$k$ 重版」$f^{(k)}$ を考えます: Alice は $k$ 個の入力 $x_1,\dots,x_k$ を持ち、Bob は $y$、添字 $i\in\{1,\dots,k\}$、そして $x_1,\dots,x_{i-1}$ (Alice の入力と一部重複) を持ち、2 人は $f(x_i, y)$ を計算したい。Alice が先に話すプロトコルがあるとき、Alice は $i$ をまだ知らないので、彼女の最初のメッセージが $x_i$ について言える情報は (もし $i$ が一様ランダムなら) 平均してわずか $a/k$ ビットしかありません。だから Bob はその最初のメッセージを当て勘で代用できます ― 当たる確率はおよそ $2^{-a/k}$ で、外れる確率はおよそ $a/k$ (この近似は $a/k$ が小さいときの級数展開)。

Lemma (Round Elimination). $f^{(k)}$ を Alice が先に話す $m$ 回のメッセージ・誤り確率 $\delta$ のプロトコルで解けるなら、$f$ を Bob が先に話す $m-1$ 回のメッセージ・誤り確率 $\delta+O(\sqrt{a/k})$ のプロトコルで解ける。

直感的には「最初のメッセージはどうせ中身が薄いので、いっそ無かったことにして、その分だけ誤り確率が少し上がるのを受け入れる」という操作です。これを $2t$ 回繰り返して Alice→Bob→Alice→… のメッセージを 1 つずつ消していくと、最終的にメッセージが 0 回のプロトコルに到達します。メッセージが 0 回なら答えを当てるしかなく、成功率はせいぜい $1/2$ です。各回の誤り確率の増加を $O(1/t)$ に抑えられれば、$2t$ 回の適用で誤り確率の合計は $1/3$ 以下に収まり、成功率 $2/3$ 以上という矛盾が生じます。したがって、そもそも $t$ 回のセルプローブで解けるという仮定自体が誤りだったことになり、$t=\Omega(\min\{\log_a w,\log_b n\})$ が従います (各ラウンドで $a$ 側・$b$ 側を交互に $k=\Theta(at^2)$ または $\Theta(bt^2)$ 個のチャンクに割って $n,w$ を縮小し、$w=O(\log(bt^2))$ または $n=2$ まで縮むのを止める時刻を調べる、という具体的な構成がこの一般論の上に乗ります)。

L14. 線形時間の整数ソートと優先度付きキュー

ソート → 優先度付きキューの還元

Thorup は「$n$ 個の $w$ ビット整数を $O(nS(n,w))$ 時間でソートできるなら、挿入・削除・最小値取得を最悪 $O(S(n,w))$ 時間で行える優先度付きキューが作れる」ことを示しました。したがって定数時間の優先度付きキューを作るには、線形時間の整数ソートが要ります ― そしてそれは次の通り、まだ全称的には解けていません。

整数ソートの現状 (調査)

方法計算量単純化できる条件
比較ソート$O(n\lg n)$―
Counting sort$O(n+2^w)$$w=\lg n$ のときだけ $O(n)$
Radix sort$O(n\cdot w/\lg n)$$w=O(\lg n)$ なら $O(n)$
vEB sort [Kirkpatrick-Reisch]$O(n\lg\lg w)$、改良版 $O(n\lg(w/\lg n))$$w=\lg^{O(1)}n$ (多重対数) なら $O(n\lg\lg n)$
Signature sort [Andersson-Hagerup-Nilsson-Raman]$O(n)$ for $w=\Omega(\lg^{2+\varepsilon}n)$―
Han$O(n\lg\lg n)$ (AC⁰)―
Han & Thorup / Kirkpatrick-Reisch$O\!\left(n\sqrt{\lg(w/\lg n)}\right)$ ランダム化すべての $w$ で $O(n\sqrt{\lg\lg n})$

つまり $w=O(\lg n)$ なら radix sort が、$w=\Omega(\lg^{2+\varepsilon}n)$ なら signature sort が線形時間を達成します。$w=\omega(\lg n)$ かつ $w=o(\lg^{2+\varepsilon}n)$ という中間の帯では、線形時間ソートが可能かどうかは未解決 (OPEN) で、既知の最良はランダム化 $O(n\sqrt{\lg(w/\lg n)})$ です。さらに「すべての $w$ に対して $O(n)$ 時間のソートがあるか」自体も講義の中で明示的に OPEN と述べられています。

Signature sort の組み立て ― 4 段重ね

$w=\Omega(\lg^{2+\varepsilon}n)$ での線形時間ソートは、小さい道具を 4 段重ねて作ります。

  1. Bitonic sequence のソート。 単調増加列の後に単調減少列が続く (循環的に見て局所最小・最大が 1 つだけの) 列を bitonic sequence と呼びます。前半と後半で対応する要素を比較・交換してから両半分を並列に再帰すると、$O(\log n)$ 段で全体がソートされます (各段で列は「bitonic な区間」に分割され、左の区間の要素は右の区間のどの要素よりも小さいという不変条件が保たれるため)。
  2. 対数時間のマージ。 $k$ 個の $b$ ビット要素をそれぞれ含む 2 つのソート済みワードは、片方を反転して連結すると 1 つの bitonic sequence になります。反転も連結もビットシフトと OR で $O(1)$ (または $O(\log k)$ の再帰) で行えるので、bitonic sort を適用すれば $T(k)=T(k/2)+O(1)$ の再帰で $O(\log k)$ 時間でマージできます。各段の「交換すべきペアを並列に交換する」操作も、要素の前に 1 ビットの予備ビットを置いておき、減算で大小を判定してマスクするビットトリックで $O(1)$ です。
  3. Packed sorting. $w\ge 2(b+1)\log n\log\log n$ ならば $k=\log n\log\log n$ 個の $b$ ビット要素を 1 ワードに詰め込めます。1 ワード内は (2) のマージを使ったマージソートで $O(k)$ 時間でソートでき、$r$ 語のソート済みリスト同士のマージも (2) を使って $O(r\log k)$ 時間。全体の再帰 $T(n)=2T(n/2)+O(\tfrac{n}{k}\log k)$ を解くと $O(n)$ になります。
  4. Signature sort 本体。 $w'\le\lg^{2+\varepsilon}n$ ビットの整数を $\lg^{\varepsilon}n$ 個の等長チャンクに切り、各チャンクを $O(\lg n)$ ビットのハッシュ (順序は保存しないが同一性は保存する) に置き換えます。得られた $O(\lg^{1+\varepsilon}n)$ ビットの signature を packed sort で線形時間ソートし、その後 (ハッシュで失った順序を復元するために) signature 上に圧縮トライを構築して、各ノードの枝を元のチャンクの値で再帰的に並べ替えます。この再帰は $1/\varepsilon+1$ 段で終わり、各段で整数のサイズは $w'$ から $w'/\lg^{\varepsilon} n + O(\lg n)$ まで縮むので、最後は再び packed sort が使える大きさになります。
Theorem (lec14). $w\ge\lg^{2+\varepsilon}n\log\log n$、整数サイズ $w'\le\lg^{2+\varepsilon}n$ のとき、signature sort は $n$ 個の $w'$ ビット整数を $O(n)$ 時間でソートする。

実務での出番 ― 正直な評価

  • MSB/CLZ・popcount などのビットトリック (強く実在する)。 fusion tree が組み立てる「ワード内の複数の値をマスク・乗算・シフトで一括処理する」考え方そのもの (word-level parallelism、俗に SWAR = SIMD Within A Register) は、現代のビットセット圧縮ライブラリで文字通り使われています。RoaringBitmap/CRoaring は popcount・CLZ を多用して圧縮ビットマップの集合演算を高速化し、Apache Lucene や Apache Spark、Druid などの検索・分析基盤で使われています。MSB/CLZ 自体は Intel の LZCNT/BSR、ARM の CLZ、GCC/Clang の __builtin_clz として 1 命令で手に入るので、fusion tree のように自分でビット操作から組み立てる必要はまずありませんが、「なぜそれが $O(1)$ で計算可能だと証明できるか」を知っておくと、専用命令がない環境 (一部の GPU カーネルや組み込み) でも同じ道具立てで実装できます。
  • van Emde Boas 木・x-fast/y-fast 木 (理論的な側面が強い)。 値域 $u$ サイズの配列を前提にする vEB 木を素直に実装することはまれで、実務ではまず見かけません。ただし「上位ビットで部屋を選び、下位ビットで中を探す」という発想自体は、IP ルーティングの最長一致検索で使われる multibit trie や、キャッシュ効率を考えた再帰的なレイアウト (van Emde Boas レイアウトと呼ばれるキャッシュオブリビアスな木の配置) に生きています。y-fast 木の「大きな構造の更新コストを小さな構造の更新回数で償却する」間接化の考え方自体は、B 木や LSM 木のノード分割・マージの設計判断にも通じる一般的な発想です。
  • Fusion tree 本体 (ほぼ理論的な興味)。 Fredman と Willard が fusion tree で示した最大の成果は、「整数ソートは比較ソートの情報理論的下限 $\Omega(n\log n)$ を本当に破れる」という可能性の証明でした。しかし現実の実装としての fusion tree をそのまま使ったシステムは見当たりません。「キーのうち比較に効くビットだけを抜き出して圧縮する」という sketching の発想は、B 木/LSM 木の SSTable で使われる接頭辞圧縮 (prefix compression) やフェンスポインタの設計判断に通じる部分がありますが、技術的に同一の仕組みではありません。
  • Predecessor の下限・round elimination (純粋に理論)。 この証明自体がプロダクションコードに現れることはありません。得られる教訓は「データ構造へのアクセスを通信のラウンドとして数える」という考え方で、これはキャッシュオブリビアスアルゴリズムや I/O 効率アルゴリズムの設計 (ブロック転送 1 回のコストをどう最小化するか) を考えるときの一般的な心構えとして実務に残っています。
  • 線形時間整数ソート (理論上の存在証明)。 Signature sort や Han-Thorup のランダム化ソートは、定数が非常に大きく、$n$ が天文学的に大きくならないと比較ソートに勝てない「ガラクシー・アルゴリズム」の典型です。実務の整数ソートはほぼ常に radix sort (または比較ベースの quicksort/mergesort) であり、GPU 向けの放射基数ソート (NVIDIA の Thrust/CUB ライブラリの radix sort など、トークン ID やキーの並べ替えに使われる) がその延長線上にあります。Thorup のソート→優先度付きキューの還元は、計算量理論上「両者は同値な難しさを持つ」ことを示す道具であり、実装上の近道ではありません。
