CPU のレジスタ・L1・L2・メインメモリ・ディスクは、速さも容量もケタ違いに違います。アルゴリズムの計算量を「比較回数」や「演算回数」だけで数える普通の解析は、この差を完全に無視しています。MIT 6.851 (Advanced Data Structures) の L07・L08・L09・L22 は、「メモリのどの階層からどの階層にデータを運んだ回数」そのものを計算量の単位にする、という立場に切り替えます。本ページはこの 4 回分の講義ノートを、電気・電子工学出身で CPU キャッシュのハードウェアとしての挙動はすでに知っているが、償却計算量やこの手の理論的なデータ構造の体系は未修という読者向けに再構成したものです。

この回の位置づけ

解きたい問題はこうです。コンピュータ科学の標準的な計算量解析 (word RAM モデル、比較回数で数える) は「1 回のメモリアクセスはどこから読んでも同じコスト」という前提を置きます。しかし実機では、レジスタ (約 0.5ns) からハードディスク (約 10ms) までの間でアクセス時間が約 7 桁違い、最も大きな 1 段だけを見てもメインメモリ (約 150ns) とハードディスク (約 10ms) の間に約 5 桁の差があります (下表の値)。読者はこの事実を電気・電子工学の立場 (SRAM と DRAM の物理的な違い、キャッシュラインのバースト転送など) から知っていますが、ここではそれを アルゴリズム設計の制約 として使います。「ブロック単位でしか転送できない 2 段階のメモリ」という抽象化を 1 つ決め、そのモデルの中で「最小の転送回数で検索・挿入・削除・ソートをするデータ構造は何か」を問うのが、この一連の講義の主題です。

この問いに答えるには、CS 学部生が前提として持っている道具がいくつか必要です。償却計算量 (amortized analysis) とその証明手段である ポテンシャル法、二分探索木・B 木の基本、そして「メモリは 1 ワードずつ読み書きできる配列」とみなす word RAM モデル です。読者はこれらを公式には学んでいない前提なので、まず簡単に補習します。

前提の補習

word RAM モデルとは。 「メモリは番地付きの配列で、1 ワード (例えば 64 bit) の読み書き・加減乗除・比較が、それぞれ定数時間でできる」という計算モデルです。LeetCode の計算量解析で暗黙に使っているモデルがこれです。今日の話の出発点は「このモデルは不正確だ」という指摘です。配列の添字が遠く離れた 2 箇所にあると、物理的には全く違うコストがかかるのに、word RAM モデルはそれを区別しません。

償却計算量 (ならし計算量) とは。 1 回の操作が時には遅くても、何回も操作を繰り返した合計時間を操作回数で割った「1 回あたりの平均コスト」が小さいことを保証する考え方です。例えば配列を 2 倍に拡張しながら追加する可変長配列は、拡張の瞬間だけ $O(n)$ かかりますが、拡張は操作回数が 2 倍になるたびにしか起きないので、$n$ 回の追加全体では $O(n)$ しかかからず、1 回あたりは $O(1)$ です。重要なのは、最悪ケースの 1 回 ($O(n)$) と 償却後の 1 回あたり ($O(1)$) は別の主張だという点です。今日出てくる構造 (Ordered File Maintenance、Cache-Oblivious 優先度付きキュー) のほとんどは、まさにこの「ならすと速い」型の保証しかできません。

ポテンシャル法とは。 償却計算量を証明する標準的な手口です。データ構造の状態に「ポテンシャル $\Phi$」という数値を割り当て、(実際のコスト) + (ポテンシャルの変化量) を「償却コスト」と定義します。$\Phi$ を「まだ払っていない将来の作業量」とみなすと直感的です。操作が高くつく瞬間は $\Phi$ が大きく減ることでそのコストを相殺し、逆に安い操作では $\Phi$ を少しずつ積み立てる、という帳簿のような役割を果たします。本ページの後半 (L22 の置換ゲームの下界証明) で、$\Phi = \sum n_{ij}\log n_{ij}$ という具体的なポテンシャル関数が登場します。

B 木とは。 二分探索木 (各ノードが 2 個の子を持つ) を一般化し、各ノードが $\Theta(B)$ 個の子を持つようにした探索木です。木の高さが $\log_2 N$ から $\log_{B+1} N$ に下がるため、「ノード 1 個 = ディスクの 1 ブロック」という対応を作れば、根から葉までのブロック転送回数を $\log_{B+1} N$ 回に圧縮できます。データベースのインデックスで事実上必ず使われている構造で、今日の話の出発点でもあります。

1. L07: 外部メモリモデルとキャッシュ非依存モデル

実機のメモリ階層は何段もありますが、まずは一番単純化した 外部メモリモデル (external memory model, 1988 年 Aggarwal と Vitter) から始めます。CPU は大きさ $M$ の高速なキャッシュとつながっていて、キャッシュは無限に大きい低速なディスクとつながっています。キャッシュもディスクも大きさ $B$ の「ブロック」単位に分かれていて、ブロック 1 個をキャッシュとディスクの間で転送すると 1 コストかかる、キャッシュに載っているデータへのアクセスは無料、というルールです。このモデルでの目標は「ブロック転送の回数」を最小化することで、word RAM モデルでの実行時間 $T(N)$ はそのまま $O(T(N))$ 回の転送で模倣できる (下限は $T(N)/B$) ことがすぐわかります。

図: ブロックサイズ $B$、キャッシュ容量 $M$。例えば大規模データベースなら「キャッシュ」= システム RAM、「ディスク」= HDD/SSD にあたる

このモデルでの代表的な結果は次の通りです (すべて講義ノートに記載の通り)。

操作外部メモリモデルでの転送回数備考
走査 (scanning)$O(\lceil N/B \rceil)$自明。切り上げが重要 ($N = o(B)$ だと損する)
検索 (B 木, 分岐数 $\Theta(B)$)$O(\log_{B+1} N)$情報理論的下限と一致し最適
ソート$O\!\left(\frac{N}{B}\log_{M/B}\frac{N}{B}\right)$$M/B$ 分木のマージソート。比較モデルで最適
置換 (permutation)$O\!\left(\min\{N, \frac{N}{B}\log_{M/B}\frac{N}{B}\}\right)$分割不可能モデル限定の結果
バッファ木 (動的ソート)$O\!\left(\frac{1}{B}\log_{M/B}\frac{N}{B}\right)$ 償却挿入・delete-min を遅延クエリとして処理

検索の下限 $\Omega(\log_{B+1} N)$ は情報理論的な議論から出てきます。$N$ 個の要素の中で自分がどこに位置するかを特定するには $\Theta(\log(N+1))$ bit の情報が必要で、キャッシュから 1 ブロック ($B$ 個) を読むたびに得られる情報は $O(\log(B+1))$ bit しかありません。$\log(N+1) / \log(B+1)$ 回より少ない回数の転送では、必要な bit 数を集めきれない、という帳尻の議論です。これは「探索木の高さの下限」を比較回数ではなくブロック転送回数で言い直したものです。

興味深いのは ソートの最適解が検索と同じ B 木ではないという点です。B 木に $N$ 回挿入してから中順巡回すると $O(N \log_{B+1} N)$ 回の転送がかかりますが、これは最適ではありません。$M/B$ 分木のマージソートは、キャッシュに収まるサブ問題に分割することで最適な $O(\frac{N}{B}\log_{M/B}\frac{N}{B})$ 回に落とせます。「検索に強い構造」と「ソートに強い構造」は同じではない、というのがここでの教訓です。

キャッシュ非依存モデル ― B と M を知らないまま最適化する

外部メモリモデルには実務上の弱点があります。アルゴリズムの中に $B$ や $M$ の値が明示的に出てくるので、階層が 2 段より多い実機 (L1/L2/メインメモリ/ディスク) では、どの境界に合わせてチューニングするかを選ばなければなりません。キャッシュ非依存モデル (cache-oblivious model, 1999 年 Frigo・Leiserson・Prokop・Ramachandran) は、アルゴリズム自身は $B$ と $M$ の値を一切知らない (コードの中に定数として出てこない) まま、どんな $B$, $M$ の組に対しても外部メモリモデルと同じ最適な転送回数を達成する、という立場です。キャッシュの管理 (何をキャッシュに残し何を追い出すか) は自動・かつオフライン最適だと仮定しますが、これは実務的な置き換え方式 (LRU・FIFO) がオフライン最適の 2 倍以内の性能を持つ (キャッシュを 2 倍に増やせば帳尻が合う) という事実で正当化されます。マルチレベルキャッシュや、$B$・$M$ の値が実行中に変わり得る環境 (他プロセスとキャッシュを共有する、など) で特に有利です。

操作キャッシュ非依存モデルでの転送回数外部メモリモデルと比べて
走査$O(\lceil N/B \rceil)$同じ (解析が $B$ だけに依存するため同じアルゴリズムでよい)
探索木 (CO B 木)$O(\log_{B+1} N)$ 償却同じ。本節の後半で詳述

キャッシュ非依存 B 木 ― van Emde Boas レイアウト

外部メモリモデルの B 木は分岐数を $B$ に合わせて作ります。$B$ を知らないキャッシュ非依存モデルでは、ふつうの完全二分探索木を、メモリ上の「並べ方」だけで同じ効果を出すという発想に切り替えます。これが van Emde Boas (vEB) レイアウトです。

まず $N$ 個の要素の完全二分探索木を考えます。木を 高さでちょうど半分に割り、上側の部分木 (高さ $\frac12 \log N$、要素数 $O(\sqrt N)$) と、その葉にそれぞれぶら下がる $O(\sqrt N)$ 個の下側の部分木 (それぞれ要素数 $O(\sqrt N)$) に分けます。下側の部分木も再帰的に同じ規則で vEB レイアウトします。メモリ上には、上側の部分木をまるごと先頭に置き、続けて下側の部分木を順番に並べます。再帰は部分木のサイズが $B$ を下回ったら止めます (それより細かく分けても得にならないので)。

図: 再帰的に高さを半分にして分割し、その順番でメモリに並べる。これだけで $B$ を知らずに局所性が確保できる

なぜこれで速くなるのか。証明のアイデアは「$B$ とちょうど釣り合う深さの層」を見ることです。木を高さの半分で切る操作を繰り返し、部分木の高さが初めて $\log B$ 以下になった層に注目すると、その層の部分木のサイズは $\sqrt B$ から $B$ の間に収まります (高さがちょうど $B$ に「踏みとどまる」層)。根から葉までの経路は高さ $O(\log N)$ なので、この層の部分木を通過する回数は $O(\log N / \log B)$ 回。各部分木はサイズが $B$ 以下なので、メモリ上で高々 2 ブロックに収まり (ブロック境界をまたいでも 2 ブロック)、1 回の通過につき定数回の転送で済みます。合計で $O(\log_B N)$ 回、つまり $O(\log_{B+1} N)$ と同じオーダーの転送回数になります。$B$ の値を使っていないのに、$B$ に合わせた B 木と同じ性能が出るというのがこの証明の核心です。

動的化 ― OFM と組み合わせる

上の構造は静的 (要素が固定) です。挿入・削除をサポートするには、要素を保存する配列側にも工夫が必要で、ここで次節 (L08) の Ordered File Maintenance (OFM) をブラックボックスとして使います。OFM は $N$ 個の要素を大きさ $O(N)$ の配列に順序を保って格納し、挿入・削除を償却 $O(\log^2 N)$ 要素の移動 (= $O(\log^2 N / B)$ 回の転送) で行える構造です (詳細は次節)。

手順は、まず OFM で $N$ 個のキー (+ 隙間) を並べた配列を作り、その上に vEB レイアウトの木を被せて、木の葉から OFM の対応する要素へポインタを張ります。内部ノードには「自分の子部分木の最大値」(隙間は $-\infty$ とみなす) を持たせます。検索は各ノードで左の子を見て左右どちらに進むかを決めるだけで $O(\log_{B+1} N)$。挿入は、まず挿入位置の次者 (successor) を検索し、OFM に要素を挿入し、変化した葉から根に向かって木を post-order (子を先に更新してから親) で更新します。削除も同様です。

更新の計算量解析は 3 層に分けて行われます。(1) サイズが $B$ 以下で、木の最後の 2 レベルに属する「小さい vEB 三角形」たち (サイズ $> B$ で小さい三角形を 2 レベル分含む「大きい vEB 三角形」の内側) ― ポスト順更新の最中はキャッシュに 4 ブロックだけ保持すれば済むので 1 個あたり償却定数回の転送で更新でき、このレベルの三角形は $O(1+\log^2 N/B)$ 個あるので合計 $O(\log^2 N / B)$ 回。(2) それらの根を葉とする「大きい vEB 三角形」の根の木 $\tau$ (サイズも $O(\log^2 N/B)$) ― サイズが (1) の読み込み量と同程度なので追加コストなしで更新できる。(3) $\tau$ の根から全体の根までの経路 ― $O(\log_{B+1} N)$ 回。合計すると

$$ \text{INSERT/DELETE} = O\!\left(\log_{B+1} N + \frac{\log^2 N}{B}\right) \text{ 回の転送} $$

これは検索の $O(\log_{B+1} N)$ より遅く、$B = o(\log N \log\log N)$ だと余分な $\log^2 N / B$ 項が無視できません。これを消すのが インダイレクション (indirection) という技法です。$N$ 個の要素を大きさ $\Theta(\log N)$ の $\Theta(N/\log N)$ 個のグループに分け、各グループの最小値だけを上の vEB+OFM 構造に載せます。検索は上の構造で $O(\log_{B+1} N)$、該当グループを 1 つ走査するのに $O(\log N / B)$ 回かかり、合計 $O(\log_{B+1} N)$。挿入・削除はグループ全体を再構成しますが、これも $O(\log N / B) = O(\log_B N)$ 回で十分安い。グループが大きすぎ・小さすぎになったときだけ分割・合併して上の構造を更新しますが、これは $\Omega(\log N)$ 回の更新につき 1 回しか起きないので償却 $O(1)$。結果として、全操作が最終的に $O(\log_{B+1} N)$ 回の転送で動く、最適なキャッシュ非依存 B 木が完成します。

2. L08: Ordered File Maintenance・List Labeling・キャッシュ非依存優先度付きキュー

Ordered File Maintenance (OFM)

OFM が解く問題は「$N$ 個の要素を、指定された順序を保ったまま、大きさ $O(N)$ の配列に格納する。要素間に $O(1)$ 個までの隙間 (空きスロット) を許す。挿入 (ある 2 要素の間に新要素を入れる) と削除をサポートする」というものです。隙間が $O(1)$ 個に保たれているおかげで、$k$ 個の要素を走査するコストは $O(\lceil k/B \rceil)$ のままです。

構造のアイデアは、配列を $\Theta(\log N)$ 要素ずつの区間に分け、その上に (概念上の) 完全二分木を乗せることです。木の各ノードはその区間に「実際に入っている要素数」と「使える全スロット数」の比、つまり密度 $\rho$ を管理します。密度が濃すぎる・薄すぎる区間を見つけたら、その区間を均等に再配置します。

図: 浅い (大きい) 区間ほどしきい値が厳しいのは、深い区間を再配置しても得られる作業量が少ないから

更新の手順は「(1) $X$ を含む葉区間 (サイズ $\Theta(\log N)$) を更新する。(2) しきい値を満たすノードが見つかるまで木を根方向にたどる。(3) そのノードの区間全体を均等に再配置する」です。償却解析の要点は、しきい値が深さごとに段階的に厳しくなっていること。ノード $D$ の区間を再配置すると、$D$ の子孫全員が同じ密度になり、しきい値がより緩い (子孫の) 側ではその後 $\Omega(m/\log N)$ 回 ($m$ は子の区間サイズ) の更新が起きるまでしきい値を破らない、と言えます。親区間 (サイズ $\le 2m$) の再配置コストをこの $\Omega(m/\log N)$ 回の更新に分配すると、1 回の更新は各高さで $O(\log N)$ 回チャージされ、木の高さが $O(\log N)$ なので合計 償却 $O(\log^2 N)$ 回の要素移動、つまり $O(\log^2 N / B)$ 回の転送になります。

講義ノートに書かれている未解決問題。 償却 $O(\log^2 N)$ が本当に最適かどうかは、当時 (2012 年の講義時点) は予想 (conjecture) にとどまるとされています。

List Labeling ― OFM より簡単な問題

List Labeling は「連結リストの各ノードに整数ラベルを振り、リストの順序どおりに単調増加させる。挿入・削除をサポートする」という、OFM より簡単な問題です (OFM は実際の値の列を保存するのに対し、List Labeling はラベル=位置の情報だけでよい)。ラベル空間 (使える整数の範囲) をどれだけ広く取れるかで、達成できる時間が変わります。

ラベル空間最良の更新/クエリ時間コメント
$(1+\varepsilon)N \ldots N\lg N$$O(\lg^2 N)$OFM を使う (線形空間)
$N^{1+\varepsilon} \ldots N^{O(1)}$$\Theta(\lg N)$しきい値を $\approx \alpha^{-d}$ とした OFM 風の手法
$2^N$$\Theta(1)$$N$ 項目に $N$ bit、区間の二分で挿入 (最大 $N$ 回ごとに 1 回全体再構築)

さらに「ノード $x$ はノード $y$ より前か」という順序クエリ (order query) まで $O(1)$ 償却更新・$O(1)$ クエリで答えられる構造があります (間接参照 (indirection) を使う)。「トップ」要約構造が複数の「ボトム」構造を束ねる形にし、ボトム構造はそれぞれサイズ $\Theta(\log N)$ で、サイズ $N = 2^{\log N}$ の指数的ラベル空間アルゴリズムでラベル付けします。トップ構造はサイズ $O(N/\log N)$ で、各要素はどれか 1 つのボトム構造を指します。このトップ側にも $\Theta(\log N)$ 要素用のラベル付けアルゴリズムを使うと、コストは $\Theta(\log N)$ per update ですが、トップの更新はボトムの更新 $\Theta(\log N)$ 回に 1 回しか起きないので償却 $O(1)$ です。各ボトム要素の最終ラベルは (トップのラベル, ボトムのラベル) の組で $O(\log N)$ bit に収まり、2 つの組を $O(1)$ 時間で比較できます。「トップのラベル 1 個を変えると、多数のボトムのラベルが一斉に動く」ことがこの高速化の核心です。

キャッシュ非依存優先度付きキュー

目標は INSERT・DELETE・DELETE-MIN を償却 $O\!\left(\frac1B \log_{M/B}\frac{N}{B}\right)$ 回の転送でサポートすることです。構造は $\Theta(\log\log n)$ 個のレベルに分かれ、サイズはおおよそ $N,\ N^{2/3},\ N^{4/9},\dots,O(1)$ と急激に小さくなります。各レベルは 1 個の up バッファと複数の down バッファ (連結リスト) から成り、要素はこれらのバッファの間を上下に移動します。サイズ $X^{3/2}$ のレベルでは up バッファのサイズは $X^{3/2}$、down バッファは最大 $X^{1/2}$ 個で各サイズ $\Theta(X)$ (最初の 1 個だけ小さいことがある) です。

常に保たれる不変条件は 3 つ: (1) 同じレベル内では down バッファの要素はすべて up バッファの要素より小さい。(2) 同じレベル内では down バッファ同士は番号順に大小関係が揃っている。(3) レベルをまたいでも down バッファはすべて大小関係が揃っている (小さいレベルの down バッファが全体的に最小)。

図: 3 つの不変条件のおかげで最小値は常に「最小レベルの先頭 down バッファ」にある

基本操作は次の通りです。

  • Find-min / Delete-min. 最小要素は常に最小レベルの先頭 down バッファにあるので、そこを見る/取り除くだけ。取り除いて down バッファが足りなくなったら pull を行う。
  • Insert. (1) 新要素を最小レベルの up バッファに追加。(2) それが down バッファのどれかより小さければ swap して down 側に入れる。(3) up バッファが溢れたら push を行う。
  • Push (レベル $X$ → $X^{3/2}$). レベル $X$ の up バッファを空にするため、中身をソートしてレベル $X^{3/2}$ の down/up バッファに (昇順に走査しながら) 分配する。down バッファが溢れたら半分に分割、down バッファの個数が増えすぎたら最後の 1 個を up バッファに吸収する。
  • Pull (レベル $X^{3/2}$ → $X$). レベル $X$ の down バッファを補充するため、レベル $X^{3/2}$ から最小の $X$ 個を持ち上げる。足りなければレベル $X^{9/4}$ から再帰的に pull する。

解析は「再帰を無視すればレベル $X^{3/2}$ での push/pull は $O\!\left(\frac{X}{B}\log_{M/B}\frac{X}{B}\right)$」というソートのコストが支配項になる (tall-cache 仮定 $M \ge B^2$ の下で、分配・スキャンのコストがソートのコストに埋もれる) という議論から始まります。各要素は各レベルで定数回しか push/pull されないので、1 要素あたりのコストは $\sum_X \frac1B \log_{M/B}\frac{X}{B}$ の形になり、$X$ が二重指数的に増えるため最後の項 (一番大きいレベル、$N$) が支配的になって、全体で $O\!\left(\frac1B \log_{M/B}\frac{N}{B}\right)$ 償却に収まります。

3. L09: Lazy Funnelsort と 2 次元領域検索

ファネル (funnel) とファネルソート

$K$-ファネルは「$K$ 枚の葉を持つ完全二分木で、各部分木自身も再帰的に $\sqrt K$-ファネル」という構造です。根の直下、$\sqrt K$ 本に分かれる辺それぞれにバッファ (サイズ $K^{3/2}$、自分自身の $K$ を使う) がぶら下がっており、$\sqrt K$ 個のバッファの総サイズは $\sqrt K \cdot K^{3/2} = K^2$ になります。木の葉は入力となるソート済みリストを指し、はじめ全バッファは空です。$K$-ファネルは合計サイズ $K^3$ の $K$ 本のソート済みリストを $O\!\left(\frac{K^3}{B}\log_{M/B}\frac{K}{B} + K\right)$ 回の転送でマージします。この $K^3$ という係数のせいで、実際のソートアルゴリズムは $N^{1/3}$-way のマージソートに $N^{1/3}$-ファネルを組み合わせる形になります ($K = N^{1/3}$ の $K$ 本のリスト、合計サイズ $K^3 = N$)。

バッファを満たす手順は再帰的です。あるバッファ (出力バッファ) を満杯にするには、その 2 つの子バッファから要素を取り出してマージします。両方の子バッファに要素がある限り、小さい方を出力バッファに移す普通の 2 入力マージです。子バッファのどちらかが空になったら、その子バッファを再帰的に補充 してからマージを続けます。「必要になった時だけ下から補充する」という遅延 (lazy) 評価がこのアルゴリズムの名前の由来です。

図: 補充は「必要になってから」(lazy) 起きる。このおかげでキャッシュに乗る分だけ再帰を深追いすればよい

分布スイープ (distribution sweeping) ― ファネルソートの二次利用

ファネルソートは「ソートする」以外にも使えます。マージの中身を単純な大小比較だけでなく、点の座標に関する補助情報を一緒に運ぶように拡張すると、値によって分割する分割統治(divide and conquer on the key value) のエンジンとしても機能します。この「ソートの仕組みをそのまま幾何的な分割統治に転用する」考え方を 分布スイープ (distribution sweeping) と呼び、以下の 2 次元領域検索で使われます。

バッチ処理の 2 次元領域検索

問題は「$N$ 個の点と $N$ 個の矩形が最初から全部与えられたとき、どの点がどの矩形に入っているかを全部まとめて答える」というバッチ版です。最適な計算量は $O\!\left(\frac{N}{B}\log_{M/B}\frac{N}{B} + \frac{\text{out}}{B}\right)$ です ($\text{out}$ は出力サイズ、つまり点と矩形の包含関係の総数)。

アルゴリズムの骨格は、まず点と矩形の角を $x$ 座標で lazy funnelsort し、続いて $x$ について分割統治しながら $y$ でマージソートする「上方向スイープライン」を行う、というものです。$x$ 方向を左スラブ $L$ と右スラブ $R$ に分けたとき、興味深いのは「矩形がスラブを完全に横断している」場合です。矩形の角が $L$ 側にあり $R$ 側まで横断している数を $C_L$ として、矩形の下端角 (lower-left corner) に出会ったら $C_L$ を増やし、上端角に出会ったら減らします。対称に $C_R$ も管理します。$L$ 側の点に出会ったときはその点のカウンタに $C_R$ を加算し、$R$ 側の点には $C_L$ を加算します。これで「スラブを横断する矩形」由来の包含関係を $O(1)$ ずつの更新で数え上げられます。

オンラインの 2 次元領域検索 ― 2 辺・3 辺・4 辺

バッチではなく「事前に $N$ 点だけ処理しておき、矩形クエリが後から来る」オンライン版では、クエリ 1 回を $O(\log_B N + \text{out}/B)$ 回の転送で答えられます。クエリの形には 3 種類あります: 2 辺 ($\le x_q,\ \le y_q$)、3 辺 ($[x_{q\min}, x_{q\max}],\ \le y_q$)、4 辺 ($[x_{q\min}, x_{q\max}],\ [y_{q\min}, y_{q\max}]$)。空間使用量はクエリの辺数が増えるほど悪化します。

クエリの種類通常の RAM モデルでの空間キャッシュ非依存での空間
2 辺$O(N)$$O(N)$
3 辺$O(N)$$O(N \lg N)$ ($O(N)$ は未解決)
4 辺$O\!\left(N \frac{\lg N}{\lg\lg N}\right)$$O\!\left(N \frac{\lg^2 N}{\lg\lg N}\right)$
講義ノート記載の未解決問題。 3 辺のクエリを $O(\log_B N + \text{out}/B)$ かつ空間 $O(N)$ で答えられる構造は、2012 年の講義時点で未解決 (OPEN) とされています。

2 辺の場合 の線形空間構造が土台になります。考え方の核は「密 (dense)」と「疎 (sparse)」という概念です。ある配列 $S$ の中で範囲 $(\le x_q, \le y_q)$ が密であるとは、「$S$ の中で $x < x_q$ を満たす点の数」が「実際にその矩形に入る点の数の 2 倍以下」であることです。配列が $x$ でソートされていて、クエリが密なら、配列を頭から走査するだけで答えの定数倍以内の点数しか読まずに答えが出ます。

最初の (失敗する) 試みは、配列を $S_0, S_1, \dots$ と階層化し、各 $S_i$ で「スパースになる境界 $y_i$」を見つけて $S_{i+1} = S_i \cap (\ast, \le y_i)$ とする方法です。任意のクエリに対してどこかの層で密になることは保証できますが、配列の総サイズが $N$ の 2 次関数になってしまう反例があります (claim 3「空間 $O(N)$」が破れる)。

正しい (2 番目の) 構成では、各段で「$x$ 方向にも」境界 $x_i$ を導入し、$P_{i-1} = S_{i-1} \cap (\le x_i, \ast)$ という部分集合を別枠で保存し、$S_i = S_{i-1} \cap \big((\ast,\le y_i) \cup (\ge x_i, \ast)\big)$ と定義し直します。配列は $P_0 P_1 \dots S_k$ の順に並べます。$|P_{i-1} \cap S_i| \le \frac12 |P_{i-1}|$ (密の定義そのもの) なので、$P_{i-1}$ の保存コストを $P_{i-1} - S_i$ に負担させると、各点がチャージされる回数は定数 ($\frac{1}{1-\frac12}=2$) 回に収まり、総空間は $O(N)$ になります。重複する点の $x$ 座標は単調に減っていくことを使えば重複判定も容易で、スキャンする点数も $O(\text{out})$ に抑えられます。この配列の先頭を指すポインタを vEB 探索木の各ノードに持たせれば、$O(\log_B N + \text{out}/B)$ の 2 辺クエリが $O(N)$ 空間で完成します。

3 辺の場合 は、葉が $x$ でソートされた vEB 探索木を作り、各内部ノードに自分の部分木が持つ点の 2 辺構造を 2 つ (左向きと右向き) 持たせます。各点は $O(\log N)$ 個の内部ノードの 2 辺構造に現れるので空間は $O(N \log N)$。クエリ $([x_{q\min}, x_{q\max}], \le y_q)$ は $x_{q\min}$ と $x_{q\max}$ の最小共通祖先を見つけ、その左の子の構造で $(\ge x_{q\min}, \le y_q)$、右の子の構造で $(\le x_{q\max}, \le y_q)$ を問い合わせて和を取ります。

4 辺の場合 は素朴には $y$ でソートした vEB 木の各内部ノードに 3 辺構造を乗せて $O(N \log^2 N)$ 空間で済みますが、$\log\log N$ 分の 1 倍だけ節約できます。高さ $\frac12 \lg\lg N$ の部分木を 1 個の次数 $\sqrt{\lg N}$ のノードにまとめて縮約すると、木の高さは $O(\lg N / \lg\lg N)$ になります。各内部ノードに 3 辺構造 2 個と、$\sqrt{\lg N}$ 個の子の間隔ごとに $x$ でソートした静的探索木を持たせます。クエリは $y_{q\min}$ と $y_{q\max}$ の最小共通祖先を見つけ、両端は 3 辺クエリで、間にある子たちは「区間に対応する $x$ 探索木」1 回のクエリでまとめて答えます。これで $O(\log_B N + \text{out}/B)$ のクエリ時間を $O\!\left(N \frac{\lg^2 N}{\lg\lg N}\right)$ 空間で達成します (通常の $O(N\log^2N)$ から $\lg\lg N$ 分の節約)。

4. L22: メモリモデルの歴史 ― なぜこんなに多くのモデルがあるのか

L22 は 6.851 の最終講義で、ここまで使ってきた「外部メモリモデル」や「キャッシュ非依存モデル」がどういう歴史的な流れの中で生まれたかを振り返ります。新しい結果というより、モデルの地図 を描く回です。

理想化された 2 レベルストレージ (idealized two-level storage)

最も単純なモデルです。CPU と、サイズ $\le B$ のアイテムを格納する「ブロック」の集合である RAM があります。ブロック内のアイテムの順序は無視し、どのブロックに入っているかだけを問題にします。ブロック操作は、2 つのブロック $i, j$ から最大 $B$ 個のアイテムを読み、3 つ目のブロック $k$ にコピーする操作です。CPU 演算は無料、アイテムは分割不可能と仮定します。

この模型での代表的な結果は置換 (permutation) の下界です。$N$ 個のアイテムを $N/B$ 個の指定されたブロックに移すには (tall disk 仮定 $N/B > B$ の下で) 平均ケースで $\Omega\!\left(\frac{N}{B}\log B\right)$ 回のブロック操作が必要です。証明はポテンシャル関数 $\Phi = \sum_{i,j} n_{ij}\log n_{ij}$ を使います ($n_{ij}$ はブロック $i$ にあってブロック $j$ 行きのアイテム数)。目標状態 (各ブロックが完全に 1 箇所行き) では $\Phi = N\log B$ ですが、ランダムな初期状態では $E[\Phi] = O(N)$。1 回のブロック操作で $\Phi$ は最大 $B$ しか増えない (不等式 $(x+y)\log(x+y) \le x\log x + y\log y + x+y$ から)ので、必要な操作回数は少なくとも $\frac{N\log B - O(N)}{B} = \Omega\!\left(\frac{N}{B}\log B\right)$。上界側は、目的ブロックの ID をキーにした radix sort 風のアルゴリズムで $O\!\left(\frac{N}{B}\log\frac{N}{B}\right)$ を達成でき、下界とほぼ一致します。

赤青ペブルゲーム (red-blue pebble game)

理想化 2 レベルモデルには「ブロック」はあっても「キャッシュ」がありません。逆に ペブルゲーム は「キャッシュ」の役割を持つ計算モデルですが、ブロックの概念がありません。まず単色版: 計算をデータ依存の DAG とみなし、(1) 先祖全員にペブルが置かれていればノードにペブルを置ける、(2) ペブルは取り除ける、というルールで全出力ノードにペブルを置くことを目指し、同時に使うペブルの最大数 (= 同時に保持しなければならない中間結果の数) を最小化します。$n$ 頂点の DAG はどれも $O(n/\log n)$ 個のペブルで実行できる、という定理があり、ここから「時間 $t$ で解ける問題は空間 $O(t/\log t)$ で解ける」($\mathrm{TIME}(t) \subseteq \mathrm{SPACE}(t/\log t)$) という計算量理論の結果が従います。

赤青ペブルゲーム はこれに「キャッシュ」の区別を加えます。赤いペブル = キャッシュ内、青いペブル = ディスク内、とし、キャッシュサイズ $M$ (同時に置ける赤ペブルの最大数) を制限します。先祖全員に赤ペブルがあればノードに赤ペブルを置ける、赤ペブルを青に変える (write)、青を赤に変える (read) という操作が加わり、read/write の回数を最小化するのが目的です。

I/O モデル = 外部メモリモデル

理想化 2 レベルモデルに「ブロック」を、赤青ペブルゲームに「キャッシュ」を、両方組み合わせたのが I/O モデルで、これは L07 で扱った外部メモリモデルそのものです。検索の下界 $\Theta(\log_{B+1} N)$ は情報理論的な議論 (1 ブロック読むごとに $\log(B+1)$ bit しか得られない) で、ソートの下界 $\Theta\!\left(\frac{N}{B}\log_{M/B}\frac{N}{B}\right)$ はカウント論法 (事前にブロック内がソートされていても、$N\log N$ bit 必要な情報のうち $N\log B$ bit しかタダでは分からない) で、どちらも L07 と同じ主張です。上界側のアルゴリズムとして、マージソートに加えて分布ソート (distribution sort) ($\sqrt{M/B}$ 分木のクイックソート風アルゴリズム) も紹介されます。

この講義ではさらに 逐次 I/O (sequential I/O) という視点を加えます。ディスク上で「順番に」読み書きする方が「ランダムに」読み書きするより速いという、実務者には馴染み深い事実をモデルに組み込んだものです。逐次マージソートは $O\!\left(\frac{N}{B}\log\frac{N}{B}\right)$ の逐次転送で最適であり、ランダム転送の回数をソートの下界の定数倍未満に抑えようとすると、逆に逐次転送が $\Omega\!\left(\frac{N}{B}\log\frac{N}{B}\right)$ 回必要になる、というトレードオフの関係が示されます。

階層メモリモデル (HMM) ― 2 段階を超える

実機には 2 段より多くの階層があります。階層メモリモデル (Hierarchical Memory Model, HMM) は、番地 $x$ へのアクセスコストを $f(x) = \lceil \log x \rceil$ とする単純化から始めます (番地が大きいほど遠い=遅い、というイメージ)。

$f(x) = \lceil\log x\rceil$ という特定の関数は本質的ではないので、一般化 $\mathrm{HMM}_{f(x)}$ では $f$ に「多項式的に有界」($f(2x) \le c\,f(x)$ となる定数 $c$ が存在する、指数関数は除外される) という条件だけを課し、$f$ を閾値関数の重み付き和 $f(x) = \sum_i w_i \cdot [x \ge x_i]$ として表します。特に $f_M(x) = [x \ge M]$ (項が 1 個、キャッシュサイズ $M$ に相当) という特殊形を考えると、「すべての $M$ に対して $\mathrm{HMM}_{f_M}$ で最適」(= $M$ の値を知らなくても最適、キャッシュ非依存と同じ発想) なアルゴリズムは 均一最適 (uniformly optimal) と呼ばれ、均一最適なアルゴリズムは実は任意の $f$ に対して最適になる、という命題が成り立ちます。これは「キャッシュ非依存アルゴリズムが多段階層でも強い」ことの理論的な裏付けです。

走査$\Theta(N-M)$$\Theta(1+1/M)$
二分探索$\Theta(\log N-\log M)$$\Theta(1+1/\log M)$

キャッシュの置換戦略についても結果があります。保守的な置換戦略 (LRU・FIFO) でサイズ $2M$ のキャッシュを使うと、サイズ $M$ での最適なオフライン戦略の最大 2 倍の時間で済む、$T_{\mathrm{LRU}}(N, 2M) \le 2\,T_{\mathrm{OPT}}(N, M)$ という結果です (サイズを $f(x)$ が 2 倍になるごとの「かたまり」に分け、LRU が追い出すときは次のかたまりに移す、という議論)。これはまさに L07 でキャッシュ非依存モデルの前提として使った「LRU/FIFO はオフライン最適の 2 倍以内」という事実そのものです。

ブロック転送まで加えた HMM with Block Transfer では、$f(x)$ の形 (対数・$x^\alpha\ (\alpha{<}1)$・線形・$x^\alpha\ (\alpha{>}1)$) によって、内積やマージ、行列積、FFT、ソート、二分探索の計算量が変わる表が示されますが、ここは「$f$ の形によって結果が質的に変わる」ことを示す一覧として眺めれば十分です。

多段 I/O モデルと UMH、そして振り返り

多段の外部メモリモデル (Memory Hierarchy Model) はキャッシュ $M_0, M_1, \dots, M_n$ を階層的に並べ、隣接するキャッシュ間でサイズ $B_i$ のブロックを時間 $t_i$ で転送できる (かつ全レベルが並行に転送可能) とするモデルです。特にアスペクト比 $\alpha = \frac{M_i/B_i}{B_i}$ とブロック成長率 $\beta = B_{i+1}/B_i$ を固定した Uniform Memory Hierarchy (UMH) モデルでは、行列の転置・行列積・FFT について $\alpha,\beta$ を使った上下界の表が与えられます。講義ノートは最後にキャッシュ非依存モデル自身も振り返り、走査は外部メモリモデルと全く同じ $O(\lceil N/B\rceil)$ である一方、検索は vEB レイアウトを使っても外部メモリモデルに完全には追いつかず、$(\lg e + o(1))\log_B N$ 回と、外部メモリモデルの $\log_{B+1}N$ 回より定数倍 ($\lg e \approx 1.44$ 倍) だけ多くかかると明言しています (動的化すれば B 木で $O(\log_B N)$ に戻せます)。最後に、この講義群全体の結論として、キャッシュ非依存モデルは、どの境界 (どの 2 つの隣接レベル) を「キャッシュ」「ディスク」とみなしても同じ解析が通用するため、多段階層モデルの特殊な一般化とみなせる、という総括がされます。ただしソートと置換はキャッシュ非依存では tall-cache 仮定 $M = \Omega(B^{1+\varepsilon})$ が必要で、この仮定を外すと外部メモリモデルの最適値に到達できないことも明言されています。

5. 操作してみる ― van Emde Boas レイアウトの再帰分割

$N=16$ 個の要素を持つ完全二分探索木 (高さ 4、ノード数 31) を例に、vEB レイアウトが「高さを半分に割る」を繰り返して木を三角形の集まりに分解していく過程を、実際にボタンを押して進めてください。下のバーは、その時点の分割に対応するメモリ上の実際の並び順 (配列としてどう直列化されるか) を表します。

デモ 1 ・ vEB 再帰分割と検索パス

「さらに分割」でレベルを進め、「戻す」で戻します。葉 (要素) を 1 つ選んで「検索」を押すと、根から葉までの経路が何個の三角形ブロックを通過するかが分かります。

分割レベル: 0 (未分割)

上段が深さ 0 (根)、下段が深さ 4 (葉 = 要素そのもの、番号 0-15)。色のついた枠が現在の分割レベルでのブロック

分割レベル 0: 木全体が 1 個のブロック。「さらに分割」を押してみてください。

読み取り。分割レベル 1 (ブロックサイズ 7) ではどの葉を検索してもブロックはちょうど 2 個、分割レベル 2 (ブロックサイズ 2-3) では常に 4 個を通過します。ブロックを小さくするほど通過するブロック数は増える ― これはまさに $\log_B N$ が $B$ を小さくすると大きくなるという関係です。重要なのは、この木は $B$ の値をまったく知らずに「高さを半分」で再帰分割しただけなのに、分割を止める深さを選べば、どんな $B$ に対してもその $B$ に見合ったブロックサイズの層がちゃんと存在するという点です。実際の cache-oblivious アルゴリズムは、どこかで木を切って止めるのではなく全階層を保持し続け、実機のキャッシュが勝手に「ちょうど良い粒度」で面倒を見てくれる、という仕組みになっています。

実務での出番

正直な評価です。「このページで解説した構造がそのままの形で動いているソフトウェア」はほとんどありません。実務で広く使われているのは、外部メモリモデルの発想 (ブロック転送回数を最小化する) の方で、キャッシュ非依存モデルそのもの (B や M をコードに一切出さない実装) はかなり限定的です。

  • B 木・B+木はまさにこの講義の L07 冒頭の結果そのものです。 PostgreSQL のデフォルトインデックス、InnoDB (MySQL) のクラスタ化インデックスはいずれも B+木で、ノードサイズをディスクページ (PostgreSQL は 8KB、InnoDB は 16KB) に合わせています。これは L07 の「外部メモリモデルの B 木、分岐数 $\Theta(B)$」をブロックサイズ $B$ を実際に意識して実装したものであり、理論と実装がほぼ 1 対 1 対応する珍しい例です (PostgreSQL の B-Tree 実装の公式ドキュメント)。
  • キャッシュ非依存 B 木の流れをくむ索引は、実際の製品になりました。 キャッシュ非依存 B 木の論文 (Bender, Demaine, Farach-Colton) の著者でもある Michael Bender と Martin Farach-Colton らは、続く論文 Cache-Oblivious Streaming B-trees (2007) で COLA (Cache-Oblivious Lookahead Array) を提案し、その考え方を Tokutek 社の TokuDB ストレージエンジン (フラクタルツリー索引) に持ち込みました。フラクタルツリー索引自体は、その後継論文群で Bε 木 (大きなノードに更新をバッファとして埋め込み、書き込みの増幅を抑える構造) として整理されており、本講義の vEB レイアウト + OFM をそのまま実装したものではない、という点は注意が必要です。その中核のキー・バリューストアは現在 PerconaFT として公開されていて、README には TokuDB の中で使われていると書かれています。ただし MySQL 系の主流のストレージエンジンは今も B+木の InnoDB で、「理論的には正しいが主流にはならなかった」という評価が公正です。
  • LSM 木 (Log-Structured Merge-Tree) は別系統です。 RocksDB・LevelDB・Cassandra が使う LSM 木は、このページの構造 (B 木や vEB レイアウト) とは異なるデータ構造で、「読み取りの転送回数」ではなく「書き込みの増幅」を最小化する設計です。ただし 動機は同じ ― ディスク (今ならしばしば SSD) への転送をブロック単位でまとめて減らす という点で、外部メモリモデルの精神を共有しています。「LSM 木はキャッシュ非依存アルゴリズムの一種」という主張は誤りで、系譜としては別物だと明言しておきます。
  • 赤青ペブルゲームは、深層学習の勾配チェックポイント (gradient checkpointing) と同じ数理です。 計算 DAG の中間結果のうちどれを「保持する (ペブルを置く)」かどれを「捨てて後で再計算する」かを選ぶ、というのがまさに torch.utils.checkpoint (PyTorch 公式ドキュメント) やアクティベーション再計算スケジューラが自動化している判断そのものです。1981 年の赤青ペブルゲームの論文が深層学習を予見していたわけではありませんが、「メモリに置くか、捨てて再計算するか」というトレードオフの形式化としては驚くほど同じ構造です。GPU メモリが足りないときに checkpoint=True にする、という実務判断の裏にある数理モデルがこれだと理解すると、抽象的なペブルゲームに具体的な手触りが出てきます。
  • GPU のメモリ階層にキャッシュ非依存モデルは「そのままは」当てはまりません。 読者の ML インフラの経験と直結する点なので明言しておきます。GPU カーネル (CUDA/Triton/NKI など) のチューニングは、共有メモリのサイズやウォープサイズ、L2 キャッシュの大きさを明示的にコードに埋め込んでタイル幅を決める、キャッシュ非依存とは正反対のアプローチが標準です。一方で、「2 段階のメモリ (高速な SRAM 的な層と低速な HBM) の間の転送回数を最小化する」という外部メモリモデルそのものの考え方は roofline 分析やタイリングの基礎理論として直接使われています。つまり役に立つのは「外部メモリモデルの発想」で、「B と M を知らずに最適化する」というキャッシュ非依存モデルの核心部分はむしろ GPU カーネル最適化の流儀とは逆方向です。
  • ファネルソート・分布スイープ・キャッシュ非依存優先度付きキューは、主に理論的な関心にとどまります。 外部ソートの実装 (例えば大規模データベースのソートオペレータ) は、ファネルソートではなく $k$ 分木マージソートや分布ソートの実務的な変種を使うのが普通で、ファネルソートの再帰的バッファ構造が実装として採用された広く知られる商用システムは見当たりません。同様に、2 次元領域検索の節で紹介した 2 辺・3 辺・4 辺の構造は、空間インデックス (PostGIS の R 木など) の実装とは別系統の理論結果です。ここは「CS 学部生が学ぶ理論の最前線」として理解するのが適切で、実務への直接移植を期待する内容ではありません。
