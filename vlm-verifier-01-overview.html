画像を読むAI(VLM)は間違える。だから信じずに、機械的に検算する。その検算器を強くしていく研究の記録。

研究過程シリーズ 第1回 ｜ 2026-08-12 時点

1 ひとことで言うと 中心アイデア

AIに請求書やレシートの画像を読ませると、たまに数字を読み間違えます。 その間違いを「AIをもっと賢くして直す」のではなく、読み取り結果が計算として辻褄が合うかを、後段の機械的な検算器でチェックするという発想です。

たとえるなら、AIが伝票を書き、経理担当(検算器)が「単価×個数＝金額になってる? 合計は合ってる?」と検算し、合わなければ差し戻す。AIを鵜呑みにせず、世界のルールで答え合わせします。

2 なぜ必要か 具体例で

AIはこう間違える

Widget A 数量2 × 単価1500 金額 = 3200 ← 本当は3000 Widget B 数量1 × 単価2000 金額 = 2000 合計 = 5200 ← 本当は5000

検算器が持つルール

金額 = 数量 × 単価 合計 = すべての金額の和 + 税 売り手 ≠ 買い手

→ 2×1500=3000 なのに3200 → 不合格。「3行目の金額が怪しい」と指摘できる。

3 これまで作った道具 全部オフラインで動く

基本の検算
単価×個数=金額 / 合計 / 売り手≠買い手 を機械チェックし、違反を列挙。
A: 候補から選ぶ
AIに「自信がない数字は候補を複数出して」と言わせ、全ルールを同時に満たす組合せを選ぶ。1個ずつ「一番自信のある値」を選ぶと全体で矛盾することがあり、それを救う。
B: 犯人特定
検算が失敗したとき、どの数字が原因かを「その値を正しく直すと違反が消えるか」で特定。どこを読み直すべきか分かる。
検算器の強さテスト
わざと壊した伝票を、検算器がどれだけ捕まえるか測る。自分の弱点を数値で把握。

4 ぶつかった壁 実データで正直に測った

本物のAI(Gemma 4B)がレシート35件を読んだ結果を検算しました。ここが一番大事な現実です。

指標数字意味
ざっくりの検出率64.8%甘く数えたときの見かけ上の値
厳密に数え直すと15.5%犯人を正しく特定できた分だけ数えると激減
整合的な誤読(死角)35.2%AIが計算の辻褄まで合わせて間違えた分。算術検算では原理的に捕まえられない
正直な現実
本当の検出力は 15.5%〜64.8%の間(幅で報告するのが誠実)。そして「辻褄を合わせた間違い」は算術チェックでは絶対に捕まらない天井がある。つまり検算だけで品質保証はできない。

5 方向転換 道具から「作り方の規律」へ

ここで発想を変えました。個別のOCRツールを磨くのではなく、「検算器そのものをどう作るか」を規律する仕組みを作る方向へ。フォーマットが決まっている領域(帳票・回路図など)なら、「正しい形」を形式的に定義して適合を見られるからです。

やめた方向
「汎用の適合チェック基盤を作る」だけ。→ これは JSON Schema や SHACL など既存技術の再発明で新しさゼロ。
選んだ方向
検算器の書き方を型で縛る。「どのフィールドを読んでよいか(footprint)」「層(だれでも書ける算術／業界／個社)」「必ず反例を持つこと」を機械強制。犯人特定や弱点測定を言語の標準機能にする。
2つの独立AIが同じ結論
戦略相談として Fable 5(3つの視点) と codex(GPT-5.5) に独立評価させたところ、全員が「PIVOT(方向を絞れば筋が良い)」で一致。「検算器の性質(読める範囲・強度・健全性)を第一級にする」ことが、既存ツールに無い本質的な差だと収束しました。

6 今回の実験と結果 方向転換は正しいか?を数字で

この新しい「検算器の書き方を縛る仕組み(DSL)」を作り、本物のレシートデータで4つのチェックをしました。

試したこと結果やさしい意味
既存の4ルールを新方式で書けるか0/4 が手抜き全部きちんと書けた。表現力の壁に当たらなかった
昔の手書きルールと同じ判定をするか35件中0件ズレ完全に同じ挙動。おもちゃではなく本物の置き換え
健全性の自動チェック4本すべて合格「正しい伝票では黙る」「必ず反例を持つ」を機械が確認
読んではいけない場所を読むバグ定義時に自動拒否既存ツール(SHACL/OPA)には無い能力。ここが差別化の証拠
結論: 方向転換は「筋が良い」と実データで確認
新方式は既存ルールを漏れなく表現でき、手書きと完全一致し、既存ツールにできない安全チェック(読む範囲の型強制)を実演できました。

7 結局、いい状況なの?

率直に言うと 「エンジニアリングは健全、方向転換の手応えあり、ただし勝ち筋の完全証明はこれから」。

良い点

  • 仕組みが設計どおり動いている
  • 都合よく水増しせず、死角(35.2%)も正直に数値化
  • 2つの独立AIが同じ方向を支持
  • 既存ツールに無い能力を実データで実演

まだの点

  • 「辻褄を合わせた間違い」は原理的に捕まらない → 価値は検出率でなく監査可能性に置く
  • AIに仕様まで書かせる案は「未信頼」扱いが必須(無限後退の危険)
  • 本当に役立つ証明には、あと数個の実験が必要

8 次にやること

  1. メタ制約が「見逃していたバグ」を型レベルで弾く例を追加する
  2. 実データが1秒未満で解けるか測る(速いなら難しい理屈は捨てて単純化)
  3. AIが書いた仕様の「間違い率」が、制約を課すと下がるかを測る(方向転換の心臓部)
  4. チェックデジットや個社ルールを試すため、合成請求書データを用意する

用語メモ: VLM=画像を読むAI / 検算器=ルールで検証する仕組み / footprint=そのルールが読んでよいフィールドの範囲 / 整合的誤読=計算の辻褄まで合った間違い(検算で捕まらない) / PIVOT=方向転換。
