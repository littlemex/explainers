この回の前提: 第 02 回 仕様とは何か

第 02 回で、プログラムが「正しい」とは仕様 (事前条件・事後条件) に対して正しいことだと学びました。ホーア論理は、この事前条件・事後条件をプログラムの文ごとに機械的につなぎ、小さな文の正しさから大きなプログラム全体の正しさを組み立てる方法です。ここでは代入・逐次・条件分岐・while という基本的な文それぞれの規則と、ループを証明する鍵になるループ不変条件を見ます。

1. ホーアの三つ組と代入の規則

ホーア論理の基本単位は {P} c {Q} という三つ組です。P (事前条件) を満たす状態から文 c を実行し、それが停止したなら、必ず Q (事後条件) を満たす状態になる、という主張を表します。1969 年の Hoare の原論文がこの記法と規則を提示し、Software Foundations の Hoare の章はこれを計算機で確かめられる形に組み直したものです。SF はこの章の目的を「Imp の正確な定義を使って、特定のプログラムが特定の仕様を満たすことを形式的に証明する道具を作ること」と述べています。

P や Q は「プログラムの状態 (変数名から値への対応) についての論理的な主張」です。SF はこれを assertion (表明) と呼び、「プログラムのメモリの状態についての論理的な主張である」と定義しています。つまり P や Q は、ある状態を受け取って真か偽かを返す関数のようなものだと考えられます。X > 5 という主張は、変数 X の値がその状態で 5 より大きいかどうかを判定します。

何もしない skip は状態を変えないので、規則は単純です。

{P} skip {P}

代入 X := a の規則は、見た目が直感に反します。

{ Q の中の X を a に置き換えた式 } X := a { Q }

事後条件 Q から逆向きに事前条件を作ります。たとえば事後条件が X > 5 だとすると、代入 X := X + 1 の前に必要な条件は、Q の中の X を X + 1 に置き換えた X + 1 > 5、つまり X > 4 です。代入はまだ実行されていないので、事前条件は「代入した後に Q が成り立つように、今の値がどうであるべきか」を表すしかなく、これが逆向きになる理由です。

2. 逐次と条件分岐をつなぐ

逐次 c1; c2 は、c1 の事後条件を c2 の事前条件としてそのまま橋渡しします。

{P} c1 {Q}    {Q} c2 {R}
----------------------------
      {P} c1; c2 {R}

条件分岐は、どちらの枝を通っても同じ事後条件 Q に着地するように、枝ごとにガード b (または ¬b) を事前条件に加えて証明します。

{P ∧ b} c1 {Q}    {P ∧ ¬b} c2 {Q}
--------------------------------------
   {P} if b then c1 else c2 {Q}

加えて consequence (帰結) の規則があります。事前条件を今より強く (満たす状態を減らす方向に)、事後条件を今より弱く (満たす状態を増やす方向に) 置き換えても、三つ組は成り立ち続けます。これにより、代入の規則が機械的に作った少し不格好な式を、人が読みやすい同値な式に置き換えられます。

3. while とループ不変条件

while は規則の中で唯一、同じ文を何回実行するか分からないまま証明しなければなりません。鍵になるのがループ不変条件 I で、「ループに入る前に成り立ち、本体を 1 回実行しても成り立ったままである」性質です。

{I ∧ b} c {I}
-----------------------------
{I} while b do c end {I ∧ ¬b}

本体を何回実行しても I は保たれるので、ループが止まった時点でも I は成り立っています。そのときガード b は偽になっているので、事後条件は I ∧ ¬b です。SF にある例では、while Y > 10 do Y := Y - 1; Z := Z + 1 end に対して不変条件 X = Y + Z を使い、ループが止まった時点で X = Y + Z ∧ Y ≤ 10 が成り立つと結論します。

同じ考え方で、掛け算を繰り返し足し算で計算するループを確かめてみます。Z := 0; C := N から始め、C ≠ 0 の間 Z := Z + M; C := C - 1 を繰り返し、N と M の積を求めます。

{ Z = 0 ∧ C = N }
while C ≠ 0 do
  { Z + C*M = N*M ∧ C ≠ 0 }
  Z := Z + M;
  C := C - 1
  { Z + C*M = N*M }
end
{ Z + C*M = N*M ∧ C = 0 }
{ Z = N*M }

不変条件は Z + C*M = N*M です。開始時は Z=0, C=N なので 0 + N*M = N*M で成り立ちます。本体を 1 回実行すると、Z は M 増え、C は 1 減るので、Z + C*M の値は変わりません (増えた M と、C が 1 減ったことで減る M が相殺する)。ループが止まると C=0 なので、不変条件から Z = N*M が consequence の規則で取り出せます。

図: 不変条件は開始時・各繰り返し・終了時のすべてで成り立ち、終了時の結論を導く足場になる。
