NKI WORKSHOP ・ 03

FlashAttention ― カーネル融合の本命

N×N の中間行列を書き出さず、SRAM の上でタイル単位に Attention を計算する

0この記事の狙い

第 2 回で「中間結果を遅い HBM に書き出さず SBUF に留める = カーネル融合」を学びました。今回はその本命、Attention をまるごと融合する FlashAttention を掘り下げます。長文 LLM を支える最重要テクニックです。

一言でいうと
素朴な Attention は、系列長 N に対して N×N の巨大なスコア行列を作り、それを遅い HBM に書き出しては読み直します。FlashAttention は、この N×N 行列を一度も作らず・書き出さず、Q・K・V を小さなタイル (ブロック) に分けて速い SRAM の上だけで計算します。鍵は online softmax ― 全体の最大値や合計を知らなくても、ブロックを見るたびに途中経過を補正しながら正しい softmax を積み上げる技法です。結果、追加メモリが O(N²) から O(N) に激減し (N×N ぶんが不要になる)、メモリの意味では長文でも破綻しません (計算量は O(N²d) のままなので、時間は依然として系列長の二乗で伸びます)。
1. Attention のおさらい ― どこに N×N が出るか 2. 【体験】N×N 中間行列のメモリ爆発 3. なぜ書き出しが無駄なのか 4. FlashAttention の発想 ― タイルに切る 5. 【体験】タイリングで SRAM に収める 6. 難所 ― softmax は「全体」が要る 7. Online Softmax ― 走りながら補正する 8. 【体験】Online Softmax の補正 9. メモリ視点のまとめ ― O(N²) → O(N) 10. まとめ

対象は AWS Trainium2。第 2 回「Roofline とカーネル融合」を前提にします (Trainium のオンチップ SRAM は SBUF (28 MiB/コア) と PSUM (2 MiB、行列積の出力先) から成ります。本稿は簡略化のため SBUF を指して SRAM と呼びますが、実装では部分スコアの行列積結果は一度 PSUM に出ます)。Attention の数式そのものは Softmax Attention の解説も参照。

1Attention のおさらい ― どこに N×N が出るか

FlashAttention が消したい「N×N」がどこで生まれるか、数式で 1 箇所に絞ります。

系列長 N (トークン数)、ヘッド次元 d とします。Attention は次の 3 段です。

# Q,K,V は各 N×d
S = Q Kᵀ / √d  ← スコア行列 S は N×N (!)
A = softmax(S)  ← 重み行列 A も N×N (!)
O = A V        # 出力 O は N×d

入力 (Q,K,V) と出力 (O) は N×d と、N に比例したサイズです。ところが途中の S と A だけが N×N ― N に二乗で膨らみます。全トークンが全トークンを見る (総当たり) から N×N になる。この N×N の中間行列こそが、メモリの主犯です。

覚えるのはこれだけ: 入出力は N に比例 (O(Nd)、d を固定すれば N に比例)、途中の S・A だけが N の二乗 (O(N²))。FlashAttention は「この N×N を作らずに済ませられないか?」という問いから生まれます。

2【体験】N×N 中間行列のメモリ爆発

系列長 N を動かすと、N×N のスコア行列がどれだけ膨らむかが分かります。入出力 (N×d) との伸び方の違いに注目してください。

青い四角が N×N のスコア行列、緑の細い帯が 入出力 (N×d) です。N を 2 倍にすると、緑は 2 倍にしか伸びないのに青は 4 倍に膨らみます。N=32k では S+A だけで数 GB ― これを HBM に確保して往復させるのが、素朴な Attention の破綻点です (オンチップの SBUF は 28 MiB 級 (NeuronCore あたり) しかないので、そもそも載らない)。

メモリは 1 ヘッド・1 シーケンスあたりの最小見積り。実際はヘッド数・バッチ分さらに増えます。

3なぜ書き出しが無駄なのか

N×N を HBM に書き出す素朴な実装が、なぜ二重に損なのかを整理します。

素朴な Attention は 3 段を別々に実行し、そのたびに N×N 行列を HBM に書いて読み直します。

# 素朴実装: N×N が HBM を何度も往復
QKᵀ → S (N×N) を HBM に書く
S を読む → softmax → A (N×N) を HBM に書く
A を読む → AV → 出力を書く

損は 2 つあります。

  1. メモリ容量の無駄: N×N を丸ごと確保する必要がある。O(N²) なので長文で GB 級になり、そもそも載らない。
  2. メモリ帯域の無駄: N×N を書いて読み直す往復が、遅い HBM の帯域を食い潰す。第 2 回の Roofline でいうメモリ律速そのもの。しかも Attention の中間行列は「一度使ったら捨てる」ので、HBM に置く意味が本来ない。
問い。N×N は「QKᵀ を計算 → softmax → V を掛ける」の途中経過にすぎない。最終的に欲しいのは出力 O (N×d) だけ。ならば N×N を丸ごと作らず、必要な部分だけ SRAM の上で計算して捨てられないか? ― これが FlashAttention の出発点です。

4FlashAttention の発想 ― タイルに切る

N×N を一度に作らない。Q・K・V を小さなブロックに切り、部分ごとに計算します。

FlashAttention は Q・K・V をタイル (ブロック) に分割します。Q のブロックを 1 つ固定し、K・V のブロックを順番に持ってきて (タイル自体は HBM から読み込む)、そのブロック分の部分的な Attention を SRAM (SBUF) 上で完結させ、N×N の中間行列を HBM に書き出しません。全ての K・V ブロックを見終わったら、その Q ブロックの出力が完成します。

# Q ブロックを固定し、K,V ブロックを順に処理
for each Q block:
  O_acc = 0, 統計 (m, ℓ) = 初期値  # m=これまでの最大値, ℓ=指数和 (詳細 6〜7章)
  for each K,V block:
    S_ij = Q_i K_jᵀ / √d  # 小さな部分スコア (ブロック×ブロック)
    O_acc, m, ℓ を更新  # online softmax で補正 (7章)
  O_i = O_acc / ℓ  # 最後に正規化して出力ブロック完成
ここが肝。作るのはブロック×ブロックの小さな部分スコアだけ。これは SRAM に収まるサイズで、使ったらすぐ捨てる。N×N の行列を全体として作ることも、HBM に書き出すことも一度もない。ある瞬間に SRAM に載っているのは処理中の 1 ブロック分 (Q・K・V の各ブロック、部分スコア、出力の途中結果 O_acc、補正用の統計 m・ℓ) だけ。Q ブロックの処理が終わるたびに出力を HBM へ書き出します。N×N を確保しないぶん、HBM 側に追加で要るメモリも統計ぶんの O(N) で済む ― ここが後で効きます (9 章)。

補足: 上のループ順序 (Q 外側・正規化は最後に 1 回) は理解しやすい FlashAttention-2 流です。原論文の FA-1 は K/V が外側・Q が内側で、毎ステップ正規化し直す方式でした。考え方は同じです。

ただし、これには 1 つ難所があります。softmax は「行全体」を見ないと計算できないのに、ブロックごとだと行の一部しか見えない。これをどう解くかが 6〜7 章の online softmax です。

5【体験】タイリングで SRAM に収める

Q ブロックを固定し、K・V ブロックを順に処理する様子を見ます。作られるのは小さな部分スコアだけ ― N×N 全体はどこにも現れません。

Q ブロック (固定中) K,V ブロック (処理中) 計算した部分スコア (SRAM・使い捨て) 作られない (N×N の残り)

左の大きな格子が「本来の N×N スコア行列」。素朴な実装はこれを全部 HBM に作りますが、FlashAttention が実際に触るのはいま光っている小さなブロック 1 つだけです。Q ブロック (橙行) を固定し、K,V ブロック (青列) を左から右へ順に処理。各ブロックは SRAM 上で計算してすぐ捨て、次へ進みます。灰色のマスはこの瞬間にはメモリ上に存在せず、N×N として一度もまとめて実体化・HBM に書き出されることはありません (ループが進むにつれて順に計算されすぐ捨てられるため)。本当に一度も計算せずスキップできるのは、下の補足にある causal mask の対角右ブロックだけです ― N×N のメモリが不要になるのがこの図の要点です。

補足: LLM (decoder) の causal mask 付きでは、対角より右のブロック (未来のトークン) はそもそも計算不要でスキップされ、さらに約半分に減ります。上図は分かりやすさのため非因果 (全ブロック処理) で描いています。

補足: 実際の NKI では、タイルのサイズはこの図のように自由には選べず、partition ≤ 128 などハードウェアの制約で決まります (次回)。

6難所 ― softmax は「全体」が要る

タイルに切ると当然ぶつかる壁。softmax の定義を思い出すと分かります。

softmax は行ごとに、こう計算します。

# 行 x = (x₁, ..., xₙ) の softmax
m = maxᵢ xᵢ  ← 行全体の最大値 (数値安定化のため引く)
ℓ = ∑ᵢ exp(xᵢ − m)  ← 行全体の指数和
softmaxᵢ = exp(xᵢ − m) / ℓ

問題は、最大値 m も 指数和 ℓ も「行の全要素」を見ないと確定しないこと。ところがタイリングでは、K・V を 1 ブロック処理した時点では行の一部しか見ていません。まだ見ていないブロックに、もっと大きな値があるかもしれない。

素朴にやると破綻する。「行全体を見てから softmax」に戻ると、結局 N×N を全部保持することになり、タイリングの意味が消えます。「行の一部だけ見て、後から来るブロックで訂正する」仕組みが要る ― それが online softmax です。

7Online Softmax ― 走りながら補正する

全体を見なくても正しい softmax を積み上げる。FlashAttention の心臓部です。

発想はシンプルです。「今まで見た範囲での最大値 m と 指数和 ℓ」を持ち歩き、新しいブロックを見るたびに更新する。もし新しいブロックにこれまでより大きい値が出たら、過去に積んだ分を割引して辻褄を合わせます。

  1. 新ブロックの最大値 m_new を見て、全体の最大値を m' = max(m_old, m_new) に更新。
  2. 最大値が上がった分だけ、これまでの指数和 ℓ と出力 O_acc を exp(m_old − m') 倍して割引 (基準が変わったので過去分を揃え直す)。
  3. 新ブロックの寄与を exp(値 − m') で足し込む。
  4. 全ブロック終了後、O_acc / ℓ で正規化 ― これが厳密に正しい softmax の結果。
なぜ正しいと言えるか。softmax は「最大値を引いて指数を取り、和で割る」だけ。基準の最大値 m が途中で変わっても、過去の項を同じ倍率で割り引けば、最初から新しい m で計算したのと数学的に同じになります。だから FlashAttention は近似ではなく厳密 ― 素朴な実装と (丸め誤差を除き) 同じ答えを出します。N×N 全体を保持せず、行ごとに追加で持ち歩く統計は m と ℓ という 2 つの小さな数 (各行 1 個ずつ) だけ (出力アキュムレータ O_acc は元々必要なもの) です。

8【体験】Online Softmax の補正

1 行分の softmax を、ブロックを 1 つずつ見ながら積み上げます。より大きい値が来たとき、走っている最大値 m と和 ℓ がどう補正されるかを見てください。

これまで見たブロック いま見るブロック まだ見ていない

各ブロックを見るたびに、走っている最大値 m と指数和 ℓ が更新されます。新ブロックにこれまでより大きい値が出た瞬間、m が跳ね上がり、過去に積んだ ℓ が割引されて基準が揃うのが見えます。全ブロックを見終わると、最後に ÷ ℓ で正規化した値が、素朴に「行全体で一気に softmax」した答えと一致します ― これが「走りながら補正しても厳密」の証拠です。

補足: 実際の FlashAttention では、途中まで積んだ出力 O_acc も同じ倍率 (exp(m_old−m')) で割り引かれます (7 章)。ここでは仕組みを追いやすいよう softmax の統計 m・ℓ だけを可視化しています。

9メモリ視点のまとめ ― O(N²) → O(N)

FlashAttention が「メモリの何を減らしたか」を数字で締めます。ここが最重要の持ち帰りです。

誤解しやすい点。FlashAttention は計算量 (FLOP) を減らしていません。QKᵀ も AV も相変わらず N² 回のオーダー。むしろ forward では online softmax の掛け直し (リスケーリング) ぶん、わずかに増えます (学習時の backward では、N×N を保存せず作り直す再計算ぶんも増える)。速くなるのは「N×N をメモリに実体化せず、HBM 往復を消した」から。第 2 回の言葉でいえば、メモリ律速だった処理のメモリ移動を潰したのです。HBM アクセス量の N² オーダー自体は残ります (Q ブロックごとに K・V を読み直すため) が、原論文では Θ(N²d²/M) (M は SRAM 容量。Θ は「ちょうどこのオーダー」の意で、ここでは O と同様に読んで問題ありません) ― SRAM が大きくヘッド次元 d が小さいほど削減率が大きく、原論文の GPT-2 設定での実測例では HBM アクセス量が約 40GB から約 4.4GB に減ったと報告されています (Trainium での削減率は実装・構成に依存)。

10まとめ

FlashAttention を一枚に整理します。

論点要点
問題素朴な Attention は N×N のスコア行列を作り HBM に書き出す。長文で O(N²) のメモリが破綻
発想Q・K・V をタイルに分け、ブロック×ブロックの部分計算だけを SRAM 上で行う。N×N を作らない
難所softmax は行全体が要るのに、ブロックでは一部しか見えない
解法online softmax。走っている最大値 m と指数和 ℓ を持ち歩き、大きい値が来たら過去分を割引して補正
厳密性近似ではない。素朴実装と丸め誤差を除き同じ答え
効果追加メモリ O(N²) → O(N)。N×N の HBM 往復がゼロ。メモリの意味で長文でも破綻しない (計算量 O(N²d) 自体は変わらない)
結論。FlashAttention はカーネル融合の到達点です。第 2 回で学んだ「中間結果を HBM に書かず SRAM に留める」を Attention に適用し、N×N という最大の中間行列を丸ごと作らないところまで突き詰めた。鍵の online softmax が「全体を見ないと解けないはずの softmax」を「走りながら補正する」問題に変換したことで、これが可能になりました。計算量は変わらないのに実用性が激変する ― 「重さの正体はメモリ移動だった」という第 2 回のメッセージの、最も鮮やかな実例です。
