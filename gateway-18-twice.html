第 18 章 同じ質問を二度する。見出しが三度ひっくり返った話

この章の 3 行 第 17 章の機構を実際に組んだら、最初にしたのは自分の見出しを否定することだった。そこから 三度ひっくり返った。裁定の有意差 (p=0.035 → p=1.0)、単体候補の支配 (run 1 → run 2 で反転)、 そして frontier 全体。一貫して機能したのは、検査をコードにして他人に攻撃させることだけだった。

1. 機構の最初の仕事は、作者の否定だった

第 17 章で「今日の最適値ではなく、価格が変わっても答えを出し直せる機構を作る」と書いた。組んだ。 候補の部分集合 × エスカレーション先を全列挙し、価格表で採点して、支配されない方針だけ返す。実測行列に かけると、報告済みの数字を厳密に再現した — 停止率 51%、一致時の正答率 90.3%、全体 89.2%、1 件 $0.00441。

そして次の行で、その方針が単体候補 1 つに両軸で負けると出した。

方針精度1 件あたり
安い 3 候補が一致で停止、食い違いは最上位が答える89.2%$0.00441
中級モデル 1 つに全部やらせる89.7%$0.00333

原因は測定ではなく比較の設計だった。すべての表が最上位モデルを「越えるべき相手」に固定し、 「ある精度を最も安く出せる単体候補はどれか」を一度も問っていなかった。その関数はリポジトリに最初から あった。

基準を選ぶことは、答えを選ぶこと 三巡の敵対レビューが同じ数字を読んで同意した。レビュアーは分析をレビューし、最適化器は 選択肢を列挙する。だから機構が見つけて、レビューは見つけられなかった。

2. その訂正も、二度目の測定で崩れた

0.5 ポイント差は、候補自身の答えのブレの中にある。だから同じ設定で行列をもう一度取った。 571 件が両方の run で完全に揃った。反転率は以前の独立な測定とよく一致した。

そして frontier の推奨は、4 つの精度床のうち 2 つで変わった。同じ機構、同じ価格、同じ問題集を 二度聞いただけである。「中級モデル 1 つを使え」も反転した — 精度は両 run で同一の 93.0% なのに、 費用が倍になった。同じプロンプトで出力の中央値が 346 トークンから 698 に増えていた。

反復で消えるものは、推奨ではない 精度が同じで費用が倍になるのは、標本のばらつきではなく候補自身の振る舞いの変化である。 どちらにせよ、二度聞いて残らない推奨は推奨ではない。

3. 検査をモジュールにしたら、レビュアーが検査を壊した

手作業の比較をコードにした。出力はスコアではなく、主張ごとの「生き残ったか」の一覧にした。 有用なのは「この推奨は成立しなかった」であって、安定性を要約した数字ではないからである。

それを二人のレビュアーに攻撃させたら、私の報告を二箇所で壊した。

共有できた item に絞ってから、run 1 を再計算していた

「run 1 が言ったこと」の列は、実際には共有部分集合の上で再計算した値だった。絞り込みだけで run 1 の答えが動くなら、存在しなかった主張の生存を検査していることになる。検査を実装したら、 4 つの床すべてで動いた。したがって「床ごとの最安方針が run 間で違う」という報告は、 反復の効果と絞り込みの効果が分離できていない。

順位の入れ替わりは、そもそも主張の資格がなかった

「不安定さは閾値付近の 1 候補に局在している」と書いた。90.4% 対 91.1% が 92.5% 対 90.7% になった、 という観測に基づいていた。8 候補なら 28 ペアある。対応のある正確検定を要求したら、run 1 の時点で この差は有意でなかった。ノイズが反転したのを、機構として報告していた。

効いた手順はひとつだけ 第 1 の訂正は 1 run から書いた。第 2 の訂正は交絡した比較から書いた。第 3 の訂正は、レビュアー 2 人が 6 つの欠陥を見つけたモジュールから書いた。各層は前より慎重で、各層とも誤っていた。 一貫して機能したのは、検査をコードにして他人に攻撃させることだけである。

4. 停止率は、手に入る中で最も誤解を招く指標

自前サービングのモデルを 9 構成ぶん測って機構に入れたら、別の発見が出た。まず、 「重みを共有する候補は相関する」は偽だった。

ペアの種類答えの不一致中央値
同一重み・構成違い (36 組)2.7% 〜 35.7%31.9%
別モデル (84 組)9.4% 〜 46.3%31.8%

中央値が一致し、同一ファミリーの最上位モデル 2 つ (9.4%) は、同一重みの構成 2 つよりずっと似ていた。 系譜は振る舞いを予測しない。だから相関はペアごとに行列から測り、系譜は「重みの版が変わったら そのペアの統計を無効化する」ためだけに残した。

そして共倒れ率 — 少なくとも一方が誤るとき両方が誤る確率 — で 120 ペアを四分位に分けると、こうなる。

相関の高い組は「より多く止まって、より悪く止まる」 停止率を最適化している人は、逆方向を最適化している。一致時の正答率と相関は −0.791。

5. 一致が何かを選別しているかを言える数字

一致時の正答率からメンバー単体の最良精度を引くと、その quorum が何かをしているかが出る。 実測で +14.8% から +0.9% まで散り、下端はほぼ同一の 2 構成が 97% の問題で止まって何も足していない形 だった。単体が二役を演じている。停止率だけでは本物と区別できない。

そして運用者が実際に感じる数字は誤停止率 — 停止率 × (1 − 一致時の正答率)、つまり 「二度目を見ずに自信をもって誤答を返す頻度」である。同じ精度床で順位が変わる。

精度床 85% を満たす方針メンバー数1 件あたり誤停止率
最安2$0.003068.2%
自信をもった誤答が最少3$0.00385 (1.26 倍)5.3%

26% 多く払うと、自信をもった誤答が 35% 減る。精度だけ見ていると両方 85% なので見えない。 そして 75% 床を満たす方針の誤停止率は 21.1% — 5 件に 1 件を、二度目を見ずに誤って返している。 精度の列は平凡に見える。

7. 自分の計測器の欠陥は、全部同じ方向に出た

この夜、自分のコードに 6 つの欠陥を見つけた。列挙する意味は、方向が揃っていることにある。

8. この章が主張しないこと

ここに出したすべての数字は、特定の知識ベンチマークの特定の fold での単一の run である。 第 2 節が存在する理由がまさにそれで、単一 run の推奨は三度反転した。ペアの不一致率は タスク分布に依存し、31.9% という値が実トラフィックに移るという証拠はない。自前モデルの構成群は まだ二度測っていない。

言えるのは、停止率を指標にするのは危険で、共倒れ率と誤停止率は測れるということ。そして 同じ質問を二度することが、三巡の敵対レビューより多くの誤りを見つけたということである。
