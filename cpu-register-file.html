レジスタファイル ― 読み 2 か所・書き 1 か所を同時に行う小さな記憶

この回の前提: 第 05 回 順序回路と時間、第 06 回 配線とバス

第 05 回のレジスタは 1 個の値を覚えるだけの部品でした。CPU には add rd, rs のように、2 つのレジスタを同時に読んで 1 つのレジスタに書き戻す命令がたくさんあるので、レジスタを 16 本ただ並べるだけでなく、「2 か所同時に読めて、1 か所に書き込める」窓口をまとめて 1 つの部品にする必要があります。これがレジスタファイルです。rj32 の dig/regfile.dig を読むと、Digital が用意している RegisterFile という部品をそのまま使っていて、読み出しと書き込みの間に隠れた約束があることが分かります。結論を先に言うと、レジスタファイルの設計で一番迷うのは本数や幅ではなく、「同じアドレスを同時に読み書きしたら、新しい値と古い値のどちらが見えるか」という約束の方です。

1. レジスタファイルとは何か ― 小さな共有メモリ

rj32 には 16 本のレジスタがあり (第 10 回で詳しく扱う ISA の話にもつながります)、各本は 16 ビットです。この 16 本をひとまとめにして、アドレスで選んで読み書きできる部品にしたのがレジスタファイルです。rj32 の dig/regfile.dig を見ると、Digital の組み込み部品である RegisterFile がそのまま使われていて、属性は Bits=16 (1 本の幅)・AddrBits=4 (4 ビットのアドレスで 2^4 = 16 本を選べる) となっています。レジスタファイルは「アドレス機能を持つ、複数本のレジスタの集合」と考えると分かりやすく、第 09 回で扱う RAM とよく似た構造を持ちますが、ポートの数が違います。

図: 16 本の 16 ビットレジスタを、4 ビットのアドレスで選べる 1 つの部品にまとめたのがレジスタファイル。

2. ポート構成 ― 読み 2 か所・書き 1 か所

Digital の RegisterFile 部品は、入力に Din (書き込むデータ)・we (書き込み許可)・Rw (書き込み先のアドレス)・C (クロック)・Ra・Rb (読み出す 2 つのアドレス) を持ち、出力に Da・Db (それぞれ Ra・Rb が指すレジスタの値) を持ちます。rj32 の dig/regfile.dig ではこれらに wrval・wr・rd・clock・rs という名前を付け、出力を rdval・rsval と呼んでいます。add rd, rs のような命令は、rd を左オペランドの読み出しアドレスと書き込み先の両方に使い、rs を右オペランドの読み出しアドレスに使うので、2 読み 1 書きという構成がちょうど合います。

図: rd は書き込み先と左オペランドの読み出しの両方に使われ、rs は右オペランドの読み出しに使われる。

3. 書き込みはクロックの立ち上がりだけ、読み出しはいつも今のアドレス

Digital の RegisterFile.java を読むと、書き込みと読み出しの扱いが非対称になっていることが分かります。書き込みは we が 1 かつクロックが立ち上がった瞬間だけ行われる、第 05 回で見た「クロックの立ち上がりで確定する」という約束に従う操作です。一方、読み出しの出力 Da・Db は、Ra・Rb が指すアドレスの内容をそのクロックのタイミングで都度読み直す動作で、アドレスを変えればすぐに別のレジスタの値が出てきます。

図: 書き込みはクロックの立ち上がりという特別な瞬間に限られるが、読み出しはアドレスが示す値を常に反映する。

4. 同じアドレスを同時に読み書きすると、どちらの値が見えるか

add rd, rs のような命令は、rd を読み出しアドレスにも書き込みアドレスにも使います。ここで疑問になるのが「同じクロックの瞬間に、同じアドレスへの書き込みと読み出しが重なったら、新しい値と古い値のどちらが見えるか」です。この約束には主に 2 つの方式があります。write-first (書き込み優先) は、同じアドレスなら書き込んだ新しい値がその場で読み出しにも反映される方式、read-first (読み出し優先) は、読み出しは書き込み前の古い値を返す方式です。Digital の RegisterFile.java を読むと、クロックの立ち上がりで先に memory.setData() を実行してから Da・Db を計算しているため、write-first の挙動になっています。

図: Digital の RegisterFile は write-first。同じアドレスへの読み書きが重なると、新しい値が読み出し側にも見える。

5. rj32 には「ゼロレジスタ」が無い

MIPS の $zero や RISC-V の x0 のように、常に 0 を返すよう固定された「ゼロレジスタ」を持つ ISA があります。これがあると、定数 0 を使う処理や「2 つのレジスタが等しいか」の比較が、特別な命令なしで素直に書けて便利です。しかし rj32 の instructions.md を見ると「16 本のレジスタのうち、特別な機能を持つのは r0 だけで、他のレジスタは自由に使える」と説明されており、その r0 の特別な機能は「読むと必ず 0 になる」ことではありません。call 命令が戻り先のアドレスを必ず r0 に書き込むという、書き込み先が固定されているという意味での特別扱いです。つまり rj32 にはゼロレジスタが無く、r0 は読み出しでは普通のレジスタと同じように振る舞います。

図: rj32 の r0 はゼロレジスタではなく、call 命令の書き込み先として固定されているだけ。

6. rj32 のレジスタ一覧と呼び出し規約

instructions.md には 16 本のレジスタの別名と、関数呼び出しでの使い方の慣習が表になっています。r0 (ra, 戻り先アドレス)、r1・r2 (a0・a1, 引数と戻り値)、r3〜r7 (s0〜s4, 呼び出し先で保存される callee-saved レジスタ)、r8〜r13 (t0〜t5, 呼び出し元が保存する caller-saved 一時レジスタ)、r14 (bp, データのベースポインタ)、r15 (sp, スタックポインタ) という割り当てです。これらはハードウェアが強制する区分ではなく、アセンブラとプログラムを書く人が守る「約束 (呼び出し規約)」です。

図: 16 本のレジスタは、ハードウェアの制約ではなく呼び出し規約という約束で役割分担されている。

7. 実装のポイント

read-first か write-first かを最初に決める。 同じアドレスへの読み書きが重なる場面 (まさに add rd, rs のような rd が読みと書きの両方になる命令) は必ず出てくるので、どちらの値が見えるかを後回しにすると、パイプライン (第 15 回) を導入したときに想定外のバグになります。Digital の RegisterFile は write-first と決まっているので、それを前提にデータパスを組みます。

ポート数は命令形式から逆算する。 rj32 の多くの命令は rd・rs の 2 オペランドなので、読み出し 2 ・書き込み 1 で足ります。3 オペランドの命令セットを作るなら、読み出しポートを 3 つに増やす必要があり、レジスタファイルの配線は読み出しポートの数に比例して増えます。

ゼロレジスタを入れるかどうかは、ハードウェアとソフトウェアのトレードオフ。 ゼロレジスタがあれば定数 0 の扱いや比較が楽になりますが、1 本のレジスタの実質的な本数を 1 つ減らすことになります。rj32 は 32 命令という小さな ISA の中で、ゼロレジスタを採用せず、全 16 本を汎用レジスタとして使う設計を選んでいます。

図: レジスタファイルの設計で判断が必要な 3 つの点。
