公開されている Jev 系を、同じ問題で並べる
短い読解では誰も学習なしに勝たない。長い文脈では Decider、採点型では学習済みが上

この章の結論。公開されている Jev 系の Kev-9B と Decider-4B を、第 48 章と同じ問題と、Kev の評価セット (764 件。Lux の論文は学習に使っていないとしている) に通しました。 学習なしの Prismyra の読み出しと比べると、短い読解 (RACE) では学習済みの 3 つ (Lux・Kev・Decider) のどれも上回らず、Kev は有意に下でした。 一方で長い文脈に埋めると Decider が学習なしより有意に上 (約 1 万トークンで +7.0 ポイント) になりました (Lux は点推定で上、Kev は同じ)。Kev の評価セットでは学習済みの 3 つがそろって +3〜5 ポイント上でした。

ただし差の多くはどの問題で学習したかと重なっています。Decider は RACE の train 分割で学習していて、Kev の評価セットは Kev 自身の開発用のセットです。 学習済みの 3 つの間は、RACE で Kev が Lux より有意に低い (−2.6 [−4.6, −0.7]) ほかは、区別できませんでした。

3. Kev の評価セットでは、学習済みが揃って上

Kev の evals/v4/transfer-v4/test.jsonl (HF の jaredpalmer/kev-suites と同じ、764 件) は System One の形そのままで配られていて、Decision の論文は「学習に使っていない」と書いています。ただしこれは Lux についての申告で、Kev にとっては自分の開発用のセット、Decider については学習データの名前を照合しただけです。 MMLU・SciQ・感情分類・攻撃的な投稿の判定・言い換えの判定・QNLI と、規則を組み合わせる問題・締め切りや権限の対比問題が入っています。これを加工せずに全員のサーバに送りました。

学習済みの 3 つは、そろって学習なしより有意に上でした。3 つの間の差 (Lux − Kev −1.1 [−3.7, +1.6] など) は区別できません。 ただし中身を分けると、Lux の優位のかなりの部分は 40 件の Score (段階で採点する型) から来ていて、それを除くと区間が 0 を含みます。 Kev は Score を除いても残りますが、これは Kev が自分の評価用に作ったセットなので、開発中にこのセットを見て選んだ分の有利がある可能性があります。

[注意] 学習なしの読み出しを不利にしていないかを確かめた。 私の変換は、選択肢を「A. 名前: 説明」の形で並べて文字の確率を読みます。Score では名前が「0」「1」「2」なので、外側の文字と内側の番号が混ざって不利かもしれません。 そこで「A. 説明」だけの形に替えて全 764 件を測り直すと、全体は 77.8% (元の 79.3% より低い)、Score は 65.0% (元の 62.5%) でした。この書式替えでは差は縮まりませんでした。ほかの書式の影響は確かめていません。

第 48 章 (RACE) と合わせると、見えてきた形はこうです。学習済みの決定モデルは、短い読解では学習なしを上回らない。長い文脈では Decider が上回り (Lux は点推定で上、Kev は同じ)、Kev の評価セットでは 3 つとも上回る。 ただし型ごとの数はまだ少なく (Score は 40 件)、「読解には効かない」とまで一般化はできません。

4. 速さは、モデルより作り方で決まる

ここで分かった大事なことは、速さが「どういう設定で動かしたか」に強く依存することです。 Kev は、リクエストをまたいで状態を覚えておく仕組み (KEV_PREFIX_CACHE) を切ると、64 問で 9.9 秒かかりました (1 問 129 ms・16 問 2.4 秒で、Lux の同梱の実装とほぼ同じ伸び方)。 同じリクエストの中で状態を共有する処理が、この仕組みの経路 (probs_and_prefix) にしか付いていないためと読めます (kev/serve.py の probs)。逆に、同じ文書を繰り返し送るとその仕組みが効き、64 問で 0.9 秒でした。 だから上の数字は「このモデルの速さ」ではなく、「この構成での、初めて見る文書 1 件の速さ」です。

まだ言えないこと

  • すべて 1 回の実行です。長い文脈の比較は 40 記事だけで、区間が広くなっています。
  • Decider の長い文脈での強さが、学習の仕方によるのか、RACE の train 分割で学習したことによるのかは分けていません。
  • Kev の評価セットは Kev 自身の開発用なので、Kev に有利な可能性があります。Decider の学習データとの重なりは、名前の照合しかしていません。
  • Lux の 9B と Decider の 4B は大きさが違い、4B の方が同等以上でした。同じ大きさでの比較はしていません。
