動的最適性 ― 一本の木であらゆる操作列に強くなれるか

スプレー木と「点集合」という幾何的な見方から、二分探索木の上限と下限を見る

← MIT 6.851 シリーズ目次へ ← コーディング基礎 シリーズ目次へ

二分探索木 (BST) は O(log n) で検索できる、というのは教科書の最初の章で学ぶ話です。しかし 「同じ木のアルゴリズムが、どんな検索列 (アクセス列) に対しても、その列に対して後から考えられる最良の木と比べて定数倍以内で済むか」 という問いには、2026 年現在も完全な答えが出ていません。この回では、この「動的最適性 (dynamic optimality)」という未解決問題を、MIT 6.851 (Erik Demaine, 2012 年春) の講義ノートに忠実に辿ります。登場するのは 1985 年に提案されたまま証明も反証もされていない スプレー木、そして二分探索木の実行を 2 次元平面上の点集合として眺める 2009 年の幾何的な見方です。デモでは実際にスプレー木へアクセス列を流し込み、その実行がちょうどこの点集合の理論と一致することを自分の目で確認できます。

この回の位置づけ

平衡二分探索木 (AVL 木や赤黒木) は「どんな検索列が来ても 1 回あたり O(log n)」を保証します。これは最悪ケースの保証であり、裏を返せば「検索列にクセがあって得をできる場面」を一切利用しません。たとえば同じキーばかり検索される列なら、そのキーを根に置いた木は 1 回あたり定数時間で済むはずです。動的最適性とは、どんな検索列が来ても、後からその列だけを見て選べる最良の木の実行に定数倍以内で近づける、単一のオンラインアルゴリズムは存在するかという問いです。

この問いを厳密に扱うには、CS 専攻でないと馴染みの薄い道具がいくつか必要です。具体的には、(1) 操作列全体でコストを均して評価する償却計算量 (amortized complexity) とその証明手段であるポテンシャル法、(2) ポインタだけで木を操作するポインタマシンという計算モデル、(3) 比較だけで木を作るとき深さがどこまで縮められるかという下限の議論です。先に手早く補習します。

前提の補習

償却計算量 (ならし計算量) とポテンシャル法

償却計算量 (amortized complexity, ならし計算量) とは、「1 回だけ見ると高くつく操作があっても、操作を $m$ 回繰り返したときの合計コストを $m$ で割った平均は低く抑えられる」という考え方です。たとえば動的配列への push_back は、容量が尽きたときに $O(n)$ かけて再割り当てしますが、再割り当て 1 回のあとは次の再割り当てまでに $n$ 回の安い push_back ($O(1)$) を挟めるので、ならすと 1 回あたり $O(1)$ になります。

この「ならし」を厳密に証明する標準的な道具がポテンシャル法 (potential method) です。データ構造の状態 $D$ に対して「蓄えられた信用」を表す関数 $\Phi(D) \ge 0$ を 1 つ決め、操作 $i$ の実際のコストを $c_i$、操作前後のポテンシャルを $\Phi_{i-1}, \Phi_i$ とすると、償却コストを

$$\hat{a}_i = c_i + \Phi(D_i) - \Phi(D_{i-1})$$

と定義します。この $\hat{a}_i$ を全操作について足すと、途中の $\Phi$ は望遠鏡式にすべて打ち消し合い、$$\sum_i c_i = \sum_i \hat{a}_i + \Phi(D_0) - \Phi(D_m)$$ が成り立ちます。$\Phi(D_0)=0$ かつ $\Phi(D_m)\ge 0$ なら、償却コストの合計は実際のコストの合計以上になるので、「どの操作の償却コストも小さい」と示せれば、合計の実コストにも同じ上限が付けられます。スプレー木の解析でよく使われるのは $\Phi(D) = \sum_v \log(\text{サイズ}(v))$ のような「木の形の乱れ」を測る関数で、1 回のアクセスで高くつく回転の分だけポテンシャルが大きく減ることを示して償却 $O(\log n)$ を導きます (この講義ノート自身はポテンシャル関数の式を明示しませんが、下で出てくる「償却 $O(1)$」「償却 $O(\log t_i)$」といった主張はすべてこの手法で証明されています)。

ポインタマシンという計算モデル

配列を使う「word RAM」モデルでは A[i] に単位時間でアクセスできますが、ポインタマシン (pointer machine) モデルでは配列添字という概念自体がなく、ノードが持つポインタを辿ることしかできません。この講義で定義する「BST モデル」はポインタマシンの部分集合で、できる操作は「左の子へ歩く」「右の子へ歩く」「親へ歩く」「ノードを回転する」の 4 つだけです。配列の二分探索のように添字 mid を計算して飛ぶことはできません。

比較ベースの木の深さの下限

$n$ 個のキーをどんな形の二分木に入れても、ノード数は深さ $d$ まででも高々 $2^{d+1}-1$ 個なので、$n$ 個を収めるには深さ $d \ge \log_2 n - 1$ が必要です ($\Omega(\log n)$)。したがって「一番深いノードだけを毎回聞いてくる」意地悪な検索列に対しては、どんな木を使っても 1 回あたり $\Omega(\log n)$ はかかります。これは後で「動的最適性は最悪ケース保証の話ではない」と区別するときの出発点になります。

1. 二分探索木をモデルとして定義する (L05)

「最善の BST はあるか」を厳密に問うには、BST でできる操作を厳密に決めておく必要があります。この講義では BST をポインタマシンの部分集合として定義します。各キーは親へのポインタ (根なら無し) と左右の子へのポインタ (無ければ null) を持ち、左の子のキー $\le$ 自分のキー $\le$ 右の子のキー、という通常の BST の順序を保ちます。許される単位コスト操作は次の 4 つだけです。

  • 左の子へ歩く
  • 右の子へ歩く
  • 親へ歩く
  • あるノード $x$ を回転する

最初の 3 つは「今どのノードを指しているか」というポインタを動かすだけで、木そのものは変えません。最後の回転だけが木の形を変える操作です。回転は、あるノード $x$ とその親 $p$ の間で行い、$x$ を一段上げます。

rotate(x) →

図: $x$ を回転すると $x$ が親 $p$ の位置に上がり、$b$ (元は $x$ の右の子) が $p$ の左の子に移る。キーの大小順 ($a \le x \le b \le p \le c$) はつねに保たれる。

このモデルは Search(x) 1 種類のクエリを支えます。根から出発し、上の操作だけを使って、必ずどこかで $x$ を持つノードを訪れればよい、というクエリです。この 2 回の講義では簡単化のため、検索は常に成功する (キーは必ず木の中にある) ものとし、挿入・削除は考えません。

2. $O(\log n)$ は最善か ― 問いの立て方を変える

AVL 木や赤黒木のような自己平衡 BST は 1 回の検索を $O(\log n)$ でこなします。$n$ 個のキーをどんな形の二分木に収めても深さは $\Omega(\log n)$ になるので、「一番深いキーだけを毎回聞いてくる」意地悪な検索列に対しては、最悪ケースでは $O(\log n)$ が最善です。しかし講義はここで問いを変えます。1 回の検索ではなく、検索列 $x_1, x_2, \dots, x_m$ 全体の合計コストで比べたら、特定の列に対してはもっと速くできる木があるのではないか。 たとえば $x_1 = x_2 = \cdots = x_m = X$ のように同じキーばかり聞かれる列なら、$X$ を根に置く木は 1 回あたり定数時間で済みます。平衡木はこの「列ごとのクセ」を一切利用しません。

3. 検索列のクセを捉える性質のはしご

「このアルゴリズムは列のクセにどれだけ適応できるか」を測るため、講義は強さの異なる性質を順に定義します。どれも償却で述べられており、個々の検索が高くつくことはあっても、列全体で均せば主張が成り立てばよい、という意味です。

Sequential Access Property (順次アクセス性)

検索列が $1, 2, \dots, n$ とキー順にすべて 1 回ずつ並んでいるとき、償却 $O(1)$ で全部こなせる 定義として要求 という性質です。配列の通りがけ順 (in-order) 走査が $O(n)$ でできることを考えれば直感的には易しそうですが、この BST モデルでは検索は必ず根から始まる約束なので、「最後に見たキーから出発する」操作は根までの回転でシミュレートする必要があり、講義では証明は省略されています。

Dynamic Finger Property (動的フィンガー性)

検索列 $x_1,\dots,x_m$ に対して、$k$ 番目の検索の償却コストが $O(|x_k - x_{k-1}|)$ になる性質です。Sequential Access Property の一般化で、「直前に見たキーと値が近いキーを聞かれたら安い」ということを言っています。BST モデルでは達成がやや難しいものの、各段に隣接ノード同士のポインタを張ったレベルリンク木を使えば、より一般的なポインタマシンでは容易に達成できます。

Static Optimality / エントロピー下限 (静的最適性)

入力列でキー $k$ が $p_k$ の割合で出現するとき、償却アクセス時間が

$$O\left(\sum_{k=1}^{n} p_k \log \frac{1}{p_k}\right)$$

に収まる性質です。これは静的な木 (操作列を見てから決めた、以後変更しない 1 本の木) が達成できる償却アクセス時間の情報理論的な下限そのもので、だから「静的最適性」と呼ばれます。$\sum_k p_k \log(1/p_k)$ は情報理論でキー $k$ を表す符号の平均長 (エントロピー) と同じ形をしていて、頻度の高いキーほど根に近く置けば短い符号 (浅い深さ) で表せる、という直感に対応します。

Working Set Property (ワーキングセット性)

$x_i$ の検索時に、直前に $x_i$ がアクセスされてから今回までに $t_i$ 個の異なるキーがアクセスされていたとすると、償却 $O(\log t_i)$ で済む性質です。「最近触ったキーはもう一度触るのが速い」という主張で、証明は省略されていますが Working Set Property は Static Optimality を含意します (ある部分列で少数のキーが頻繁に出現するなら、ワーキングセット性はそれらへのアクセスを確実に速くするからです)。

Unified Property (統一性) BST では未解決

$x_i$ と $x_j$ ($i\lt j$) の間に $t_{i,j}$ 個の異なるキーがアクセスされたとすると、検索 $x_j$ のコストが

$$O\Big(\min_{i\lt j} \log\big(|x_i - x_j| + t_{i,j} + 2\big)\Big)$$

に収まる性質です。Working Set Property と Dynamic Finger Property の両方を一般化し、両方を含意します。「最近触ったか、空間的に近いか、どちらかの意味で近いキーなら安い」という最も強い適応性の主張です。この性質を満たす BST が存在するかどうかは未解決です。ポインタマシン全体ならこの性質を達成するデータ構造が知られていますが、BST では加法的に $O(\log\log n)$ 余計にかかるものが最善として知られています。

図: 矢印は「含意する (より強い)」方向。Unified Property が頂点にあり、未解決のまま最も強い性質として残っている。

4. 動的最適性 (Dynamic Optimality) の定義

ある BST アルゴリズムが動的最適であるとは、どんな検索列に対しても、そのアルゴリズムの総コストが、その列だけを見てから選べる最良の (オフラインの) BST アルゴリズムのコストの定数倍以内に収まることです。「オフライン最適」とは、列が分かったうえで最小コストになるよう木の作り方・回転のタイミングまで事後に選べる、理想化されたアルゴリズムのコストです。動的最適性は オンラインアルゴリズムがオフライン最適に対して $O(1)$-競合的 (competitive) であることを要求する、非常に強い主張です。

未解決問題。 オンラインで動的最適な BST アルゴリズムは存在するか。オンラインで動的最適なポインタマシンのアルゴリズムは存在するか (オフライン最良の BST、あるいはオフライン最良のポインタマシンのどちらと比べても)。どちらも分かっていません。 現在知られている最善は、次節で見る $O(\log\log n)$-競合的なオンラインアルゴリズム (Tango 木) です。動的最適だろうと予想されている候補もありますが、証明は誰も持っていません。

5. スプレー木 ― zig-zig と zig-zag

スプレー木は Sleator と Tarjan が 1985 年に提案した BST です。キー $x$ を検索するときは、根から普通に下まで降りて $x$ に到達したあと、$x$ を根まで引き上げるという後処理 (スプレー) を行います。引き上げ方には 2 種類あり、$x$ が親 $p$ の子でさらに $p$ が祖父 $g$ の子である場合は zig-zig、$x$ と $p$ が $g$ から見て左右で向きが違う場合は zig-zag を使います。

zig-zig: $g \to p \to v$ が同じ向きに連なっている場合

rotate(p); rotate(v) →

図: zig-zig は「$p$ を回転してから $v$ を回転する」の 2 段階。単純に $v$ を 2 回回転させる (move-to-root) のとは違う動きになるのがポイント。

zig-zag ($v$ が $p$ の片側、$p$ が $g$ の反対側の子になっている場合) では $v$ を 2 回連続で回転します。$v$ が根に達するか、根の子になるまでこれを繰り返し、根の子になった時点では最後に 1 回だけ単純な回転をして終えます。スプレー木が「move-to-root (単純に $v$ を毎回 2 回回転するだけ)」と違うのは、zig-zig の存在そのものです。$p$ を先に回転するこの一手間が、償却 $O(\log n)$ を成り立たせる鍵になります。

Working Set Property証明済み Sleator & Tarjan (1985)

つまりスプレー木は、このはしごのうちかなり上の段まで実際に証明された性質を持ちながら、肝心の頂点である動的最適性だけは 40 年近く未解決のままです。

6. 幾何的な見方 ― アクセス列を点集合として描く (L06)

ここからは 2009 年の論文 (Demaine, Harmon, Iacono, Kane, Pătraşcu, The geometry of binary search trees) に基づく見方です。キー集合を $\{1,\dots,n\}$ とし、アクセス列 $x_1,\dots,x_m$ が与えられたとき、$i$ 回目に $x_i$ を検索したという事実を、座標 $(x_i, i)$ の点として描きます。横軸がキー (空間)、縦軸が時刻です。

どんな BST アルゴリズムで検索を実行しても、根から $x_i$ までの経路上のノードは必ず触れます (そうしないと $x_i$ に辿り着けない)。そこで「時刻 $t$ に触れたキー $y$」をすべて点 $(y,t)$ として描くと、1 回の検索がだいたい何ノード触れたか (=コスト) は、その時刻の行にある点の個数で測れます。1 回の検索で同じノードに定数回より多く触る理由は普通ないので、点の総数は BST の総コストと定数倍の違いしかありません。

図: 1 回目 (t=1) は 3 だけに触れる。2 回目は 3→1 の経路で {3,1}。3 回目は 3→4 で {3,4}。4 回目は 3→1→2 で {3,1,2}。この点集合がそのまま「この木でこの列を実行したコスト」を表す。

定義 (arborally satisfied, 木として充足された点集合)。 ある点集合が「arborally satisfied」であるとは、同じ横線・同じ縦線に乗らない任意の 2 点について、その 2 点が張る長方形 (内部または境界) の中に別の点が存在することです。上の図の点集合はこの条件を満たしています。

定理。 点 $(x_i, i)$ からなる点集合が arborally satisfied であることと、それがある BST アルゴリズムによる入力列 $x_1,\dots,x_m$ の有効な実行 (=そのアルゴリズムが各時刻に触れたノードの集合) に対応することは同値です。

系。 したがって、最適な BST 実行は、入力の点を含む「最小の arborally satisfied 点集合」を見つける問題と同値です。

未解決問題。 最小の arborally satisfied 点集合を見つける計算の複雑さは分かっていません。$O(1)$ 近似アルゴリズムは存在するのでしょうか。

証明の方向性は 2 つあります。(1) 任意の有効な BST 実行の点集合が arborally satisfied であること: 点 $(x,i)$, $(y,j)$ ($x\lt y$, $i\lt j$) を取ると、時刻 $i$ 直前の $x,y$ の最小共通祖先 (LCA) が $x$ 自身でなければその LCA が長方形の中の点になり、時刻 $j$ 直前の LCA が $y$ 自身でなければ同様、どちらでもなければ $x$ と $y$ は互いに祖先関係にあり、どこかの時刻 $k$ で $y$ が $x$ の上に回転されたはずなので $(y,k)$ が長方形の中に入ります。(2) 逆に、arborally satisfied な点集合から有効な BST 実行を作れること: 各ノードを「次に触れる時刻」でヒープ順に並べた treap として組み立て、触れた部分が常に連結な部分木になることを使って構成できます。

7. Greedy アルゴリズムとオンライン化

最小の arborally satisfied 点集合を近似する単純な方法が greedy アルゴリズムです。点集合を時刻の行ごとに 1 行ずつ処理し、今の行までで条件を満たすために必要な点をそのつど追加していきます。このアルゴリズムが最適 (Opt) の定数倍、あるいは Opt + O(m) で済むことが予想されていますが、証明はされていません。

定理。 オンラインで動く arborally satisfied 点集合アルゴリズムがあれば、それを $O(1)$ の定数倍遅いだけのオンライン BST アルゴリズムに変換できます。証明の骨格は、1 回のアクセスで触れたノードを split tree (ノードを根に持ち上げてから切り離すのを償却 $O(1)$ でできる構造) に保持し、親の木を「直前に触れたノードで順序づけた treap」として組み直すことで、前後 (predecessor/successor) のノードへの参照を効率よく更新しながら、arborally satisfied 点集合アルゴリズムの判断を定数倍の遅さでシミュレートする、というものです。

系。 もし greedy アルゴリズムが本当に $O(\mathrm{Opt})$ であると証明されたなら、この変換と合わせて動的最適性そのものが解決します。これがこの分野で greedy アルゴリズムが特別な注目を集めている理由です。

8. Independent Rectangle 法で下限を作る

ここまでは上限 (アルゴリズム) の話でした。ここからは下限 (どんな BST でもこれより速くはできない) を証明する道具です。2 点 $a,b$ を結ぶ直線の傾きが正なら、その 2 点が張る長方形を plus-rectangle (プラス長方形、スラッシュ「/」型)、傾きが負なら minus-rectangle (マイナス長方形、バックスラッシュ「\」型) と呼びます。

定義 (独立な長方形の組)。 2 つの長方形 $ab$ と $cd$ が「独立」であるとは、(i) どちらも充足されておらず (中に別の点が無い)、かつ (ii) どちらの長方形の角も、もう一方の長方形の内部に厳密に入っていないことです。

plus-rectangle (傾き正, 「/」)

minus-rectangle (傾き負, 「\」)

図: 2 点を結ぶ直線の傾きの符号で長方形を 2 種類に分ける。独立性の判定はこの符号を揃えた長方形どうしで考える。

点集合 $P$ に対して $\mathrm{OPT}$ を「$P$ を含む最小の arborally satisfied 超集合」、$\mathrm{MAXIND}$ を「$P$ が定義する長方形の中で取れる独立な長方形の最大個数」とすると、次が成り立ちます。

$$\mathrm{OPT} \ge |\text{input}| + \tfrac{1}{2}\,\mathrm{MAXIND}$$

証明は、符号を plus 側だけに絞った補題から組み立てます。plus-rectangle だけがすべて充足されている状態を「plus-satisfied」と呼び、$\mathrm{OPT}^+$ をその最小超集合、$\mathrm{MAXIND}^+$ を plus-rectangle だけで取れる独立集合の最大個数とすると、$\mathrm{OPT}^+ \ge |\text{input}| + \mathrm{MAXIND}^+$ が成り立ちます。証明の骨格は課金論法です。独立な plus-rectangle の中で最も幅の広いものを $ab$ とし、それと交わる他の長方形を「$a$ を共有」「$b$ を共有」「どちらも共有しない」の 3 種に分けると、独立性より「$a$ 共有」は左に、「$b$ 共有」は右に集まり、その間に点を持たない縦の切れ目 $v$ が必ず取れます。$v$ の左で最も右上にある点 $p$、右で最も左下にある点 $q$ を取ると、$pq$ はちょうど水平になる (そうでなければ $pq$ が新しい plus-rectangle を作り、その中に点が無ければ充足条件に反する) ことが示せます。この水平な $pq$ に $ab$ の分を課金し、同じ組 $(p,q)$ が二度課金されないことから、水平線上の点の個数が独立長方形の個数以上必要だと分かります。これを両方の符号について行い、$\mathrm{OPT} \ge \max(\mathrm{OPT}^+,\mathrm{OPT}^-) \ge \tfrac12(\mathrm{OPT}^++\mathrm{OPT}^-) \ge |\text{input}| + \tfrac12 \mathrm{MAXIND}$ と平均を取ると定理が出ます。

BST の実行と arborally satisfied 点集合が同値だったことを思い出すと、これはそのまま BST の性能の下限になります。「この入力列にはこれだけの独立長方形が取れる」と示せれば、どんな BST でもそれ以上の点を触らざるを得ない、ということです。

9. Wilber の下限と key-independent optimality

Wilber の第 2 下限

入力の点集合の各点 $p$ について、$p$ より下にあって「直交的に見える」点 (= $p$ とその点を結ぶ長方形の中に他の点が無い点) をすべて集め、高さで並べたとき、$p$ から見て左右のどちら側にあるかが何回入れ替わるか (アルテネーション数) を数えます。これを全ての点 $p$ について合計したものが Wilber の第 2 下限 (Wilber2) です。アルテネーションが起きるごとに、符号の異なる独立長方形を 1 つ追加できる、というのが証明の骨格です。

未解決問題。 $\mathrm{OPT} = \Theta(\mathrm{Wilber2})$ かどうかは分かっていません。

Key-independent optimality (キーに依存しない最適性)

キーの値そのものに意味がない (ランダムに並べ替えても困らない) 場合を考えます。このとき $\mathbb{E}[\mathrm{OPT}]$ はちょうど working-set 下限と同じ大きさになることが分かっており、したがってスプレー木はキーに依存しない意味で最適だと言えます。証明の要は、ランダムな置換のもとでは $\mathbb{E}[\mathrm{Wilber2}(x_i)] = \Theta(\log t_i)$ になることです。

Wilber の第 1 下限とビット反転列

入力のキーを根に持つ「下限用の木」$P$ を 1 本固定します。$P$ の各ノード $y$ について、アクセス列 $x_1,\dots,x_n$ の中で「$y$ の左部分木へのアクセス」と「$y$ の右部分木へのアクセス」が交互に切り替わる回数 ($y$ やその外へのアクセスは無視) を数え、全ノードについて合計したものが Wilber の第 1 下限 (Wilber1) です。交替が起きるたびに独立長方形が 1 つ追加できる、というのが証明の骨格です。

例: ビット反転列。 $0,1,2,3,\dots$ を 2 進数で書いて、桁を逆順に並べ替えると $0,4,2,6,1,5,3,7,\dots$ という列ができます。これを完全二分木への検索列として使うと、各ノード $y$ のアルテネーション数はちょうど $y$ を根とする部分木のサイズに一致し、

$$\mathrm{Wilber1} = \Theta(n \log n) \;\Rightarrow\; \mathrm{OPT} = \Theta(n \log n)$$

が成り立ちます。これは「どんな木を使っても、この列には平均 $\Theta(\log n)$ かかる」という具体的な下限の実例です。

未解決問題。 すべてのアクセス列に対して、$\mathrm{OPT} = \Theta(\mathrm{Wilber1})$ となる下限用の木 $P$ を選べるかどうかは分かっていません。

10. Tango 木 ― $O(\log\log n)$-競合的な BST

Tango 木 (Demaine, Harmon, Iacono, Pătraşcu, 2004) は、現在知られている中で最良の競合比 ($O(\log\log n)$) を持つ BST です。これは平衡木が達成する $O(\log n)$ 競合比からの大きな前進です。走行時間は Wilber の第 1 下限より $O(\log\log n)$ 倍だけ高く、裏を返せばこれは「Wilber1 が本当の $\mathrm{OPT}$ からどれだけ離れうるか」の上限にもなっています。実際、下限用の木 $P$ を列を見る前に固定しなければならない (オンラインアルゴリズムは必ずそうする) なら、Wilber1 は $\mathrm{OPT}$ から $\Omega(\log\log n)$ 離れうることが分かっており、この手法ではこれ以上は改善できません。

仕組みは、完全二分木 $P$ を $O(\log n)$ サイズの補助木 (auxiliary tree) の集まりに分割することです。各ノード $y$ に「最後にアクセスがあった側の子」を preferred child (優先子) と呼び、優先子どうしを繋いだ鎖を preferred path (優先パス) と呼びます。1 回のアクセスでは、根から目的のキーまでの経路上にある複数のノードで優先子が切り替わることがあり、その切り替え 1 回ずつが Wilber1 のアルテネーション 1 回分に対応します。この 1 回のアクセスで起きる切り替えの総数が、次に出てくる「跨ぐ補助木の本数 $k$」を決めます。

図: 各ノードは直近にアクセスのあった子 (優先子) を持ち、優先子どうしを繋いだ太線が 1 本の優先パスを作る。

各優先パスは、深さ順ではなくキーの昇順で並べた、サイズ $O(\log n)$ の平衡二分木 (補助木) に格納します。$P$ の高さが $\log n$ なので補助木のサイズは $\log n$ 以下、1 本の補助木内の検索は $O(\log\log n)$ です。1 回のクエリで $k$ 本の補助木を跨ぐ必要があれば、合計 $O(k\log\log n)$ かかります。ここで $k = 1 + (\text{このアクセスで Wilber1 が増えた分})$ なので、Wilber1 の増分と比例した追加コストで済み、全体の競合比が従います。

優先パスが切り替わるたびに補助木を更新する必要があります。深さ $d$ より下にあるパスは、キーの区間 $[\min,\max]$ にちょうど対応するので、「深さ $d$ より下を切り離す」操作はキーの昇順でのある区間を切り出す split に、新しいパスを付け足す操作は concatenate に対応します。パスの根に特別な色を付けて「無いもの」として扱うことで、高さ $O(\log n)$ の補助木 1 本だけに対する split・concatenate で済み、これらは平衡 BST なら $O(\log(\text{サイズ}))=O(\log\log n)$ でできるので、全体として $O(\log\log n)$-競合性が保たれます。

11. Signed Greedy ― 上限と下限を挟み込む

第 7 節の greedy アルゴリズムを少し変えた signed greedy は、下限を与えるために使われます。やり方は同じ「行ごとに処理して必要な点を足す」掃き方ですが、signed greedy では片方の符号の長方形だけ (plus だけ、または minus だけ) を充足させます。追加される点は毎回、独立な長方形 1 つに対応します。$\mathrm{OPT}^{+/-}$ を、plus-satisfied な超集合と minus-satisfied な超集合の和集合として最小のものと定義します。

$$\max(\text{+greedy}, \text{−greedy}) = \Theta(\text{最大独立長方形の下限})$$

証明は $\mathrm{OPT} \ge |\text{input}| + \tfrac12\max(\mathrm{MAXIND}) \ge \tfrac12\max(\text{+greedy},\text{−greedy}) \ge \tfrac12\max(\mathrm{OPT}^+,\mathrm{OPT}^-) \ge \tfrac14(\mathrm{OPT}^++\mathrm{OPT}^-) \ge \tfrac14\mathrm{OPT}$ という不等式の輪を作ることで、両端が定数倍で挟み込まれる形になります。

通常の greedy は有効な BST 実行に対応し、$\mathrm{OPT}$ の上限を与えます。signed greedy は (片方の符号しか見ていないので) 有効な BST には対応しませんが、すべての有効な BST の下限を与えます。両者の違いは、signed greedy が plus 側と minus 側の相互作用を無視していることです。plus-rectangle を充足するために足した点が、新たな未充足の minus-rectangle を生む (あるいはその逆) ことがありえますが、signed greedy はそれを勘定に入れません。greedy と signed greedy が常に定数倍以内かどうかは予想にとどまっています。

実務での出番

この回の内容の大半 ― arborally satisfied 点集合、independent rectangle 下限、signed greedy、動的最適性そのもの ― は現役の未解決問題そのものであり、理論の最前線に立つための道具です。業務コードにそのまま出てくることはまずありません。一方で、一部の道具は実際にコードとして動いています。

スプレー木そのものは、実在するプロダクトの内部データ構造として使われています。 たとえば GCC (GNU Compiler Collection) は自前のスプレー木ライブラリ include/splay-tree.h を持ち、コメントには「木の基本操作はすべて償却 $O(\log n)$」と明記されています。コンパイラ内部で位置情報やシンボルのマップなど、アクセスに強い局所性 (同じキー周辺を繰り返し触る) があるデータに向いた選択です。

一方で、レイテンシの最悪値そのものがシビアな場所では、償却保証つきの木は避けられる傾向があります。 実際、Linux カーネルの rbtree (赤黒木) のドキュメント は赤黒木を選んだ理由として「挿入・削除とも回転の回数が定数個に収まる、リアルタイムに保証された worst-case 性能」を挙げています (スプレー木への言及はありませんが、償却ではなく worst-case の保証を重視する姿勢そのものが、この回で見た「性質のはしご」のどこに実務上の価値があるかを教えてくれます)。償却 $O(\log n)$ のスプレー木は、平均では速くても、1 回だけ見ると $O(n)$ かかるアクセスがあり得ます。スケジューラのように 1 回ごとの上限が重要な場所では、この違いが致命的になります。

スプレー木を部品として使う応用もあります。Link-cut tree (リンクカット木) は、根付き木の集合 (森) を動的に繋げたり切ったりしながら、パス上の演算を償却 $O(\log n)$ で行うデータ構造で、内部的に各パスをスプレー木として保持します。競技プログラミングやグラフの動的連結性アルゴリズムの研究でよく使われる、実際に動く応用例です。

「Working Set Property」という名前自体は偶然の一致ではありません。OS のワーキングセットモデル (Denning, 1968, working set) ― 「プロセスが直近の時間窓で触ったページの集合をメモリに残しておけば良い」という、ページング・キャッシュ管理の古典的な考え方 ― と全く同じ直感を BST に移植した名前です。CPU キャッシュや OS のページング、LRU キャッシュのような「最近触ったものはまた近いうちに触る確率が高い」という経験則に馴染みのある読者には、ここが一番つながりを感じやすい部分だと思います。ただし BST の Working Set Property は「異なるキーの個数」を厳密に数えた理論的な保証である点で、実装上の LRU ヒューリスティックとは別物であることは区別してください。

幾何的な見方 (arborally satisfied 点集合) と independent rectangle 法そのものは、現時点では理論的な分析の道具であり、実装として出回っているものではありません。 ただしこの「オンラインアルゴリズムの総コストを、後から分かるオフライン最適と比べる」という発想 (競合比分析) 自体は、OS のページキャッシュ置換アルゴリズムの理論 (LRU の $k$-競合性など) でも使われており、CPU/OS のキャッシュに詳しい読者にとっては「競合比」という評価軸自体に既視感があるはずです。
