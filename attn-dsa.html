DSA — top-k で疎に選ぶ

SWA が「近く」で絞るなら、DSA は「重要さ」で絞る。内容依存の動的な疎選択

0この章の狙い

この記事は Attention の基礎、および前章までの MLA・SWA を前提にします。まだの方は先に Softmax Attention をビジュアルに理解する と MLA — KV を低ランク潜在に圧縮する を読んでください。

一言でいうと
DSA (DeepSeek Sparse Attention) は、MLA で圧縮した KV の上に軽量な Lightning Indexer を載せ、各クエリが全トークンのうち重要な上位 $k_{\text{top}}$ 個だけを選んで疎に Attention する仕組みです。前章の SWA が「直近 $w$ トークン」という位置で固定した窓を使うのに対し、DSA は「今のクエリにとってどれが重要か」を内容を見て動的に選びます。窓の外に置き去りにされていた遠い重要トークンも、内容次第で拾えるようになります。
1. 何を解決する手法か 2. 数式で見る DSA 3. 計算量 4. 【構成】Lightning Indexer と top-k 選択 5. 【体験】k を動かして捨てる重みを見る 6. 代表モデルと系統上の位置 7. まとめ

1何を解決する手法か

SWA の窓は位置で切る。しかし重要なトークンは位置と関係なく現れる。

前章の SWA は「直近 $w$ トークンだけを見る」という単純な規則で参照範囲を絞り込みました。これは実装が軽く KV-Cache も窓幅で頭打ちになる一方、窓の外にある重要なトークンを内容に関わらず切り捨てるという弱点を持ちます。長い文書の冒頭で定義されたキーワードが、文書の終わりで再び参照されるようなケースには手が出せません。

ここで問われるのは「参照するトークンを、位置ではなく内容で動的に選べないか」という着想です。実際、Attention の重みを観察すると、多くのクエリで注意質量は少数のトークンに強く集中する傾向が経験的に報告されています (H2O・Quest の観測)。だとすれば、全トークンをスコアだけ安く計算し、上位 $k_{\text{top}}$ 個だけを選んで厳密に Attention すれば、精度をあまり落とさずに参照量を絞れるはずだ、というのが疎選択の狙いです。

ここは保証ではなく観測に基づく設計です。 「捨てた重みが小さければ出力誤差も小さい」という不等式自体は数学的に成り立ちますが、肝心の「実際に集中する」という前提は事前に保証された性質ではありません。H2O (arXiv:2306.14048) や Quest (arXiv:2406.10774) はこれを観測として報告しており、DSA を含む疎選択系の品質は、この経験則の上に成り立っています。
先行研究として NSA (Native Sparse Attention, arXiv:2502.11089) と MoBA (Mixture of Block Attention, Kimi, arXiv:2502.13189) があります。「学習の段階から疎パターンを焼き込む」という発想の流れを汲み、DSA もこの系譜の上に位置づけられます。DSA は MLA の低ランク圧縮 KV をベースに、軽量な Indexer で top-k 選択を組み合わせる点が特徴です。

2数式で見る DSA

全トークンに安いスコアを付け、上位 $k_{\text{top}}$ だけを厳密な Attention に回します。記号は本シリーズ共通のものを使います。

クエリ $q_t$ に対し、Lightning Indexer が各キー $k_s$ に軽量スコア $I(q_t,k_s)$ を付けます。このスコアで上位 $k_{\text{top}}$ 個を選んだ集合を参照集合 $\mathcal{S}$ とします。

# Indexer スコアで全トークンを安く評価
I(q_t, k_s)  for all s
# 上位 k_top 個だけを参照集合に
S = top_k_top{ I(q_t, k_s) }

まず全トークン上の本来の Attention 重みを $\alpha_j$ とし、素の出力を $o = \sum_{j=1}^{N} \alpha_j v_j$ とします。捨てた参照先の重みの総和を $\varepsilon$ とします。

$$ \alpha_j = \mathrm{softmax}_{j=1,\dots,N}\!\left(\frac{q_t^\top k_j}{\sqrt d}\right), \qquad \varepsilon = \sum_{j \notin \mathcal{S}} \alpha_j $$

選ばれた $\mathcal{S}$ の上だけで、$\alpha_j$ を再正規化した重み $a_i = \alpha_i / (1-\varepsilon)$ ($i \in \mathcal{S}$) を使い、疎な出力 $\hat o$ を得ます。これは本シリーズ共通の疎選択の誤差上界に一致します。

$$ \hat o = \sum_{i \in \mathcal{S}} a_i\, v_i, \qquad \|o - \hat o\| \le 2\varepsilon \max_i \|v_i\| $$
この不等式は $\mathcal{S}$ を再正規化して使う限り、どんな $\mathcal{S}$ でも無条件に成り立ちます (係数 2 は近似ではなく厳密な上界)。DSA の設計が賭けているのは、Indexer が選ぶ上位 $k_{\text{top}}$ に、本来の Attention 重みの大部分 (=大きい $\alpha_j$) が集中しているということです。これが成り立つ範囲では $\varepsilon$ は小さく、出力誤差も小さく抑えられます。

3計算量

Indexer のスコア付けは全トークンにかかりますが軽量です。重い厳密 Attention は選ばれた $k_{\text{top}}$ 個だけに絞られます。

時間計算量 (prefill / 学習時)

Indexer のスコア計算は 1 クエリあたりなら $O(N)$ で済みますが、全クエリ分を合計する prefill 全体では依然$O(N^2)$ です。ただし Indexer はヘッド数や精度 (FP8 等) を絞った軽量設計のため、この $O(N^2)$ 項の係数は非常に小さく抑えられています。一方、重い厳密な Attention 計算は選んだ $k_{\text{top}}$ トークンだけに絞られるため$O(N \cdot k_{\text{top}} \cdot d)$ 級 ($k_{\text{top}} \ll N$) に収まります。実効的な支配項は軽量な Indexer 側ではなく、係数が大きい厳密 Attention 側を削減できたことで決まります。

Decode 時のボトルネック

1 トークン生成ごとに、重い MLA 潜在 KV を読むのは選ばれた $k_{\text{top}}$ 個の分だけで済みます (Indexer 用の軽量なキーは毎ステップ $N$ 個をスキャンしますが、コストは軽量です)。窓固定の SWA と違い、どのトークンが選ばれるかはクエリ次第で毎回変わるため、「読む量」自体は $k_{\text{top}}$ に絞られても、「保持しておくべき KV の総量」は削れません (次項で詳述)。

KV メモリの $N$ 依存

DSA が持つ KV は MLA 相当の圧縮済み潜在表現です。ただし SWA のように窓外を丸ごと捨てて KV-Cache を頭打ちにすることはできません。「どのトークンが後で top-k に選ばれるか」は事前に分からないため、基本的には全 KV を HBM に保持し続ける必要があります。DSA が削るのは帯域と計算であって、KV の容量そのものではないという点が SWA との重要な違いです。

O(N k d)長文脈の実効計算量
k ≪ N読む KV は少数
容量不変保持する KV は MLA 相当のまま

4【構成】Lightning Indexer と top-k 選択

全 KV トークン列に Indexer がスコアを付け、上位 $k_{\text{top}}$ 個だけが点灯して実際の Attention に使われる様子です。k スライダで点灯数が変わります。

top-k
全トークン (Indexer 評価対象) 選ばれた上位 k (実 Attention 対象) クエリ

すべてのトークンに Lightning Indexer が軽量なスコア $I(q_t,k_s)$ を付けます (青)。その中から上位 $k_{\text{top}}$ 個だけが選ばれて点灯し (緑)、その集合 $\mathcal{S}$ だけで実際の Attention 計算 (softmax と value の重み付き和) を行います。MLA が圧縮を担い、DSA は「読む対象を絞る」役割を分担している点に注目してください。

5【体験】k を動かして捨てる重みを見る

top-k スライダを動かして、(a) 選ばれるトークン、(b) 捨てた注意質量 $\varepsilon$ が k とともにどう減るかを見ます。これは「注意質量が少数のトークンに集中する」という H2O・Quest 的な観測を模式化したデモです。

top-k
8選択トークン数 k
—捨てた重み ε

この曲線は $k_{\text{top}}$ を増やすほど $\varepsilon$ (捨てた重みの総和) が減っていく様子を示す模式図です。「集中度が高い」設定では、少数の k でも $\varepsilon$ が急速に小さくなります ― これはまさに「注意質量が少数のトークンに集中する」という経験的観測が成り立つときの理想的な挙動です。ボタンで「集中度: 低い」に切り替えると、同じ k でも $\varepsilon$ が減りにくくなる (=疎選択の前提が崩れたときの挙動) を比較できます。数値は観測の傾向を直感的に伝えるための模式的な可視化であり、実測値ではありません。

6代表モデルと系統上の位置

DSA は MLA の子として位置づき、GLM-5 系が採用したと報告されています。後継ノードとしての CSA/HCA にも触れます。

DSA に先行する 2025-02 には、同じく「内容依存の疎選択」を扱う先行研究として NSA (Native Sparse Attention, arXiv:2502.11089) と MoBA (Mixture of Block Attention, Kimi, arXiv:2502.13189) が公開されています。両者はトークン単位の top-k を選ぶ NSA と、ブロック単位で疎に attention する MoBA という違いを持ちつつ、いずれも「学習の段階から疎パターンを焼き込む」発想を採ります。DSA (DeepSeek Sparse Attention) の考え方は、これらに続いて DeepSeek-V3.2 で 2025-09 にモデルとして先行公開され、その後 arXiv:2512.02556 (2025-12) として論文化されたと整理されています。NSA/MoBA が from-scratch で疎を焼き込むのに対し、DSA (V3.2) は既存モデルへの継続学習で indexer を導入した点が異なります。GLM-5 は DSA を採用したと報告されており ([報告], arXiv:2602.15763)、indexer と呼ぶ機構が各クエリに対して重要なトークンを上位 $k_{\text{top}}$ 個だけ選び、そこだけを参照します。GLM-5.2 では、この indexer を疎注意 4 層ごとに共有する IndexShare を導入し、1M 文脈時のトークンあたり FLOPs を約 2.9 分の 1 にしたと報告されています ([報告])。

系統上、DSA はMLA の上に積まれた技術です。MLA が「KV そのものを低ランク潜在に圧縮する」のに対し、DSA は「圧縮された KV の中から、クエリごとに重要な部分だけを動的に選ぶ」役割を追加します。両者は独立した目的を持ち、組み合わせて使われます。

CSA / HCA (DeepSeek-V4 の後継ノード)。 DeepSeek-V4 "Towards Highly Efficient Million-Token Context Intelligence" (arXiv:2606.19348、2026-06) で、CSA (Compressed Sparse Attention) と HCA (Heavily Compressed Attention) と呼ばれる圧縮 Attention のハイブリッドが確定情報として提案されています。系譜上は「DSA の先、圧縮と疎選択をさらに組み合わせた後継ノード」として位置づけられます。DSA (2025-09 モデル先行公開 / 2025-12 arXiv:2512.02556) → CSA/HCA (2026-06 arXiv:2606.19348) という公開順序は確定しています。具体的な数式・圧縮率の詳細は本稿の範囲を超えるため、系統上の位置づけのみをここで扱います。

7まとめ

論点要点
やることLightning Indexer が全トークンに軽量スコアを付け、上位 $k_{\text{top}}$ 個だけを厳密な Attention の対象にする
数式$\mathcal{S}=\mathrm{top}_{k_{\text{top}}}\{I(q_t,k_s)\}$、$\hat o=\sum_{i\in\mathcal{S}}a_i v_i$ ($a_i=\alpha_i/(1-\varepsilon)$)、誤差は $\varepsilon=\sum_{j\notin\mathcal{S}}\alpha_j$ で $\|o-\hat o\|\le 2\varepsilon\max\|v_i\|$ に上界
時間計算量長文脈で $O(N k_{\text{top}} d)$ 級 ($k_{\text{top}}\ll N$)。Indexer 自体は prefill 全体で $O(N^2)$ だが係数が非常に小さい
KV の $N$ 依存保持する KV は MLA 相当で容量は不変。削るのは帯域と計算
SWA との違いSWA=位置で固定 (窓)。DSA=内容依存で動的選択
品質保証誤差の不等式は定理だが「集中している」ことは経験則 (H2O・Quest の観測)
系譜上の兄弟NSA (arXiv:2502.11089, トークン単位 top-k) / MoBA (Kimi, arXiv:2502.13189, ブロック単位)。いずれも DSA に先行 (2025-02)
代表モデルDeepSeek-V3.2 (先行) / GLM-5・GLM-5.2 ([報告] IndexShare)
後継ノードCSA/HCA (DeepSeek-V4, arXiv:2606.19348、2026-06 で確定) ― 圧縮と疎選択の複合、詳細は本稿の範囲外
結論。DSA は「MLA が圧縮した KV を、さらにクエリごとの重要度で動的に絞る」という一手を加えました。SWA が位置で切る単純さを持つのに対し、DSA は内容を見て選ぶ分だけ柔軟ですが、KV の容量そのものは削れないという代償を負います。次章では、この「参照を減らす」路線とはまったく異なる、softmax を外して状態を固定する線形 Attention の系統に進みます。
