メモリとアドレス ― ROM と RAM、ハーバード型とノイマン型

記憶素子は 1 ビットのレジスタの集まりに過ぎないが、アドレスで選んで読み書きする「記憶」として使うには、読み出しのタイミングという地味だが壊れやすい約束を守る必要がある

この回の前提: 第 05 回 順序回路と時間、第 08 回 レジスタファイル

CPU が命令を実行するには、命令そのもの (プログラム) と、計算の途中結果 (データ) をどこかに置いておく必要があります。レジスタファイルは数十個分の記憶しか持てないので、もっと大量の記憶であるメモリが要ります。メモリは第 05 回のレジスタ (D フリップフロップ) をアドレスで選んで並べたものですが、「アドレスを入れたら何クロック後に値が出てくるか」という読み出しのタイミングを間違えると、CPU 全体が正しく動かなくなります。ここでは ROM と RAM の違い、同期読み出しが 1 クロック遅れる理由、そして rj32 がプログラム用とデータ用のメモリをなぜ分けているか (ハーバード型) を見ていきます。

1. ROM と RAM の違い ― 書けるかどうかより先に、配線の形が違う

「ROM は読み出し専用、RAM は読み書きできる」という説明は結果であって、原因ではありません。回路としての本質的な違いはクロック入力があるかどうかです。ROM はアドレス線 A と有効化線 sel を入れると、クロックを待たずにその瞬間のデータが出力 D に現れる組み合わせ回路です。RAM は中に第 05 回で見た D フリップフロップが並んでいるため、書き込みにはクロックの立ち上がりが必要な順序回路になります。

rj32 のプログラムメモリは実行中に書き換える必要が無いので ROM 的な読み出し専用の使い方で十分です。一方データメモリは store 命令で値を書き込む必要があるため、クロックに同期した書き込みができる RAM が必須です。

図: ROM はクロック入力を持たず常に組み合わせ的に出力する。RAM は書き込みにクロックの立ち上がりが必要。

2. 同期読み出し (Block RAM) が 1 クロック遅れる意味

FPGA の中にある大容量のメモリ素子は Block RAM と呼ばれ、容量と配線のしやすさを優先した代わりに読み出しも必ずクロックの立ち上がりで確定するという制約を持ちます。Digital のマニュアルは Block-RAM (separated ports) を「クロックの立ち上がりでのみ出力が更新される」と説明しており、これは ROM のように「アドレスを入れた瞬間に出力が変わる」組み合わせ回路とは明確に違う挙動です。

つまり、あるクロックでアドレスを入れても、そのデータが出力に現れるのは次のクロックの立ち上がりの後です。rj32 の experiments/bram_diagram.dig と bram_io.dig では、読み出し用のアドレス (raddr) ・クロック (rclk) ・データ (rdata) が書き込み用 (waddr・wclk・wdata) と別の端子として用意されており、読み出し自体がクロックに同期した動作であることが端子の形からも分かります。

図: Block RAM はアドレスを与えたクロックの次の立ち上がりで、初めて出力が確定する。

3. ハーバード型とノイマン型 ― 命令とデータは同じメモリに置くか

CPU がメモリにアクセスする経路の作り方には大きく 2 つの流派があります。ノイマン型 は命令もデータも同じ 1 つのメモリに置き、同じアドレス空間・同じバスでアクセスします。ハーバード型 は命令用のメモリとデータ用のメモリを完全に分け、別々のアドレス・別々のバスでアクセスします。

Digital に付属するサンプル CPU を比べると違いがはっきりします。ProcessorVonNeumann.dig は Instruction 信号とデータ読み書きが同じメモリ回路を共有するノイマン型です。これに対し rj32 は、命令フェッチ用のアドレス線 A_prog ・データ線 D_prog と、データアクセス用のアドレス線 A_data ・データ線 D_in/D_out が最初から別の端子として用意されており、ハーバード型です。README にも「data memory is accessed only through load/store instructions, and data memory is separate from program memory」と明記されています。

図: ノイマン型は命令とデータが同じバスを取り合うが、ハーバード型は別のバスなので取り合わない。

4. rj32 がデータと命令を分ける理由

ハーバード型の一番の利点は、命令のフェッチとデータへのアクセスを同じクロックで同時に行えることです。ノイマン型で 1 つのメモリしか無ければ、「次の命令を読む」のと「今の命令がデータを読み書きする」のは同じポートを取り合うので、同じクロックでは片方しかできません。rj32 は第 09 回の前提である第 05 回・第 08 回で見た「読みポートと書きポートを分ける」という発想を、レジスタファイルだけでなくメモリ全体の設計にまで広げたとも言えます。

代償もあります。ハーバード型は配線とメモリ素子を 2 系統分用意する必要があり、プログラムを実行中に書き換える (自己書き換えコードや、実行時にコンパイルしたコードをその場で実行するような用途) には向きません。FPGA では Block RAM をいくつも内蔵しているため、2 系統に分けることのコストが小さく、rj32 のように ice40 のような小型 FPGA をターゲットにする設計では現実的な選択です。

図: 命令フェッチとデータアクセスのバスを分けると、両方を同じクロックで並行して進められる。

5. 実装のポイント

読み出しの 1 クロック遅れを帳尻合わせする。 rj32 の dig/memaccess.dig には、データメモリとの間に D_FF (D フリップフロップ) が 1 つ挿入されています。これは「メモリへアドレスを出したクロックの、次のクロックでデータが返ってくる」というタイミングに、CPU の他の部分 (control.dig のストール制御) を合わせ込むための部品です。組み合わせ回路の ROM のつもりで RAM を配線すると、実際には 1 クロック前のアドレスに対応する古いデータを読んでいる、という分かりにくいバグになります。設計の最初から「このメモリは何クロックで返すか」を書き出しておくことが大切です。

アドレスの単位を決めてから配線する。 rj32 の命令セットドキュメントには、load/store 命令について「現状はメモリがワード単位でアドレス付けされていて、バイト単位になっていない (実装未完了)」という注記があります。16 ビット CPU では「アドレス 1 つで何バイト進むか」はワード単位 (1 進むと 2 バイト先) とバイト単位 (1 進むと 1 バイト先) のどちらもありえ、後から変えるとオフセット計算の式が全部変わります。rj32 自身もこの点を未解決の課題として残しており、「後からでも直せる」と楽観せずに先に決めておくべき設計判断の実例です。

プログラムメモリと I/O を同じアドレス空間に混ぜない。 ハーバード型でも、データメモリの中にメモリマップト I/O (周辺機器をメモリアドレスとして見せる仕組み、詳しくは第 18 回) を混ぜる設計はよくあります。rj32 の datamemio.dig では、データメモリ本体と I/O へのアクセスを req/ack の要求・応答線で切り分けており、アドレスの範囲だけで暗黙に判定するのではなく、明示的な信号で経路を分けています。

図: データメモリの出力が 1 クロック遅れるぶん、それ以外の制御信号 (命令の情報) も D_FF という別経路で 1 クロック遅らせて帳尻を合わせる。D_FF は Data Memory の後段ではない。

6. メモリマップト I/O の入口 ― req/ack という約束

メモリへのアクセスを要求してから完了するまでに時間がかかる場合 (今回の BRAM の 1 クロック遅れや、将来の外部バス) に備え、rj32 の datamemio.dig は req (要求) と ack (応答) という 2 本の信号でメモリアクセスの開始と完了を分けて扱っています。CPU 側は「アクセスしたい」という req を出し、メモリ側の準備ができたら ack を返す、という単純な握手 (ハンドシェイク) です。

この握手の形は、第 17 回で扱う Wishbone バスのような本格的なバスプロトコルの最小版だと考えると理解しやすくなります。今の段階では「アドレスを出して即座に値が返ってくる」という思い込みを捨て、「要求してから応答が来るまでに時間がかかることがある」という前提で設計しておくと、後からバスやキャッシュを足すときに作り直しが少なくなります。

図: req で要求し ack で完了を知らせる握手は、応答にかかる時間を仮定しない設計を可能にする。
