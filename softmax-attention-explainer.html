Softmax Attention をビジュアルに理解する

Query が Key を見て Value を混ぜる ― その計算がなぜ重く、FlashAttention がなぜ効くのか

0この記事の狙い

Attention は Transformer の心臓です。数式 softmax(QKᵀ/√d)V は短いのに、なぜ長い文脈で急に重くなるのか、なぜ FlashAttention が必須なのかは、式だけ見ても掴めません。ここでは「絵と動き」で、計算の中身とボトルネックの正体を腹落ちさせます。

一言でいうと
Attention とは「各トークン (Query) が、文中の全トークン (Key) との関連度を内積で測り、その重みで全トークンの中身 (Value) を加重平均する」操作です。全員が全員を見るので、トークン数 N の二乗に比例する計算とメモリが発生します。これが長文で重くなる根本理由で、FlashAttention はその N² の中間行列を主記憶に書かずに済ませることでメモリ往復の問題を回避します (計算量 O(N²d) 自体は残ります)。

1Attention は何をやっているか

数式の前に、比喩で全体像を掴みます。

図書館で調べ物をする場面を想像してください。あなたは知りたいこと (Query) を持っています。棚の本にはそれぞれ見出し (Key) と中身 (Value) があります。あなたは各本の見出しと自分の問いを照合し、関連が強い本ほど大きく参照し、複数の本の中身を混ぜて答えを作ります。これが Attention です。

3 つの登場人物。Query = 今知りたいこと (今のトークンが発する問い)。Key = 各トークンの「見出し」。Value = 各トークンの「中身」。
Query と Key の内積で関連度 (Attention スコア) を測り、その重みで Value を加重平均する。これがすべてです。

重要なのは、Query・Key・Value はいずれも入力トークンのベクトルに、それぞれ別の重み行列を掛けて作られる射影だという点です。同じトークンから「問い」「見出し」「中身」の 3 つの顔を作り出しているイメージです。

2Scaled Dot-Product Attention の数式

比喩を数式に落とします。1 行ずつ分解すれば怖くありません。

系列長 N (トークン数)、ヘッドあたりの次元 d (=d_k、実際は 64〜128 程度。モデル全体の次元 d_model とは別) とします。入力から 3 つの行列 Q, K, V (いずれも N×d) を作ります。Attention はこの一本の式です。

# Scaled Dot-Product Attention
Attention(Q,K,V) = softmax( QKᵀ / √d ) V

これを 3 段に分けます。

  1. スコア行列 S = QKᵀ (N×N)。Query i と Key j の内積が S[i,j]。全 Query × 全 Key の総当たりなので N² 個の数が生まれる。ここが重さの震源地。
  2. スケール & softmax。S を √d で割ってから、各行ごとに softmax。これで各行が「合計 1 の重み (確率のようなもの)」になる。
  3. Value の加重平均 =AV。softmax 後の重み行列 A (N×N) を V に掛け、各 Query の出力 (N×d) を得る。関連の強い Value ほど大きく混ざる。
# 3 段に分けて書くと
S = Q Kᵀ         # (N×N) 生スコア
A = softmax(S / √d)  # スケールしてから行ごと softmax
out = A V        # (N×d) 出力
覚えるべき形は 3 つ。QKᵀ で関連度を測り (N²)、softmax で重みに変え、V を混ぜる。この N² の中間行列 S / A が、後で計算量とメモリの両方のボトルネックになります。

3なぜ √d で割るのか

式にひとつだけある謎の √d。これには明確な理由があります。

Query と Key の内積は、d 個の積の和です。初期化時の典型的な仮定として各成分が独立に平均 0・分散 1 のとき、内積の分散は次元 d に比例して大きくなります。d=128 なら内積の振れ幅は標準偏差にして約 11 (√128 ≈ 11.3) になります。

この大きな値をそのまま softmax に入れると、スコアの振れ幅が大きいほど、最大要素にほぼ全重みが集中しやすくなります (softmax の飽和)。飽和領域では勾配がほぼ 0 になり、学習が進みません。

√d で割ると内積の分散が約 1 に正規化され、softmax が飽和せず、なだらかな重み分布が保たれます。「次元が大きいほど内積が暴れるのを、√d でちょうど打ち消す」のがスケーリングの意味です。d ではなく √d なのは、内積の標準偏差が √d なので、標準偏差で割れば分散がちょうど 1 に揃うからです。

4【体験】Query が Value を混ぜる

1 つの Query を動かして、各 Key との関連度 (softmax の重み) と、その重みで Value がどう混ざるかを見ます。Query を Key に近づけると、その Key の重みが上がります。

スケール β(=1/√d, 温度の逆数)
Query (あなたの問い) Key (各トークンの見出し) 出力 (Value の加重平均)

Query (橙) を Key (青) に近づけると、その Key との内積が大きくなり、棒グラフの重み (softmax) が跳ね上がります。緑の点は、その重みで全 Value を混ぜた出力で、関連の強い Key の方へ引き寄せられます。スケール β を上げる (= 温度を下げる) と分布が鋭く (勝者総取りに)、下げるとなだらかになります。√d で割るのは、この β を 1/√d に設定して分布が鋭くなりすぎる (飽和) のを防ぐ操作にあたります。

5位置情報の入れ方 (RoPE は軽く)

Attention 単体には「順序」の概念がありません。ここだけ簡単に補足します。

マスクなしの素の Attention は、入力トークンを並べ替えると出力も同じ順で並べ替わるだけ (permutation-equivariant) で、各トークンが受け取る内容は語順に依存しません。つまり「近く/遠く」「前/後ろ」を区別できない (厳密には causal mask があると位置が部分的に漏れますが、それだけでは不十分)。そこで位置情報を別途注入します。現代の LLM で主流なのが RoPE (Rotary Position Embedding) です。

RoPE の発想は「Query と Key のベクトルを、その位置に応じた角度だけ回転させる」こと。回転させてから内積を取ると、内積の値が2 つのトークンの相対的な距離に依存するようになります。これで「近い/遠い」が Attention スコアに自然に反映されます。絶対位置ではなく相対位置が効くのが RoPE の強みです。

RoPE は本記事の主題ではないので、ここでは「位置に応じてベクトルを回す仕掛け」とだけ押さえてください。仕組みの詳細 (複素数表現・周波数の割り当て・長文外挿) は別記事で扱います。

6なぜ計算が重いのか — N² の壁

Attention の重さの正体は、2 章で生まれた N×N の行列です。

スコア行列 S = QKᵀ は N×N。系列長 N が 2 倍になると、この行列の要素数は 4 倍になります。計算量は O(N²·d)、中間行列のメモリは O(N²) で、いずれも N について二乗です。

ここが長文 LLM の泣きどころ。文脈長を 512→32k に伸ばすと、Attention のコストは 約 4,000 倍。モデルの他の部分 (FFN など) が N に比例 (O(N)) なのに対し、Attention だけ N² で伸びるので、長文になるほど Attention が全体を支配します。

しかも問題は計算量だけではありません。この N×N 行列をGPU の主記憶 (HBM) に書き出して読み直すと、そのメモリ往復が帯域を食い潰します。次章で N を動かして体感し、8 章でボトルネックの正体を突き止めます。

7【体験】系列長 N とコスト

系列長 N を動かして、計算量 (N²) とメモリが二乗で膨らむ様子を見ます。実際の LLM の文脈長 (4k〜128k) を意識してください。

棒グラフは、系列長に対する Attention (N²) と FFN 等 (N) のコストの伸びを対比しています。N が小さいうちは FFN が支配的でも、N が伸びると Attention の青い棒が二乗で突き抜けていきます。「スコア行列の概算メモリ」は1 ヘッド・1 シーケンスあたりの最小見積り (S+A を fp16 で) で、N=32k で数 GB。実際はヘッド数とバッチのぶんさらに倍増するので、これを素直に確保するのは非現実的だと分かります。

8何バウンドの処理か

「重い」と一口に言っても、計算が重いのかメモリ移動が重いのかで対策が変わります。Attention は場面によって両方です。

処理が何で律速されるかは Arithmetic Intensity (演算強度 = 演算量 / メモリ移動量) で決まります。GPU の「1 バイト運ぶ間にできる演算数」の分岐点より上なら compute-bound、下なら memory-bound です。Attention は使われ方で二つの顔を持ちます。

場面状況律速
学習 / PrefillN 個のトークンをまとめて処理。大きな行列積が主。compute-bound 寄り
(ただし素朴実装は N² 行列の HBM 往復で memory-bound 化)
推論の Decode (1 トークン生成)Query は 1 本だけ。過去 N トークンの K,V を全部読む。強く memory-bound
Decode が memory-bound になる理由。1 トークン生成するのに、過去全トークンの Key と Value (KV cache) を HBM から読む必要があります。読む量は N に比例して増えるのに、行うのは Query 1 本ぶんの小さな計算だけ。運ぶバイトに対して演算が少なすぎる = メモリ帯域で律速。だから LLM 推論は「KV cache をいかに小さく・速く扱うか」の戦いになります。読む量を減らす量子化・GQA/MQA、メモリ管理を効率化してバッチを広げるPagedAttention など、狙いの異なる対策が併用されます。
Prefill も油断できない。行列積そのものは compute-bound ですが、素朴に実装すると N×N のスコア行列を HBM に書いて softmax でまた読む往復が入り、memory-bound に転落します。これを防ぐのが次章の FlashAttention です。

9FlashAttention — 融合カーネル

N² 行列を主記憶に書かなければ、メモリ往復は消せる。これが FlashAttention の核心です。

素朴な Attention は 3 段 (S=QKᵀ → A=softmax(S) → AV) をそれぞれ別カーネルで実行し、N×N の中間行列 S・A を HBM に書いては読み直します。N² のデータを 2 往復以上させるので、長文では帯域が完全に飽和します。

# 素朴実装: N×N 行列が HBM を何度も往復
QKᵀ → S (N×N) を HBM に書く
S を読む → softmax → A (N×N) を HBM に書く
A を読む → AV → 出力を書く

FlashAttention は、Q・K・V を小さなブロック (タイル) に分割し、1 つの融合カーネルの中で「部分的な QKᵀ → 部分 softmax → 部分 AV」をオンチップ (SRAM) だけで進めます。鍵は online softmax: 全体の最大値や合計を最初に知らなくても、ブロックを見るたびに途中経過を補正しながら正しい softmax を積み上げる技法です。

FlashAttention が消したもの。N×N の中間行列 S・A を一度も HBM に書きません。追加で確保するメモリは N² ではなく O(N) 級で済みます。HBM アクセス量は論文では Θ(N²d²/M) (M はオンチップ SRAM の容量)。N² のオーダー自体は残ります (入力ブロックを繰り返し読み直すため。直感的には、K,V 全体 Nd を Q タイルの数 ≈Nd/M 回なめるので Nd×Nd/M = N²d²/M) が、係数が SRAM 容量ぶん小さくなり、実測でアクセスが数倍〜10 倍ほど減ります。計算量そのもの (O(N²d)) はむしろ再計算で微増しますが、memory-bound だった処理のメモリ往復を潰すので実効速度が大きく上がります。
誤解しやすい点 (その1)。FlashAttention は近似ではありません。出力は素朴実装と数値的に (ほぼ) 一致する厳密なアルゴリズムです。速くなるのは「計算を省いた」からではなく「メモリ往復を省いた」から。LayerNorm/RMSNorm 等でも複数カーネルを 1 つに融合して中間結果の書き出しを省く同種の最適化があり、それと同じ思想です。
誤解しやすい点 (その2)。FlashAttention が主に効くのは学習 / Prefill の N² 往復です。推論の Decode では中間行列がそもそも小さく (1×N)、律速はKV cache の読み出しなので、そこは FlashAttention では消えません。Decode 側は量子化・GQA 等の別対策が担います (Flash-Decoding はまた別の並列化の工夫)。

10【体験】標準 vs FlashAttention

標準実装と FlashAttention で、N×N 行列が HBM とオンチップの間をどう扱われるかを見ます。往復するデータ量に注目してください。

HBM ↔ コア間の移動 オンチップ (SRAM) の計算

標準では巨大な N×N 行列 (赤) が HBM を往復します。FlashAttention に切り替えると、Q・K・V をタイル単位で読み込み、オンチップで online softmax まで完結させ、N² の中間行列を一度も書き出しません。往復するのは入力タイルと出力だけ (ただし入力タイルは複数回読み直されるので往復がゼロになるわけではなく、N² 行列の往復が消えるのがポイント ― 9章の Θ(N²d²/M) 参照)。長文ほどこの差が効きます。

11まとめ

Attention の要点を一枚に整理します。

論点要点
やっていることQuery が Key との内積で関連度を測り、softmax の重みで Value を加重平均
数式softmax(QKᵀ/√d)V。中間に N×N のスコア/重み行列
√d の意味内積の分散を約 1 に正規化し softmax の飽和を防ぐ
計算量O(N²d)。文脈長を伸ばすと N について二乗で重くなる
Prefillcompute-bound 寄り (素朴実装は N² 往復で memory-bound 化)
Decode強く memory-bound。KV cache の読み出しが律速
FlashAttentionN² 行列を HBM に書かない厳密アルゴリズム。メモリ往復を潰して高速化
位置情報素の Attention は語順を持たない。RoPE 等で注入 (別記事)
結論。Attention の美しさは「全員が全員を見て加重平均する」という一様な仕組みにあり、その代償が N² のコストとメモリです。計算量そのものを O(N²d) から動かすのは難しく、FlashAttention はむしろ再計算で演算がわずかに増えるにもかかわらず速い。「N² の中間行列を主記憶に書かない」というメモリ側の工夫だけで実用性を劇的に上げたのです。長文 LLM を支えているのは、この「重さの正体はメモリ移動だった」という洞察です。
