ALU ― 足し算の回路を引き算にも比較にも使い回す

専用の引き算回路は作らない。加算器 1 個を、引き算・論理演算・シフト・比較のすべてに使い回すのが ALU の設計の核心

この回の前提: 第 03 回 組み合わせ回路、第 04 回 2 進数と CPU の計算

ALU (Arithmetic Logic Unit, 算術論理演算装置) は、add・sub・and・or・shl のような命令を実際に計算する部品です。素直に作るなら、足し算専用の回路と引き算専用の回路を別々に用意したくなりますが、実際の ALU は 1 個の加算器を使い回し、引き算は「もう一方の入力を反転してから加算器に通す」というトリックで済ませます。rj32 の ALU 回路 (dig/execute.dig) を実際に読むと、この使い回しの跡と、比較結果の作り方、シフトをまとめて処理する「ファネルシフタ」という仕組みがそのまま確認できます。結論を先に言うと、ALU は専用回路の集まりではなく、1 個の加算器をできるだけ多くの命令で使い回す設計です。

1. ALU は何を受け取り、何を返す部品か

rj32 の ALU 回路 (dig/execute.dig) を見ると、入力は L (左オペランド、16 ビット)・R (右オペランド、16 ビット)・op (どの演算をするかを選ぶ 3 ビットの制御信号) の 3 つです。出力は result (16 ビットの計算結果) と、分岐命令で使う比較結果のフラグ (eq・ne・lt・ge・lo・hs など) です。この op は、instructions.md が説明する命令エンコーディングの「func コード (ALU の機能を選ぶ部分)」に対応します。

図: ALU は L・R・op を受け取り、result と比較用の各フラグを返す。

2. 加算器を引き算に使い回す仕組み

第 04 回で見た 2 の補数では、$a - b$ は $a + (\text{¬}b) + 1$ と同じ値になります (¬b は b の各ビットを反転した値)。これを使うと、引き算専用の回路を新しく作らなくても、足し算の回路 1 個だけで加算と減算の両方をこなせます。rj32 の dig/execute.dig では、R は 16 ビットの Not で反転した ¬R と、反転しない R の 2 つに分かれ、Multiplexer (切り替え器) がどちらか一方を Add ブロックの b 入力へ渡します。この切り替えを決める 1 本の線は op の 1 ビットで、同じ線が Add のキャリー入力 (c_i) にもつながっています。つまり「減算のときは ¬R を選び、同時にキャリー入力に 1 を入れる」が 1 本の線で同時に起きる配置で、まさにこのトリックそのものです。Add のキャリー出力は C という名前の Tunnel (離れた場所へ名前で信号を運ぶ部品) に出て、後で見る符号なし比較に使われます。

図: op の 1 ビットが Mux で ¬R を選ぶと同時に Add のキャリー入力 c_i に 1 を入れる。1 本の線で、1 個の Add ブロックが加算にも減算にもなる。キャリー出力 C は符号なし比較に使われる。

3. 比較結果の作り方 ― キャリーとオーバーフローから 6 種類のフラグを作る

rj32 には if.eq・if.lt・if.ult のように、符号付き・符号なしで別々の比較命令があります (第 04 回参照)。dig/execute.dig を見ると、eq (等しい) は、ALU の xor 演算の出力 (L と R の各ビットが同じなら 0 になる) を Comparator で定数 0 と比べて作り、ne はその否定です。引き算の結果ではなく xor の出力を使うので、加算器を通らずに等しさが分かります。lo (unsigned lower, 符号なし未満) と hs (unsigned higher or same, 符号なし以上) は、Add ブロックが引き算として動いたときのキャリー出力 C をそのまま使って作られています。符号付きの lt・ge は、キャリーだけでなくオーバーフロー V も絡めて XOr や And/Or で組み立てる必要があり、符号なし比較より配線が 1 段階複雑になっています。

図: 符号なし比較 (lo/hs) はキャリー C だけで作れる (分岐してそのまま出る) が、符号付き比較 (lt/ge) は C と V を組み合わせる必要がある。

4. ファネルシフタ ― 3 種類のシフトを 1 つの回路でまとめる

rj32 には shl (論理左シフト)・shr (論理右シフト)・asr (算術右シフト) の 3 つのシフト命令がありますが、dig/funnelshifter.dig を見ると、これらを 3 つの別回路として作ってはいません。入力 16 ビットの値 I に加えて、符号拡張した上位ビットを足した「2 倍幅の値」を Splitter と BitExtender で作り、その中から amt (シフト量 4 ビット)・dir (方向)・arith (算術シフトか論理シフトか) に応じて 16 ビット分の「窓」を切り出す、という 1 つの回路で 3 種類のシフトすべてを処理しています。切り出す窓の位置は、まず 4 ビット単位 (0・4・8・12 ビット) で大まかに決め、続けて 1 ビット単位 (0〜3 ビット) で微調整する、2 段階のマルチプレクサで選ばれます。

図: ファネルシフタは amt を「4 ビット単位」と「1 ビット単位」の 2 段階に分けて窓の位置を選ぶ。shl/shr/asr はこの窓の作り方 (dir・arith) の違いだけで表現される。

5. op コード ― Multiplexer が候補の中から 1 つを選ぶ

第 06 回で見たとおり、ALU は候補の結果を 1 本の線に無理やり押し込む共有バスではなく、Multiplexer (Selector Bits = 3) に複数の候補をすべて入力しておき、op の 3 ビットで 1 つだけを選ぶ作り方になっています。加算/減算の結果、ファネルシフタの結果、論理演算 (and/or/xor) の結果などが候補としてこの Multiplexer に集まり、instructions.md の命令表にある add・sub・and・or・xor・shl・shr・asr という並びに対応する選択値が割り当てられています。

図: 複数の候補の計算結果を Multiplexer に集め、op の値で 1 つを選んで result として出す。

6. 実装のポイント

引き算専用の回路を別に作らない。 加算器と減算器を別々に用意すると、回路の規模がほぼ 2 倍になります。R を Not で反転した値を Multiplexer で選び、その選択線をキャリー入力にも渡すだけで、1 個の Add ブロックが両方の役目を果たせることを、まず確認するのが設計の第一歩です。

符号付き比較と符号なし比較を混同しない。 lo・hs (符号なし) はキャリーだけで作れますが、lt・ge (符号付き) はオーバーフローも組み合わせないと正しくなりません。この 2 系統を同じ論理で済ませてしまうのが、ALU を自作するときによくある間違いです。

似た処理は 1 つの回路にまとめる。 シフト命令を 3 つとも別回路で作ると配線も検証も 3 倍になりますが、rj32 のファネルシフタのように「窓を切り出す位置を変えるだけ」で表現すれば、1 つの回路と 1 回の検証で済みます。

図: ALU を自作するときに判断を誤りやすい 3 つの点。
