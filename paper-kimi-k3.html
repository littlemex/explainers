Kimi K3 は何が珍しいのか

2.8T パラメータ MoE が積んだ、KDA だけではない設計の数々を読む

← 論文理解シリーズの目次へ

0この記事は何を読み解くのか

Kimi K3 (Moonshot AI, 2026-07) は「オープンウェイトで最大級」なだけでなく、注意機構・MoE・層の繋ぎ方・学習基盤のあちこちで独自の工夫を積んでいるモデルです。この記事はその工夫を、初学者でも辿れるように整理します。

一言でいうと
Kimi K3 は総パラメータ 2.8 兆・有効活性化 1040 億の MoE モデルで、1M トークンのネイティブ文脈長とネイティブなマルチモーダル (画像・動画) 対応を持ちます。系列方向には線形 Attention (KDA) を 3、通常の Attention (Gated MLA) を 1 の比率で混ぜるハイブリッド構成を採り、深さ方向にも Attention 型の選択的参照を重ねる (Attention Residuals) という、珍しい二段構えの設計です。これらのアーキテクチャ改良にデータ・学習レシピの改善を合わせて、前世代の Kimi K2 比でスケーリング効率が約 2.5 倍になったと報告されています。

1なぜハイブリッドか — KDA 3 : Gated MLA 1

まず一番目立つ設計判断から見ます。K3 は全層を線形 Attention (KDA) にはしません。

KDA (Kimi Delta Attention) は、状態を固定サイズに保ちながら系列を処理する線形 Attention の一種で、Gated DeltaNet の忘却ゲートをチャネルごとに細粒度化した手法です (仕組みの詳細は Attention 系列の KDA — Kimi Delta Attention を参照してください)。計算量が系列長に比例する ($O(N)$) ので長文脈に強い一方、状態が固定サイズなので、大昔の情報を薄めずに正確に引き出すのは通常の Attention (KV を全部保持する $O(N^2)$ 系) が得意です。

K3 はこのトレードオフを両方使うことで解決します。論文いわく、各ブロックは KDA を 3 層、続けて Gated MLA (通常の Attention の効率化版) を 1 層という構成で、これをモデル全体で繰り返します。さらにバックボーンの最後にもう 1 層 Gated MLA を追加し、必ず「最終層は大域 Attention」で終わるようにしています。

比喩。KDA 3 層は「直近の会議メモを要約しながら持ち歩く秘書」、Gated MLA 1 層は「必要なときに議事録の原本を丸ごと読み返す係」です。ほとんどの処理は要約 (KDA) で速く済ませ、ときどき原本 (Gated MLA) を引いて精度を取り戻す ― これが 3:1 の比率の狙いです。

2【体験】局所反復 vs 大域アクセス

KDA と Gated MLA で、情報の流れ方がどう違うかを見ます。

注目するトークン 12
KDA: 固定状態を毎ステップ更新して引き渡す Gated MLA: 過去すべてに直接アクセス

KDA モードでは、注目トークンは直前の状態 1 つだけを受け取ります。過去の情報はすべてそこに圧縮されており、更新のたびに (チャネルごとの速さで) 少しずつ薄れます。Gated MLA モードでは、注目トークンから過去のすべてのトークンへ直接線が引かれます― トークンごとのエントリを系列長方向には圧縮せず保持したまま、欲しい記憶を直接取りに行けます (MLA は 1 トークンあたりの KV を潜在ベクトルに圧縮しますが、それは次元方向の圧縮で、系列に沿った圧縮ではありません)。K3 は 3 層薄めたら 1 層で読み直す、を繰り返すことで、速さと正確さの両方を狙っています。

3RoPE を完全に捨てる — NoPE-MLA

もう 1 つの珍しい判断が、位置符号化の扱いです。

MLA (Multi-head Latent Attention) 自体は Kimi K2 / K2.5 でも使われていましたが、K2 では RoPE (回転位置符号化) を組み合わせていました。K3 は MLA に入力依存・チャネルごとの出力ゲートを追加して「Gated MLA」にする一方、そのすべての MLA 層から RoPE を完全に外し、NoPE (位置符号化なし) に切り替えました。ML 基礎シリーズの 位置をどう教えるか — RoPE と NoPE をゼロから で見た「明示的な位置符号化がなくても位置情報は他の経路から漏れる」という考え方の、frontier 級モデルでの実践例です (ただし K3 の場合、位置を運ぶのは因果マスクではなく次段落の KDA の仕組みです)。

なぜ K3 で成立するのか。K3 では位置の情報をKDA の再帰的なゲーティングと減衰の仕組みがすでに運んでいます (「何ステップ前の情報か」に応じて減衰するので、暗黙に順序を符号化している)。だから MLA 側はRoPE で位置を教え直す必要がない、というのが論文の説明です。副産物として、1M トークンまで RoPE の周波数調整や YaRN のような再チューニングが一切不要になりました (これは ML 基礎シリーズの RoPE 解説で見た PI/NTK/YaRN の悩みそのものを、そもそも発生させない選択です)。

4Stable LatentMoE — 896 分の 16 を安定に選ぶ

MoE 側の工夫です。K3 は 896 個という非常に細かく分割されたエキスパートから、トークンごとに 16 個だけを使います (疎度は 896/16 = 56)。

LatentMoE は、選ばれたエキスパートに送る表現をモデル全体の幅 $d$ のままにせず、幅 $\ell$ の小さな潜在空間に圧縮してから送ります (共有エキスパートだけは全幅のまま処理)。これにより、896 個という多さでも通信・計算コストが現実的に収まります ― 「Latent」の名の由来はここです。

ただしこの極端な疎さは 2 つの副作用を生みます。(1) 縮小 → エキスパート内部のゲート付き FFN → 展開、というほぼ4 回連続の行列積になるため活性化が暴走しやすい (activation explosion)。(2) 約 900 個のエキスパートの負荷を均すのが、既存の負荷分散手法の想定を超えて難しい。K3 はこれに3 つの工夫で対処しています。

  • 展開前の RMSNorm: 潜在空間から元の幅へ戻す直前に正規化を挟み、暴走の芽を摘む。
  • SiTU-GLU: 活性化関数の出力を tanh でなめらかに頭打ちさせ、特定チャンネルの値が暴走するのを抑える。
  • Quantile Balancing (QB): 各エキスパートのスコアに足すバイアスを、そのエキスパートが「目標負荷に到達するために必要な採用ライン (分位点)」から直接求め、動的に調整する負荷分散則。
要するに。「896 個から 16 個を選ぶ」という極端な疎さを安定に回すための下支えが、展開前 RMSNorm・SiTU-GLU・Quantile Balancing の 3 点です。次の体験ではこの中の負荷分散 (QB) の効果を単純化して体感します。

5【体験】ロードバランスが崩れると何が起きるか

エキスパートへのルーティングを繰り返し、Quantile Balancing の強さを変えると負荷の偏りがどう変わるかを見ます。

Quantile Balancing の強さ 60%
各エキスパートが受け取った負荷 (64 グループに縮約表示) 目標負荷 (均等な場合)

Quantile Balancing の強さを 0 にしてトークンを流すと、人気の高いエキスパート (グラフの一部の棒) にどんどん負荷が積み重なり、ごく一部の棒だけが伸びて残りはほぼ空になります。強さを上げるほど、人気エキスパートのバイアスが下がって選ばれにくくなり、負荷を受け取るグループの数が増え、棒の高さが目標負荷 (橙線) に揃っていくのが見えます。「896 分の 16」という極端な疎さで学習が崩れないのは、この負荷分散を含む§4 の 3 つの工夫が合わさっているためで、このデモはその一因を単純化して再現したものです。

デモの注意。ここでの更新則 (人気度スコアからバイアスを引く) は負荷分散の一般的な考え方を模式化したもので、論文の Quantile Balancing (Top-(k+1) 選択から採用ラインを直接求める手続き) そのものではありません。スライダーの「強さ」も論文のパラメータではなく、本デモ独自の単純化です。

6Attention Residuals — 深さ方向にも Attention

K3 で最もユニークな設計がこれです。普通のモデルは層の出力をただ足し算 (残差接続) しますが、K3 はその均等な足し算を、Attention による選択的な参照に置き換えます。

ふつうの残差接続は、後続の層の入力に「それまでの層の出力をすべて (重み 1 で) 蓄積したもの」を渡します。Attention Residuals (AttnRes) は、参照する側ごとに学習可能な「疑似 Query」 $w$ を持たせ、それより前の出力 (＝疑似 Key/Value) に対してAttention と同じ仕組みで重み付き平均を取ります。トークン埋め込みそのものも、$i=0$ 番目の参照先として key/value 集合に含まれます。

$$ \alpha_{i\to l} = \frac{\exp\big(w_l^\top \mathrm{RMSNorm}(f_i(h_i))\big)}{\sum_{j<l}\exp\big(w_l^\top \mathrm{RMSNorm}(f_j(h_j))\big)} $$

($i=0$ のときは $f_i(h_i)$ をトークン埋め込みそのものと読み替えます。)

粒度の注意。ここで示した式は「層」単位の一般形 (Full AttnRes) です。K3 の実装 (Block AttnRes) では、この $l,i$ が個々の層ではなく「12 層ずつまとめたブロック」番号に置き換わります (12 層区切りで 8 ブロック、末尾は端数、埋め込み層を 1 ブロックとして数えると全体で 9 ブロック)。以降の説明とデモは直感のために「層」を「ブロック」の代わりの模式的な単位として使っています。
比喩。「深さ方向の Attention」というアイデアそのものは新しくありませんが (層・ブロック方向の重み付き結合は複数の先行研究で試みられています)、K3 は2.8T 規模の frontier モデルにこれを実装した点が実務上の見どころです。系列方向の Attention (KDA/MLA) が「どのトークンを見るか」を学ぶのと対に、深さ方向の Attention Residuals は「どのブロックの出力を見るか」を参照する側ごとに学ぶ仕組みです。RMSNorm は、出力の大きいブロックが重みを独占しないようにする安全弁です。

7【体験】層をまたいで「見に行く」重み

ある層が、それより前のどの層をどれだけ重視するかを、標準の残差接続と比べます (前節の注意の通り、実際は「層」ではなく「ブロック」単位です)。

注目する層 l 12
層 i → 層 l への重み

標準の残差接続では、すべての先行層の出力が重み 1 でそのまま蓄積されます (棒は「均等な重み」の模式表示で、実際は平均ではなく足し算です)。Attention Residuals では、参照する側ごと・入力ごとに重みが変わり、ある層は数層前を強く参照し、別の層は入力に近い浅い層を強く参照する、といった選択的な参照が可能になります。棒の高さが不揃いになるほど「選んで見ている」ことを表します (デモの Key ベクトルは固定した乱数で、実際の入力依存の隠れ状態ではありません)。

8学習基盤の珍しい工夫 — CPU DRAM・一時停止できる砂場

アーキテクチャだけでなく、2.8T パラメータを実際に学習・運用するための基盤にも珍しい工夫があります。

(用語) DP ランク=データ並列の分担単位。ZeRO-2=勾配やオプティマイザ状態を DP ランク間で分割して重複を減らす手法。microVM=1 台の物理機に多数の隔離環境を軽量に載せる仮想化方式 (K3 では Firecracker を採用)。

共通する発想。2.8T パラメータ・1M トークン・百万トークン規模のエージェント軌跡という 3 つの「大きさ」をすべて GPU メモリだけで抱えるのは無理があります。一時停止したサンドボックスがメモリも CPU も消費しないという設計は、論文によればエージェントがモデルの推論結果を待っている時間がサンドボックス生存期間の最大 98% を占めるという観察に基づいています ― 待ち時間の大半を「何も食わない」状態にできれば、並行して保持できるエージェント数が跳ね上がります。K3 は「今すぐ計算に使わないものは CPU 側 (DRAM) に退避し、必要になったら戻す」という判断をあちこちに仕込むことで、GPU をボトルネックにしない基盤を作っています。

9精度戦略 — FP8 で貯め、MXFP4 で配る

数値精度の使い分けも徹底しています。

  • 事前学習: backward のために保存しておく活性化の多くをブロック単位の FP8 量子化 (＋オフロード) でメモリ節約 (これは活性化の記憶を軽くする策で、学習の演算そのものを FP8 で行っているかは今回参照した範囲では確認できていません)。
  • 事後学習: SFT 以降で量子化を意識した学習 (QAT: Quantization-Aware Training。量子化後の精度低下を見越して、学習中からその劣化ごと最適化する手法) を行い、パラメータ記憶の大半を占めるMoE エキスパートの重みを MXFP4、その入力活性化を MXFP8 に量子化。Attention の射影や LatentMoE の射影・共有エキスパートなど、それ以外の成分は量子化の対象から外している。
ねらい。896 個もあるエキスパートの重みはメモリの大半を占めるので、そこだけ 4 ビットまで削って配布・推論コストを下げる一方、量子化の影響を受けやすい非エキスパート部分は高い精度を保つ、という選択的な量子化です。学習時から量子化を見据えて訓練 (QAT) しておくことで、配布時の劣化を抑えています。

10都市伝説チェック — Graviton は本当に使っているのか

「K3 は AWS Graviton (ARM CPU) を使っている」という話をよく見かけるので、ここで正直に検証します。

結論: 一次資料 (Kimi K3 技術レポート, arXiv:2607.24653) 本文に "Graviton" ないし "ARM" への言及は見つかりませんでした。Sebastian Raschka のアーキテクチャ解説や日本語コミュニティ記事にも、Graviton/ARM の記載は確認できていません。技術レポートが明示的に述べている「珍しい CPU の使い方」は次の通りです (§8 参照): (1) 勾配シャードを CPU DRAM に保持する Pipeline ZeRO-2、(2) 退避した KV キャッシュ・プレフィックスを CPU DRAM の外部プールに置く仕組み、(3) 一時停止中はメモリも CPU も消費しない resumable microVM サンドボックス。いずれも「CPU (の主に DRAM 容量) を GPU の避難先として使う」という設計で、CPU の種類 (Graviton/ARM か x86 か) は論文中で特定されていません。

もし Graviton 採用について具体的な出典 (ブログのどの節、どのスライドか) があれば、それは技術レポート本体ではなく、Moonshot AI や AWS 側の別の発表・インフラ紹介の可能性があります。本記事では裏付けが取れなかった主張を断定で書かないという方針上、ここでは「未確認」として明記します。なお本記事の検証は技術レポートの本文テキストを機械的に抜き出して検索したものであり、図・表・脚注や OCR で読み取れなかった箇所は取りこぼしている可能性があります。「本文に見当たらない」は「存在しないことの証明」ではなく、現時点で確認できていない、という限定付きの結論です。
