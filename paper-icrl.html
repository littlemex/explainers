SFT なしで道具を使わせる

お手本を「プロンプトの中」に置いて RL を回し、少しずつ消していく — ICRL を読む

← 論文理解シリーズの目次へ

0この記事は何を読み解くのか

ICRL (In-Context Reinforcement Learning, NUS ほか, arXiv:2603.08068) は、言語モデルに検索エンジンや Python 実行といった外部ツールを使わせる訓練から、教師ありファインチューニング (SFT) の工程をまるごと取り除くことを狙った論文です。取り除いた穴を何で埋めるのか、そこが読みどころです。

一言でいうと
ツール使用を教える定番の手順は「SFT でお手本の軌跡を模倣させてから RL」ですが、SFT には大量の注釈済み軌跡が必要です。ICRL は SFT を捨てる代わりに、RL のロールアウト用プロンプトの中に少数のお手本 (few-shot 例) を置いたまま学習を始めます。そして学習が進むにつれてお手本の数を 3 個 → 2 個 → 0 個と段階的に減らし、最終的にお手本なしでツールを呼べる状態へ移行させます。お手本は 3 個だけ (GPT-5.2 に生成させたもの) で、Qwen2.5-7B の 5 つの QA ベンチマーク平均で 49.12 EM、SFT を使う既存手法の最良 (ParallelSearch 41.78) を +7.34 ポイント上回ったと報告されています。

1何が問題なのか — SFT の値札

まず、この論文が消したがっている工程が何なのかを確認します。

言語モデルに検索エンジンを使わせたいとします。モデルは「考える → 検索クエリを出す → 返ってきた文書を読む → また考える → 答える」という手順を、決まった書式で踏まなければいけません。ICRL が採用する書式は、Search-R1 系の研究で定番になった XML タグです。

<think> どの大統領か調べる必要がある </think> <search> president who set two term limit precedent </search> <information> Doc 1(Title: ...) ... Doc 3(Title: ...) ... </information> ← 検索エンジンが挿入 <think> George Washington だ。次に就任日を調べる </think> <search> when did George Washington enter office as president </search> <information> Doc 1(Title: ...) ... </information> ← 検索エンジンが挿入 <think> 1789 年 4 月 30 日 </think> <answer> April 30, 1789 </answer>

(論文 Table 5 の実例を要約したものです。Bamboogle の「2 期までという慣例を作った大統領はいつ就任したか」という 2 段推論の問題に、ICRL 訓練後の Qwen2.5-7B が 2 回の検索で正解しています。)

この書式と手順を教える方法は、大きく 2 つに分かれます。

やり方中身問題
コールドスタート型
(SFT → RL)		まず正解の軌跡を大量に集め、それを模倣する SFT で「書式と段取り」を体に入れる。その後 RL で精度を伸ばす軌跡の注釈・合成に大きな費用がかかる。人手なら高価、モデル合成なら強いモデルの API 費用と品質管理が必要
RL のみ検証可能な報酬 (正解かどうか) だけで、最初から RL を回す初期のモデルは道具の呼び方を知らないので、ほとんどのロールアウトが失敗する。探索が働かず学習が進まない

ICRL の主張はこうです。SFT が担っていたのは「良い初期方策を与えること」であって、そのためにモデルの重みを書き換える必要は必ずしもない。お手本をプロンプトに置いておけば、重みを触らずに同じ効果 (良い初期方策) が得られるのではないか、と。

ここが発想の中心です。SFT はお手本を重みに焼き付ける方法、few-shot プロンプトはお手本を文脈に置く方法です。後者は無料で始められますが、推論のたびに長いプロンプトを払い続ける必要があります。ICRL は「文脈に置いて始め、RL で重みが育ったら文脈から外す」という時間差の使い分けをします。次の節では、なぜ「良い初期方策」がないと RL が本当に動かないのかを、GRPO の式まで降りて体験します。

2【体験】RL 単体が動かない本当の理由

「探索が非効率だから」ではもったいないので、勾配が消える仕組みそのものを見ます。

ICRL が使う RL アルゴリズムは GRPO です。GRPO は 1 つの問題 $q$ に対して$N$ 本のロールアウト (この論文では 8 本) を同じ方策から生成し、そのグループ内での相対的な良さを学習信号にします。価値関数 (critic) を持たない代わりに、グループの平均と標準偏差で報酬を正規化します。

$$ A_i = \frac{R(\tau_i) - \mathrm{mean}\{R(\tau_1),\ldots,R(\tau_N)\}}{\mathrm{std}\{R(\tau_1),\ldots,R(\tau_N)\}} $$

この式には見逃せない性質があります。8 本すべてが同じ報酬だったとき、分子が 0 になり、そのグループからは何も学べません。道具の呼び方を知らないモデルで RL を始めると、8 本すべてが失敗する (報酬が全部 0) 状態が延々と続きます。「探索が非効率」というより、学習信号そのものが存在しないのです。

平均より上 (この振る舞いを増やす) 平均より下 (減らす) グループ全体が同じ報酬 = 勾配ゼロ

お手本 0 個・報酬は正解のみにしてグループを何度も引いてみてください。8 本が全滅して灰色になる (勾配が消える) グループが大半を占めます。お手本 3 個に切り替えると、当たりと外れが混ざったグループが増え、$A_i$ に符号がつきます。これが「few-shot 例が RL を離陸させる」の中身です。

もう 1 つ、この体験で見えることがあります。報酬に形式点 (0.2 の重み) を足すと、正解が 1 本もないグループでも報酬に差がつくため、勾配ゼロのグループが激減します。ICRL の報酬設計 (§5) は「正解に近づける」だけでなく、初期段階で学習信号を枯らさないための仕掛けとしても効いています。

デモの注意。ここで使っている「お手本の数ごとの正解率・書式違反率」は直感のために私が置いた例示値で、論文が報告している数値ではありません (論文は shot 数ごとの成功率を報告していません)。グループ内報酬が完全に一致したときの扱いも、実装によっては分母に微小項を足して 0 除算を避けるなど差があります。デモが示しているのは「全員同点だと学べない」という $A_i$ の構造的な性質と、形式点がそれを緩めることの 2 点だけです。

3ICRL の中身 — お手本をプロンプトに置く

手法そのものは驚くほど単純です。単純さがこの論文の売りでもあります。

ロールアウト用プロンプト

RL のロールアウト (方策にサンプルを生成させる工程) で使うプロンプトは、次の 3 段構えです。

[1] 指示: think/search/information/answer タグの使い方の説明。「何回検索してもよい」 [2] お手本: "Here are some examples:" の後に、問題と解答軌跡のペアを k 個 Example Problem: q_demo Example Solution: <think>...</think> <search>...</search> <information>...</information> <think>...</think> <answer> a </answer> (これを k 回繰り返す。k = 0 のときは [2] のブロック全体を消す) [3] 本番: "Now solve the following problem:" + 実際の質問

方策はこの追加文脈 $\mathcal{P}_k$ に条件づけられた形になります。$k$ 個のお手本を含むプロンプトを $\mathcal{P}_k$ と書くと、

$$ \pi_\theta(y \mid \mathcal{P}_k, q, \mathcal{T}) = \prod_{t=1}^{|y|} \pi_\theta\big(y_t \mid \mathcal{P}_k,\, y_{<t},\, q,\, \mathcal{H}_t\big) $$

$\mathcal{H}_t$ は「それまでにモデルが取った行動と、ツールが返した観測」の履歴です。ツール $\mathcal{T}$ は文字列から文字列への関数 (検索クエリを渡すと上位 $k$ 件の文書が返る) としてモデル化されます。

カリキュラム: 3 → 2 → 0

学習はこう進みます。まず $k=3$ で RL を回します。ある程度学習が進んだところでいったん止め、プロンプトからお手本を 1 つ減らして ($k=2$) 学習を再開します。最後にお手本を全部外して ($k=0$) 学習を続けると、モデルはプロンプトの足場なしでツールを呼べるようになっている、という筋書きです。Algorithm 1 では、段ごとに学習データの分割 $\mathcal{D}^{(k)}$ を切り替えることも明示されています (同じ問題を段をまたいで再利用しない)。

ここが再現性の弱点です。論文本文は段の切り替え条件を「Once sufficient learning progress is observed (十分な進捗が観測されたら)」としか書いておらず、各段のステップ数を数値で示していません。なお arXiv の LaTeX ソースには、コメントアウトされた旧稿として「訓練の崩壊を避けるため各段はおよそ 100 ステップ、段 $i$ のチェックポイントを段 $i+1$ の初期モデルにする」という記述が残っています。公開された本文からは削られているため、追試するときは自分で決め打つしかありません。

GRPO と loss masking

最適化は GRPO です。目的は「報酬の期待値を上げつつ、参照モデルから離れすぎない」という標準形です。

$$ \max_{\pi_\theta}\ \mathbb{E}_{q\sim\mathcal{D},\, y\sim\pi_\theta(\cdot\mid q,\mathcal{T})}\big[r_\phi(q,y)\big] \;-\; \beta\,\mathbb{D}_{\mathrm{KL}}\big[\pi_\theta(y\mid q,\mathcal{T})\,\|\,\pi_{\mathrm{ref}}(y\mid q,\mathcal{T})\big] $$

ツールを使う RL に特有の処理が loss masking です。ロールアウトの列には、モデルが書いたトークンと検索エンジンが挿入したトークンが混ざっています。後者はモデルの意思決定の産物ではないので、方策勾配の対象から外します。次節でこれを目で見ます。

検索の回数 3

2 つのことが見えます。1 つは、ロールアウトのトークンの大半は検索結果であるということ。検索 3 回でも、モデルが書いた部分より挿入された文書のほうが長くなります。loss masking を切ると、この「他人が書いた文章」を模倣する方向に勾配が流れてしまいます。

もう 1 つは予算の話です。お手本 3 個のプロンプトは上限 5000 トークンの相当部分を占め、検索回数を増やすと応答側は上限 2048 トークンに迫ります。お手本を外すことは、精度のためだけでなく、文脈の予算を推論と検索結果に明け渡すためでもあります。few-shot プロンプトを永久に付けたままにする運用は、推論費用の面でも割に合いません。

デモの注意。各セグメントのトークン数 (think 40、search 12、information 300、answer 15、お手本 1 個 700 など) は桁感を合わせた例示値で、論文の実測ではありません。論文が数値で述べているのはプロンプト上限 5000 トークン・応答上限 2048 トークン・1 問あたり最大 6 回の検索・1 クエリあたり上位 3 文書という設定だけです。なお、挿入された検索結果が応答側の 2048 トークンに算入されるのかどうかは論文に明記がなく、このデモは「算入される」と仮定して描いています。

5報酬設計 — 正解 8 割・形式 2 割

報酬は 2 項の重み付き和です。単純ですが、重みと罰則の中身に読みどころがあります。

$$ r_\phi(q,y) = \alpha \cdot \mathrm{reward}_{\text{acc}} + (1-\alpha)\cdot \mathrm{reward}_{\text{format}}, \qquad \alpha = 0.8 $$

正解の項 $\mathrm{reward}_{\text{acc}}$ は完全一致 (exact match) で、正解文字列と一致すれば 1、そうでなければ 0 です。形式の項は1.0 から違反ごとの罰則を引いたものです。

$$ \mathrm{reward}_{\text{format}} = 1.0 - \sum_{v \in \mathcal{V}} \mathrm{penalty}(v) $$
違反論文が挙げる理由罰則
<answer> タグがない構造化された答えを必ず出させる0.5
<answer> タグの対応が崩れている正しい XML 構造が必要0.2
<think> タグがない推論を示すべき0.15
<think> タグの対応が崩れている正しい XML 構造が必要0.1
<search> を使っていない使える道具は使うべき0.1
答えの中身が空実質的な答えを書くべき0.2
この表から読み取れること。罰則の合計は 1.15 なので、$\mathrm{reward}_{\text{format}}$ は最悪 $-0.15$ まで落ちます。つまり全部違反すると報酬が負になり、単に 0 点なのではなく積極的に押し下げられます。また注目すべきは「<search> を使っていない」に 0.1 の罰則が付いている点です。これは「道具を使うこと自体」への直接の報酬で、検索が不要な問題でも検索を促す圧力になります。§7 で見るアブレーションの挙動 (検索せずに即答する失敗) と表裏の関係にあります。

なお、論文本文には「正確さに基づく明示的な報酬やモデルによる報酬付けを使う手法を上回った」という一文がありますが、ICRL 自身の報酬は完全一致という明示的な正確さ報酬です。ここは筆が滑った記述と読むのが自然です。

7アブレーションが本当に語っていること

論文で唯一のアブレーションは、カリキュラムの刻み方の比較です。この結果の読み方には注意が必要です。

3 段階 (3 → 2 → 0) と 4 段階 (3 → 2 → 1 → 0) を比べると、4 段階のほうが全 5 データセットで壊滅的に低いという結果になりました (§6 のアブレーション表示で確認できます)。平均 49.12 に対し 17.76 です。論文はこれを「お手本を早く削りすぎると早すぎる打ち切りを招き、複数ターンの推論が弱くなる」と説明し、検索ターン数の分布を根拠に挙げます。

検索ターン数1234567
3 段階 (累積終了率 %)0.0929.6570.2684.9493.7996.99100.00
4 段階 (累積終了率 %)23.2059.3983.3992.8097.4698.6899.91

確かに 4 段階のモデルは 23.2% の問題を検索 1 回で切り上げています (3 段階は 0.09%)。しかし「早すぎる打ち切り」だけでこの落差を説明するのは苦しいです。4 段階モデルの TriviaQA は 20.8 で、検索も学習もしていない素の Qwen2.5-7B の直接応答 (40.8) の半分しかありません。訓練によって元の性能を大きく損なっているのですから、これはカリキュラム設計の優劣というより、その条件で訓練が崩壊したと読むほうが素直です。

この比較から言えること・言えないこと。言えるのは「1-shot の段を挟む設定で、少なくとも 1 回、訓練が壊れた」ことです。言えないのは「刻みを細かくすると悪い」という一般則です。段の切り替え条件も学習率も乱数種も 1 通りしか報告されていないため、崩壊の原因が「1-shot の段の存在」なのか、その段の学習が長すぎた・短すぎたといった運用なのか、単なる 1 回の事故なのかを切り分けられません。ICRL のカリキュラムは効いているとしても、この図はその頑健さについては悪い知らせです。

8学習の途中で何が起きているか

Figure 3 の学習曲線 (Qwen2.5-7B、3-shot / 2-shot / 0-shot の 3 段) から、論文が読み取っている挙動です。

観測される量挙動論文の解釈
応答の長さお手本ありの段では安定。0-shot に切り替えた直後に短くなり、その後また伸びる足場を外された直後は短く崩れるが、長く構造化された出力を自力で組めるようになっていく
報酬訓練全体を通してほぼ横ばい形式と正解しかない疎な信号なので、報酬曲線からは進捗が見えにくい
有効な検索呼び出しの回数0-shot の段で増加するお手本がなくても道具を呼ぶ振る舞いが内部化された、という主張の主要な証拠
報酬が横ばいなのに評価が上がる、という組み合わせが要点です。これは報酬が飽和した (完全一致は当たるか外れるかの粗い信号) 一方で、方策の中身 — 何回検索するか、どこで打ち切るか — が変化し続けていることを意味します。報酬曲線だけを見て「学習が止まった」と判断すると、この種の訓練では判断を誤ります。逆に言えば、ICRL の進捗を監視する指標は報酬ではなく「有効な検索呼び出しの回数」だということです。追試するなら、まずここを計測できるようにしておくべきです。

9批判的に読む — 7 つの留保

手法の発想は魅力的です。だからこそ、数値をそのまま持ち帰る前に確認しておくべき点を挙げます。順序は影響の大きい順です。

(1) 検索器が何なのか、論文の中で食い違っている

これが最も重い問題です。実験設定の節 (§3.1) は「現実のツール使用を模すため、全モデルで Serper API を統合し、Google 検索から実時間の結果を取得する」と書いています。ところが実装詳細の節は「検索には BM25 検索器を使い、クエリごとに上位 3 文書を返す」と書いています。前者はライブの Web、後者は固定コーパスの古典的な語彙一致検索で、まったく別物です。

なぜ重いのか。比較対象の Search-R1・ZeroSearch・ParallelSearch の数値は各論文からの引用値で、それらは2018 年の Wikipedia ダンプ + E5 系の密ベクトル検索という共通設定で測られたものです。もし ICRL だけがライブの Google 検索を使っていたなら、+8.94 という差は手法の差ではなくコーパスと検索器の差で説明できてしまいます。TriviaQA での伸びが特に大きい (3B で +18.1) ことも、この仮説と整合します。どちらの記述が正しいのかは論文からは判定できません。追試する側にとっては、ここが最初に潰すべき点です。

(2) 「減らすこと」の効果を示す対照実験がない

ICRL の主張の核はお手本を段階的に減らすカリキュラムです。ところが実験にあるのは「3 → 2 → 0」と「3 → 2 → 1 → 0」の比較だけで、もっとも自然な対照である「3-shot のまま最後まで RL を回す」が測られていません。それがないと、報告された性能が「few-shot 例を入れて RL したこと」の効果なのか、「途中で減らしたこと」の効果なのかを分離できません。0-shot で評価するのだから 3-shot 固定では最後に不利になる、という反論はありえますが、それを数字で見せるのがまさに必要な実験です。

(3) ベースラインが引用値で、一部は明らかに壊れている

Qwen2.5-3B の CoT の平均が 1.52 EM (TriviaQA で 3.2) と報告されています。素の直接応答が 14.50 なのに、思考させると 10 分の 1 になるというのは手法の性能ではなく評価の失敗です。完全一致で採点しているため、CoT が長い前置きを付けると文字列が一致しなくなる、という類の現象でしょう。壊れたベースラインは相対比較を無意味にはしませんが (ICRL の相手は Search-R1 や ParallelSearch です)、表全体の数値が同じ厳しさで作られているとは仮定できないことを示しています。

(4) お手本 3 個は無償ではない

「注釈済みデータ不要」は正確ではありません。ICRL はGPT-5.2 に生成させた 3 例を使っています。量は劇的に少ない (数千件の SFT データに対して 3 例) ものの、性質としては強いモデルからの蒸留です。しかも例はたった 3 個なので、その 3 例の選び方・質に結果が敏感である可能性が高いのに、例を差し替えた場合の感度は測られていません。「安い」は正しく、「supervision なし」は言い過ぎ、というのが公平な整理です。

(5) 段の切り替え条件が不明で、頑健性の証拠がない

§3 で見たとおり、段の切り替えは「十分な進捗が観測されたら」という定性的な記述だけです。そして §7 で見たとおり、刻みを 1 つ増やした設定では訓練が崩壊しています。手順の中で最も重要な判断が人の目に委ねられ、その判断を間違えると壊れるという組み合わせは、実務で採るには不安が残ります。

(6) 差の大きさに対して試行回数が足りない

QA 側は各データセット最大 500 問なので、平均 7 ポイント差は統計的にはまず安全です。一方数式側の AIME は 1 年分 30 問で、2.4 ポイントは 1 問未満に相当します。さらに乱数種は 1 つだけで、種を変えた再現は報告されていません。§7 の崩壊が示すとおり、この訓練は run 間の分散が小さいとは言えません。

(7) 記法と予算に小さな不整合がある

数式では$N$ がお手本の数と GRPO のグループサイズの両方に使われています (Algorithm 1 では「$\mathcal{P}_N$ から $k$ 例を選ぶ」一方で「$N$ 本の軌跡をサンプルする」)。実際にはお手本 3 個・グループ 8 本です。また応答上限 2048 トークンで最大 6 回の検索を許すという設定は、1 クエリ 3 文書という取得量と噛み合っておらず (§4 参照)、検索結果が上限に算入されるのかどうかが読み取れません。

それでも残るもの。以上を差し引いても、「SFT の代わりに、お手本を文脈に置いた状態で RL を始める」という発想そのものは筋が通っており、安いという点は動きません。§2 で見た「グループ内の報酬が全員同点だと勾配が消える」という GRPO の性質は実在し、few-shot 例はそれを最小の費用で崩す手段です。疑わしいのは報告された数値の大きさと、カリキュラムの刻みという細部への帰属であって、着想ではありません。
