二分探索 ― 正しさと境界条件をビジュアルに

ソート済み配列を対数時間で探す。鍵は lo/hi/mid が守り続ける不変条件

← コーディング基礎 シリーズ目次へ

二分探索は「配列を半分に割って捨てる」だけの単純な操作の繰り返しですが、境界の書き方をひとつ間違えるだけで無限ループや off-by-one に陥ります。ここでは、なぜ正しく動くのかを「不変条件 (invariant)」という考え方から説明し、$O(\log n)$ の理由、半開区間と閉区間の違い、オーバーフロー回避、lower_bound/upper_bound までを図と数式で確認します。

1. なぜ $O(\log n)$ なのか

二分探索は「ソート済みの配列が前提」です。中央の要素 mid を見て、目的の値より小さければ右半分だけを、大きければ左半分だけを残す。1 回の比較で残る要素数が半分になるので、$n$ 個の要素が 1 個になるまでの繰り返し回数はおよそ $\log_2 n$ 回です (厳密には最悪 $\lfloor \log_2 n \rfloor + 1$ 回程度)。

図: 1 回の比較で残る候補数が半分になるため、繰り返し回数はおよそ $\log_2 n$ 回で済む

2. 不変条件 (invariant) ― lo / hi / mid が守るもの

二分探索の正しさは「ループの間、常に成り立ち続ける命題」= 不変条件で保証されます。半開区間 $[lo, hi)$ を使い、a[mid]==x で即座に return する「完全一致探索」版で説明すると、不変条件は次の通りです。

「目的の値 $x$ が配列内に存在するなら、その位置は常に $[lo, hi)$ の中にある」

ループの各ステップはこの命題を破らないように lo か hi だけを動かします。a[mid] を調べた時点で、mid 自身は必ず「捨てる側」に含まれるので、区間は毎回確実に縮みます。ループが終わるとき ($lo = hi$) には区間の幅が 0、つまり空区間になっており、これは「配列全体を調べ終えても $x$ が見つからなかった」ことを意味します。(区間の幅が 1 点に絞られて答えが確定する、という形にしたい場合は lower_bound 型の不変条件 ― 答えは常に閉区間 $[lo, hi]$ にあり、$hi$ の初期値は $n$ ― を使う必要があり、本ページの半開区間・完全一致探索の説明とは前提が異なります。)

図: mid 自身は必ずどちらかの捨てる側に含まれるので区間は毎回確実に縮む (緑の帯の中に x があるはず、という命題を保ち続ける)

3. なぜ mid = lo + (hi - lo) / 2 なのか

直感的には mid = (lo + hi) / 2 でよさそうに見えますが、これは 整数オーバーフローの罠があります。オーバーフローは正確には $lo + hi > \text{INT\_MAX}$ のときに発生し、lo・hi の両方が $2^{30}$ (約 10 億) 程度を超えていれば十分に起こり得ます (「配列の最大インデックス付近」である必要はありません)。実際に Java の Arrays.binarySearch にはこの折り返りバグが実在し、2006 年に発覚して修正されたことで知られています。

mid = lo + (hi - lo) / 2 は数学的には同じ値ですが、$hi - lo$ は常に区間の幅 (小さい値) なので、この式全体が int の範囲を超えません。

// オーバーフローの恐れがある書き方
int mid = (lo + hi) / 2;

// 安全な書き方
int mid = lo + (hi - lo) / 2;

4. 半開区間 $[lo, hi)$ と閉区間 $[lo, hi]$ ― 無限ループの典型ミス

二分探索の実装は「区間をどう表すか」で 2 系統に分かれます。どちらも正しく書けますが、更新式を混ぜると無限ループになります。

区間の形終了条件更新 (小さい側を捨てる)更新 (大きい側を捨てる)
半開 $[lo, hi)$while (lo < hi)lo = mid + 1hi = mid
閉 $[lo, hi]$while (lo <= hi)lo = mid + 1hi = mid - 1
典型ミス。閉区間 $[lo, hi]$ の終了条件 (lo <= hi) を使っているのに、大きい側を捨てるとき hi = mid としてしまうと、lo == hi == mid の状態から一歩も進めず無限ループします。半開区間なら hi = mid で正しく縮みますが、閉区間なら必ず hi = mid - 1 にしなければなりません。区間の種類と更新式は必ずセットで覚える必要があります。

半開区間版の完全な実装

int binarySearch(int[] a, int x) {
  int lo = 0, hi = a.length;      // 半開区間 [lo, hi)
  while (lo < hi) {                // 幅 0 になるまで
    int mid = lo + (hi - lo) / 2;  // オーバーフロー安全
    if (a[mid] == x) return mid;   // 見つかった
    else if (a[mid] < x) lo = mid + 1; // [lo, mid] を捨てる
    else hi = mid;                  // [mid, hi) を捨てる
  }
  return -1;                        // 幅 0 = 見つからなかった
}

5. lower_bound と upper_bound

値がちょうど見つかるかどうかだけでなく、「以上の最小位置」(lower_bound) や「より大きい最小位置」(upper_bound) を求める二分探索もよく使われます。重複がある配列で「挿入すべき位置」や「範囲の左右端」を求めるときに使います。

  • lower_bound($x$): $a[i] \ge x$ を満たす最小の $i$。「$x$ 未満」を捨てながら縮める。
  • upper_bound($x$): $a[i] > x$ を満たす最小の $i$。「$x$ 以下」を捨てながら縮める。

両者の違いは比較演算子の 1 文字 (< か <=) だけですが、この 1 文字が「値 $x$ が複数個並んでいる範囲の左端を返すか右端を返すか」を決めます。
