269. Alien Dictionary

辞書順に並んだ単語リストから、未知のアルファベットの並び順を 1 つ復元する。隣り合う単語を比べて「この文字はこの文字より前」という制約を辺にし、トポロジカルソートで順序を決める。

問題

ある未知の言語も、英語のアルファベットと同じ 26 文字を使いますが、文字の並び順 (どれが「小さい」か) は違います。その言語の辞書順で並んでいる (と仮定してよい) 単語のリスト words が与えられます。words に現れる文字をすべて 1 回ずつ、その言語での小さい順に並べた文字列を返してください。そのような並べ方が存在しない (並びに矛盾がある) 場合は空文字列 "" を返します。正しい並べ方が複数ある場合は、どれを返しても構いません。

  • 通常の辞書順と同じルールが使われているとします。つまり、2 つの単語を先頭から比べて最初に違う文字が出てきた位置で、その文字同士の大小で単語全体の大小が決まります。また、一方がもう一方の接頭辞 (prefix) であれば、短い方が辞書順で先に来ます。
  • words の中に、ある単語 a の後ろに、a を接頭辞とするもっと短い単語 b が出てくる場合は、どんな文字順でもこの並びを満たせないので、答えは "" です (例: ["abc", "ab"])。

制約

  • 1 <= words.length <= 100
  • 1 <= words[i].length <= 100
  • words[i] はすべて小文字の英字のみからなる

例

words = ["wrt","wrf","er","ett","rftt"] → "wertf" (妥当な順序ならほかの文字列でもよい)
"wrt" と "wrf" は 3 文字目で初めて違うので、t が f より先 (t → f)。"wrf" と "er" は 1 文字目が違うので w → e。"er" と "ett" は 2 文字目が違うので r → t。"ett" と "rftt" は 1 文字目が違うので e → r。これらをつなぐと w → e → r → t → f となり、"wertf" が得られます。
words = ["z","x"] → "zx"
1 文字だけの単語を比べると z が x より先。
words = ["z","x","z"] → ""
z → x (1 番目と 2 番目) かつ x → z (2 番目と 3 番目) になり、z が x より先かつ x が z より先という循環が生まれるので、矛盾として "" を返します。

考え方

隣り合う 2 つの単語を比べ、最初に違う文字が出てくる位置を見つけると、「前の単語の文字 → 後の単語の文字」という 1 つの順序制約がわかります。これを 26 文字を頂点とした有向グラフの辺だと考えると、「全部の制約を満たす文字の並び」は、このグラフのトポロジカルソート (すべての辺が「前 → 後」の向きを守るように頂点を並べる並べ方) そのものです。

トポロジカルソートは、まだ「前」を待っている制約が残っていない文字 (入次数、つまり自分より前にあるべき文字の数が 0 の文字) から順に確定させていく方法 (Kahn のアルゴリズム) で求められます。確定させた文字から出ている辺をすべて取り除く (つまり相手の入次数を 1 減らす) と、また新しく入次数 0 になる文字が出てくるので、それをキューに入れて繰り返します。

最後まで確定できる文字の数が、登場した文字の種類数より少なければ、どこかに循環があって順序を決められないということです。このときだけ "" を返します。
「短い単語が長い単語の後に出てくる、かつ長い方が短い方の接頭辞になっている」ケースは、文字同士の比較では見つかりません (違う文字が 1 つも無いからです)。ここだけ特別にチェックが必要です。

動くデモ

黄色が今比べている文字、青が「次に来る」とわかった文字です。辺は「矢印の根もと → 先の文字」の順序制約を表し、緑は確定して順序に追加した文字です。

解答 (C++)


class Solution {
public:
    string alienOrder(vector<string>& words) {
        unordered_map<char, unordered_set<char>> adj;
        unordered_map<char, int> indeg;
        for (const string& w : words) for (char c : w) { adj[c]; indeg[c]; }

        for (int i = 0; i + 1 < (int)words.size(); i++) {
            const string& a = words[i], &b = words[i + 1];
            int n = min(a.size(), b.size());
            bool found = false;
            for (int j = 0; j < n; j++) {
                if (a[j] != b[j]) {
                    if (!adj[a[j]].count(b[j])) {
                        adj[a[j]].insert(b[j]);  //@edge
                        indeg[b[j]]++;
                    }
                    found = true;
                    break;
                }
            }
            if (!found && a.size() > b.size()) return "";  //@invalid
        }

        queue<char> q;
        for (auto& [c, d] : indeg) if (d == 0) q.push(c);
        string order;
        while (!q.empty()) {
            char c = q.front(); q.pop();
            order += c;  //@pop
            for (char nxt : adj[c]) if (--indeg[nxt] == 0) q.push(nxt);
        }
        if (order.size() != indeg.size()) return "";  //@cycle
        return order;
    }
};
時間計算量O(C)。C は全単語の合計文字数です。隣接単語の比較は各単語ペアで最初の違いまでしか見ないので、全体で単語の合計長に収まります。トポロジカルソートは頂点数 (最大 26) と辺数に比例します。
空間計算量O(1) 相当 (文字種は最大 26 なので、グラフと入次数の表は定数サイズです)。

よくある間違い

  • 単語全体を文字コードで比較してしまい、1 文字ごとの順序制約を作らない。
  • 「長い単語が短い単語の接頭辞で、かつ後に出てくる」ケースを見落とし、矛盾した入力を受け入れてしまう。
  • 同じ文字ペアの制約を何度も辺として数え、入次数を余分に増やしてしまう (すでにある辺なら追加しない)。
  • 最後に「確定した文字数 == 登場した文字種の数」を確認せず、循環があっても途中までの結果を返してしまう。

確認問題

Q1. なぜ隣り合う単語だけを比べればよいのですか? 全ての単語の組を比べなくてよいのですか?

辞書順に並んでいるという前提から、隣り合う単語同士の制約をすべて集めれば、それより離れた単語同士の関係は推移律 (a が b より前、b が c より前なら a は c より前) で自動的に満たされます。

Q2. 答えが複数ありうるのはどんなときですか?

まだ比較されていない文字同士、つまりグラフ上で辺がつながっていない文字同士は、どちらを先にしても制約に違反しません。そのため複数の妥当な並びが存在します。
