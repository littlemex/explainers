703. Kth Largest Element in a Stream

テストの点数が次々流れてくる中で、常に「上から k 番目に大きい値」を答え続ける。サイズ k の最小ヒープを持てば、その先頭がいつも答えになる。

問題

あなたは大学の入試事務局の一員で、受験者のテストの点数の中から、リアルタイムに「上から k 番目に高い点数」を把握し続ける必要があります。これは、新しい受験者が点数を提出するたびに、面接や入学の合格ラインを動的に決める助けになります。

与えられた整数 k に対して、テストの点数の流れを保持し、新しい点数が提出されるたびに「上から k 番目に高い点数」を返し続けるクラスを実装してください。より正確には、すべての点数を並べたときの、大きい方から数えて k 番目の点数を求めます。

KthLargest クラスを実装してください。

  • KthLargest(int k, int[] nums) 整数 k と、点数の流れ nums を使ってオブジェクトを初期化する。
  • int add(int val) 新しい点数 val を流れに追加し、これまでに出てきた点数の集まりの中で、k 番目に大きい要素を返す。

制約

  • 0 <= nums.length <= 10^4
  • 1 <= k <= nums.length + 1
  • -10^4 <= nums[i] <= 10^4
  • -10^4 <= val <= 10^4
  • add の呼び出しは最大 10^4 回まで。

例

["KthLargest","add","add","add","add","add"] [[3,[4,5,8,2]],[3],[5],[10],[9],[4]] → [null,4,5,5,8,8]
KthLargest kthLargest = new KthLargest(3, [4, 5, 8, 2]); で開始する (k = 3)。
kthLargest.add(3) → 4 を返す。
kthLargest.add(5) → 5 を返す。
kthLargest.add(10) → 5 を返す。
kthLargest.add(9) → 8 を返す。
kthLargest.add(4) → 8 を返す。
["KthLargest","add","add","add","add"] [[4,[7,7,7,7,8,3]],[2],[10],[9],[9]] → [null,7,7,7,8]
KthLargest kthLargest = new KthLargest(4, [7, 7, 7, 7, 8, 3]); で開始する (k = 4)。
kthLargest.add(2) → 7 を返す。
kthLargest.add(10) → 7 を返す。
kthLargest.add(9) → 7 を返す。
kthLargest.add(9) → 8 を返す。

考え方

呼び出しのたびに全部の点数をソートし直せば答えは出ますが、点数が増えるたびに O(n log n) かかり、add が最大 10^4 回呼ばれると遅すぎます。

欲しいのは「上から k 番目の値」だけなので、すべての点数を覚えておく必要はありません。これまで見た中で上位 k 個の値だけをサイズ k の最小ヒープ (優先度付きキュー。常に最小値を一瞬で取り出せる木構造) に入れておきます。最小ヒープの先頭には、その k 個の中で最も小さい値、つまり「上から k 番目の値」そのものが乗っています。

新しい点数 val が来たら、まずヒープに入れます。これでヒープのサイズが k を超えたら、先頭 (= その時点での最小値、つまり k + 1 番目以下の値) を 1 つ取り除きます。こうして常にサイズを k に保てば、ヒープの先頭がそのまま答えになります。

初期化時に渡される nums も、add を呼ぶのと同じ手順で 1 つずつヒープに入れてしまえば、コンストラクタと add のロジックを共通化できます。
k > nums.length のときは、最初のヒープのサイズが k に届きません。この状態で add が呼ばれ、ヒープのサイズがちょうど k になった瞬間が最初の有効な答えです (制約上、答えが存在しないタイミングで add の戻り値が使われることはありません)。

動くデモ

黄色が今追加した値、赤がヒープから追い出された (捨てられた) 値です。ヒープは配列として、添字 0 を根とする二分ヒープの形で木も並べて表示します。

解答 (C++)


class KthLargest {
public:
    KthLargest(int k, vector<int>& nums) : k_(k) {
        for (int x : nums) add(x);  //@init
    }

    int add(int val) {
        heap_.push(val);  //@push
        if ((int)heap_.size() > k_) heap_.pop();  //@evict
        return heap_.top();  //@top
    }

private:
    int k_;
    priority_queue<int, vector<int>, greater<int>> heap_;  // サイズ k の最小ヒープ (これまでの上位 k 個)
};
時間計算量add は O(log k) (push と、必要なら pop の 2 回のヒープ操作)。コンストラクタは nums.length 個に対して add を呼ぶので O(n log k)。
空間計算量O(k)。ヒープには常に高々 k 個しか入りません。

よくある間違い

  • 最大ヒープを使い、全要素を保持してしまう。これだと k 番目を取り出すのに毎回 k 回 pop する必要があり、サイズ k の最小ヒープより遅くなります。
  • ヒープのサイズが k を超えたときに pop し忘れ、ヒープがどんどん大きくなってしまう (先頭が「上から k 番目」ではなくなる)。
  • コンストラクタで nums をヒープに全部入れるだけで、サイズを k に絞らずに終えてしまう。

確認問題

Q1. なぜ最小ヒープのサイズを k に保つと、先頭が「上から k 番目」になりますか?

ヒープに入っている k 個は、これまで見た値のうち上位 k 個です。その中で最小の値 (ヒープの先頭) は、上位 k 個の中でいちばん小さい、つまり全体で見ると「上から k 番目」にちょうど一致します。

Q2. k が非常に大きく、点数の総数に近い場合はどうなりますか?

ヒープのサイズが点数の総数に近づくので、メモリと計算量は O(n log n) に近づきます。それでも「毎回全体をソートし直す」方法より速いままです。

Q3. 215. Kth Largest Element in an Array (ストリームでなく、固定の配列から 1 回だけ k 番目を求める問題) とはどこが違いますか?

あちらは 1 回限りの問いなので quickselect (ソートせずに k 番目を見つける選択アルゴリズム) で平均 O(n) にできます。この問題は値が次々追加されるストリームなので、追加ごとに素早く答えを更新できるヒープの方が向いています。
