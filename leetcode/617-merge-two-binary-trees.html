617. Merge Two Binary Trees

2 つの二分木を 1 つに重ね合わせる。両方にノードがあれば値を足し、片方にしか無ければそのノードをそのまま使う。

問題

2 つの二分木 root1 と root2 が与えられます。

片方の木をもう片方の上に重ねて置いたときのことを想像してください。2 つの木のノードのうち、重なる位置にあるものと、重ならない位置にあるものがあります。この 2 つの木を 1 つの新しい二分木にマージする必要があります。マージの規則は、2 つのノードが重なる場合はその値を足し算して新しいノードの値にし、重ならない場合は null でない方のノードを新しい木のノードとして使う、というものです。

マージした木を返してください。

注: マージの処理は、必ず両方の木の根のノードから始めなければなりません。

制約

  • 2 つの木を合わせたノードの個数は [0, 2000] の範囲です。
  • -10^4 <= Node.val <= 10^4

例

root1 = [1,3,2,5], root2 = [2,1,3,null,4,null,7] → [3,4,5,5,4,null,7]
root1 は根が 1 で、左の子が 3 (さらに左の子として 5 を持つ)、右の子が 2 です。root2 は根が 2 で、左の子が 1 (さらに右の子として 4 を持つ)、右の子が 3 (さらに右の子として 7 を持つ)。重なる位置では値を足し算します: 根は 1 + 2 = 3、左の子は 3 + 1 = 4、右の子は 2 + 3 = 5。root1 側にしかない 5 (左の子の左の子) と、root2 側にしかない 4 (左の子の右の子) と 7 (右の子の右の子) は、そのまま新しい木のノードとして使われます。
root1 = [1], root2 = [1,2] → [2,2]
root1 は根 1 だけの木です。root2 は根が 1 で、右の子が 2 です。根は両方にあるので 1 + 1 = 2。右の子は root2 にしかないので、そのまま 2 を使います。左の子はどちらの木にも無いので、結果の木にも左の子はありません。

考え方

木を重ねる作業は「根でどうするか」を決めたあと、「左の子どうし」と「右の子どうし」でも全く同じ作業をすればいいので、再帰 (同じ処理を小さい問題に対して自分自身で繰り返し呼ぶこと) にぴったりの形をしています。

1 つの位置について考えられるのは次の 3 パターンです。

  • 両方にノードがある → 値を足して新しいノードを作り、左の子どうし・右の子どうしを再帰でマージする。
  • 片方にしかノードが無い → そのノードをそのまま新しい木の一部として使う (もう片方には何も無いので、足す相手がいません)。
  • 両方に無い → 何も作らない (null のまま)。
「片方に無い」ときに 0 を足したノードを新しく作ってしまう人がいますが、そうすると元の木には無かったノードが増えてしまいます。片方が無いときは、存在する方のノードをそのまま使うのが正しい方法です。
「両方に無い」場合を別の条件として書く必要はありません。root1 が無いときに root2 をそのまま返すコードを書けば、root2 も無ければ自動的に null が返るので、これで両方無いケースも一緒にカバーできます。

動くデモ

左 2 つの木が入力 (root1, root2)、黄色が今マージしている位置です。右の木は、できあがったマージ後の部分木で、緑が完成したノードです。

解答 (C++)


class Solution {
public:
    TreeNode* mergeTrees(TreeNode* root1, TreeNode* root2) {
        if (!root1) return root2;  //@only2
        if (!root2) return root1;  //@only1
        TreeNode* merged = new TreeNode(root1->val + root2->val);  //@sum
        merged->left = mergeTrees(root1->left, root2->left);  //@left
        merged->right = mergeTrees(root1->right, root2->right);  //@right
        return merged;
    }
};
時間計算量O(min(m, n))。m, n はそれぞれの木のノード数です。両方にノードがある位置だけ再帰が深く進み、片方が無くなった位置でそれ以上は進みません。
空間計算量O(min(m, n))。再帰の深さの分だけ呼び出しスタックを使います。

よくある間違い

  • 片方のノードが無いときに、無い方を値 0 のノードとして扱って足し算してしまう。無い方はそのまま使うのが正しく、新しいノードを作る必要はありません。
  • root1 を直接書き換えてマージ結果にしてしまう。問題を解くだけなら動きますが、元の木を壊さずに新しい木を作りたい場合は new TreeNode(...) で新しく作る必要があります。
  • 左の子と右の子のどちらかだけ再帰して、もう片方を忘れる。両方の子について再帰を呼ぶ必要があります。

確認問題

Q1. 両方の木が空 (ノードが 1 つも無い) ときの答えは?

null (空の木) です。root1 が無いので return root2 が実行され、root2 も無いのでそのまま null が返ります。

Q2. 元の木 root1, root2 を壊さずにマージするには、どこに注意すればよいですか?

merged->left = ... のように既存のノードを直接つなぎ直すのではなく、両方にノードがある位置では必ず new TreeNode(...) で新しいノードを作ることです。片方にしかない位置では、そのノードをそのまま新しい木の一部として共有しても (壊さなければ) 問題ありません。

Q3. この再帰は深さ優先 (DFS) と幅優先 (BFS) のどちらですか?

深さ優先です。1 つの位置について、左の子をマージし切ってから右の子に進むのではなく、再帰呼び出しの順番どおり左の部分木を最後まで掘り進めてから戻ってきます。BFS で段ごとに書くこともできますが、再帰の方が自然に書けます。
