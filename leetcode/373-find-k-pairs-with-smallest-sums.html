373. Find K Pairs with Smallest Sums

ソート済みの 2 つの配列から、和が小さい組を k 個取り出す。最小ヒープに「次に小さくなりそうな組」だけを持たせれば、全部の組を作らずに済む。

問題

非減少順 (隣と同じ値があってもよい、広い意味での昇順) にソートされた 2 つの整数配列 nums1 と nums2、そして整数 k が与えられます。

1 番目の配列から 1 つ、2 番目の配列から 1 つ選んだ要素の組を (u, v) と定義します。

和が最も小さい k 個の組 (u1, v1), (u2, v2), ..., (uk, vk) を返してください。

例

nums1 = [1,7,11], nums2 = [2,4,6], k = 3 → [[1,2],[1,4],[1,6]]
考えられる組を和が小さい順に並べると [1,2],[1,4],[1,6],[7,2],[7,4],[11,2],[7,6],[11,4],[11,6] となり、先頭の 3 個を返します。
nums1 = [1,1,2], nums2 = [1,2,3], k = 2 → [[1,1],[1,1]]
考えられる組を和が小さい順に並べると [1,1],[1,1],[1,2],[2,1],[1,2],[2,2],[1,3],[1,3],[2,3] となり、先頭の 2 個を返します。

制約

  • 1 <= nums1.length, nums2.length <= 10^5
  • -10^9 <= nums1[i], nums2[i] <= 10^9
  • nums1 と nums2 はどちらも非減少順にソートされています。
  • 1 <= k <= 10^4
  • k <= nums1.length * nums2.length

考え方

素直に考えると、すべての組 nums1.length × nums2.length 通りを作ってソートし、先頭 k 個を取ればよさそうです。しかし配列の長さが 10^5 にもなるので、組の総数は最大で 10^10 通りにもなり、作ることも、ソートすることもできません。

ここで使うのは「次に小さくなりそうな組だけを覚えておく」という考え方です。両方の配列はソート済みなので、nums1[i] を固定したとき、和が小さい順に試すべき相手は nums2[0], nums2[1], nums2[2], ... の順です。つまり (i, j) という組を使ったら、次に有力な候補は同じ i に対する (i, j+1) だけでよく、それを最小ヒープ (常に一番小さい値を一瞬で取り出せる木構造) に入れておきます。

最初にヒープへ入れるのは (nums1[i] + nums2[0], i, 0) を i = 0, 1, ..., min(k, nums1.length) - 1 の分だけです (答えは k 個しか要らないので、nums1 側の候補も k 個で十分)。ヒープから和が最小の組 (i, j) を取り出して答えに加え、j + 1 がまだ nums2 の範囲内なら (nums1[i] + nums2[j+1], i, j+1) を新しくヒープへ入れます。これを k 回繰り返せば、ヒープの大きさは常に O(k) に収まります。

nums1 の先頭 k 個分だけをヒープの種にすれば十分な理由は、答えの k 個の組それぞれが使う nums1 側の添字は、重複を許してもちょうど k 通りしか登場できないからです。i >= k の行は、より小さい和を持つ行が先に k 個分使い切られるため、答えに入る前に処理が止まります。
(i, j) を取り出すたびに (i+1, j) も (i, j+1) も両方ヒープに入れてしまうと、同じ組を何度も重複して入れてしまいます。片方 (ここでは j 方向) だけを進めるのが正解です。

動くデモ

黄色が今 nums1 / nums2 で指している添字の組、青がヒープから取り出されて答えに決まった組です。右のヒープには (和, i, j) の組が並びます。

解答 (C++)


class Solution {
public:
    vector<vector<int>> kSmallestPairs(vector<int>& nums1, vector<int>& nums2, int k) {
        vector<vector<int>> res;
        if (nums1.empty() || nums2.empty() || k <= 0) return res;
        int n1 = (int)nums1.size(), n2 = (int)nums2.size();
        auto cmp = [](const array<int,3>& a, const array<int,3>& b) { return a[0] > b[0]; };  //@cmp
        priority_queue<array<int,3>, vector<array<int,3>>, decltype(cmp)> pq(cmp);
        for (int i = 0; i < min(n1, k); i++) pq.push({nums1[i] + nums2[0], i, 0});  //@seed
        while (!pq.empty() && (int)res.size() < k) {
            auto top = pq.top(); pq.pop();  //@pop
            int i = top[1], j = top[2];
            res.push_back({nums1[i], nums2[j]});  //@push
            if (j + 1 < n2) pq.push({nums1[i] + nums2[j + 1], i, j + 1});  //@next
        }
        return res;
    }
};
時間計算量O(k log k)。ヒープの大きさは常に O(k) で、取り出し・追加を合わせて最大 O(k) 回行います。
空間計算量O(k)。ヒープと答えの配列に使います。

よくある間違い

  • すべての組を 2 重ループで作ってからソートしてしまい、配列が大きいと時間・メモリの両方で間に合わない。
  • (i, j) を処理するたびに (i+1, j) と (i, j+1) の両方をヒープに入れてしまい、同じ組を二重に数える。
  • nums1 の全要素を種としてヒープに入れてしまい、nums1.length が k より大きいときに無駄な候補を抱える (min(k, nums1.length) 個で十分)。

確認問題

Q1. ヒープの種を nums1 の先頭 k 個に絞れるのはなぜですか?

答えの k 個の組は、nums1 側の添字をどれだけ重複して使っても合計で k 回しか登場しないため、i が k 以上になる行は答えに届く前に処理が止まるからです。

Q2. なぜヒープから取り出した後は j 方向にだけ進めるのですか?

i 方向にも進めてしまうと、同じ (i+1, j) という組が複数の経路から重複してヒープに入ってしまいます。i ごとに「次に試す j」を 1 つだけ管理すれば、重複なくすべての組を小さい和の順に発見できます。

Q3. k が nums1.length * nums2.length ちょうどのとき、答えはどうなりますか?

制約でその場合も保証されているので、すべての組を和が小さい順に並べた配列がそのまま答えになります。アルゴリズムはヒープが空になるまで自然に動作します。
