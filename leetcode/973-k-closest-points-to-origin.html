973. K Closest Points to Origin

原点から近い点を k 個選ぶ。距離の 2 乗でサイズ k の最大ヒープを保てば、ソートせずに答えが絞り込める。

Mediumヒープ (優先度付きキュー)
← LeetCode 問題集の一覧へ LeetCode の原文を開く ↗

問題

points[i] = [xi, yi] が XY 平面上の点を表す配列 points と、整数 k が与えられます。原点 (0, 0) に最も近い k 個の点を返してください。

XY 平面上の 2 点間の距離は、ユークリッド距離 (直線距離) です。すなわち √((x1 - x2)² + (y1 - y2)²) です。

答えはどんな順番で返してもかまいません。答え (どの k 個の点が選ばれるか) は一意に決まることが保証されています (ただし、その k 個をどの順番で並べるかは問いません)。

制約

  • 1 <= k <= points.length <= 10^4
  • -10^4 <= xi, yi <= 10^4

例

points = [[1,3],[-2,2]], k = 1 → [[-2,2]]
(1, 3) と原点の距離は √10。(-2, 2) と原点の距離は √8。√8 < √10 なので (-2, 2) の方が原点に近いです。最も近い k = 1 個だけを求めるので、答えは [[-2,2]] です。
points = [[3,3],[5,-1],[-2,4]], k = 2 → [[3,3],[-2,4]]
[[-2,4],[3,3]] のように順番を入れ替えた答えも正解として認められます。

考え方

全部の点を距離でソートして先頭 k 個を取れば答えは出ますが、O(n log n) かかります。欲しいのは上位 k 個だけなので、全体を並べ切る必要はありません。

そこで、サイズ k の最大ヒープ (優先度付きキュー。先頭に最も大きい値が来る木構造) に、今までに見た点の中で「原点に近い方から k 個」を保ちます。点を 1 つ見るたびにヒープへ入れ、サイズが k を超えたら、ヒープの先頭 (= 入っている k 個の中で最も遠い点) を 1 つ追い出します。すべての点を見終えたとき、ヒープに残っている k 個が答えです。

距離を比べるだけなら、平方根 (√) を計算する必要はありません。a < b なら a² < b² (どちらも 0 以上なので) なので、距離の 2 乗のまま比較すれば十分で、浮動小数点の計算を避けられます。

サイズ k の最小ヒープで「遠い方から」持つのではなく、最大ヒープで「近い方から k 個」を保つのが考え方です。先頭にある最大値が、追い出すべき (最も遠い) 候補になります。
k がほぼ points.length のときは、ヒープがほとんど縮まらず、追い出しがほとんど起きません。それでも正しく動きますが、「k が小さいときほど速い」という性質がなくなる点に注意してください。

動くデモ

黄色が今見ている点、赤がヒープから追い出された点、緑が最終的に答えに残った点です。

解答 (C++)


class Solution {
public:
    vector<vector<int>> kClosest(vector<vector<int>>& points, int k) {
        auto dist2 = [](const vector<int>& p) { return (long long)p[0] * p[0] + (long long)p[1] * p[1]; };
        auto cmp = [&](const vector<int>& a, const vector<int>& b) { return dist2(a) < dist2(b); };  // 距離の2乗が大きいほど優先
        priority_queue<vector<int>, vector<vector<int>>, decltype(cmp)> heap(cmp);
        for (auto& p : points) {  //@scan
            heap.push(p);
            if ((int)heap.size() > k) heap.pop();  //@evict
        }
        vector<vector<int>> res;
        while (!heap.empty()) { res.push_back(heap.top()); heap.pop(); }  //@drain
        sort(res.begin(), res.end(), [&](const vector<int>& a, const vector<int>& b) { return dist2(a) < dist2(b); });
        return res;
    }
};
時間計算量O(n log k)。n 個の点それぞれでヒープ操作 (O(log k)) を行います。
空間計算量O(k)。ヒープには常に高々 k 個しか入りません。
別解: quickselect (平均 O(n))

答えの順番を問わないことを使い、配列全体をソートせずに「距離の 2 乗で見て k 番目に小さい値」を基準に左右へ分割する quickselect (クイックソートの分割操作だけを繰り返して k 番目を探す方法) を使うと、平均 O(n) で済みます。最悪ケースは O(n²) ですが、分割の基準をランダムに選べば実用上は問題になりません。

vector<vector<int>> kClosest(vector<vector<int>>& points, int k) {
    auto dist2 = [](const vector<int>& p) { return (long long)p[0] * p[0] + (long long)p[1] * p[1]; };
    int lo = 0, hi = (int)points.size() - 1;
    while (lo < hi) {
        long long pivot = dist2(points[hi]);
        int p = lo;
        for (int i = lo; i < hi; i++) if (dist2(points[i]) < pivot) swap(points[i], points[p++]);
        swap(points[p], points[hi]);
        if (p == k) break;
        else if (p < k) lo = p + 1;
        else hi = p - 1;
    }
    return vector<vector<int>>(points.begin(), points.begin() + k);
}

よくある間違い

  • 最小ヒープを使い、距離が近い点を先に追い出してしまう (追い出すべきは「最も遠い」点なので、ヒープの先頭には最大値が来る最大ヒープが必要です)。
  • 比較のたびに sqrt を呼んでしまい、余計な計算と浮動小数点の誤差のリスクを増やす。距離の 2 乗のままで比較できます。
  • x, y が最大 10^4 なので x² + y² は最大で約 2 × 10^8 になり、int の範囲 (約 2.1 × 10^9) にはまだ収まりますが、他の問題で値が大きくなる場合に備えて long long で計算する習慣をつけておくと安全です。

確認問題

Q1. 距離の 2 乗で比較してよいのはなぜですか?

距離はどちらも 0 以上なので、a < b ⟺ a² < b² が成り立ちます。大小関係さえわかればよいので、2 乗のままで比較しても結果は変わりません。

Q2. なぜ最小ヒープではなく最大ヒープを使うのですか?

ヒープに残しておきたいのは「近い方から k 個」です。サイズが k を超えたときに追い出すべきは「その中で最も遠い点」なので、先頭に最大値が来る最大ヒープが必要です。最小ヒープだと先頭が最も近い点になり、間違って一番良い点を追い出してしまいます。

Q3. k = points.length のときはどうなりますか?

ヒープのサイズが points.length を超えることがないので、追い出しは一度も起きません。全ての点がそのまま答えになります (順番は距離の順に並び替えられます)。
