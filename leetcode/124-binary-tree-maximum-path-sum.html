124. Binary Tree Maximum Path Sum

木の中のどこからどこまでを通ってもよい道の中で、値の合計が最大になる道を探す。各ノードで「自分を頂点にして左右へ少し降りる道」の最良を記録しつつ、上へは一方向だけを持って返す。

問題

二分木における道 (path) とは、並んだノードの列であって、列の中で隣り合うどの 2 つのノードの間にも辺 (エッジ) があるものです。1 つのノードは列の中に 1 回しか現れません。道は根を通る必要はありません。

道の道の和 (path sum) とは、道の中のノードの値の合計です。

二分木の根 root が与えられたとき、空でない道のうち道の和が最大になるものの値を返してください。

例

root = [1,2,3] → 6
最適な道は 2 -> 1 -> 3 で、道の和は 2 + 1 + 3 = 6 です。
root = [-10,9,20,null,null,15,7] → 42
最適な道は 15 -> 20 -> 7 で、道の和は 15 + 20 + 7 = 42 です。根の -10 を含めると和が減るので、この道には含めません。

制約

  • 木のノード数は [1, 3 * 10^4] の範囲。
  • -1000 <= Node.val <= 1000

考え方

道は根を通らなくてもよいうえ、木の中のどのノードから始まり、どのノードで終わってもよいので、素朴に全パターンの道を試すのは大変です。ここで、道の形をよく見ると、1 つの頂点 (道の中で一番上にあるノード) から、左右どちらか一方、または両方へ下がっていく形しかありません。

そこで各ノードについて、「自分を頂点として、左の子方向と右の子方向それぞれへ最大でどこまで値を伸ばせるか (下方向への最大の伸び、gain と呼びます)」を再帰で計算します。

  • 左の子からの gain と右の子からの gain を、それぞれの子に再帰で聞きます。
  • gain が負なら、その方向には伸びない方がよい (0 として扱う。つまりその枝を切る) ことにします。
  • 「自分を頂点にして、左右どちらにも伸ばした道」の和 (自分の値 + 左gain + 右gain) を、答え (全体の最大値) の候補として記録します。これは「道の中で一番上にあるノードが自分であるケース」をすべて尽くしたことになります。
  • 一方で、親に返す値 (自分を通って 1 本道として上へ伸ばせる gain) は、左右どちらか良い方だけを使います。道は 1 本の列なので、親から見て自分を経由してさらに上へ伸ばすなら、自分より下は 1 方向にしか進めないからです。
「答えの候補を記録する」ところと「親へ返す値」が別物であるのに注意してください。答えの候補は左右両方を使ってよい (頂点だから) ですが、親へ返す値は左右の良い方 1 つだけです。
値が負の子方向を 0 にせず素直に足すと、合計を減らす枝まで含めてしまいます。max(gain, 0) で負の方向を切り落とすのが肝心です。

動くデモ

黄色が今計算中のノード、青がその時点で選ばれた全体の最大値 best を作った頂点、グレーが「負なので切り落とした」方向です。

解答 (C++)


class Solution {
public:
    int maxPathSum(TreeNode* root) {
        int best = INT_MIN;
        gain(root, best);
        return best;
    }
private:
    // node を頂点にして、下方向だけに伸ばせる最大の道の和を返す
    int gain(TreeNode* node, int& best) {
        if (!node) return 0;
        int leftGain = max(gain(node->left, best), 0);  //@left
        int rightGain = max(gain(node->right, best), 0);  //@right
        best = max(best, node->val + leftGain + rightGain);  //@best
        return node->val + max(leftGain, rightGain);  //@return
    }
};
時間計算量O(n)。各ノードを 1 回だけ訪れ、その場で左右の gain を使って計算します。
空間計算量O(h)。h は木の高さで、再帰スタックの深さです。

よくある間違い

  • 負の gain を 0 にせず足してしまい、答えが本来より小さくなる。
  • 親へ返す値にも leftGain + rightGain (両方) を使ってしまい、1 本の道として成立しない形 (Y 字で枝分かれした道) を上に伝えてしまう。
  • best の初期値を 0 にしてしまい、全ノードが負の値のとき (例えば木が 1 ノードだけで値が -5) に誤って 0 を返してしまう。ノードが最低 1 個は存在する (空でない道が必須) ので、初期値は INT_MIN にします。

確認問題

Q1. なぜ親に返す値は左右の良い方 1 つだけなのですか?

道は 1 本の列であり、同じノードを 2 回通れません。あるノードを通って「さらに上の祖先」まで道を伸ばすなら、そのノードの下は 1 方向にしか進めないからです。

Q2. 全ノードが負の値だったら答えはどうなりますか?

空でない道が必須なので、1 ノードだけの道が選ばれます。具体的には、木の中で一番大きい (絶対値が一番小さい負の) 値がそのまま答えになります。

Q3. 道の長さ (ノード数) が最大になる問題 (直径、543. Diameter of Binary Tree) とはどこが似ていますか?

どちらも「各ノードを頂点として、左右それぞれの下方向の最良を合わせる」という同じ形の再帰を使います。直径では値の合計ではなく深さを数える点だけが違います。
