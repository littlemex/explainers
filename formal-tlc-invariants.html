この回の前提: 第 08 回 TLA+ 最初の仕様

前回、時計が 1 から 12 を繰り返すという「動き方」だけの仕様を書きました。今回は、常に成り立っているべき条件を不変条件 として書き加え、それが本当に常に成り立つかを TLC に確かめさせます。崩れていた場合に TLC が何を出力するかも見ます。不変条件は、仕様を書いた人が「これは絶対に成り立っていてほしい」と考えた性質を、機械が検査できる 1 つの式として書き下したものです。

1. 不変条件とは何か ― TypeOK を書く

TLA+ は動的型付けの言語で、変数にどんな値を代入しても構文的には通ります。そこで多くの仕様では、変数が思っている種類の値を持っているかどうかを、自分で型チェックの式として書きます。この式はよく TypeOK という名前を付けられ、初期状態でも、どのように遷移した後でも、常に真であるべき条件、すなわち不変条件 (invariant) として扱われます。

例えば、0 から定数 MaxVal までを巡るカウンタ n を考えます。TypeOK == n \in 0..MaxVal と書けば、「n は 0 から MaxVal までの整数である」という条件になります。これが常に真であれば、n が負の数になったり MaxVal を超えたりしていないことが保証されます。不変条件は型の確認だけでなく、「2 つの変数の関係が常に保たれているか」のような、システム固有の性質も同じ書き方で表せます。

プログラミング言語の型チェッカーと違い、TLA+ 自身は n に文字列や集合を代入しても構文として拒否しません。もし Next の書き方を間違えて n が範囲外の値になるような式を書いてしまっても、TLA+ の解析だけではその間違いに気づけません。TypeOK という不変条件を自分で用意し、TLC に検査させることで、初めてその種の間違いを検出できるようになります。これは TLA+ を使う上でのよくある慣習であり、他の仕様でもほぼ必ず最初に書く不変条件です。

2. TLC はどう検査するか ― 到達可能な状態を幅優先に調べる

TLC は、初期状態から始めて Next で定義されたアクションを使い、到達できる状態を幅優先 (breadth-first) に 1 つずつ生成していきます。新しく生成した状態ごとに、指定した不変条件が成り立つかを確認します。すべての不変条件が成り立つなら次の状態へ進み、どこかで崩れていればその場で探索を止めます。

不変条件が崩れた状態が見つかると、TLC は初期状態からその状態まで実際にどう遷移したかという具体的な反例 (counterexample) のトレースを報告します。各ステップでどの変数がどの値に変わったかが順番に並ぶので、どこで何が起きて条件が崩れたのかを後から追えます。到達可能な状態をすべて生成し終えて、どの状態でも不変条件が崩れなければ、TLC は検査が通ったと報告します。ただしこれは、検査に使った小さな定数の範囲の中で保たれているという意味にすぎず、もっと大きな定数でも保たれる保証ではありません。この限界は第 12 回の状態爆発で詳しく扱います。

今回のカウンタのように、不変条件が常に崩れないよう遷移規則が作られている仕様では、TLC はすべての状態を調べ終えて「違反は見つからなかった」と報告します。一方、次回は意図的に不変条件が崩れる仕様を用意し、TLC が実際にどんな反例を出すかを具体的に見ます。

3. .cfg の書き方 ― CONSTANTS・INIT・NEXT・INVARIANT

TLC に仕様を渡す設定ファイル (.cfg) には、何を初期状態とし何を遷移とするかを INIT と NEXT という 2 行で指定する書き方があります。前回使った SPECIFICATION と同じ役割を、別の書き方で指定する方法です。検査したい不変条件は INVARIANT で指定し、仕様の中で CONSTANT と宣言した定数には、.cfg の CONSTANTS で具体的な値を与えます。どちらの書き方でも TLC の動きは変わらず、仕様とは別のファイルに検査の設定を分けておける、という点が共通しています。

---- MODULE Counter ----
EXTENDS Naturals

CONSTANT MaxVal

VARIABLES n

TypeOK == n \in 0..MaxVal
Init == n = 0

Next ==
  \/ (n < MaxVal /\ n' = n + 1)
  \/ (n = MaxVal /\ n' = 0)

Spec == Init /\ [][Next]_n

====

Next の定義は \/ で 2 つの場合に分かれています。「n が MaxVal 未満なら n' = n + 1」と「n が MaxVal なら n' = 0」のどちらか一方が、その時の n の値に応じて選ばれます。このカウンタは、n が MaxVal まで来たら 0 に巻き戻ります。対応する .cfg は次のようになります。

CONSTANTS
  MaxVal = 3

INIT Init
NEXT Next

INVARIANT TypeOK

図: TLC は到達可能な状態を 1 つずつ生成し、毎回 TypeOK が崩れていないか確認する。崩れればその場で反例を出す。
