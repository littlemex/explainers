Engram の発想をどう良くするか
Fable 5.2 と考え、学習し直さずに確かめた

結論から。小さな GPT に入れた Engram の表は、学習用の文章を覚え込み、学習用の文章に一度も出てこなかった 3-gram（直前の 3 トークンの並び）の位置で損をして、得の大半を打ち消していました。そこで、学習で見なかった、または 5 回未満しか見なかった 3-gram の位置だけ、3-gram の 8 行を読まずに 0 にすると、学習し直さずに、テスト用の文章のパープレキシティ（低いほど良い）が Engram の 29.39 から 28.71 に下がりました（3 seed の平均、2.3% 低い）。9 節では学習し直し、学習用の文章と表を 3 つに分けて、各位置に自分の文章を学習していない表だけを読ませると、出現回数の表なしでテストが 28.50（3.1% 低い）になり、暗記がほぼ消えました。8 節では、足切りを出現回数に応じてなめらかにすると 28.59（2.7% 低い）まで下がり、表の得は「見た並びの続きを思い出すこと」から来ていると確かめました。

この文書でやったこと。前の記事の実測を Fable 5.2 に渡して改善のアイデアを 4 往復で出してもらい、Opus 5.5 にその案と実験を厳しく査読させました。そのうえで、公開済みの 3 seed の学習済みモデルを CPU で動かし、学習をし直さない解析と対照実験を回しました。

1. 何をしたか

出発点は、前の記事「DeepSeek の Engram を小さな GPT に組み込み、n-gram の表引きの中身を見る」の結果です。12 ブロックの GPT に Engram を 1 つ入れて WikiText-103 で学習すると、序盤の損失は早く下がるのに、学習を終えた後のテスト用の文章のパープレキシティは Engram なしとほぼ同じでした。この「最後に差が消える」理由を探し、直す方法を考えるのが目的です。

2. 表は学習用の文章を覚え込んでいた

2 つのモデルは同じ順番で同じ窓を読んで学習したので、学習中の損失も同じバッチどうしで比べられます。学習を終える直前の 200 回では、Engram ありの学習損失は Engram なしより 0.151 低いのに、検証用の文章（学習に使っていない文章）では 0.010 しか低くありませんでした。

初めて読む文章が多い間は 2 本の線が重なり、一度読んだ文章が増えるほど学習用の文章の差だけが開きます。このモデルは dropout（学習中だけ一部の計算を止める仕組み）を使っていないので、学習中と評価中で計算が違うせいではありません。表の得の大部分は、一度読んだ文章の暗記です。Fable 5.2 は 2 往復目でこの読み方を「A: 既読の文章の暗記」として挙げ、時系列で見分けられると書きました。

3. 損をしていたのは、学習に無い 3-gram の位置

検証用の文章の 247,296 か所それぞれで、Engram ありとなしの損失の差を取り、その位置で終わる 3-gram が学習用の文章に何回出たかで分けました。回数は、Engram が行を選ぶのに使う「そろえた番号」（大文字と小文字や前の空白だけが違うトークンを 1 つにまとめた番号）で数えています。

検証用の文章の 25.5% の位置は、学習用の文章に一度も出てこなかった 3-gram で終わっていて、そこでは Engram ありのほうが 1 位置あたり +0.098 悪くなっていました。得が最も大きいのは 10〜99 回の帯（-0.093）です。学習に無い 3-gram の位置での損（寄与 +0.0250）は、ほかの帯の得（-0.0350）の約 71% を打ち消していました。

なぜ損をするのかは、表の作りから説明できます。学習用の文章には異なる 3-gram が 38,249,328 種類あり、1 頭の範囲は 65,587 行しかないので、使われた 1 行を平均 583 種類の 3-gram が共有しています。学習に無い 3-gram が読む 8 行には、ほかの 3-gram が書いた中身しか入っていません。一方、行の純度（1 行の読み出しのうち、最も多い 1 種類が占める割合）で分けても差はほぼ同じで、効いていたのは「その行が誰に書かれたか」ではなく、「引く側の 3-gram がその行に書いたことがあるか」でした。

4. ゲートは文脈で選んでいるが、閉じ切れない

ゲートは、読んだ行から作った value を何倍して足すかを決める 0 と 1 の間の数です。前の記事ではゲートの平均が 0.66 で、多くの位置で開いていることから「ゲートは選んでいないのでは」とも読めました。評価のときだけゲートを定数にしてみると、それは違いました。

ゲートを定数 0.66 にすると 29.84 で、ふつうの Engram（28.97）より悪く、Engram なし（29.26）より悪くなりました。ゲートは位置ごとに意味のある選び方をしています。ゲートが低い 20% の位置で表引きを飛ばしても 28.98 で、ほぼ変わりません。ただし、ゲートと 3-gram の出現回数の対数の相関は 0.28 と弱く、ゲートが 0.7 未満の位置（全体の約 34%）ではまだ Engram が損をしていました。ゲートは隠れ状態と key の向きを比べるだけで、その 3-gram を学習で見たかどうかは知りません。

5. 実験: 学習で見なかった 3-gram の行を読まない

3 節の結果から、学習用の文章でほとんど見なかった 3-gram の位置では、3-gram の 8 行を読まないほうが良いはずです。学習し直さずに、評価のときだけ、その位置の 3-gram の 8 行を 0 にしてみました。2-gram の 8 行と、ゲートと足し込みの計算はそのままです。「5 回未満」の位置は、テスト用の文章の 42.9% でした（一度も出ていない 3-gram は 25.8%）。

テスト用の文章では、Engram の 29.39 が 28.71 になり、Engram なしの 29.35 も下回りました。3 seed のどれでも下がり（29.39 → 28.72, 29.55 → 28.83, 29.23 → 28.58）、窓を引き直す bootstrap の 95% 区間でも、Engram に対する下げ幅の上端は対数で -0.0206 と 0 を下回りました。検証用の文章でも 28.97 から 28.33 に下がり、学習に一度も出てこなかった 3-gram と同じ数の位置を無作為に選んで 0 にすると、検証でも 29.79 に悪化しました。

対照の結果から、効いているのは「0 にする位置の選び方」だと分かります。同じ数の位置を無作為に選ぶと 30.71、よく出る 3-gram の位置を選ぶと 32.67、すべての位置で 3-gram の行を 0 にすると 32.14 で、どれもふつうの Engram より悪くなりました。0 にする位置を 1 つ後ろにずらすと 29.24 で、わずかに良くなります。ほとんど見なかった 3-gram は続けて現れやすく、ずらした位置の 64% は元の位置と重なっているためです。重なりの割合に比べて下げ幅がずっと小さいので、ずらすと効き目の大半が消えると読めます。また、同じ位置で Engram 全体を飛ばすと 30.09 に悪化しました。2-gram の 8 行は、3-gram を見ていない位置でも役に立っています。

気を付けること。この足切りは、学習用の文章の 3-gram の出現回数という、Engram なしのモデルが持っていない情報を使っています。そのため「Engram なしより 2.2% 低い」は公平な比較ではなく、言えるのは「同じ Engram のモデルが、出現回数の表を足すと 2.3% 良くなる」までです。また、3 seed はハッシュの係数を共有しているので、どの 3-gram がどの行でぶつかるかは 3 本とも同じです。

6. 改善の形: 見た並びの集合を持つ

この結果を設計に戻すと、Engram に「学習で十分に見た 3-gram の集合」を 1 つ足す形になります。集合を引くのも、行番号を計算するのと同じくトークンの番号だけでできるので、行番号がブロック 0 の計算より前に分かる、という Engram の性質はそのまま残ります。足切りした位置では 3-gram の 8 行を取りに行かなくてよいので、表を GPU の外に置く構成では、読み出しも減ります。

この足切りは、古典的な n-gram の言語モデルの back-off（長い文脈を十分に見ていないときは、短い文脈に落として予想する方法。Katz の方法など）と同じ考え方です。3-gram を見ていなければ、2-gram の 8 行だけを使います。集合の大きさは、5 回以上出た 3-gram（2,931,704 種類）を誤り 1% の Bloom filter（「入っていない」とは決して間違えない、小さな集合の表し方）で持つと約 4 MB で、すべての 3-gram（38,249,328 種類）でも約 46 MB です。Engram の表は float32 で約 270 MB です。

8. もう一歩: 4 往復目のアイデアと、その結果

なめらかな足切りが効くのは、1〜4 回しか見なかった 3-gram にも、続きを覚えている位置が混ざっているからです（下の 3 つめの結果）。前回の足切りではそこも 0 にしていましたが、なめらかな足切りなら少しは読みます。c/(c+2) でもほぼ同じでした（テスト 28.61）。頭ごとの足切りが悪いのは、よく見た 3-gram でも、1 つの行の読み出しのうち自分の分は真ん中で約 5% しかないので、1% や 5% のしきい値では、よく見た 3-gram の役に立つ行まで消えてしまうと考えられます（推測）。

害は、ゲートではなく足し込む中身から来る

Engram の wkv は bias の無い線形なので、3-gram の行を「ゲートに入る key」と「足し込む value」の片方だけから消せます（Fable 5.2 の I-1）。

value からだけ消すと前回の足切りとほぼ同じで、key からだけ消すと、ふつうの Engram とほぼ同じでした。学習に無い 3-gram の位置で損をしているのは、ゲートの開け方の誤りではなく、足し込む中身そのものです。そのため、6 節の案 B（出現回数をゲートに入れる）より、案 A（学習時から足切りする）が本命になります。0 の代わりに平均で埋める案（I-2）は、0 より少し悪くなりました。

表は「次に来る語」を覚えている

3 節では、位置をその位置で終わる 3-gram の出現回数だけで分けました。ここでは、さらに「その 3-gram のすぐ後に、いま当てるべき語が来る並び（4-gram）が、学習用の文章にあったか」でも分けました（I-3）。当てるべき語を使うので、推論には使えない解析専用の分け方です。検証用の文章の 47% の位置で、その 4-gram が学習にありました。

差を決めているのは 3-gram の出現回数よりも、「次の語まで含めて学習で見たか」でした。1,000 回以上出たよく知られた 3-gram でも、次の語が学習に無かった位置では Engram が損をしています。表の得は、見た並びの続きを思い出すことから来ており、続きが違えばその分だけ外れます。2 節の「学習用の文章でだけ得が大きい」とも合います。出現回数の足切りが効くのは、回数の少ない 3-gram ほど、次の語が学習に無い位置の割合が高いからです。

推論時の工夫で取れる分は、ほぼ取り切った

足切りで下がった損失のうち、0 にした位置そのものの分は -0.0191、それ以外の位置の分は -0.0030 で、効き目のほとんどは切った位置に出ていました（I-5）。一方、学習に無い 3-gram の位置は、足切りした後も Engram なしより 1 位置あたり +0.034 悪いままでした（足切り前は +0.098）。2-gram の行と、表に仕事を預けて育った backbone の分が残っていると考えられます（推測）。ここから先を取るには、学習し直す必要があります。

4 往復目のアイデアの一覧

#アイデア状態結果、またはねらい近い先行研究（Fable 5.2 の記述）
I-1足切りを key と value に分ける実施害は value 経由。value だけ消すと前回の足切りと同じ効き目、key だけでは効かないpath patching（Goldowsky-Dill ら 2023）と同じ形
I-20 ではなく平均で埋める実施0 より少し悪い。捨てるmean ablation
I-3次の語も学習にあったかで分ける実施どの回数の帯でも、次の語が学習にあれば得、無ければ損。表は続きを覚えているWitten-Bell、Kneser-Ney
I-48 頭の読み出しの揃い方から、見たことのない 3-gram を当てる未実施当たれば Bloom filter が要らなくなるHash Embeddings（Svenstrup ら 2017）
I-5足切りの効き目がどこに出るか実施効き目の大半は切った位置そのもの。切った後も、学習に無い 3-gram の位置は Engram なしより悪い—

II-2学習中に一部の 3-gram の行番号を無作為に差し替える未実施（学習が要る）学習中に、見たことのない並びの行を読む練習をさせる確かでない（Fable）
II-3ハッシュの係数を変えて 1 本学習する未実施（学習が要る）改善案ではなく、3 seed が係数を共有している測定の穴を埋める—

9. 学習し直して確かめた: 表を 2 つに分けると暗記が消える

8 節で、推論時の工夫で取れる分はほぼ取り切ったと分かったので、学習し直す案を 3 つ試しました。学習の設定は前の記事と同じで（3,600 ステップ、1 本あたり GPU 1 枚で約 28 分）、窓の取り方も同じ乱数で同じにしています。

案学習のときにすること
学習時から足切り（6 節の案 A）3-gram の出現回数から自分の 1 回を引いた数が 5 未満の位置で、3-gram の 8 行を 0 にする。評価のときは引かずに数える
学習時から、なめらかな足切り同じ数え方で、3-gram の 8 行を c/(c+5) 倍にする
表を 2 つに分ける（8 節の II-1）学習用の文章を記事ごとに交互に A と B に分け、表も A と B の 2 つにする。A の記事の位置は B の表の値を読み、勾配は A の表に流す（B の記事はその逆）。評価のときは 2 つの表の平均を読む。表 1 つの行数は半分にして、全体の大きさを元と同じにした

表を 2 つに分けると、どの表も、自分が学習した文章の位置では一度も読まれません。そのため学習中も、検証と同じく「表がまだ見ていない並び」を読む場面が自然に現れます。

学習時から足切りしても、暗記は残りました。学習用の文章での得は -0.150 で、ふつうの Engram（-0.151）とほとんど同じです。2 周目には、5 回以上出た 3-gram の続きも、2-gram の行も覚えられるからだと考えられます（推測）。成績も、ふつうの Engram に推論時の足切りを足したほうが良く、案 A は 6 節で決めた「推論時の足切りより 0.3 以上下がる」に届かず不合格です。

表を 2 つに分けると、暗記がほぼ消えました。学習用の文章での得は -0.151 から -0.007 に縮み、検証での得は -0.010 から -0.025 に増えました。3 seed のどれでも、検証とテストの両方でふつうの Engram より下がっています。

10. まだ分からないこと

  • 表を分ける方法は、大きな規模でも効くか。9 節の結果は、1.18 億トークンを約 2 周する 1 つの規模だけです。1 周しかしない大規模な学習では、表が既読の文章を読む場面がもともと少ないので、効き目は小さいかもしれません。表の行数を増やした場合も、2 つに分けた版の 1 seed しか測っていません。
  • 大きな規模でも同じか。1.18 億トークンを約 2 周する小さな設定では、検証の位置の 26% の 3-gram が学習に無く、1 行を約 583 種類が共有します。1 周しかしない大規模な学習では、暗記の量も衝突の量も違います。
  • ハッシュの組み合わせが変わっても同じか。3 seed はハッシュの係数を共有しているので、どの 3-gram がどの行でぶつかるかは同じです。
  • n-gram の統計を足すだけの方法と比べてどうか。足切りは、学習用の文章の出現回数という、Engram なしのモデルが持っていない情報を使っています。Engram なしのモデルに n-gram の言語モデルを混ぜる方法との比較はしていません。
