第 19 章 探索の勝者を引用してはいけない。床推薦 10 通りのうち 9 通りは保証されていなかった

この章の 3 行 第 18 章は「同じ質問を二度する」ことで自分の見出しを三度ひっくり返した。今回ひっくり返ったのは その二度する道具そのもので、しかも見つけたのは繰り返しではなく他人が既に書いた論文だった。 571 問で 480 通りの方策から最良を選ぶと勝者の精度は 6.7 ポイント上振れし、 5 床 × 2 run の 10 通りのうち 9 通りで推薦は引用された床を満たしていなかった。

1. 何が問題なのか。宝くじを 480 枚買って一番当たった 1 枚を見せる

この機構がやっていることは単純である。候補の組み合わせ・停止条件・エスカレーション先を全部列挙して 方策を作り、「精度がこの床を超えるもののうち、いちばん安いもの」を返す。第 18 章までの 「80% 床なら API 不使用で $0.00048」「85% 床で $0.00306」はすべてこの返り値である。

問題は、方策を採点した項目と、方策を選んだ項目が同じことにある。571 問での精度は真の精度の まわりにばらついた推定値で、480 通り分そのばらつきを引いてから最大値を選べば、勝者の推定値は 真の値より高い側に張り出す。これは測定の誤りではなく、探索の性質である。正しく測っても起きる。

直感で見る 真の精度がぴったり 85.0% の方策を 480 通り用意して、全部を同じ 571 問で採点する。どれも真の値は同じ なのに、いちばん高く出たものは 89.1% を示す (互いに独立とした 200 回のシミュレーションの中央値。 範囲は 88.3〜91.4%)。そこで「89% の方策を見つけた」と書けば、存在しないものを報告したことになる。 実際の 480 通りは同じ 8 候補の組み替えなので互いに強く相関しており、この数字はその意味で上限側の 見積もりである。

2. どれだけ上振れるかを触って確かめる

下は、ある方策が 問中いくつ正解したかと、その方策が 何通りの候補から選ばれたかを動かして、保証できる下限がどう動くかを見るものである。上限側は 議論に関係しないので下限だけを出す。

下限は Wilson 区間。探索の補正は Bonferroni (有意水準を α/K に締める)。

触ると 3 つのことが分かる。方策の数を 1 通りにすると、探索の代金はゼロになる — 選んでいない なら払うものはない。項目数を増やすと両方の下限が点推定に近づく — 幅は 1/√n で縮む。そして方策の数を増やしても幅の伸びは緩やかで、しかし止まらない — 分位点は √(log K) のように伸びるので、480 から 2000 に増やしても劇的には 悪化しない。逆に言うと1 通りとの差は最初の十数通りでほとんど付いてしまう — 使う分位点は 1 通りで 1.96、10 通りで 2.81、480 通りで 3.88、2000 通りで 4.21 である。

「精度が足りない」とは言っていない nemotron + qwen-next → terra は両 run で最安の勝者に選ばれていて、点推定は 85.3% と 87.4% である。言えないのは「85% を満たす」という保証の方で、実際の精度が 85% を 下回っているという主張ではない。区間は片側の言明で、「まだ establish されていない」と 「否定された」は別のことである。

4. なぜ繰り返しでは見つからなかったのか

第 18 章の道具は「同じ行列を二度取って、推薦が変わるかを見る」ものだった。今回の 9 件のうち 8 件は run 2 でも同じ方策が勝っている。

未保証の推薦は、普通に再現する 上振れは探索の構造から来るので、二度目の探索でも同じ方向に同じだけ働く。だから 「二度測る」という道具では原理的に検出できない。第 18 章の三つの反転はすべて run 間の ばらつきが原因で、繰り返しがそれを掴めたのは当然だった。この欠陥は種類が違う。

だから機構の側では、この 2 つを別の欄に分けた。再現しなかったとそもそも保証されていないを 同じリストに混ぜると、安定した行列が壊れて見え、逆に片方に畳むと、どこでも保証されていない推薦が 「再現した」だけで通ってしまう。

Reproduction
├─ claims     : run 1 が言ったこと 対 run 2 が言ったこと  (再現の話)
└─ selection  : run 1 の推薦が、それを見つけた探索を払った後も床を満たすか  (保証の話)
                ↑ 第 2 列が存在しない。二度目の収集では治らないし、明らかにもならない

5. 見つけたのは論文だった。そして他に 5 つ見つかった

この欠陥は arXiv:2608.08265 が定式化している。「同じ例で最良固定モデルを選んでから同じ例で 対検定すると、対推論が無効になる」。あの論文の報告は、8 チェックポイント × 4 ベンチで oracle 差は 9.7〜30.7 ポイントあると保証できるのに実運用可能なルータが回収するのはその 7.5〜14.4% だけで、11 方策の最良に同時区間を張ると下限は全条件で 0 になる、というものである。 上の表はその現象の、この規模での実測にあたる。

同じ調査で、この機構が高い代金を払って辿り着いた結論のうちいくつが既に published だったかも 分かった。

6. 閉じたと思っていた道が開いた

第 16 章は「カスケード自身の履歴から『誰も解けない』を予測する」問題に AUC = 0.5000 という 厳密な答えを出した。近似ではなくぴったり 0.5 で、理由は明快である。決定が問題になる瞬間 — 安い層が全部失敗して、いちばん高い層を呼ぶかどうかという瞬間 — では、条件付ける集合が 31 項目すべてで同一 (同じ 8 つの失敗) なので、事後分布も同じ、予測値も同じ 1 つの数になる。 だから学習規則ではなく固定の打ち切り深さにしかなり得ない、という結論だった。

これは正しいのだが、「出力側の信号に限れば」という条件が付いていたことを、今回の調査が 明らかにした。arXiv:2607.08456 は 5 モデル 3 系統 (2B〜14B) で、「この答えは間違いか」と 「そもそも答えられるか」は別の軸だと測っている。

信号「答えられるか」の判別
通常の answer-confidenceほぼ偶然水準
P(IK) / P(True)ほぼ偶然水準
「前提は偽か」とモデルに直接聞くほぼ偶然水準
隠れ状態への線形プローブAUROC 0.69 〜 0.77

しかもこの盲点は規模で縮まらない。論文の言い方が的確で、 「モデルは問題を表現しているが、それを報告しない」。前提確認を指示すると健全な前提まで 争い出して誤った異議が 57% になるが、プローブでその指示をルーティングすると異議の適合率が 約 3 倍になる。二軸で方策を作ると正答被覆 0.75 を保証でき、単一閾値では 0.31 だという。

自前サービングの、数えていなかった価値 API 候補では隠れ状態が取れない。だから API だけのカスケードでは固定打ち切り深さ (請求の 24.4% 節約 / 捨てた仕事の 9.7% を失う) が唯一の選択肢のままである。 しかし自前で回している箱では隠れ状態が取れる。これは「安いモデルを自前で持つ」ことの 価値として、費用の表にも品質の表にも一度も載っていなかった項目である。 第 17 章の logprob margin (AUC 0.838) はこの方向の一番浅い版で、まだ出力側の信号である。

ただし置き換えではなく仮説である。論文の「答えられない」は主に答えが存在しない、前提が偽で あって、こちらの 51 件は答えはあるが誰も届かない問題である。同じ軸が通るかは分からない。

7. で、どうすればいいのか

3 つあり、どれも正当で、値段が違う。

  1. 床に余裕を持たせる。 上の表の関係を素直に読むと、480 方策・571 問の規模では 床 + 7 ポイントの点推定を要求すれば保証が出る。運用がいちばん簡単で、いちばん高い。
  2. 探索を小さくする。 480 通りは「メンバーは 3 つまで」で出てくる数である。2 つまでに 落とすか候補を先に絞れば補正が軽くなる。ただし絞る操作を同じデータでやると同じ罪を犯すので、 絞る根拠は別の fold から来る必要がある。
  3. 項目を増やす。 幅は 1/√n で縮むので、571 から 2,284 に増やせば半分に なる。いちばん高い。

なお使った Bonferroni は保守的である。480 の方策は同じ 8 候補を同じ 571 問で組み替えたもので 互いに強く相関しているから、本当に必要な同時性の要求はこれより弱く、adj は達成可能な 下限より低い。その方向を選んだ理由は 1 つで、ここで直している欠陥は「測っていない精度で推薦が 配備される」ことだからである。低すぎる下限は配備を遅らせるだけだが、高すぎる下限は配備を 承認してしまう。

8. この章が主張しないこと

自前サービングの箱は上の表に入っていない。現在配信されていないので二度目が取れず、 API 8 候補のみの部分集合である。したがって第 18 章の「80% 床なら API 不使用で $0.00048、 85% 床で $0.00306」も点推定であって保証ではないが、その表に補正を当てるには箱を含む表で 方策数を数え直す必要があり、まだやっていない。80.1% と 85.0% という値が床にほとんど余裕を 持っていないことから、結果は予想できるがそれは予想である。

文献側は arXiv の検索とアブストラクトだけで、本文は読んでいない。だから 「見つからなかった」は「存在しない」ではなく「この検索語では出てこなかった」である。 第 5 節の 2 つの空白の主張はその弱さを負っている。引用した数字はすべて各論文のアブストラクトからで、 こちらで再現したものではない。

言えるのは、探索の勝者は点推定で引用できないということ、その代金はこの規模で 3.5 ポイントあるということ、そしてそれを見つけたのは繰り返しではなく文献だったという ことである。
