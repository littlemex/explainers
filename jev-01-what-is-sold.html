TypeSafe が 2026-09-15 に公開した Jev について、公開文書から確実に取れる事実だけを並べ、 そのうえで「賢さ」を支えている測定が何を測っているのかを検算します。

一言でいうと
Jev の速さと安さは第三者も確認しています。しかし賢さの証拠は、正解表を使わない自作の測定 1 種類だけで、 その測定は「賢い 2 モデルの確率の平均」をお手本にしています。 お手本が 2 者のちょうど中間にあるので、お手本の 2 者自身は満点を取れず、平均を写すだけのモデルが満点を取れます。 「お手本に近い」と「正しい」は、この設計では切り離されています。
1. 公開されている事実 2. 唯一の定量証拠が何を測っているか 3. 中間の利得 — 教師が満点を取れない 4. 2 者がそろって誤る問題 5. 「安い」は何と比べた数字か 6. 一番安い反証

1公開されている事実

意見を混ぜず、公開記事とドキュメントから取れることだけを置きます。

項目内容
性格文章を書かない。決められた選択肢から選び、複数の質問の答えを 1 回の計算でまとめて返す
値段入れる文章 100 万トークンあたり 0.042 ドル。出す答えは無料
速さ0.07〜0.5 秒。比較対象の生成モデルは 3〜329 秒とする
宣伝193.6 倍速い、444.6 倍安い、System One タスクで最上位モデルと同等の知能
型の保証決めた形以外を返せない。「型エラーは数学的に不可能」
入力上限state と質問で共有して約 32,000 トークン。質問を増やすと state の枠が減る
学習RLCD (Reinforcement Learning for Calibrated Decisions)。目的だけ公開、式・データ・構造は非公開
公開ベンチ意図的に一切出さない。「公開ベンチには一切の重みを置くな」を作法として提示
唯一の定量証拠自作の workflow evals 4 本。正解ラベルを使わず、GPT-6 Astra と Fable 5.1 の確率の平均をお手本にする

自分で認めている留保も記事に並んでいます。測定は自社のチームが作った、お手本が OpenAI と Anthropic 寄りになる、デモの入力は自社に有利な形、うそ率 0% は実測でなく型の保証からの演繹、 Wikiracing の比較では相手の AI をわざと「じっくり考えないモード」にした。

ここが構造的におかしい。「公開ベンチは出さない」と「自作の測定は正解を使わない」が同時に成立しています。 つまり Jev の賢さについて、外部の正解と見比べて検証された数字は 1 つも存在しません。 弱点を自分で列挙している姿勢は誠実ですが、弱点の列挙は証拠の代わりになりません。

2唯一の定量証拠が何を測っているか

Jev の予測を p、Astra と Fable の確率ベクトルを a と f、お手本を r = (a+f)/2、外部の正解を y とします。 TypeSafe が測っているのはお手本への距離 D(p, r)、賢さや正答率として必要なのは正解への損失 L(p, y) です。 D が小さくても、お手本自身の損失 L(r, y) が分からなければ、絶対的な正しさは何も分かりません。

学校のテストで言えば、採点を正解表ではなく、よくできる生徒 2 人の答案の真ん中とくらべている状態です。 以下、この採点でどんなことが起きるかを 2 つ見ます。

3中間の利得 — 教師が満点を取れない

距離が二乗誤差だとすると、教師 a 自身のスコアは次のようになります。

‖a − r‖² = ‖a − (a+f)/2‖² = (1/4)·‖a − f‖²

f も同じです。つまり Astra と Fable が完全一致しない限り、どちらも満点にならない。 一方、2 者の平均をそのまま再現するモデルは距離ゼロ、すなわち満点です。 教師より賢くなくても、教師より高いスコアが取れる設計になっています。

図 1. お手本が中間にあるので、教師の 2 者は必ずお手本から離れ、中間を狙う模倣器だけが満点を取る。 「Jev がグラフの右下を独占」という図の縦軸は、この性質を持つ採点で作られている。

42 者がそろって誤る問題

Astra と Fable がそろって同じ誤答に 0.9 を置いたとします。お手本もその誤答に 0.9 を置きます。すると、

  • Jev が同じ誤答に 0.9 を置けばお手本と完全一致 → 高得点
  • Jev が正答に 0.9 を置けばお手本から遠い → 減点

2 者は似た教材で育っているので、そろって誤ることは珍しくありません。作った意地悪な例ではありません。

そしてここが振り分けに直接ひっかかります。振り分けで金が生まれるのは、まさに上位モデルが外す問題です。 後の回で使う実測でも、安いモデルが高いモデルより良かった問題が 488 問中 44 問、 自前のモデルが高いモデルより良かった問題が 56 問ありました。 上位モデルの答えを正解あつかいする採点は、振り分けがもうかる場所にちょうど 0 点をつけます。

なお「近さ」の測り方 (二乗誤差か、比か、相関か) は公開されていません。どれを使うかで順位が入れ替わるので、 グラフの縦軸そのものが未定義だということになります。あとから都合のよい測り方を選べる状態です。

5「安い」は何と比べた数字か

Jev は 100 万トークンあたり 0.042 ドルです。ふつうの API と比べると、

比較相手倍率
安いモデル (100 万 0.20 ドル)4.76 倍
高いモデル (100 万 10 ドル)238 倍
宣伝の 444.6 倍が必要とする相手100 万あたり約 18.7 ドル

入力単価だけでは 444.6 倍に届きません。出す文章の値段や、長く考えたぶんの値段が入った数字に見えます。 ただし相手が誰なのか、何トークン使ったのか、何回呼んだのか、失敗をどう数えたのかが書かれていないので、 この倍率は確かめようがありません。TypeSafe 自身も「実際の得はこれより小さい方に寄る」と書いています。

条件が入れ替わっている疑い (未確認)。速さの 193.6 倍は 0.07〜0.5 秒 対 3〜329 秒から出ており、 分母はじっくり考えるモードの相手に見えます。一方 Wikiracing の賢さ比較では相手を 考えないモードにしたと自ら書いています。速さは考えるモード、賢さは考えないモードの相手という 組み合わせなら、比較として成り立ちません。早期アクセスで最初に潰すべき事実問題です。

6一番安い反証 — Jev すら要らない

公開されている測定 4 本で、Astra と Fable 自身を採点します。2 者がおたがいにどれだけ一致するかが、 この採点で取れる実際の上限です。Jev の公表点数がその上限を超えていれば、 「中間を写している」ことの決定的な証拠になります。かかるお金は数ドルです。

次に安いのは、正解のある公開データで 2 者がそろって誤る部分集合を作り (数百問で足ります)、 そこでの Jev の正解率を全体と比べること。一致度と正解率が乖離する場所を直接見ます。

この 2 つはどちらも、Jev の内部を知らなくても、公開情報と数ドルの API 費用で実行できます。 賢さの主張は、こんなに安く反証できる形で出されています。

次の回。ここまでは「何を売っているか」でした。次は「中身は何か」です。 Jev は当初エンコーダ型だと考えていましたが、外部の調査は疎な MoE を土台にして、 生成をやめて確率の読み出しを付けたものを指しています。この違いは、後の実験の設計を根本から変えます。
