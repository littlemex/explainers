安全性と活性 ― 悪いことが起きないことと、良いことがいつか起きること

不変条件だけでは「いつか応答が来る」ことは保証できない。TLC の反例で、公平性がなぜ要るのかを確かめる

← 形式検証シリーズ目次へ

この回の前提: 第 09 回 不変条件と TLC、第 10 回 並行のバグを捕まえる

第 09 回では、TLC に不変条件を調べさせて「悪いことが起きていないか」を検査しました。不変条件は 安全性 (safety) という種類の性質の代表です。今回はもう一つの種類、活性 (liveness) ― 良いことがいつか起きる、という性質を見ます。活性を本当に検査するには 公平性 (fairness) という仮定が追加で要ります。小さな仕様と TLC の反例で、その理由を確かめます。

1. 安全性 ― 悪いことが起きない、を正確に言うと

安全性とは「システムが許されたことしかしない」という性質です。AWS の形式手法チームの論文は、安全性を what the system is allowed to do (システムが何をしてよいか) として定義し、例として「常にすべての確定済みデータが存在し正しい」を挙げています。これは第 09 回で検査した不変条件とまったく同じ形の性質です。

安全性には 1 つ気づきにくい性質があります。何もしない振る舞いは、安全性を必ず満たします。 初期状態が不変条件を満たしているなら、そこから一歩も動かず同じ状態に留まり続ける振る舞いは、悪い状態に一度も入らないので安全性に違反しません。つまり安全性だけでは、「システムが実際に仕事を進める」ことまでは保証できないのです。これが、活性という別の種類の性質が必要になる理由です。

図: 初期状態に留まり続けるだけの振る舞いも安全性には違反しないため、安全性だけでは仕事が進むことを保証できない。

2. 活性 ― 良いことがいつか起きる、だが邪魔する振る舞いがある

活性は「システムがいつか必ずすることになっている」という性質です。同じ論文は活性を what the system must eventually do (システムがいつか必ずすることになっているか) として定義し、「要求を受けたら、いつか必ず応答しなければならない」を例に挙げています。TLA+ では「いつか」を <> (eventually) という記号で書きます。

変数 x, y を持つ、次のような小さな仕様を考えます。SetX は x が FALSE の間だけ x を TRUE にできるアクション、ToggleY は y を反転させるだけのアクションです。知りたいのは <>(x = TRUE) ― x はいつか必ず TRUE になるか、です。

SetX ==
  /\ x = FALSE
  /\ x' = TRUE
  /\ UNCHANGED y

ToggleY ==
  /\ y' = ~y
  /\ UNCHANGED x

Next == SetX \/ ToggleY

Spec == Init /\ [][Next]_Vars

この仕様だけでは答えは「いいえ」です。[Next]_Vars は「Next が起きる」か「何も変わらない」のどちらも許すので、公平性がなければ SetX を一度も実行しない振る舞いが仕様に含まれてしまいます。TLC が実際に反例として示すのは、最も単純な「初期状態のまま何もせず止まり続ける」振る舞いです (ログには Stuttering と出ます)。ToggleY だけを永遠に繰り返す振る舞いも、同じく x を FALSE のままにする反例です。第 1 節の「何もしない振る舞いは安全性を必ず満たす」が、活性ではそのまま弱点になるわけです。

3. 公平性で「選び続けない」振る舞いを締め出す

この「ずっと選べるのに選ばれない」という状況をなくすのが 公平性 (fairness) です。弱公平性 WF_vars(A) は、あるアクション A がある時点から先ずっと有効な状態が続くなら、その振る舞いの中で A が少なくとも一度は実行されなければならない、という追加の制約です。

Spec == Init /\ [][Next]_Vars /\ WF_Vars(SetX)

WF_Vars(SetX) を付け加えると、SetX は x = FALSE の間ずっと有効であり続ける以上、いつか必ず選ばれなければならなくなります。この制約のもとでは <>(x = TRUE) が常に成り立ちます。TLC の設定ファイル (.cfg) では、どの性質を検査するかを PROPERTY で指定します。

SPECIFICATION Spec
PROPERTY EventuallyX

公平性は「現実のスケジューラは、できる仕事をいつまでも後回しにし続けない」という仮定を明示する道具です。どの操作に公平性を仮定するかは設計判断であり、何にでも公平性を付けてしまうと、実際には起こり得る「後回しにされ続ける」という状況を見落とすことになります。

図: 公平性が無ければ ToggleY だけの無限往復 (や、何もせず止まり続けること) が反例になり、WF_Vars(SetX) を付ければ SetX がいつか実行される。
