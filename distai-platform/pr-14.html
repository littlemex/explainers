1. なぜ「そのまま」写すのか

元のリポジトリ distributed-ai には、長く保守する基盤と、日付付きの 1 回限りの実験が同居している。基盤だけを新しいリポジトリに移すとき、移す作業と直す作業を同じ PR に混ぜると、レビューする人は「どの差が移したせいで、どの差が直したせいか」を見分けられなくなる。そこで、まず無変更で写して基準にし、直すことはすべて別の Issue (#5〜#13) と PR に分けた。

2. 何が入っているか

写したのは 192 ファイルで、Terraform の本体 (infra/eks の直下の .tf)、Helm chart、運用のスクリプト、テスト、設計の記録 (ADR) からなる。この PR はこれらを読む必要はなく、数と置き場所だけを確かめればよい。

3. 「何も変えていない」をどう証明しているか

PR の Test Plan は、誰でもそのまま流せるコマンドの一続きである。元と先の両方を clone して、中身とファイルのモードを比べる。モードまで比べるのは、スクリプトの実行権限 (38 ファイル) が落ちると、中身が同じでも動かなくなるからである。

  1. 本当に無変更か。Test Plan を流して IDENTICAL と SAME-MODES が出るかを見る。手元で流せないときは、PR の Files changed が「追加のみ、192 ファイル」であることを見る。
  2. 公開してよいか。この PR で公開になるのは、元のリポジトリですでに公開されているものと同じ中身である。そのうえで、新しいリポジトリの名前で出してよくないもの (社内の用語、古い URL) が #13 に挙がっているかを見る。

気を付けること。動いているテスト用クラスタは、このツリーより古い設定で作られていた (CPU のプールの回収の設定が main と違う、Issue #6)。証拠を取るときは、今のクラスタに当てるのではなく、このツリーから作り直したもので取る。
