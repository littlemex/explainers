Flow Matching をゼロから直感で掴む

ノイズがデータへ「流れる」様子を、実際に動かしながら理解する

0この記事の狙い

元記事は最終的に Meta Flow Matching の話ですが、その土台の Flow Matching が分からないと読めません。ここでは Flow Matching だけを、数式より先に「絵と動き」で腹落ちさせます。

一言でいうと
Flow Matching とは「ノイズの点群を、少しずつ動かしてデータの点群に変形する」ための動かし方 (速度場) をニューラルネットに学習させる生成モデルです。各点をどっちにどれだけ動かすかを教える「風向き地図」を学ぶ、と思ってください。
1. 生成モデルの共通目標 — 砂を並べ替える 2. 「流れ」と速度場という考え方 3. 【体験】ノイズがデータに流れる 4. 核心のトリック — 直線でつなぐ 5. 【体験】平均すると魔法が起きる 6. 学習の目的関数 (損失) 7. 生成 = ODE を解くだけ 8. 拡散モデルとの違い 9. 元記事へ — Meta Flow Matching

1生成モデルの共通目標 — 砂を並べ替える

まず「生成する」とは何かを、砂のイメージで揃えます。

画像生成でも分子生成でも、生成モデルがやりたいことは共通です。簡単に作れるランダムなノイズ (標準ガウス分布、つまり中央にこんもり積もった砂山) を、本物のデータが従う複雑な分布 (例えば「猫の画像すべて」が作る形) へと並べ替えることです。

出発点 p₀ = ノイズ (簡単・既知)。到着点 p₁ = データ (複雑・サンプルしか手に入らない)。
生成 = p₀ の砂を p₁ の形に積み替える手順を見つけること。

GAN は「一発で積み替える関数」を敵対的に学び、拡散モデルは「ノイズを少しずつ消す」ことで積み替えます。Flow Matching は「砂の一粒一粒を、連続時間でなめらかに動かす速度」を学ぶ、という第三の道です。

2「流れ」と速度場という考え方

Flow Matching の "flow" が何を指すのかを定義します。

時間 t を 0 から 1 まで動かすとします。t=0 でノイズ、t=1 でデータです。各時刻の砂の積もり方 (確率密度) を pₜ と書き、これを確率パス (probability path) と呼びます。ノイズの山からデータの形へ変形していく「パラパラ漫画」です。

この変形を起こす主役が速度場 (velocity field) vₜ(x) です。これは「時刻 t に、位置 x にいる砂粒は、どの向きにどれだけの速さで動くべきか」を返すベクトルの地図です。天気図の風向き矢印そのものだと思ってください。

# 砂粒 (サンプル) の動き方。速度場に従って流れるだけ
dx/dt = vₜ(x)     # これを t:0→1 で積分すると、ノイズ点がデータ点に着く

速度場と密度の変化は連続方程式 (continuity equation) で結ばれます。「砂は湧いたり消えたりせず、ただ流れて移動するだけ」という保存則です。

∂pₜ(x)/∂t = −∇·( pₜ(x) · vₜ(x) )
ここまでの要点。正しい速度場 vₜ さえ手に入れば、生成は「ノイズ点を放り込んで流すだけ」になります。問題は「その正しい速度場をどうやって学ぶか」です。ここが Flow Matching の核心で、4 章で解きます。

3【体験】ノイズがデータに流れる

まず結論の絵を見ます。学習済みの速度場に従うと、こんもりしたノイズの山が、狙った形 (ここでは二日月・二クラスタ) へ流れていきます。

速さ
ノイズ由来の砂粒 (流れている途中) 本物のデータ分布 (ゴール)

いま各粒は「自分がどこへ行くべきか」を速度場から受け取り、少しずつ移動しています。誰も一粒ごとに行き先を指図していないのに、群れ全体がデータの形に収束します。この "群れを正しい形に運ぶ地図" こそが学習対象です。次章で、その地図をどうやって作るかという一番のキモに入ります。

4核心のトリック — 直線でつなぐ

「正しい速度場」を直接知る方法はありません。ここで Flow Matching の天才的な発想が出ます。

正しい速度場 vₜ* を厳密に書くと、無数のサンプルにわたる期待値と密度の割り算が入り、そのままでは計算できません (元記事の複雑な数式はこれ)。そこで発想を逆転させます。

難しい「全体の地図」を最初から求めるのをやめる。代わりに、ノイズ点 x₀ とデータ点 x₁ をランダムに 1 個ずつペアにして、まっすぐな直線で結ぶ。この直線上の「進むべき向き」なら、誰でも計算できる。

ペアを直線補間します。これを条件付き経路 (conditional path) と呼びます。

# 位置: t=0 でノイズ点、t=1 でデータ点。ただの直線
xₜ = (1 − t)·x₀ + t·x₁

# この直線を進む速度は、時間で微分するだけ。定数ベクトル！
dxₜ/dt = x₁ − x₀

ここが最重要ポイントです。1 本の直線に対する「正解の速度」は x₁ − x₀ という引き算一発で分かります。無数のペアそれぞれについて、この超簡単な正解が手に入る。ではこの「バラバラな直線たちの速度」を教師にしてネットを訓練すると、何が学ばれるのでしょうか。次章で体感します。

5【体験】平均すると魔法が起きる

同じ場所を、違うペアの直線が別々の向きに通り過ぎます。ネットはその「平均の向き」を学びます。すると個々の直線は消え、なめらかな正しい速度場が浮かび上がります。

ノイズ点 x₀ データ点 x₁ 平均速度場 (矢印)

「条件付き経路」では、各ペアがてんでバラバラの直線で交差しながら進みます。混沌に見えます。ところが 「平均の速度場」に切り替えると、同じ位置を通る直線たちの向きが平均され、1 枚のなめらかな風向き地図になります。

魔法の正体。個々の直線 (ペア) の向きは x₁−x₀ で計算できる。ネットに「位置 x と時刻 t を入れたら、そこを通る全直線の向きの平均を答えよ」と学習させる。平均された場は、実は 2 章の計算不能だったはずの正しい速度場 vₜ* と一致することが数学的に証明されています。
つまり「計算できる簡単な教師 (直線の向き) を集めて回帰するだけで、計算できないはずの正解にたどり着く」。これが Flow Matching の一番おいしいところです。

6学習の目的関数 (損失)

5 章の「平均を学ぶ」を、そのまま損失関数として書き下します。難しく見えて、やっていることは二乗誤差回帰です。

本当に最小化したいのは、ネットの速度場 vₜ(x;ω) と真の速度場 vₜ* のズレです。でも vₜ* は未知でした。

# 理想の損失（v* が未知なので、このままでは計算できない）
Lideal = E[ ‖ vₜ(x;ω) − vₜ*(x) ‖² ]

ここで 4 章のトリックを使います。vₜ* を、計算できる直線の速度 x₁−x₀ に置き換えても、最適解が変わらないことが証明されています。こうして実際に回せる損失 (Conditional Flow Matching 損失) になります。

# 実装できる損失：直線の向き(教師) にネットを合わせるだけ
LCFM = E(x₀,x₁), t ‖ (x₁ − x₀) − vₜ( (1−t)x₀+t·x₁ ; ω) ‖²
  1. データ点 x₁ を 1 個、ノイズ点 x₀ を 1 個ランダムに取る
  2. 時刻 t を [0,1] から一様乱数で取る
  3. 直線上の点 xₜ = (1−t)x₀ + t·x₁ を作る
  4. ネットに (xₜ, t) を入れ、出力を「正解の向き x₁−x₀」に近づける (二乗誤差)
  5. 1〜4 を大量に繰り返す。ネットは自然に「平均の向き = 正しい速度場」に収束する
拡散モデルのような複雑なノイズスケジュールや、スコアの重み付けは不要。「直線を引く → その傾きに回帰する」だけ。これが Flow Matching が実装も学習も安定していると言われる理由です。

7生成 = ODE を解くだけ

学習が終われば、生成は驚くほど単純です。

学習済みの速度場 vₜ(x;ω*) があれば、ノイズ点を 1 個サンプルして、常微分方程式 (ODE) を t:0→1 で数値積分するだけです。3 章で見た動きがまさにこれです。

x₀  ~  ノイズ   # スタート地点をランダムに引く
dx/dt = vₜ(x;ω*)   # 学習済みの風に乗って流す
x₁ = x₀ + ∫₀¹ vₜ(x;ω*) dt   # 到着点が生成サンプル

数値積分は最も単純にはオイラー法で、x ← x + v·Δt を数十ステップ回すだけ。拡散モデルが数百〜千ステップ必要だったのに対し、Flow Matching は経路が直線に近いため少ないステップで生成でき、速いのが実利上の強みです。

8拡散モデルとの違い (ざっくり)

「結局、拡散モデルと何が違うの？」に答えます。

観点拡散モデルFlow Matching
学習するもの各時刻のノイズ (スコア ∇log p)速度場 vₜ(x) (動く向き)
ノイズの入れ方決められた確率過程 (SDE)自分で決めた任意の経路 (例: 直線)
経路の形曲がりくねる直線に近づけられる
生成ステップ数多い (数百〜)少なくて済む (速い)
実装の素直さノイズスケジュール等が煩雑直線を引いて回帰、と単純
ただし対立概念ではありません。拡散モデルは Flow Matching の枠組みで「特定の曲がった経路を選んだ特殊ケース」として書き直せます。Flow Matching は「経路を自由に設計してよい」一般化であり、その中で一番素直な直線を選んだのが人気の Rectified Flow です。

9元記事へ — Meta Flow Matching とは

ここまでで Flow Matching が分かったので、元記事の主題に橋渡しします。

通常の Flow Matching が学ぶのは 1 本の平均的な速度場 vₜ(x) です。条件付き版 (CFM) では、人間が与えるラベル c ごとに vₜ(x|c) を学べます。しかしどちらも学習時に見た分布にしか対応できません。

元記事の Meta Flow Matching (MFM) は、ここをさらに一段抽象化します。ラベル c の代わりに、初期分布 p₀ そのものの形をネット (GNN) で読み取って埋め込み φ(p₀) を作り、それを条件にします。

FM  : vₜ(x)          # 1 本の平均軌道
CFM : vₜ(x | c)      # 人間が与えたラベル c 別
MFM : vₜ(x | φ(p0))  # 初期分布の形そのものを条件にする
MFM の本質。「ある分布からある分布への移動の答え」ではなく、「任意の分布を見せられたら、どう動かすべきかという解き方」を学ぶ。だから学習時に一度も見ていない新しい分布 (元記事の未知の文字 X, Y や、新しい患者の細胞集団) にも、「風に乗るように」正しく対応できる。これが「確率分布空間 (Wasserstein 多様体) の上でダイナミクスを学ぶ」というタイトルの意味です。

つまり元記事は、Flow Matching を「個々のデータ点を動かす」レベルから「分布そのものを動かす」レベルへ持ち上げた研究です。本記事の 1〜7 章 (点を速度場で流す) が完全に土台になっているのが分かるはずです。
