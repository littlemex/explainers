 03 ・ カーネル融合の本命

FlashAttention

N×N のスコア行列を作らず、Q・K・V をタイルに分けて SRAM 上で Attention を計算する。中間行列 HBM 書き出しの無駄、online softmax で走りながら厳密に補正する仕組み、O(N²)→O(N) のメモリ削減を動くアニメで理解する。

プロファイラの読み方

当て推量ではなく、プロファイルでボトルネックを一意に特定する。Eager → Compile → Compile+NKI の 3 段階比較で host overhead を切り分け、エンジン稼働率・DMA キュー・理論値とのギャップを読む力を動くアニメで身につける。

 05 ・ オンチップに刻む

タイリング

SBUF に載りきらない大きな行列を、固定サイズのタイルに分割して処理する。なぜ 128×512 なのか ― partition 128 と PSUM バンク幅 512 というハードウェアの制約からタイルの形が導かれることを、数式と動くアニメで理解する。

 06 ・ 形が性能を決める

データレイアウトと並列化

Trainium では全ては 2D (128 partition × free)。どの軸を partition に置くかで transpose の要不要が決まり、reduction は free 軸に沿う。レイアウト設計と access pattern、そして並列化への拡張を動くアニメで理解する。

 07 ・ エンジンを遊ばせない

ソフトウェアパイプラインと allocation

あるタイルを計算する裏で次のタイルを先読みする二重バッファ。手動 allocation でアドレスの曖昧さを消すとコンパイラが自動でパイプライン化できる。逐次とパイプラインのガントチャート比較で腹落ちさせる。
